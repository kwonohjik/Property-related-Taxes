# 재개발 신고서 양식 표 — 합계 일관성 + 1세대1주택 가시화

## Context

사용자 사례 입력으로 화면에 표시된 결과에 4가지 의문:

| # | 화면 | 사용자 기대 | 진단 |
|---|---|---|---|
| 1 | 필요경비 합계 **0** | 9M (양도비) | **코드 버그** — line 593이 line 505 덮어쓰기 |
| 2 | 양도차익 합계 **148M** | 741M | 12억 안분 후 과세대상 (라벨 misleading) |
| 3 | "1세대1주택 + 12억 안분"이 무근거 발동 | 1세대1주택 여부 확인 절차 필요 | **엔진 가드는 있음**, **UI 가시성 부족** |
| 4 | 검산식 (양도가-취득가-필요경비) 불성립 | 일관된 합계 | §166②1호 의제구조 본질 — 안내 부재 |

## 원인 정리

### A. 코드 버그 (즉시 수정)
`FilingFormTableHelpers.ts:593`이 line 505에서 설정한 분기 합 9M을 `estimatedLumpDeduction ?? 0`로 덮어쓴다.

### B. 12억 안분 자동 발동 가시성 부재
엔진은 가드 있음:
```ts
// transfer-tax-redevelopment.ts:60,80-83
const isOneHouseSingle = input.isOneHousehold === true && input.householdHousingCount === 1;
const isHighValue = isOneHouseSingle && input.transferPrice > 1_200_000_000;
const redev = isHighValue ? applyHighValueAllocation(...) : redevRaw;
```

**문제**: 1세대1주택 입력이 **Step4 "보유 상황"** 단계에 있고, **Step1의 재개발 자산 카드와 분리되어** 사용자가 잊거나 의식 못 함. 결과 화면에도 가시화되지 않음.

→ 사용자는 "근거 없이 12억 안분이 자동 적용된" 것으로 인식 (실제로는 Step4 입력에 따른 결과).

### C. §166②1호 의제구조 본질
재개발 양도차익은 단순매매 산식이 아닌 3분기 의제 안분 합. 사례 45 anchor 12개로 검증된 값(산출세액 11,311,377)이 정확. 단:
- 12억 안분 전 양도차익 총액 ≈ 741M (실가 산식)
- 12억 안분 후 (과세대상) ≈ 148M
- 안분 비율 = (1,500 − 1,200) ÷ 1,500 = 0.2 → 741 × 0.2 = 148.2 ✓

화면 행 라벨 "전체 양도차익"은 사실 **12억 안분 후 과세대상**이라 misleading.

## 수정 방향

### 수정 1: 필요경비 합계 버그 (즉시)
`FilingFormTableHelpers.ts:583-593`의 redev-3split 블록에서 line 593 (`setNum("expenses", "total", r.estimatedLumpDeduction ?? 0)`) 제거. line 505의 분기 합이 유지됨.

### 수정 2: 재개발 결과 카드 — 1세대1주택 + 12억 안분 적용 여부 명시
`RedevelopmentDetailCard.tsx`에 신고서 양식 표 위 안내 박스 추가:

**1세대1주택 + 12억 초과 케이스 (현재 사례)**:
```
[1세대1주택 적용] [12억 초과 안분 적용]
  - 1세대 여부 / 세대 보유 주택수 1채: Step4 입력값 기반
  - 양도가액 1,500M > 12억 → §95③·시행령 §160 안분
  - 과세대상 비율 = (1,500 − 1,200) ÷ 1,500 = 20%
  - 12억 안분 전 양도차익: 741M (참고)
  - 12억 안분 후 (과세대상): 148M
```

**다주택 또는 1세대1주택 미적용 케이스**:
```
[일반 과세 (12억 안분 미적용)]
  - 1세대1주택 미적용 (사유: 다주택·1세대 아님 등) → §95③ 비과세 안분 없음
  - 전체 양도차익 ≈ 741M 모두 과세대상
```

데이터: `result.redevelopmentDetail.highValueAllocation`이 부착되어 있으면 1세대1주택 + 12억 초과 케이스, undefined면 일반 과세 케이스.

### 수정 3: 신고서 양식 표 헤더 §166 의제구조 비고
표 상단에 1줄 안내 (emerald 박스):
> 시행령 §166②1호 의제구조 — 분기별 양도가·취득가는 의제 안분값입니다. 합계 행의 단순 산식(양도가 − 취득가 − 필요경비) 검산은 본문 산식이 아닙니다.

### 수정 4: "전체 양도차익" 라벨 명확화
`FilingFormTableHelpers.ts` rowOrder에서 재개발 모드일 때 라벨 분기:
- 12억 안분 적용 시: "**과세대상 양도차익 (12억 안분 후)**"
- 12억 안분 미적용 시: "**과세대상 양도차익**"
- 12억 안분 전 원본 양도차익 행을 보조 표시 (선택, 합계 열만)

### 수정 5: Step1 재개발 자산 카드 — 1세대1주택 입력 가이드
`RedevelopmentBlock.tsx`에 안내 박스 1개 추가 (sky tone, ⓘ 아이콘):
> 1세대1주택 + 12억 초과 비과세 안분은 다음 단계 "보유 상황 → 세대·주택 현황"의 입력에 따라 자동 적용됩니다. 다주택·1세대 미해당이면 전체 과세됩니다.

가시성: `propertyType === "redevelopment_apt"` 진입 시 항상 표시.

## 검증

### 자동
- `npx tsc --noEmit` 0건
- `npx vitest run __tests__/tax-engine/transfer-tax/redevelopment/` 회귀 0건 (엔진 미변경이라 자동)

### 수동
- **사례 1 (1세대1주택 + 12억 초과)**: Step4에서 1세대 ON + 1채 → 결과 표 "12억 안분 적용" 배지, 양도차익 148M, 필요경비 9M 표시
- **사례 2 (1세대1주택 + 12억 이하)**: 양도가 1,000M으로 재계산 → "전액 비과세" 또는 일반과세 분기 확인
- **사례 3 (다주택)**: Step4에서 1세대 ON + 2채 또는 3채 → "일반 과세 (12억 안분 미적용)" 배지, 양도차익 741M(= 분기 합) 표시, 12억 안분 없음
- **사례 4 (1세대 미해당)**: Step4에서 1세대 OFF → 사례 3과 동일 처리 확인

## 사용자 정정 안내

수정 후 결과 카드에 다음 정보가 노출됨:
- (a) 1세대1주택 적용 여부 (Step4 입력값 표시)
- (b) 12억 안분 적용 여부 + 비율
- (c) 12억 안분 전·후 양도차익 비교
- (d) 신고서 양식 합계 행은 §166 의제구조라 단순 검산 불성립 명시

→ 사용자가 "왜 148M인지" 명확히 추적 가능.
