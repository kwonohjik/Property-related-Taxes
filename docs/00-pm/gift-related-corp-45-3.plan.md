## 2. 계산식 — ★3개 비율 분리 (혼동 금지)

### 2.1 §45의3①2호 계산식
```
증여의제이익 = 세후영업이익 × (특수관계법인거래비율 − 거래비율차감) × (주식보유비율 − 보유비율차감)
```

⚠️ **아래 4개 비율은 별개 개념**. **중소기업은 우연히 거래50·보유10으로 ⑦⑨와 같아 본 사례에서 구분이 안 보임** → 중견·일반 분기 구현 시 반드시 분리:

| 비율 | 용도(단계) | 일반 | 중소 | 중견 | 근거 |
|---|---|---|---|---|---|
| 정상거래비율 | 과세요건(3) | 30% | 50% | 40% | §34의3⑦ ✓실측 |
| 한계보유비율 | 수증자(4) | 3% | 10% | 10% | §34의3⑨ ✓실측 |
| **계산식 거래비율차감** | 증여이익(6) | 5% | 50% | 20% | §45의3①2호 박스 ⚠️**미렌더**→흐름도 |
| **계산식 보유비율차감** | 증여이익(7) | 0% | 10% | 5% | §34의3⑬: 가목=한계보유비율·나목=한계×50% ✓실측 / 다목0=흐름도 |

- **보유비율차감 확정 근거**(§34의3⑬ 본문): *"가목 「한계보유비율을 초과하는 주식보유비율」 / 나목 「한계보유비율의 100분의 50을 초과하는 주식보유비율」"* → 중소 10%·중견 5%(=10%×50%). 일반(다목)은 §34의3⑬ 미언급 → 흐름도 0%.
- ⚠️ **거래비율차감(5/50/20)은 법 본문 박스 미렌더** → 흐름도 보충. **중소(50%)만 정상거래비율과 일치, 중견(20%≠⑦40%)·일반(5%≠⑦30%)은 다름**. → **Design 단계 법령집/유권해석으로 거래비율차감 본문 재확인 필수**(추정 금지). 사례 재현(중소)은 50% 확정 → anchor 영향 0.
- 차감 후 음수는 0.

## 4. 계산 파이프라인 (8단계 — 양 검토자 실측 검증 ✓)

- 갑 간접 = B경유 30%×30%=9% + C경유 10%×10%=1% = **10%**

### 단계 3 — 거래비율·과세요건 (수혜법인 단위 1회, §45의3①1호)
- 특수관계매출 = 3,000+10,000+2,000 = **15,000**

## 5. 핵심 함정 (Pre-Do anchor 선검증)

1. **3개 비율 혼동** ★★★ — 정상거래비율(§⑦ 30/50/40)·한계보유비율(§⑨ 3/10/10)·계산식 차감비율(거래 5/50/20·보유 0/10/5)은 별개. **중소만 우연히 같아 사례로 구분 불가** → 엔진 상수를 3종 분리 정의, 중견·일반 anchor 별도(법령검토 F-1~F-4). 거래비율차감 본문은 Design 재확인.
2. **정확분수 vs 교재반올림** ★★★ — 갑 직접 = 1,296,000,000 × (1/12) × 0.19 = **20,520,000원**. 교재 8.33% 반올림 = 20.51백만. 합계 36,720,000 vs 교재 36.71백만. **엔진=정확분수, anchor=정확값, 교재차 주석**. (memory `project_gift_capital_decrease_multi`·`bigint-round-half-up`)
3. **한계보유비율 간접 우선차감 — 음수 방지 로직** ★★★ (§⑬·법령검토 F-9) — 단순 뺄셈(간접−한계) 시 음수. 반드시 단계7 `min/max` 패턴. anchor로 음수 불발생 검증.
4. **수증자별 과세제외매출 상이** ★★★ (§⑭3호) — 세후영업이익·거래비율이 수증자마다 다름. `rulingShareholderStakes`를 **shareholderId로 매칭**해 각 수증자 D출자분만 가산(코드검토 #4).
5. **지배주주판정 간접 ≠ 수증자판정 간접** ★★ — 판정용 모든경유(C포함, 갑 간10), 수증자/증여이익은 §⑱법인 경유만(C제외, 갑 간9). **2모드 헬퍼 분기**(코드검토 #5).
6. **`recipientBreakdown[]`·집계는 배열/Record (Map 금지)** ★★★ — Map은 `NextResponse.json`에서 `{}` 소실→크래시 (memory `feedback_engine_result_map_json_loss`·코드검토 #2).
7. **§⑲ 단일법인 의제** ★ — 특수관계법인별 분할 금지, 합산 1건.
8. **`computeWeightedPerShare` 부적합** ★ — §39 증자후 1주평가용. §45의3 비율곱은 `safeMultiplyThenDivide`(tax-utils:104)·`applyRateFraction`(:121) 직접 사용(코드검토 #11).

## 6. 입력 데이터 모델 골격 (옵션 A — Design에서 정밀화)

> 정확 shape는 `gift-related-corp-45-3.engine.design.md`. **Simplicity First**: 사례 범위(2단계 간접: 개인→법인→수혜법인)로 한정. 다단계·나목 1천억·다목은 SCOPE_OUT(YAGNI).

### 6.1 3층 구조 (memory `feedback_flat_vs_nested_form_field_decision` — 코드검토 #8)
- **폼(UI) = string flat row** (`RcShareholderRow`·`RcIntermediaryRow`·`RcSalesRow`) — 기존 cap-table·cd-multi 패턴.
- **Adapter** = `gift-deemed-api.ts` `buildDeemedGiftInput` case에서 string→number·분수 변환 + nested 조립 (= ⑬ body, 코드검토 #1).
- **엔진 = nested number/분수**:
```
RelatedCorpInput
├ enterpriseSize: "small" | "medium" | "large"     // 정상·한계·차감 3비율 분기
├ 수혜법인: totalSales, preTaxAdjOperatingIncome, taxableIncome, corporateTaxNet(=산출세액−공제감면, F-10)
├ shareholders[]:    { id, name, relation(self/relative/other), directRatio{n,d}, isCorporate }
├ intermediaryCorps[]: { corpShareholderId, stakeInBeneficiary{n,d},
│                        owners[]: { individualId, ratio{n,d} } }   // → §⑱ 자동판정 + 2모드 간접보유
└ salesPartners[]:   { id, name, salesAmount, isRelated,
                       exclusionType?: ExclusionType,                // ⑩ enum (1·5호 등)
                       rulingShareholderStakes[]?: { shareholderId, ratio{n,d} } } // ⑭3호 수증자별 매칭
```

### 6.2 엔진 자동 산출 경로
- 간접보유 **2모드**(`computeIndirectRatio(mode: "ruling"|"recipient")`): ruling=전경유, recipient=§⑱법인(`owners`에서 **단계1 산출 지배주주등(지배주주+친족)** 합산 30%↑ 자동판정, F-11) 경유만. ★판정 순서: 단계1(ruling 간접→지배주주·친족 확정) → 단계4(지배주주등 확정 후 §⑱ 간접출자법인 판정→recipient 간접) — 순환 없음.
- 지배주주(직+ruling간접 최고) → 특수관계매출·과세제외매출·거래비율 → 수증자(직+recipient간접>한계) → **수증자별** 세후영업이익(rulingStakes 매칭 D출자분)·거래비율 → 직접/간접 증여의제이익.
- cross-field(지분합 등)는 **validate/useMemo 파생** — useEffect→store 미러링 금지(memory `mirror-pattern`·코드검토 #9).

### 6.3 결과 타입
```
RelatedCorpResult (DeemedGiftResult 확장)
├ deemedGiftValue: number          // 전 수증자 합계 (36,720,000)

│    recipientName, directGain, indirectGain, subtotal,

└ rulingShareholder, tradeRatio, taxableExcludedSales ...  // echo
```
