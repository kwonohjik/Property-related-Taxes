## 0. 실측

종부세 2단계 주택 카드, **저장된 동·호가 없는 상태**에서 상세주소 칸에 입력했다. 상세주소 칸이 보이는 두 경우를 모두 쟀고 결과가 같았다.
- 고를 세대가 없는 주소(개별주택처럼 동·호가 빈 행)
- 세대 목록 조회 실패(502)

같은 입력을 현재 master와 #2343 이전 코드(카드가 `value`에 동·호를 넘기지 않음)로 비교했다.

## 1. 원인

- 이 카드에는 상세주소를 저장할 필드가 없다. 칸 값은 저장된 동·호를 이어 붙인 것이다(`PropertyCardEditor.tsx:105`).
- 입력은 `onChange({ ...value, detail })`(`components/ui/address-search.tsx:295~296`) → 카드의 띄어쓰기 파싱(`PropertyCardEditor.tsx:144~151`) → 저장 → 다시 합성으로 돈다.
  - 「1」처럼 「동」·「호」가 없는 중간 입력은 빈 값으로 파싱되고, 합성된 칸이 그 즉시 비워진다(#2343 이전부터).
  - #2343이 `value`에 저장된 동·호를 넣었다(`:108~113`). 동이 저장된 뒤 입력에는 `v.dong`이 실려 파싱을 건너뛰고(`v.dong ?? …`), 저장된 동으로 다시 합성된다 → 「동」에서 멈춤.
- #2343 검증은 동·호가 **이미 저장된** 상태의 입력만 쟀다. 저장된 동·호가 없을 때 한 글자씩 치는 경로는 재지 않았다.

## 2. 수정안

- **R1. 이 카드에서는 상세주소 칸을 그리지 않는다.**
  - `AddressSearch`에 선택 prop `hideDetailInput?: boolean`을 둔다(기본 `false` — 다른 호출부 동작 그대로).
  - `true`면 세대 목록이 없을 때의 상세주소 칸(`address-search.tsx:474~485`)을 그리지 않는다. 세대 드롭다운·「동/호수 조회 중...」·`knownHasUnits` 안내는 그대로다.
  - `PropertyCardEditor`만 `hideDetailInput`을 넘긴다. 동·호는 드롭다운(세대가 있을 때)과 별도 「동」·「호수」 칸(늘 보임)으로만 입력한다.
- **R2. 카드의 상세주소 파싱을 걷어낸다.** R1 뒤에는 파싱할 상세주소 입력이 없다. 남는 `onChange` 경로는 주소 선택(`detail: ""`)·지우기(`""`)·동 선택(`detail: 동, ho: undefined`)·호 선택(`dong`·`ho` 실림)이다. 네 경로 모두 파싱 결과가 `v.dong ?? ""`·`v.ho ?? ""`와 같은지 Do에서 실측으로 확인한 뒤 `onUpdate({ …, dong: v.dong ?? "", ho: v.ho ?? "" })`로 바꾼다. 같지 않은 경로가 나오면 R2는 하지 않는다.
- #2343(R1 — `value`에 동·호 전달)은 그대로 둔다. 다시 열 때 목록 복원과, 단동·칸 비움에서 다른 세대 가격이 들어가던 결함 차단이 그것에 달려 있다.

## 4. 구현 순서

1. R1: `AddressSearch` `hideDetailInput` + `PropertyCardEditor` 전달
2. R2: 네 `onChange` 경로의 파싱 결과 동치 실측 → 같으면 파싱 제거
3. 회귀 spec 갱신·추가, 뮤테이션

## 5. 검증 계획

- **회귀 E2E**(`comprehensive-property-card-dongho.spec.ts` 갱신)
  - 신규 H-1: 세대가 없는 주소 → 상세주소 칸이 없다 → 별도 「동」·「호수」 칸에 한 글자씩 「101동」·「501」을 치면 그대로 저장되고 조회가 `dong=101동 ho=501`로 간다
  - 신규 H-2: 목록 조회 실패 → 상세주소 칸이 없다 → 저장된 동·호가 그대로이고 조회가 그 세대로 간다(K-3 대체)
  - K-5 대체: 세대를 고르지 않은 주소는 다시 열어도 목록을 다시 부르지 않는다(요청 횟수) — 파싱 단언은 뺀다
  - K-1·K-2·K-4는 그대로 통과해야 한다
  - R2를 하면: 동만 고름 → 호가 비워진다 · 다른 주소 선택 → 동·호가 비워진다 · 지우기 → 비워진다
- **반례**(다른 호출부): `address-dongho-remount-other-calcs`·`transfer-address-units-remount`·렌더 테스트 `address-dongho-remount-callers` 그대로 통과(상세주소 칸이 있는 호출부)
- **뮤테이션**: `hideDetailInput` 조건 제거 → H-1·H-2 실패 / 카드에서 prop 전달 제거 → 같음
- **기존 E2E**: `comprehensive-*` 전 spec · 주소 검색을 쓰는 spec
- **pre-push 게이트**: 워크트리라 husky가 돌지 않는다. 폰트·톤·다크 짝·러너, typecheck, lint, 범위 선택 테스트를 수동으로 돌린다
