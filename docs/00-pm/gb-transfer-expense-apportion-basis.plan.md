## 0. 한 줄 요약

일반건물(실거래가 경로)은 양도비를 토지·건물로 나눌 때 **양도시 기준시가 비율**을 고정으로 쓴다(`general-building-route-actual.ts:360`). 사용자가 정한 규칙 «양도비는 자산가액으로 배분한다 — 실가나 감정가액이면 그 가액으로, 환산가액이면 기준시가로»는 이 한 줄과 어긋난다: 구분 기재(실가)·감정평가가액으로 양도가액을 나눈 경우에도 양도비는 기준시가로 나뉘어 **양도가액과 양도비가 서로 다른 비율**이 된다.

- **전수 조사 결과**: 같은 성격의 배분은 split·PHD·겸용(새 안분)·컴패니언 묶음이 **이미 «적용 양도가액 비례»**다(§2.2). 규칙과 어긋나는 곳은 일반건물의 **3곳**(실가 경로 · 증축 경로 · 환산 경로 자산총액 swap)뿐이다.
- **«자산가액»의 해석이 갈린다**(양도측 vs 취득측, §3). 양도측(= 각 파트에 **적용된 양도가액**)으로 읽는 것이 코드 어휘(`saleSplitMode: actual/appraisal/apportioned`)·겸용 선례(R-2)와 맞고, **환산 파트와 실가 파트가 섞여도 같은 잣대**가 선다. 취득측으로 읽으면 환산 파트(기준시가)와 실가 파트(실가)가 한 비율에 섞여 단위가 맞지 않는다. 권장은 양도측이나 **사용자 확인이 필요하다**(Q-1).
- **실측**: 실가 경로에서 구분 기재 70:30·양도비 5,000,000이면 토지분 3,771,045 → 3,500,000(파트 배분만 이동). **세액은 두 파트의 세율·공제 속성이 같으면 불변**(취득일 동일 시 343,740,000 그대로)이고, 속성이 다르면(토지 1999·건물 2022 취득) 27,321원 ~ 2,103,354원 변동한다(§4.1).
- **기존 테스트**: 실가·증축 변경은 기존 테스트 29,490건 실행에서 **기대값 변경 0건**(§4.5 — 통과 29,139건, 최초 실패 39건은 단독 재실행 시 통과한 부하성 실패). 환산 swap까지 바꾸면 **2건**(F9 배분 basis 앵커·W-1b 차액)이 바뀐다 — 기존 설계 앵커를 뒤집는 것이라 별도 결정이다(Q-5).
- **부수 발견(현행 결함)**: 상세명세서 «자산별 양도비» 산식이 새 입력(양도비·자본적지출)에서는 `0 × 920,550,000 / (…) = 3,771,045`로 **값을 못 만드는 산식**을 낸다(§4.4). 배분 기준을 바꾸면 이 표시를 같이 고쳐야 한다.
- **소수 비율 곱 1원 과소**(`Math.floor(x * ratio)`)는 일반건물 4곳 · 환산 swap 2곳 · split/PHD 3곳에 있다. 공용 정수 헬퍼 `apportionByStdPrice`(`lib/tax-engine/std-price-apportion.ts:20`)로 바꾼다(§5.6). 실무형 입력의 발생률은 0~0.016%로 낮지만 정책(정수 연산)상 같이 고친다.

## 1. 사용자 규칙과 법령

### 1.1 사용자 규칙 (2026-10-22, 그대로 따른다)

> 양도비는 **자산가액으로 배분**한다. 자산가액이 **실가나 감정가액**이면 그 실가 또는 감정가액으로, **환산가액**이면 **기준시가**로.

종전 규칙(2026-08-07 «P-2 확정 규칙», `gb-actual-path-sale-split-noop.plan.md` §5)은 «양도가액=양도시 · 일괄 취득가액=취득시 · 자본적지출=취득시 · **양도비용=양도시(기준시가)**»였다. 이번 규칙은 그 표의 **양도비용 한 줄**을 «적용 자산가액 비례»로 대체한다. 양도가액·일괄 취득가액·자본적지출 줄은 이번 규칙의 대상이 아니다(Q-4 참조).

### 1.2 법령 (KoreanLaw MCP 2026-10-22 원문 실독)

### 1.3 규칙이 법문과 어떻게 대응하는가

- 후문의 «**해당 자산의 가액에 비례**»가 규칙의 직접 근거다. 법문은 **무슨 가액인지(양도가액 · 취득가액)를 말하지 않고 시점도 정하지 않는다** — 본문의 «취득 또는 양도 당시의 기준시가»는 *구분 불분명 시 안분 방법*에 딸린 문구이고, 후문과 한 문장으로 이어지지 않는다. 따라서 «양도비 = 양도시 기준시가»(종전 P-2)는 법문에서 도출된 것이 아니라 *해석*이었고, 이번 규칙도 *사용자 도메인 규칙*이다. **새 법령 해석을 더하지 않는다** — 법문과 충돌하지 않는 범위에서 후문의 «가액»을 사용자가 정한 대로 읽는다.
- 규칙의 «실가 → 감정가액 → 환산(기준시가)» 서열은 저장소가 이미 쓰는 **양도가액 안분 서열**과 같다: 구분 기재(§100②, 실가) → 감정평가가액(부가령 §64①1호 단서) → 기준시가(같은 호 본문 · 소령 §166⑥). `saleSplitMode`도 `actual / appraisal / apportioned` 3지선다다(`lib/stores/calc-wizard-asset-split-acq.ts:107`). 양도가액 안분 결과가 곧 «각 파트에 적용된 가액»이다.
- 구분 기재가 §100③ 30% 의제로 안분값에 되돌려지면 «적용된 가액»은 되돌려진 값이다 — 양도비도 그 값을 따른다(`allocateBundledTransferPrice` 결과 `allocation`이 이미 그 값).

## 3. «자산가액»의 해석 — 양도측 vs 취득측 (사용자 확인 필요)

| | **양도측 (T) — 권장** | 취득측 (A) |
|---|---|---|
| «자산가액» = | 각 파트에 **적용된 양도가액**(구분 기재 / 감정평가가액 / 기준시가 안분 결과) | 각 파트의 **취득가액**(실지취득가액 / 감정가액 / 환산취득가액) |
| «실가» = | 계약서 구분 기재(`saleSplitMode: actual`) | 파트 실지취득가액(`landAcquisitionPrice` 등) |
| «감정가액» = | 양도시 감정평가가액(`…AppraisalAtTransfer`) | 취득 감정가액(`isAppraisalAcquisition`) |
| «환산가액이면 기준시가로» = | 양도가액을 기준시가로 안분(`apportioned`)했으면 양도시 기준시가 | 환산취득 파트면 (취득시) 기준시가 |
| 코드 어휘와의 정합 | `saleSplitMode` 3지선다 · 부가령 §64①1호 서열 · 겸용 R-2 · split · 컴패니언 묶음이 이미 이 읽기 | 취득가액 3종(실가·감정·환산)과 용어는 맞으나 **양도비는 양도 때 생긴 비용**이라 취득가액 비례의 근거가 약함 |
| **파트 모드가 섞인 경우**(토지 환산 + 건물 실가 등) | 두 파트 모두 양도가액이 있어 **같은 잣대**로 비례 | 환산 파트는 기준시가, 실가 파트는 실가 — **단위가 다른 두 값**을 한 비율로 묶어야 해 성립하지 않는다 |
| 현행과 달라지는 곳 | G1 양도비 · G2 양도비 (· G4 Q-5) | G1 양도비(→ 파트 실지취득가액 또는 취득시 기준시가) · G3(이미 양도가액 — 뒤집어야 함) · split·겸용·컴패니언도 뒤집어야 함 |

⇒ 이 계획서는 **T를 전제로 설계**한다(§5). A를 택하면 이미 부합하는 split·겸용·컴패니언·G3 4개 경로가 오히려 규칙 위반이 되어 범위가 전 경로로 번진다 — 그 선택은 사용자 결정이다(Q-1).

### 3.1 비용 항목별 적용 해석 (T 기준)

| 항목 | 규칙 적용 | 근거·비고 |

### 3.2 해석이 갈리는 지점 (사용자 결정 쟁점)

1. **자본적지출**: 파트별 실지취득가액이 둘 다 있는 경우(`hasBothPartPrices`)에도 현행은 취득시 기준시가를 요구(`requireAcqStd`)하고 그 비율로 나눈다. 규칙을 «실가면 실가로»로 확장하면 그 경우 `landAcq : buildingAcq`로 나눠야 한다 — Q-4.
2. **취득·양도 basis가 다른 경우**(양도 구분 기재 + 취득 환산 등): 양도비는 양도 사실에만 의존하므로 T에서는 영향 없음. A에서는 취득 쪽 basis를 따라야 해 불일치가 생긴다.
3. **환산 파트와 실가 파트가 섞인 경우**: T는 문제없음(G3 이미 부합). A는 성립하지 않음.
4. **legacy 혼합 경비**: Q-3.

## 9. 확인 필요 · 미검증

1. **«자산가액» 해석(Q-1)** — 사용자 규칙 문구만으로는 양도측/취득측이 확정되지 않는다. §3 비교가 판단 재료다.
2. **전체 테스트 불안정**: 최초 전체 실행의 39건 실패(§4.5)는 4파일 단독 재실행에서 통과했다. 베이스라인(프로토타입 없음) 전체를 같은 부하에서 재실행해 동일 증상인지는 *확인하지 않았다*.
3. **실사용 빈도**: 구분 기재·감정평가 + 양도비 + 파트 속성 상이의 3조건 동시 발생률은 telemetry가 없어 알 수 없다. §4.1은 조건이 맞을 때의 크기만 보인다.
4. E2E · 브라우저 · 전체 vitest(`__tests__/e2e` 제외 전건) 미수행.
5. 선행 계획서 §8-1이 인용한 세액(340,195,616 → 340,198,517)은 이 계획서에서 *재현하지 않았다* — 시료가 다르다.
6. **관찰(범위 밖)**: `bundled-sale-apportionment.ts:41-53` `apportionAmount`가 `Math.round`(반올림)를 쓴다 — 프로젝트 정책 «Math.round 금지·세액은 절사»와 어긋나는지 별건 확인 필요. `bundled-companion-split.ts:207,255` 면적 비율 `Math.floor(total * excessRatio)` 1원 과소도 별건.
7. 환산 swap 혼합 모드(G3)·자산총액(G4)의 **불일치 자체**(같은 swap이 모드에 따라 양도비를 다른 basis로 나눈다)는 현행 설계 결과이며, 이번 규칙 적용 여부는 Q-5로 묻는다.
8. 법령 인용: 신규 조문 상수는 없다. §100② 후문을 별도 상수로 두려면 `legal-codes/transfer.ts`와 verify:legal manifest에 등록해야 한다(현재 «후문» 단독 인용은 코드 주석뿐).
