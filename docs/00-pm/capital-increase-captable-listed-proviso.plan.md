# §39 증자 **cap-table 경로**의 주권상장법인 단서 — 조사·구현 계획서 v1.0

> 선행: Phase D(PR#992)가 §39 **sub-case 경로**·§39의3·전환주식·전환사채에 §29②1가·3나 단서를 적용하며 **cap-table 경로는 명시적으로 제외**했다.
> 작성 기준: **추정 금지** — 법문은 KoreanLaw MCP 본문, 수치는 throwaway probe 실측. 미검증은 "확인 필요" 명시.
> ⚠️ 본 계획은 **착수 계획이 아니라 조사 계획**이다. §4의 법령 근거가 확보되기 전에는 세액을 바꾸지 않는다(memory `feedback_unverified_authority_blocks_tax_change`).

---

## 0. 한 줄 요약 / 결론 먼저

**"cap-table에 단서가 미구현"이 문제가 아니다.** PR#992로 sub-case 경로만 고쳐진 결과, **같은 사실관계에서 두 경로가 서로 다른 세액을 낸다.**

| 경로 | B(수증자)의 증여재산가액 | 상태 |
|---|---:|---|
| §39 **sub-case** (§29②1가 단서 적용, PR#992) | **180,000,000** | 현행 |
| §39 **cap-table** (단서 미적용) | **300,000,000** | 현행 — **+120,000,000** |
| cap-table에 단서를 **naive 적용**했다면 | **20,000,000** | ❌ 채택 불가(§2) |

세 값 모두 **probe 실측**이다(§1). 사용자가 「단일」/「다주주」 모드 중 무엇을 고르느냐에 따라 **120,000,000이 갈린다**.

그리고 naive 적용이 왜 안 되는지도 실측으로 확정됐다 — **Phase D 계획서 v1.1 §3-B의 서술을 정정한다**:

> ~~"저가/고가 방향이 주주마다 갈린다"~~ → **정확한 사유는 「zero-sum(balanced) 불변식 붕괴」**다(§2).
> `direction`은 cap-table 입력에서 **전역 단일값**이고 min/max 선택에 쓰이지도 않는다(`capital-increase-allocation.ts:34·63` — 특수관계 게이트 전용). 방향이 주주별로 갈린다는 v1.1 서술은 **코드 실측과 다르다**.

## 1. 실측 (throwaway probe, 재현 입력 포함)

```ts
// 주주 2인 · 저가발행 · 실권주 전량 재배정
const SH = [
  { id: "A", preShares: 60_000, entitledShares:  60_000, subscribedShares:      0, relatedTo: ["B"] },
  { id: "B", preShares: 40_000, entitledShares:  40_000, subscribedShares: 100_000,
    reallocatedShares: 60_000, relatedTo: ["A"] },
];
// preIssuePrice 20,000 · newSharePrice 10,000 · direction "low"
// ⇒ preTotal 100,000 · issuedActual 100,000 · 이론 ㉯ = 15,000
```

| 측정 | 값 |
|---|---|
| `calcCapitalIncreaseAllocation` `perShareAfter` | **15,000** |
| 〃 `byShareholder` delta | A **−300,000,000** / B **+300,000,000** |
| 〃 `reconciliation` | `{ totalGain: 300,000,000, totalLoss: 300,000,000, balanced: true }` |
| 〃 `perBeneficiary[B].total` | **300,000,000** |
| `calcCapitalIncreaseGift` 단서 **無** (동일 사실, `forfeitedShares: 60,000`) | **300,000,000** ⇒ **대수적 동치 확인** |
| 〃 단서 **有** (`isListed: true, listedMarketAvg: 13,000`) | **180,000,000** |
| cap-table ㉯를 13,000으로 **naive 치환** 시 delta | A **−420,000,000** / B **+20,000,000** |

> 📌 **동치가 성립하던 것은 단서 이전까지다.** 단서 없을 때 두 경로가 300,000,000으로 일치했다는 사실이, 단서 적용 후 180,000,000 ↔ 300,000,000으로 갈린 것이 **회귀임을 증명**한다.

## 2. naive 적용이 불가능한 이유 — zero-sum 붕괴 (실측 근거)

cap-table의 `perShareAfter`(㉯)는 **가중평균**이므로 항등식이 성립한다:

```
Σ postValuation = (preTotal + issuedActual) × ㉯ = Σ preValuation + Σ paidIn
⇒ Σ delta = 0  ⇒  totalGain == totalLoss  (reconciliation.balanced)
```

이 항등식 위에 모델의 두 축이 얹혀 있다:
1. **누가 증여자/수증자인지**를 `delta` 부호로 판정 (`:49·70`)
2. **증여자별 배분**을 `손해비례 = −d.delta / totalLoss`로 계산 (`:81`)

단서의 ㉯는 **시장가(외생값)** 라 가중평균이 아니다 ⇒ 항등식이 깨진다. 실측: `Σ delta = −420,000,000 + 20,000,000 = −400,000,000 ≠ 0` (= 200,000주 × (15,000 − 13,000)).

⇒ `balanced: false`가 되고, 배분 분모(`totalLoss` 420,000,000)와 배분 대상(`b.delta` 20,000,000)이 **서로 다른 기준**이 된다. 결과값 20,000,000은 법정 산식값 180,000,000과도 어긋난다. **단순 치환은 어떤 해석으로도 정당화되지 않는다.**

**모델 자체의 정합성 문제이지 법 해석 문제가 아니다** — 이 부분은 근거 조사 없이 확정할 수 있다.

## 3. 선택지 4안 — 각 안이 요구하는 근거

| 안 | 내용 | 위 사례 B 값 | 필요한 근거 |
|---|---|---:|---|
| **A. 호별 산식 재도입** | 수증자별 이익을 §29②1~5 호별 산식으로 직접 계산(sub-case와 동일 경로), 증여자 배분만 손해비례 유지 | **180,000,000** | 배분 기준을 **이론 ㉯**로 두는 것의 근거 (혼합 기준) |
| **A′. 비율 스케일** | 이론 delta에 `(단서㉯ − 인수가) ÷ (이론㉯ − 인수가)`를 곱함 | **180,000,000** | ⚠️ 위 사례에선 A와 일치하나 **일반적으로 일치하지 않는다**(§3-주의). 순수 구성물 — 근거 없음 |
| **B. naive 치환** | ㉯만 교체 | 20,000,000 | ❌ **§2로 배제 확정**(근거 조사 불요) |
| **C. 상장 시 cap-table 차단** | 상장법인이면 다주주 모드를 막고 단일(sub-case) 모드로 안내 | (계산 안 함) | **근거 불요** — 조용한 오답 대신 명시적 차단 |
| **D. 현행 유지** | 단서 미적용 | 300,000,000 | ❌ 경로 불일치 지속 — 이미 회귀 상태 |

> ⚠️ **A′가 A와 일치하는 것은 우연이다(실측).** 수증자 delta는 `(㉯−인수가)×인수신주 + 기존주식수×(㉯−증자전평가)` 두 항으로 분해되고 **두 항이 ㉯에 다르게 반응**한다. 위 사례 B: 이론 `5,000×100,000 + 40,000×(−5,000) = 300,000,000`, 단서 `3,000×100,000 + 40,000×(−7,000) = 20,000,000`. 단일 비율 스케일(3/5 → 180,000,000)은 이 구조를 재현하지 못하며 **오직 특정 파라미터에서만 호별 산식과 같아진다**. ⇒ **A′는 후보에서 제외 권고**.

**⇒ 실질 후보는 A(근거 필요)와 C(근거 불요)뿐이다.**

### A의 걸림돌 — 모델 설계 취지와 충돌

cap-table의 설계 취지는 파일 상단 주석에 명시돼 있다(`capital-increase-allocation.ts:6~7`):

> 「이는 교재 호별 산식(§29②1~5)과 대수적으로 동치이며 … **유형 추론 없이 case-independent하게** 6사례를 재현한다」

A는 「다목」(배정받은 실권주수 / 초과분 신주수 / 제3자배정 신주수)을 cap-table 입력에서 **유형별로 도출**해야 하므로 case-independent를 포기한다. `forfeitedBy()`(`:26~29`)가 실권주는 이미 계산하지만, 다목(제3자배정)·라목(초과배정) 분기는 **현재 도출 경로가 없다** — **확인 필요**(입력만으로 유형 판별이 가능한지 실측 필요).

## 4. 법령 조사 프로토콜 (D-0 게이트 — 이 단계 통과 없이 착수 금지)

### 4-1. 이미 시도한 검색과 결과 (2026-08-02, KoreanLaw MCP)

| 도메인 | 질의 | 결과 |
|---|---|---|
| `tax_tribunal` | "증자 실권주 재배정 상장법인 증자후 1주당 평가가액 단서" | **0건** |
| `tax_tribunal` | "증자 실권주" | 72건 — 훑은 15건 중 **상장법인 단서 + 다수 증여자 배분 직접 쟁점 0건** |
| `nts` | "증자에 따른 이익 증여자별 안분 다수 증여자" | **0건** |
| `nts` | "증자 상장법인 평가가액" | 1건(「증자시의 증여의제가액 계산시 **비상장**법인의 증자전 1주당 평가가액」, 2003.10.10) — **본건 무관** |

⇒ **현재까지 직접 근거 미발견.** 아래 4-2를 수행하기 전에는 A를 채택할 수 없다.

### 4-2. 남은 조사 항목 (순서대로)

1. **「증여자별 배분」의 법적 지위** — §39는 「이익을 얻은 자」의 증여재산가액만 정하고 증여자 특정·배분 산식을 두지 않는다(§29②1~5 본문 확인 완료). 배분은 §47(증여자별 과세표준)에서 요구되는 것이므로, **배분 기준이 이익 산정 기준과 달라도 되는지**가 A의 핵심 쟁점이다.
   - 조사처: 「상증법」§47·§4의2 본문 재확인 · `tax_tribunal` "증여자별" · `nts` "증여자별 과세가액" · §39의3 저가에서 이미 채택한 **조심2010서3741**(현물출자 증여자별 구분계산)의 논거가 §39에도 미치는지.
2. **상장법인 실권주 재배정 실사례** — `tax_tribunal` 72건 중 상장법인 사안 필터링(현재 훑은 15건은 대부분 비상장·명의신탁). `precedent` 도메인 병행.
3. **호별 산식 다목의 cap-table 도출 가능성**(법령 아닌 **코드 실측**) — `CapShareholder` 입력만으로 가·다·라목을 구분할 수 있는지. 불가하면 A는 입력 필드 추가를 수반한다.

### 4-3. 종료 판정 (기계적)

- 4-2의 1이 **긍정 근거 확보** → **A 착수**(§5).
- 근거 **미발견 또는 상충** → **C 채택**(§6). 조용한 오답보다 명시적 차단이 낫다 — memory `feedback_no_unfavorable_application_without_legal_basis`·`feedback_no_silent_apportion_fallback`의 취지.
- 어느 쪽이든 **B·D는 채택하지 않는다**(§2·§0).

## 5. A 채택 시 구현 스케치 (근거 확보 전 착수 금지)

- `CapitalIncreaseAllocationInput`에 `isListed?`·`listedMarketAvg?` 추가(sub-case와 동일 필드명).
- 수증자별 이익 = 호별 산식(`applyListedPerShareBound(theoretical, input, direction === "high" ? "max" : "min")` 기준) — sub-case와 **같은 헬퍼**를 쓴다.
- 증여자 배분(`donors`·`totalLoss`)은 **이론 ㉯ 기준 유지** → `reconciliation.balanced` 불변식 보존.
- 결과에 `theoreticalPerShareAfter` echo + 「배분 기준은 이론값, 이익 산정은 단서값」을 결과뷰에 명시(2원 기준을 숨기지 않는다).
- **14지점**: ①②(폼 `ciAllocIsListed`·`ciAllocListedMarketAvg`) · ④ API · ⑤ UI(`CapitalIncreaseAllocationFields`) · ⑧ validate(상장 ON·평균 ≤ 0 차단) · ⑨ 타입 · ⑬ Zod(`capitalIncreaseAllocationSchema`) · ⑩⑪ 결과 표시. ③⑫⑭ N/A.

## 6. C 채택 시 구현 스케치 (근거 미확보 시 기본값)

- `CapitalIncreaseAllocationFields`에 상장 토글을 **두지 않는다**(현행 유지).
- 대신 **안내 카드**: 「주권상장법인은 §29②1가·3나 단서로 증자 후 1주당 평가가액이 달라집니다. 다주주 모드는 이 단서를 반영하지 않으므로, 상장법인은 **단일 모드**로 계산하세요.」
- ⑧ validate 차단은 **하지 않는다** — 비상장 다주주 사용을 막지 않기 위해. 상장 여부를 다주주 모드가 알 방법이 없으므로 **안내에 그친다**(자동 판정 금지).
- 비용 ≈ UI 10줄 + anchor 1건. 경로 불일치는 **해소되지 않고 문서화**된다.

## 7. anchor 설계 (A·C 공통 선행)

착수 여부와 무관하게 **지금 고정해야 하는 것**이 하나 있다 — 두 경로의 현재 값 차이다.

| ID | 내용 | 기대 |
|---|---|---|
| **CT-1** | §1 입력으로 cap-table 실행 | `perShareAfter` 15,000 · B 300,000,000 · `balanced: true` |
| **CT-2** | 동일 사실 sub-case(단서 無) | 300,000,000 — **두 경로 동치** |
| **CT-3** ⭐ | 동일 사실 sub-case(단서 有 13,000) | 180,000,000 — **경로 불일치 120,000,000을 명시적으로 동결** |

CT-3은 "이 차이를 알고 있다"는 표시다. A 착수 시 CT-1이 180,000,000으로 바뀌고 CT-3과 일치하게 된다(그때 anchor를 갱신). C 채택 시 CT-1·CT-3은 **그대로 유지**되고 안내 카드 anchor가 추가된다.

> ⚠️ anchor 파일 주석에 **"이 불일치는 의도된 미해소 상태이며 근거 조사 대기 중"**을 명시한다. 명시 없이 두면 다음 사람이 "버그"로 보고 naive 치환(B)을 시도한다.
