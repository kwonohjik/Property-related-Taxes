## 1. ⚠️ 범위 재정의 — 「8호·9호 의제」보다 넓다

선행 계획서는 C를 「§104⑤ 후단 **8호·9호 동일 자산 의제** 미구현」으로 적었다.
조사해 보니 **그것은 더 큰 공백의 한 조각**이었다.

> §104⑤ 본문: 「해당 과세기간에 제94조제1항제1호ㆍ제2호 **및 제4호**에서 규정한 자산을
> **둘 이상 양도**하는 경우 …」

**§104⑤은 부동산(§94①1·2호)과 기타자산(§94①4호)을 원래 한 덩어리로 본다.** 그런데 우리는
부동산 엔진과 주식 엔진이 분리돼 있어:

| 조합 | §104⑤ 적용 |
|---|---|
| 부동산 2건 | ✅ `transfer-tax-aggregate` |
| 기타자산 2건 | ✅ `stock-transfer-aggregate` (PR#1026·#1028) |
| **부동산 1건 + 기타자산 1건** | ❌ **전혀 적용되지 않는다** |

⇒ C의 정확한 범위는 **「§104⑤이 부동산 ↔ 기타자산을 아우르지 못한다」**이고,
**8호·9호 동일 자산 의제는 그 안의 특수 규칙**(2호 계산 시 두 호를 한 버킷으로)이다.

## 2. 법령 (본문 전부 확보 — 보류 사유 없음)

| 조문 | 내용 |
|---|---|
| §104⑤ 본문 | 「§94①1호ㆍ2호 **및 제4호** … **둘 이상 양도** … 각 호의 금액 중 **큰 것**」 |
| §104⑤1호 | 「해당 과세기간의 양도소득과세표준 **합계액**에 §55①의 세율」 ⇒ **부동산 + 기타자산 전부 합산** |
| §104⑤2호 | 「§104①~④·⑦에 따라 계산한 **자산별** 산출세액 합계액」 + 예규(재산-536) 「자산별 = **각 호별로 합산한 자산**」 |
| §104⑤ 본문 **후단** | 「제2호의 금액을 계산할 때 **제1항제8호 및 제9호의 자산은 동일한 자산으로 보고**」 ⇒ 부동산 비사토(8호)와 비사토 과다소유법인 주식(9호)이 **한 버킷** |
| 실무 교재 ③ | 「…실질은 비사업용 토지가 양도되는 것과 같다고 보기 때문에 … **누진세율 효과가 반영된 산출세액으로 비교되어야 합리적**이므로 2018.4.1. 이후 양도분부터 … **동일한 자산으로 보아 양도소득금액을 합산하여 세율을 적용**한다」 |

📌 교재는 「**양도소득금액**을 합산」이라 쓰지만, 법문 §104⑤2호는 「자산별 **산출세액**」이고
산출세액은 과세표준 × 세율이다. 부동산 정본도 **과세표준 합산**으로 구현했다
(`clauseBucketKey` → `mergedBase = Σ taxBase`). ⇒ **과세표준 합산**이 맞다(교재 표현이 느슨).

## 3. 실측 — 과소 **25,680,000**

부동산 비사업용 토지 1건(§104①8호) + 기타자산 9호 주식 1건, 2024년 양도:

| | 과세표준 | 세액 |
|---|---:|---:|
| 부동산 비사토 (기본공제 250만 소진) | 243,500,000 | 96,940,000 |
| 기타자산 9호 | 300,000,000 | 124,060,000 |
| **현행 단순합** | | **221,000,000** |
| 「동일한 자산으로 보아」 합산 (543,500,000 × 52% − 35,940,000) | 543,500,000 | **246,680,000** |
| **차이** | | **25,680,000 과소** |

⚠️ **현재 제품에서 이 값을 한 화면에 낼 수 있는 경로는 없다.** 사용자가 두 계산기를 각각 돌려
더하면 221,000,000이 나온다 — 실무상 **틀린 금액**이다.

## 5-A. 🔄 자가 검토 결과 (v1.1) — 초판 설계는 실현 불가능했다

### F-1 🔴 「{호, 과세표준}[]」으로는 **2호를 재계산할 수 없다**

초판은 조정 레이어가 호별 과세표준만 받아 2호를 전면 재계산한다고 했다. **같은 호라도 세율이
입력에 의존하므로 불가능하다**:

- §104①**2호**는 「40%(**주택 등은 60%**)」 — 같은 2호인데 물건 종류로 갈린다
- §104①**1호**도 「§55①에 따른 세율(**분양권의 경우에는 100분의 60**)」 — 1호 안에서 갈린다
  (`transfer-tax-rate-clause.ts:35` · PR#1021 가드가 고정한 함정)
- §104⑦은 **후단 MAX**(단기세율과 비교)가 걸려 있어 보유기간·물건까지 필요하다

부동산 정본이 버킷 대표의 **`rateInput`을 통째로 실어 보내는**(`transfer-tax-aggregate-helpers.ts:528·624`
`calcTax(mergedBase, bucket[0].rateInput)`) 이유가 바로 이것이다 — dual-truth 방지.

⇒ **조정 레이어는 2호를 전면 재계산하지 않는다.** 세율이 **호만으로 확정되는 호**만 재합산하고,
나머지는 각 엔진이 낸 값을 그대로 받는다.

| 호 | 세율이 호로 확정되는가 | 조정 레이어가 재계산 |
|---|---|---|
| §104①**8호·9호** | ✅ 기본세율 + 10%p **단일 표** | ✅ **한 버킷으로 재합산** |
| §104①1호 | ❌ 분양권 60% 예외 | ❌ (C-2b로 분리) |
| §104①2·3호·⑦호·10호 | ❌ 물건·보유기간 의존 | ❌ 엔진 값 그대로 |

### F-2 🔴 「2-3 이관」은 삭제한다

F-1 때문에 부동산 §104⑤ 로직을 조정 레이어로 옮길 수 없다. 옮긴다 해도 얻는 것은 「한 곳에
모음」뿐인데 **anchor 수십 건의 회귀 위험**을 진다. ⇒ 각 엔진은 자기 §104⑤을 **그대로 유지**하고
조정 레이어는 **그 위에 얹힌다**.

### F-8 🟠 1호끼리의 교차 합산은 **C-2b로 분리**

부동산 §104①1호 자산과 기타자산(§104①1호)도 **같은 호**라 예규상 합산 대상이다. 그러나 1호는
분양권 60% 예외가 있어(F-1) 재계산 조건이 8호·9호처럼 깔끔하지 않다.
⇒ **C-2는 교재 ③이 명시한 8호·9호 의제로 범위를 좁힌다.** 1호 교차는 C-2b.

### 정정된 조정 레이어 인터페이스

```ts
interface CrossClauseInput {
  /** §104⑤1호용 — 부동산 + 기타자산 **전체** 과세표준 합계 */
  totalTaxBase: number;
  /** §104①8호(부동산 비사토) 과세표준 */
  clause8TaxBase: number;
  /** §104①9호(비사토 과다소유법인 주식) 과세표준 */
  clause9TaxBase: number;
  /** 8호·9호를 **뺀** 나머지 호의 2호 세액 합 — 각 엔진이 이미 계산한 값 */
  otherClausesTax: number;
  /** §104⑤ 본문 괄호 — 감면세액(F-4). 없으면 0 */
  reductionTax: number;
}
```
- **2호** = `otherClausesTax` + `f₈₉(clause8TaxBase + clause9TaxBase)`
- **1호** = `f_기본누진(totalTaxBase)`
- **MAX** — 단, 비교는 **감면세액 차감 후**로 하고 채택된 호의 **산출세액**을 반환(§104⑤ 본문 괄호)

⇒ 각 엔진은 **「8호(9호) 과세표준」과 「그 외 2호 세액」을 분리 노출**하면 된다(2-1의 정정된 요구).

## 8. 범위 밖

- **차손 통산(§102②)** — 주식 엔진 미구현(PR#1026에서 확인한 별건). 크로스 통산은 더 뒤.
- **부동산 ↔ 주식(§94①3호) 합산** — §104⑤ 본문이 **3호를 열거하지 않으므로 대상이 아니다**.
- 「법인세법 §55의2②」 비사업용 토지 판정 엔진 구현 — 법인의 자산 구성 사실(B 계획서 §7과 동일).

## 9. 착수 판단

- **C-1 ✅ 완료**(PR#1030) — 세액 변경 0, 사용자 보호 효과가 즉시 있다.
- **C-2는 v1.1에서 범위가 줄어 실행 가능해졌다.**
  - 이관(2-3)을 삭제해 **기존 anchor 회귀 위험이 사라졌다**(F-2). R-1도 크로스 경로에서만 발현한다.
  - 재계산 대상을 **8호·9호 한 버킷**으로 좁혀 인터페이스가 5개 숫자로 닫힌다(§5-A).
  - ⚠️ **C-2-3′(최소 입력 1칸)까지 해야 사용자 가치가 생긴다**(F-6). 엔진만 만들면 호출자가 없다.
- **C-2b(1호 교차)는 PR#1021 가드가 고정한 분양권 60% 함정을 먼저 풀어야 한다**(F-8).
- **C-3은 UI 설계가 선행**이다. 통합 마법사인지 교차 입력 확장인지부터 정해야 한다.
  R-2(기본공제 중복)도 여기서만 해소된다.
