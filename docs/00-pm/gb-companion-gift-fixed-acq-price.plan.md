## 2. 재현 (probe 실측)

### 2.1 픽스처
일반건물 컴패니언(2번째 자산) + 토지 1필지 함께 양도(`assetSplitMode: "companion"`, `bundledSaleMode: "actual"`). 일반건물: 양도시 토지 205㎡ × 5,514,000 · 건물 259,072,400, 토지 증여 신고가액(파트) 400,000,000 · 건물 200,000,000, 토지 취득일 2005-05-01 · 건물 2010-05-01. 같은 자산을 **주 자산 위치**에도 둔다(대조).

### 2.2 신고가액(`fixedAcquisitionPrice`) 값에 따른 응답

|---|---|---|---|---|---|

| 〃 | 주 자산 | 347,730,000 | 347,730,000 | 347,730,000 | 347,730,000 |
| 분리 ON · 토지 증여 + 건물 매매 환산 | 컴패니언 | **400** | 354,424,038 | 354,424,038 | 354,424,038 |
| 분리 ON · 토지 증여 + 건물 증여 | 컴패니언 | **400** | 347,730,000 | 347,730,000 | 347,730,000 |

| **분리 OFF 일괄 증여** | 컴패니언 | 400 (⑧도 `fixedAcquisitionPrice` 차단) | 534,134,685 | 347,730,000 | **0** |
| 〃 | 주 자산 | 400 `acquisitionPrice`(⑧도 차단) | 534,134,685 | 347,730,000 | 0 |
| **부담부증여** · 토지 증여 2005 (두 자산 모두 부담부증여 GB) | 컴패니언 | **400** | 178,762,436 | 178,762,436 | 178,762,436 |

- 분리 ON 에서는 값이 파트 가액으로 대체돼 **응답 필드(취득가액 열)까지 같다**(`acq=[100M,400M,200M]` 불변). 분리 OFF 일괄 증여에서는 값이 취득가액을 정하므로 세액이 바뀌고 ⑧도 요구한다 — 정합.
- 주 자산 위치는 분리 ON·부담부증여 모두 200 이다(주 자산 ⑫ 에는 이 요구가 없다).
- 건물 증여 + 토지 매매(자산 단위 취득원인이 매매)는 매매 갈래로 가서 일반건물 제외 — 200(§3 표).
- 와이어(④): 분리 ON 다른 날은 `isSeparateAcquisition: true`(실측). 같은 날은 정의상 false(`transfer-tax-split-acq-mode.ts:401` — 두 날짜가 같으면 false)이고 ④는 다를 때만 true 를 싣는다(선례 `companion-split-fixed-acq-price.plan.md` §1.3) — **같은 날 와이어 값은 직접 보지 않았다(코드 근거)**. `fixedAcquisitionPrice` 는 비어 있으면 안 실린다(실측).

## 4. 원인 · 수정안

### 4.1 원인
`transfer-tax-schema-companion-refines.ts:119-126` — `!isBuildingCauseMixCompanion(c) && fixedAcquisitionPrice 없음` 이면 이슈. 일반건물은 취득가액을 서브객체(`generalBuildingValuation`)의 파트 값(분리 ON) 또는 일괄 값(분리 OFF)이 정하고, 부담부증여는 §159 가 정한다. 자산 전체 칸은 분리 OFF 일괄에서만 쓰인다.

### 4.2 후보 a 의 사전 실측 (임시 적용 → 측정 → 원복, `diff` 확인)
증여 갈래 조건에 `c.burdenedGiftInfo !== undefined || generalBuildingValuation.landAcquisitionPrice > 0` 면제를 넣고 §2.2 의 모든 셀을 다시 쟀다.

| 셀 | 결과 |
|---|---|
| 분리 ON 4셀(다른 날 3 · 같은 날 1) 컴패니언 | 400 → **200**, 세액은 §2.2 주입 값과 같다(347,730,000 · 354,424,038) |
| 부담부증여 2셀 | 400 → **200**, 세액 178,762,436 · 109,572,047 (주입 값과 같다) |
| 분리 OFF 일괄 증여(컴패니언·주 자산) | **그대로 400**(⑧ 차단과 짝) |
| 주 자산 위치 | 불변 |

### 4.3 선택지
| 안 | 내용 | 평가 |
|---|---|---|
| **a. 면제 둘 (권고)** | 부담부증여 면제 + 일반건물 파트 취득가액(`landAcquisitionPrice > 0`) 면제 | 매매 갈래의 별개 취득 면제와 같은 형태. 분리 OFF 일괄은 ⑧·⑫ 가 함께 요구하는 정합 유지. 세액 불변. 주석이 약속한 「부담부증여 제외」를 코드가 이행. |
| b. 판정을 `isSeparateAcquisition` 으로 | 매매 갈래와 같은 플래그 | **같은 날 분리 ON 을 못 잡는다**(정의상 false — 코드 근거, b 를 적용해 재지는 않았다). §2.2 의 같은 날 셀이 계속 400 이 될 것이라 기각. |
| c. 일반건물 통째 제외 | 매매·신축 갈래처럼 `generalBuildingValuation === undefined` 만 | 가장 단순하나 **분리 OFF 일괄 증여의 ⑫ 보호까지 사라진다**(API 직접 호출에서 취득가액 0 가능 — 「확인 필요」). ⑧ 이 UI 를 막으니 화면 결과는 같다. |
| d. ④ 가 파트 합을 `fixedAcquisitionPrice` 로 실음 | 화면에 없는 합성값 | 자동 fallback 금지와 충돌, 환산·감정 파트에서 합이 취득가액이 아님 — #2373 에서 같은 이유로 기각. |
| e. ⑧ 이 자산 전체 칸을 요구 | UI 통과를 막음 | 값이 쓰이지 않는 칸을 요구 · 부담부증여는 칸이 없어 막다른 길. 기각. |

### 4.4 보조 — 화면 정리 (Q-2)
분리 ON 에서 증여 블록의 「증여 신고가액」 칸은 쓰이지 않는 필수 칸이다. 매매 블록은 분리 ON 에서 자산 단위 취득축을 숨긴다(`hideAssetAcqAxis={isSeparate}`). 증여 블록에 같은 게이트(`CompanionAcqGiftBlock` prop 추가)를 주면 ⑫ 면제와 화면이 맞고 사용자가 의미 없는 값을 넣는 일이 없어진다. 칸이 숨겨져도 이미 입력된 값은 상태에 남아 ④ 가 보낼 수 있으나 값이 쓰이지 않아 무해하다(선례 `companion-split-fixed-acq-price.plan.md` §1.4).
