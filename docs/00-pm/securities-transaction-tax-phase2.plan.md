## 0. 한눈에

Phase 1은 현행 세율 단일 + "과거 거래일 경고"로 출시했다(당시 시행일을 2026.1.2로 오인 — 실제 신세율은 영 36001호 **2026.1.1 시행**, §1-2 Critical 정정). Phase 2는:

- **Track A**: 양도일(거래일) 기준 **연도별 탄력세율 자동 적용** — 2021-01-01 이후 양도 전 구간 정확 산출. 경고는 매트릭스 커버 범위 밖(2021-01-01 미만)으로 후퇴.
- **Track B**: 다자산 합산 결과(`StockTransferAggregateResult`)에 증권거래세 **합산 echo 필드** 추가 — 단, 실측 결과 **다자산 UI 자체가 미연결**(아래 §3)이므로 엔진 필드+anchor만, UI는 범위 외.

신규 입력 필드 0 유지 — `transferDate`는 기존 input. 작업 무게중심은 **엔진 세율 결정 로직 + anchor 재설계**.

## 1. 연도별 세율 매트릭스 (KoreanLaw 축자 검증 완료)

### 1-1. 검증 방법·출처

KoreanLaw `applicable_law` 도구로 기준일별 시행 중이던 시행령 버전을 특정·본문 확인:
- 2025-06-15 시점: 영 제35359호(2025.2.28 시행, **MST 269487**) §5
- 2023-06-15·2024-06-15 시점: 영 제33209호(2023.1.1 시행, **MST 247529**) §5
- 2022-06-15 시점: 영 제31448호(2021.2.17 시행, **MST 229429**) §5
- 2021-01-15 시점: 영 제31290호(2020.12.29 공포, **2021.1.1 시행**, MST 225167) §5 — 단서(8·23/10000) 존재 + **부칙 §2 적용례 "제5조의 개정규정은 이 영 시행 이후 주권을 양도하는 분부터 적용"** 축자 확보
- 2026-01-01 시점: **영 제36001호(2025.12.31 공포, 2026.1.1 시행, MST 282431)** §5 — 코스피 5·코넥스 10·3호 20, "현행과 비교 ✅ 동일". **§5 세율 개정의 진짜 주체** (35947호는 부처명 타법개정 — compare_old_new 실측으로 §5 무변경 확인)

2023~2025 버전 §5는 **단서에 연도 구간별 세율을 내장**("2021.1.1~2022.12.31는 1만분의 8, 2023년은 1만분의 5, 2024년은 1만분의 3…")하므로 본문 자체가 연혁표 역할 — 아래 매트릭스는 전부 조문 축자값이다.

### 1-2. 확정 매트릭스 (분자, 분모 10000 고정)

| 양도일 구간 | 코스피 §5 1호 | 코스닥·K-OTC §5 3호 | 코넥스 §5 2호 | 비상장 법 §8① | 코스피 농특세 |
|---|---|---|---|---|---|
| 2021-01-01 ~ 2022-12-31 | **8** | **23** | 10 | **43** (법 §8① 단서) | 15 |
| 2023-01-01 ~ 2023-12-31 | **5** | **20** | 10 | 35 | 15 |
| 2024-01-01 ~ 2024-12-31 | **3** | **18** | 10 | 35 | 15 |
| 2025-01-01 ~ **2025-12-31** | **0 (영)** | **15** | 10 | 35 | 15 |
| **2026-01-01** ~ (현행) | 5 | 20 | 10 | 35 | 15 |

핵심 포인트:
- **신세율(5·20) 시행일 = 2026년 1월 1일** — §5 세율 개정은 **영 제36001호(2025.12.31 공포, 2026.1.1 시행, MST 282431)**. 2026-01-01 시점 조회로 직접 검증(코스피 5·3호 20 + "현행과 비교 ✅ 동일"). Phase 1이 인용한 "영 35947호(2026.1.2 시행)"는 **부처명 타법개정으로 §5와 무관**(신구대조 실측 — §5 변경 없음) → ⚠️ **Phase 1의 경고 경계(2026-01-02)는 1일 오류였음** (§2-3에서 정정 작업 포함).
- **코스피 2025년 구간은 증권거래세 0%지만 농특세 15/10000은 과세** — 농특세법 §4 7호 단서("영의 세율이 적용되는 유가증권시장 양도는 비과세 제외")가 정확히 이 케이스를 위한 단서임이 Phase 1 검증에서 확인됨. → totalTax = 농특세만.
- 비상장 43/10000(2021~2022)은 법 §8① 단서(Phase 1에서 본문 확인: "2021.1.1.~2022.12.31.까지는 1만분의 43").
- 코넥스 10/10000·농특세 15/10000은 전 구간 불변(코넥스는 2022~2026 4개 버전 본문 모두 동일 확인).

### 1-3. 확인 항목 처리 현황 (13단계 검토에서 V-1·V-3 해소)

| # | 항목 | 상태 |
|---|---|---|
| V-1 | 2021-01-01~02-16 마이크로 윈도우 | ✅ **해소** — 영 31290호가 2021.1.1 시행이며 단서(8·23/10000) 포함, 부칙 §2 적용례로 "시행 이후 양도분부터" 명시(§1-1). 2021-01-01 양도분부터 8·23 적용 확정 — §1-2 매트릭스 그대로 유효 |
| V-2 | 2021~22 버전 §5 3호 각 목 구성(K-OTC 나목 존재 여부) | ⏳ **잔여(Do)** — `applicable_law` 응답이 3호 두문·세율만 표시, 가·나목 본문 미표시. `get_historical_law`(MST 229429 또는 225167) §5 전문으로 확인. 불일치 시 K-OTC만 별도 구간열 분리 |
| V-3 | 농특세법 §5①5호 15/10000 기간 불변 | 🔶 **간접 확인** — 2021-06-15 시점 조회 결과 §5① 표는 여전히 파싱 누락이나, 2021~2026 전 개정 부칙 발췌에 §5①**5호** 개정 흔적 0건(2022·2024 개정은 §5①2호 금융투자소득 문구만). 15/10000 불변으로 판단, 표 축자 확인만 Low 잔여(법제처 원문) |

## 2. Track A — 엔진 설계 방침

### 2-1. 데이터 모델 (memory `feedback_historical_tax_tables` — 역사 데이터는 정적 상수)

```ts
// lib/tax-engine/data/securities-transaction-tax-rates.ts (신규)
// 개정 없는 역사 데이터 — DB 아닌 정적 상수. 분모 10000 고정.
export interface StxRatePeriod {
  /** 구간 시작일 (양도일 >= from) — "YYYY-MM-DD" */
  from: string;
  /** 구간 종료일 (양도일 <= to). 현행 구간은 null */
  to: string | null;
  kospiNum: number;
  kosdaqKotcNum: number;   // §5 3호 가·나목 동률 (전 구간)
  konexNum: number;
  unlistedNum: number;     // 법 §8① (한시 단서 포함)
  /** 구간별 인용 — 시행령 버전·단서 명시 */
  reference: string;
}
export const STX_RATE_PERIODS: StxRatePeriod[] = [ /* §1-2 표 5행 */ ];
export const STX_CUTOFF_DATE = "2021-01-01";  // 미만 → 현행 세율 적용 + "당시 세율 미지원" 경고 (§2-2 resolve 2번과 동일)
```

- 농특세 15/10000은 구간 무관 상수 유지(V-3 간접 확인 — §1-3).
- **Date 경계 비교 방식 — Phase 1 패턴 일관 (실측)**: Phase 1 구현이 `new Date("2026-01-02")`(UTC ISO 자정) vs `transferDate`(date-coerce 경유 Date) 비교(`securities-transaction-tax.ts:169-173` 실측). 구간 from/to도 동일하게 `new Date("YYYY-MM-DD")` ISO 파싱으로 생성 — **로컬 타임존 생성자(`new Date(2026,0,2)`) 혼용 금지**(KST 9시간 오차로 경계일 오판). 경계 포함관계는 anchor A-26~29로 고정.

### 2-2. resolve 로직

```
resolveStxRates(transferDate?: Date): { period: StxRatePeriod; cutoffWarning: boolean }
1. transferDate 미제공 → 현행 구간 + 경고 없음 (Phase 1 동작 보존 — inline 미리보기에서 양도일 미입력 시)
2. transferDate < 2021-01-01 → 현행 구간 적용 + warning "2021-01-01 이전 양도 — 당시 세율 미지원, 거래일 기준 세율 별도 확인 필요"
3. else → STX_RATE_PERIODS 구간 매칭 (from <= d <= to)
```

- `calcSecuritiesTransactionTax(params, transferPrice)` 시그니처 **무변경** — 내부에서 resolve 호출. UI·메인 엔진·exempt 경로 호출부 3곳 수정 0.
- `SecuritiesTransactionTaxResult` 타입 **무변경** — `appliedRateNum`이 구간값으로 바뀌고 `rateReference`가 구간 인용으로 바뀔 뿐. (UI 카드는 num/den 파생이라 자동 추종 — Phase 1 설계의 보상.)

## 3. Track B — 다자산 합산 echo (실측으로 스코프 축소)

### 3-1. 실측 결과 (2026-06-11)

- 엔진 `calculateStockTransferTaxAggregate`(`stock-transfer-tax.ts:570~`)·route `handleAggregate`·신고서 helpers의 multi-컬럼 분기(`StockFilingFormTableHelpers.ts:84~96`)는 존재.
- 그러나 **클라이언트 연결 0건**: `aggregate=` prop을 신고서 테이블에 전달하는 곳 없음, stock store에 다자산 입력 모드 없음, 결과뷰·Step4·api 변환에 aggregate 참조 없음. → **다자산 UI는 미구현 골격**.

### 3-2. 스코프 결정

- **B-1 (본 Phase)**: `StockTransferAggregateResult`에 합산 필드만 추가 + anchor. UI 없음.
  ```ts
  /** 종목별 증권거래세 echo 합산 (증권거래세분·농특세분·합계 — 이미 floor된 값의 단순합, 안분 없음).
   *  필수 필드 — each_item·aggregate 두 분기 모두 채움(optional 불필요). */
  totalSecuritiesTransactionTax: {
    securitiesTransactionTax: number;
    agriculturalTax: number;
    totalTax: number;
  };
  ```
  - floor 안분 잔액 이슈 없음(종목별 독립 floor 후 합 — memory `feedback_floor_residual_absorption` 비해당, 주석 명기).
  - `each_item`·`aggregate` 두 모드 공통으로 items[].securitiesTransactionTax 합산. 비과세 종목도 echo가 있으므로 포함(별도 세금 — 양도세 비과세와 독립).
- **B-2 (범위 외 — 별도 기능)**: 다자산 UI 입력·표시 전체 연결. 본 계획에 포함하지 않음.
- 케이스: **B-01** 2종목(코스피 1억 + 코스닥 1억, 2026-06-15) → 합산 {50,000+200,000=250,000 / 농특 150,000 / 합계 400,000}. **B-02** K-OTC 비과세 종목 포함 시 echo 합산 유지.
