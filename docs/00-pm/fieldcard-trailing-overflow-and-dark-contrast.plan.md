## A. FieldCard 오른쪽 배지(`trailing`)가 카드 밖으로 나간다

### A-1. 문제(실측)

| 사안 | 폭 | 카드 안쪽 오른쪽 끝 | 줄 오른쪽 끝 | 상태 |
|---|---|---|---|---|
| `inh1987` 「상속세 신고 시 평가방법」(Select + 「상증법 §60」) — 선택 전 | 375 | 273 | 304 | 카드 밖 31px |
| 같은 칸 — 「보충적평가액 (공시가격)」 선택 | 375 | 273 | 362 | 카드 밖 89px |
| 같은 칸 — 선택 | 320 | 218 | 362 | 카드 밖 144px · 페이지 가로 스크롤 |
| `inh1980` 「상속세 신고가액 (상증법 평가액)」(입력칸 + 「상증법 §60~66」) | 320 | — | — | 카드 밖으로 넘침 |
| 위 모든 칸 | 1280 | — | — | 넘침 없음 |

`inh1980`의 입력칸 카드는 375에서는 넘치지 않았다.

### A-2. 원인

- `components/calc/inputs/FieldCard.tsx:57`: 카드 루트가 모바일(sm 미만)에서 단일 열 `grid`다.
- `:80`: 본문 `div.space-y-1.5`가 grid 항목인데 `min-width`가 기본값 `auto`다. 그래서 본문이 안쪽 콘텐츠의 최소 폭보다 좁아지지 않는다.
- `:82-84`: 입력 자리는 `flex-1 min-w-0`이고 배지 자리는 `shrink-0`이다. 입력 자리의 `min-w-0`은 줄 안에서만 효과가 있다. 본문 자체가 카드보다 넓어지는 것은 막지 못한다.
- `PostDeemedInputs.tsx:193-197`: Select 트리거 안의 값이 `SelectValue`가 아니라 직접 쓴 `<span>`이다. 트리거의 `whitespace-nowrap`(`components/ui/select.tsx:44`)을 그대로 받고, 말줄임(`line-clamp-1`은 `data-slot=select-value`에만 걸린다)이 없다.

DOM 실험으로 확인했다. 본문에 `min-w-0`을 넣으면 줄이 카드 안으로 들어온다. 375에서 줄 오른쪽 끝이 362에서 273이 됐다.

### A-3. 영향 범위(정적 집계)

- `<FieldCard>` 사용처 804곳 중 `trailing`을 쓰는 곳은 **53곳**이다(`stacked` 1곳 포함).
- 입력 자리의 종류는 다음과 같다.

| 종류 | 곳 |
|---|---|
| DecimalInput | 16 |
| CurrencyInput | 11 |
| DateInput | 8 |
| RadioCardGroup | 6 |
| div | 4 |
| **Select** | **4** |
| native input | 2 |
| 기타 | 2 |

- **Select 4곳**:
  - `PostDeemedInputs.tsx:167`
  - `nbl/OtherLandDetailSection.tsx:364`·`:467`
  - `nbl/GracePeriodSection.tsx:129`
- `trailing` 없이 단위(`unit`)만 쓰는 카드도 같은 본문 구조다. 수정안 V1의 영향 대상이 된다.

### A-4. 수정안 — 실측 비교

카드마다 하위 요소 전부의 위치·크기를 수정 전후로 비교했다. 아래 실측 범위는 다음과 같다.
- 시드 3종 × 320·375·1280 = 9화면, FieldCard 42개.
- 10개 계산기 기본 화면 × 375·1280 = 20화면, FieldCard 28개.

| 안 | 변경 | 바뀐 카드 | 그중 지금 넘치지 않던 카드 | Select 칸(`inh1987`) 375 | 입력칸(`inh1980`) 320 |
|---|---|---|---|---|---|
| V0 현행 | — | — | — | 카드 밖 31~89px | 카드 밖 |
| **V1** | 본문에 `min-w-0` | 3 | **0** | 카드 안 · **Select 글자가 배지와 겹침**(선택 후) | 카드 안 · 겹침 없음 |
| V2 | V1 + `trailing`이 있는 줄에 `flex-wrap` · 입력 자리 `basis-auto` | 6 | **3** | 카드 안 · 겹침 없음 · 배지는 다음 줄 | 카드 안 · 배지는 다음 줄 |

- **V1**은 이번 실측 범위에서 지금 넘치는 카드만 바꿨다. 넘치는 Select 칸은 트리거가 87px로 줄었다. 그런데 직접 쓴 `<span>` 글자가 트리거 밖으로 나가 배지와 겹쳤다. 겹침은 320(선택 전·후)과 375(선택 후)에서 생겼다. **V1만으로는 Select 칸이 더 나빠진다.**
- **V2**는 Select 칸을 375에서 해결한다. 대신 지금 넘치지 않는 입력칸 카드 3개(`inh1980` 375에서 2개, 320에서 1개)도 배지를 다음 줄로 내린다. 공용 컴포넌트라 이런 부수 변경이 53곳 전체에 생길 수 있다.
- **V2, 320**: 「보충적평가액 (공시가격)」 글자가 트리거보다 29px 길어 여전히 카드 밖으로 나간다. 375는 들어온다.

**권고 V3 = V1(공용) + Select 칸만 V2 방식(옵트인)**
- `FieldCard`에 V1(본문 `min-w-0`)을 넣는다. 넘치지 않는 카드는 바뀌지 않는다(이번 실측 범위 기준).
- `trailing` 줄바꿈은 옵트인 prop(가칭 `wrapTrailing`)으로 열고, Select 4곳에만 켠다. 입력칸 카드는 V1만 받는다.
- Select 칸 결과는 V2 측정값과 같고, 입력칸 결과는 V1 측정값과 같다. V3 조합 자체를 한 화면에서 함께 잰 것은 아니므로 Do 1단계에서 측정한다.

### A-5. 확인 필요 — Do 1단계에서 측정

1. **53곳 전수**: 이번 실측은 3곳(Select 1·입력칸 2)뿐이다. 나머지 50곳은 상태를 만들어야 렌더된다. 따라서 다음 순서로 측정한다.
   - 기존 E2E 전 spec의 종료 시점에 일회성 측정 훅을 붙인다.
   - 화면의 모든 FieldCard를 V0 대 V3로 대조한다. 기준은 375·1280에서 「바뀐 카드 ⊆ 넘치던 카드」인지, 그리고 「글자↔배지 겹침 0」인지다.
   - 훅은 커밋하지 않는다. 소요 시간은 확인 필요다.
2. **NBL Select 3곳**(`OtherLandDetailSection`·`GracePeriodSection`)은 미측정이다.
3. `trailing` 없는 카드(751곳) 중 지금 넘치는 카드가 있으면 V1로 안쪽이 줄어든다. 그 결과 글자가 잘리거나 겹치는지는 1번 측정에 포함한다.

### A-7. Do 1단계 결과 — V3 기각(2026-10-19)

A-5 1번 측정을 실행했다.
- **방법**: 측정 훅을 이 워크트리의 복사본 `node_modules/@playwright/test`에만 임시로 넣었다(원복함). 그 상태로 V3 구현 코드에서 전체 E2E를 돌렸다(2,475건 · 279 spec · 2,450 passed).
- **측정 시점**: 각 테스트의 종료 화면에서 원래 폭·375·768 세 폭으로 모든 FieldCard를 쟀다.
- **비교**: V3(실제 코드)와 V0(DOM에서 V3 클래스를 걷어낸 상태)를 대조했다.
- **기록 규모**: 4,207건, FieldCard 측정 약 43,800회.

| 폭 | 측정 | V0 넘침 | V3 넘침 | V3에서 바뀐 카드 | 그중 V0에서 안 넘치던 카드 | 글자↔배지 겹침 V0 → V3 |

**측정 잡음(세부 기록으로 확인, 위 수치에 섞여 있음)**
- 1280의 「넘침」 대부분은 1px 반올림이다(예: 본문 오른쪽 980 vs 카드 안쪽 979).
- 「안 넘치던 카드가 바뀜」 중 상당수는 Select의 숨은 1×1 `input`이다. 페이지의 다른 카드가 길어지면서 카드 기준 세로 위치만 밀린 것이다. 다음 측정에서는 둘 다 걸러낸다.

**실제 결함(세부 기록으로 확인)**
1. **V1이 줄지 않는 입력을 누르면 넘침이 겹침으로 바뀐다.** 375에서 카드별 겹침을 집계한 결과는 다음과 같다(측정 횟수 기준).

   | 칸 | V0 | V3 |
   |---|---|---|
   | 「증여 등기접수일」(DateInput + 배지) | 카드 밖 넘침, 겹침 없음 | **겹침(새로 생김, 33회)** |
   | 「취득가액 산정방식」 | 넘침 + **이미 겹침**(31회) | 겹침 그대로 |
   | 「증축일」 | 넘침 + **이미 겹침**(12회) | 겹침 그대로 |
   | Select 옵트인 3곳(「사유」·「체육시설 종목」·「부대편성인원」) | 겹침(6회) | **해소** |

   - DateInput은 날짜 세 칸이 고정 폭이라 줄지 않는다. 그래서 계획서의 「Select 4곳만 옵트인」은 대상이 부족하다.
   - 「취득가액 산정방식」·「증축일」은 수정 전부터 375에서 글자가 배지와 겹치던 **기존 결함**이다. 이번 측정으로 처음 드러났다.
2. **768(sm 이상, 라벨-좌/입력-우 2열)에서도 날짜칸이 넘친다.** 대표 사례는 「양도일」·「신고일」이다. 입력 자리가 122px인데 DateInput이 150px라 카드 밖으로 28px 나간다. V1은 본문만 122px로 줄이고 DateInput은 그대로라 해결하지 못한다. 기존 결함이고 범위는 375보다 넓다.
3. **V3를 적용한 상태에서 E2E 3 spec이 실패했다.**
   - 실패 spec: `transfer-nbl-revenue-deemed-common`·`transfer-replacement-house`·`transfer-single-loss-gain`.
   - A를 되돌린 상태(B만 적용)에서는 3 spec 6건이 모두 통과했다.
   - 실패 원인이 V3 레이아웃 변화인지 측정 훅의 부하인지는 분리하지 못했다(확인 필요).

**조치**: A의 코드 변경은 되돌렸다(보관: 세션 스크래치패드 `fc-v3.patch`). B만 먼저 PR로 낸다. A는 아래 후보를 같은 방식으로 다시 측정한 뒤 재결정한다.
- **V4 후보**: 본문 `min-w-0` + `trailing`이 있는 줄은 항상 `flex-wrap` + 입력 자리 `flex-basis: min-content`.
  - 입력의 **최소** 폭과 배지가 한 줄에 안 들어갈 때만 배지가 다음 줄로 간다. 줄어드는 입력칸은 최소 폭이 작아 줄바꿈이 일어나지 않는다. 그래서 「넘치던 카드만 바뀐다」를 옵트인 없이 노릴 수 있다.
  - 실측 전이다.
