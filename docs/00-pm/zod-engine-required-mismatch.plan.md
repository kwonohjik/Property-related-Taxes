# Zod(⑫) ↔ 엔진 입력 필수 여부 불일치 — 전수 점검 기록 · 남은 과제

- 작성: 2026-09-30 · 브랜치 `fix/zod-engine-required-mismatch`
- 계기: E-14l(#1873) — `generalBuildingValuationSchema`의 취득시 기준시가가 `optional`인데 엔진은 필수 `number`라서,
  API 직접 호출로 비워 보내면 **200 + NaN**(건물 카드) 또는 **200 + 조용한 0**(토지 카드, 세액 85,868,200 vs 48,415,400)이 됐다.
  #1873은 그 스키마만 고쳤고 「다른 서브스키마는 점검하지 않았다 · 0으로 흡수되는 경우는 NaN 가드가 못 잡는다」를 남겼다.
- 이 문서는 **점검 기록**(무엇을 어떻게 보았고 무엇이 나왔는가)과 **이 PR에서 고치지 않은 확정 결함 목록**이다.
  줄 번호는 적지 않는다(머지 후 드리프트) — 착수 전 현행 코드로 재확인할 것.

## 1. 방법

1. **타입 수준 전수 비교** — `z.output<스키마>`와 엔진 입력 타입을 TypeScript 컴파일러 API로 재귀 대조했다
   (`as unknown as` 캐스트로 엔진에 넘기는 모든 route: 증여·증여의제·상속(하위 객체 7종)·재산세·양도세 감면·일반건물
   payload·주식 3종). 엔진이 필수인데 스키마가 optional/누락인 키는 **9건**뿐이었다
   (사전증여 `isHeir` 4 · 장기임대 `rentalYears`/`rentIncreaseRate` 2 · 일반건물 payload 날짜·가액 3). 모두 아래에서 판정했다.
   ⇒ 남은 위험은 **의미 수준**이다: 양쪽 다 optional인데 엔진이 어떤 분기에서 **필수로 취급**하는 값(`?? 0`, `|| 0`,
   기본값 분기)이고, ⑧(UI validate)은 그 값을 요구한다.
2. **의미 수준 점검** — route별 5개 레인이 ⑧ 필수 규칙 ↔ ⑫ refine ↔ 엔진 소비 지점을 대조하고, 후보마다
   **실제 route 핸들러로 probe**(값 있음 / 생략의 status·NaN·0·세액)를 돌렸다. 분류:
   - **A** 엔진이 부재를 올바르게 처리(명시 분기·법령상 맞는 기본값·⑧도 선택) → 정상
   - **B** 엔진이 필요로 함 → undefined가 닿아 NaN / throw(500) / **조용한 0·기본값**
   - **C** route·④가 UI·법령이 정당화하지 않는 fallback을 채움
3. **도달 경로** — 확정 결함마다 폼 → ④ → ⑧로 UI가 누락을 만들 수 있는지 확인(「UI 도달」 / 「API 전용」).

## 4. 남은 확정 결함 (이 PR 범위 밖)

범위 규칙: 확정 결함이 ≈15건을 넘어 **양도세 + UI 도달 전부 + 수치 영향이 큰 API 전용**만 이 PR에서 고쳤다.

### 6.1 법령 근거 (KoreanLaw MCP 본문 확인)

- **P3** — 지방세법 시행령 §118: 「법 제112조제1항제1호에 따른 산출세액과 같은 항 제2호 및 같은 조 제2항에 따른 산출세액 **각각에 대하여**」
  상한을 산출한다. 같은 조 2호 가목이 직전 연도 세액을 모를 때의 산정 방법(직전 연도 법령·과세표준으로 계산, 과세된 세액이 있으면 그 세액)을,
  나목이 신축·증축을 정한다 — 「모르면 상한을 건너뛴다」는 규정은 없다. 주택은 지방세법 §122 단서로 현행 제외되나
  법률 제19230호 부칙 §15가 종전 주택분에 2028.12.31.까지 종전 §122를 적용한다.
- **A7** — 지방세법 시행령 §28의2 1호: 가목 수도권(「수도권정비계획법」 §2 1호) 시가표준액 1억원 이하 / 나목 수도권 외 2억원 이하.
  소재지에 따라 한도가 갈리고 추정 규정이 없어, 생략을 비수도권으로 읽을 근거가 없다.
