## 0. 한 줄 요약

«구분 기재»(`saleSplitMode: "actual"`)를 고르고 토지·건물 양도가액을 **둘 다 비우면**, 일반건물 ⑧은 **아무것도 막지 않고** 엔진은 양도시 기준시가(감정평가 양쪽이 있으면 감정평가)로 안분한다. 결과는 «기준시가 안분» 선택과 **세액·토지분 양도가액이 원 단위까지 같고** 판정 흔적(`saleSplitJudgment`)도 없다. split은 같은 상황을 **근거가 전무할 때만** 막는다(V4) — 양도시 기준시가 양쪽 또는 감정평가 양쪽이 있으면 통과시키는데, 이는 **2026-07-29 사용자 확정 규칙 ①과 #2402가 의도적으로 만든 셀**이다. 겸용만 두 칸 필수다.

⇒ «구분 기재를 골랐으면 두 칸을 채워야 한다»로 일반건물을 막는 것은 쉽다(⑧ 한 검사). 그러나 **split과 같은 규칙을 적용하면 일반건물은 영향이 없고**(양도시 기준시가가 항상 필수 입력), **일반건물만 막으면 split보다 엄격한 비대칭이 새로 생기며**, split까지 막으면 **기존 확정 결정 셀 30개(72 중)와 회귀 가드 테스트 17건이 뒤집힌다.** 이는 구현 전에 사용자가 정할 쟁점이다 → **멈춘다**.

## 1. 법령 (KoreanLaw MCP 2026-10-22 원문 실독)

| 조문 | 내용 | 근거 |
|---|---|---|
| 「소득세법」 §100② | 양도가액을 실지거래가액으로 산정하는 경우 토지와 건물 등을 함께 양도했으면 **각각 구분하여 기장**하되, **가액 구분이 불분명할 때에는** 양도 당시의 기준시가 등을 고려하여 대통령령으로 정하는 바에 따라 **안분계산** | `get_law_text(mst=280405, jo=제100조)` 시행 2026-01-01 · 상수는 `TRANSFER.BUNDLED_APPORTIONMENT`(「소득세법 시행령」 §166⑥)로만 존재한다 — **§100② 자체의 상수는 없다**(Do 시 신설 필요) |

**법령이 말해 주는 것**: 구분 기장이 **없으면**(두 칸 비움) §100②가 안분을 명한다. 즉 «구분 기재 + 두 칸 비움»의 엔진 결과(기준시가/감정 비례 안분)는 **법정 결과**다 — 틀린 세액이 아니다. 문제는 법이 아니라 **사용자가 고른 방식이 결과에 반영되지 않았는데 화면 어디에도 그 사실이 없다**는 점(UX·자동 fallback 금지 원칙의 해석)이다. 이 계획서는 **법령 해석을 새로 더하지 않는다.**

- split의 ⑧ 통과 30셀 = (감정 없음 ∧ 기준시가 양쪽) 12 + (감정 양쪽 ∧ 기준시가 양쪽) 12 + (감정 양쪽 ∧ 기준시가 없음 ∧ 실가/실가) 6. **전부 «사용자가 직접 입력한 안분 근거»가 있는 셀**이다. 근거가 전무한 12셀(감정 없음 ∧ 기준시가 없음)은 양도일 무관하게 이미 차단된다(T-7).
- 일반건물이 split보다 «더 많이 통과하는» 것처럼 보이는 24 vs 30은 셀 구성 차이일 뿐, **일반건물은 양도시 기준시가가 필수라 split의 «기준시가 양쪽 있음» 조건이 항상 참**인 경로다 — 즉 split 규칙을 그대로 적용하면 일반건물의 «actual + 빈칸»은 **항상 통과**한다.

- 환산 파트(split 토지 환산) 셀: 환산 파트의 기준시가 분모가 없으면 V7이 막고, 있으면(= 안분 근거도 있음) 통과 — 별도 축으로 새 갭은 없다.

일반건물만 막는 경우의 상호작용: **기존 테스트 실패 0** (strict 격자에서 일반건물 쪽 실패 없음). 대신 **split과 비대칭**이 생긴다 — 같은 화면 문구(«미입력 시 나머지에서 자동 계산»)·같은 3지선다인데 split은 기준시가가 있으면 통과, 일반건물은 차단.

## 6. 선택지와 설계 (사용자 결정 후 확정)

| 안 | 내용 | 효과 | 비용 |
|---|---|---|---|
| **A. 현행 유지(변경 없음)** | 규칙 ①·#2402·§100②의 «구분 기장 없으면 안분»을 그대로 둔다. 일반건물은 split 규칙을 따르는 상태(양도시 기준시가가 필수 입력이라 항상 통과)임을 문서·테스트로 고정 | 확정 결정 0개 뒤집힘 | 사용자가 «구분 기재»를 골랐으나 입력을 잊은 경우 조용히 안분 — **침묵** |
| **B. 현행 + 흔적 표시** | A + 결과/신고서에 «구분 기재를 선택했으나 양도가액이 입력되지 않아 양도시 기준시가(감정평가)로 안분했다» 한 줄을 표시. 엔진 `judgment`가 구분 없음일 때 null이라 ⑦ 표시용 echo(`echo-field-pattern`) 필요 | 막지 않되 침묵 해소 | ⑦ 변경(결과 카드·신고서 두 경로), 별도 계획 필요 |
| **C. 일반건물만 막기** | `validateGbSaleAxis`에 V8-b 옆 검사 1개(`actual ∧ 두 칸 비움 ∧ !증축?`) | 기존 테스트 0 · 일반건물 24셀 차단 | **split보다 엄격한 비대칭 신설** · ⑫ 불가 · 증축 처리(F36식 제외 여부) 추가 쟁점 |

| **E. strict 통일** | split·일반건물 모두 근거 불문 차단 + ⑫ V4 동시 | 겸용과 완전 일치 | **규칙 ①과 #2402를 모두 뒤집는다** — 테스트 17건 + 격자 3종 재작성 |

**권장: A 또는 B.** 근거 — (1) §100②가 구분 기장 부재 시 안분을 명해 결과가 법정이다 (2) 안분 근거(기준시가·감정)가 모두 **사용자가 직접 입력한 값**이라 `feedback_no_silent_apportion_fallback`이 금지하는 «시스템이 값을 지어내는» 안분이 아니라고 2026-07-30 검토(`transfer-tax-validate-split.ts:503-510`)가 이미 결론 냈다 (3) C는 비대칭, D·E는 확정 정책 번복이다. 다만 «골라 놓고 잊은» 사용자 경험이 문제라고 판단하시면 B가 규칙을 뒤집지 않고 침묵만 없앤다. **이 판단은 사용자 몫**이다.

## 9. 확인 필요 · 미검증

1. 일반건물 «함께 양도(컴패니언)» 격자는 시드가 ⑧ 「계약서상 양도가액」 요구에 막혀 만들지 못했다. 일반건물이 컴패니언으로 지원되는지 자체가 코드 판독 미완 — 단건·다건·지분 축 B만 실측했다.
2. 프로토타입은 ⑧만 변경했다 — ⑫를 함께 조일 때(D·E)의 400 셀 수는 측정하지 않았다(ⓐ split ⑫ V4 :420-425가 «actual ∧ 두 칸 비움 ∧ !hasSaleRatio»로 이미 일부를 막는다).
3. 137파일 선택 실행이며 전체 vitest는 아니다(머신 부하 50+로 전체 실행이 25분 이상 걸려 중단했다). 선택 기준은 `saleSplitMode|SaleSplit|sale-split` 문자열이다 — 이 문자열 없이 `landTransferPrice`만 쓰는 테스트가 있으면 누락될 수 있다.
4. 결과 화면이 «구분 기재가 안 쓰였다»를 표시하는지는 코드 판독으로만 확인했다(`components/calc`에서 `saleMode` 참조 0건 · `saleSplitJudgment` null). 브라우저·E2E 미수행.
5. 사용 빈도 불명(telemetry 없음). 기본값이 `apportioned`라 사용자가 «구분 기재»를 직접 골라야 발생한다.
