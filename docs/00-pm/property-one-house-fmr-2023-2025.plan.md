# 재산세 1세대1주택 공정시장가액비율(시행령 §109①2호 단서 각 목) 연도 확장 v3 구현 계획

작성일: 2026-06-25
발견 경위: 도시지역분 세부담상한 v2(PR#363) 구현 중 probe로 발견 — `project_property_housing_transitional_cap` §v3 갭
상태: 계획 (법령 2024·2025 검증 완료, 2023 확인 필요)

---

## 1. 배경·문제

`calcTaxBase`(`lib/tax-engine/property-tax.ts:120-152`)는 1세대1주택 공정시장가액비율(FMR) 특례를 **2022년(단일 45%)·2026년(구간별 43/44/45%)만** 분기하고, **2023·2024·2025년은 분기 없이 `getFairMarketRatio` fallback = 0.60**(주택 표준)을 적용한다.

- 시행령 §109①2호 단서는 매 연도 1세대1주택에 대해 60%보다 낮은 특례 비율을 정하는데, 엔진이 2023~2025 3개 연도를 누락.
- **실측(probe, 2026-06-25)**: 용인 기흥 구갈동 아파트(공시 518,000,000, 2025, 1세대1주택, 직전공시 481,000,000)
  - 엔진: `taxBase = 518,000,000 × 0.60 = 310,800,000`, 산출(특례세율) 457,800
  - 구청: 과세표준 **223,036,000**, 산출(특례세율) 266,072
- **세부담상한이 binding인 경과조치 케이스에서는 확정세액이 상한액으로 수렴해 최종 결과 영향 없음**(PR#363 TC-U3가 236,869/305,630 일치). 그러나 **상한 미적용(직전세액 미입력·산출<상한·일반 2025 1세대1주택)** 케이스는 과세표준·산출세액이 과다.

## 2. 법령 근거 (KoreanLaw 검증)

`legal_analysis(applicable_law)` 시행령 §109 @ 각 과세기준일(6.1):

| 기준일 | 시행 버전 | §109②2호 단서 | 판정 |
|---|---|---|---|
| 2023-06-01 | [시행 2023.5.30.] 제33489호 | "다만, **2022년도**에 납세의무 성립 … 1세대1주택 … 100분의 45" | 🟡 2023년도 각 목 단서 **미확인** (6.1 시행본은 2022년도 단서 잔존) |
| 2024-06-01 | [시행 2024.5.28.] 제34528호 | "다만, **2024년도**에 납세의무 성립 … 1세대1주택 … **다음 각 목의 구분에 따른다**" | ✅ 구간별 적용 확정 |
| 2025-06-01 | [시행 2025.5.27.] 제35544호 | "다만, **2025년도**에 납세의무 성립 … 1세대1주택 … **다음 각 목의 구분에 따른다**" | ✅ 구간별 적용 확정 |

- **각 목 비율 = 43%(공시 3억 이하) / 44%(6억 이하) / 45%(6억 초과)** — 엔진 2026 상수(`ONE_HOUSE_FMR_RATIO_1/2/3` = 0.43/0.44/0.45)와 동일.
  - 근거: ① 2025·2024 단서가 2026과 동일하게 "각 목의 구분" 구조, ② **구청 실측 재현으로 2025 6억 이하 = 44% 확정**(아래 §3).
- ⚠️ **2023년도는 확인 필요 (단, 60% 가능성에 무게)**: applicable_law @ 2023-06-01이 "2022년도 45%" 단서만 반환 → 2023년도 1세대1주택 각 목 특례가 §109 6.1 시행본에 없음. **기존 코드 증거 corroborating**: `comprehensive-historical.ts:192` 주석이 "그 외(2021·**2023~** … 또는 다주택·법인): 100분의 60(본문) — KoreanLaw 행위시법 축자 확정"으로 **2023 재산세 1세대1주택 = 60%(특례 없음)**를 이미 확정 인용. → 2023은 **갭이 아닐 가능성**(현행 60% fallback이 정답). 단 단정 금지 — get_law_text 전문 + chain_amendment_track(신구대조)로 Do 단계 선확정 후 처리(60%면 무변경, 각목이면 집합 추가). 확정 전까지 **2024·2025만 즉시 적용**.

> 추정 금지: 각 목 비율은 §109 전문(get_law_text)에서 efYd별로 가/나/다 직접 확인 후 상수 동결. 본 계획의 43/44/45는 2026 상수 + 구청 44% 실측 근거이며, Do 단계에서 2024·2025 efYd 전문으로 재확인.

## 3. 구청 실측 재현 anchor (손계산 검증 완료)

입력: 공시 518,000,000 · 2025 · 1세대1주택 · 직전공시 481,000,000 · 6억 이하 → FMR 44%

```
① calcTaxBase (FMR 44%):        518,000,000 × 0.44 = 227,920,000
② §110③ 직전 과세표준 상당액:    481,000,000 × 0.44 = 211,640,000
③ 과세표준상한액 = ② + (① × 5%): 211,640,000 + floor(227,920,000 × 0.05=11,396,000) = 223,036,000
④ cappedTaxBase = min(①, ③):    min(227,920,000, 223,036,000) = 223,036,000  ✓ 구청 일치
⑤ 산출(특례세율, 1.5억~3억):     120,000 + (223,036,000 − 150,000,000) × 0.0020 = 266,072  ✓ 구청 일치
```

- **현재 엔진(FMR 0.60)**: ① 310,800,000 → §110③ 상당액 481M×0.60=288,600,000 → 상한 288,600,000+15,540,000=304,140,000 → min(310,800,000, 304,140,000)=304,140,000 ≠ 223,036,000. 과세표준 과다.
- → FMR 44% 적용 시 과세표준·산출이 구청과 정확히 일치. **§110③ 과세표준상한제는 동일 FMR을 직전/당해에 모두 적용하므로 본 수정과 정합**(`applyHousingTaxBaseCap`이 `calcTaxBase` 반환 `fairMarketRatio`를 재사용 — 자동 연동).

## 7. 🔴 종부세 연동 영향 — 두 FMR 경로의 비대칭 (실측 확정)

종부세에는 재산세 FMR이 흘러드는 **두 개의 독립 경로**가 있다 (실측):

### 경로 1 — 재산세 determinedTax (calcTaxBase FMR 사용 → v3 **영향받음**)
`calculatePropertyTax({objectType:"housing", isOneHousehold, targetDate})` 직접 호출 4곳:
- `comprehensive-tax.ts:245` (트랙 B, §122 직전공시 입력)
- `comprehensive-tax.ts:276` (트랙 A, 다가구 `calcMultiFamilyHousingTax`)
- `comprehensive-tax.ts:289` (일반 트랙)
- `comprehensive-housing-tax-cap.ts:54` (`buildHousingPropertyTaxWithCap` — 직전 표준세율 산출)

`isOneHousehold = !isCorporate && input.isOneHouseOwner && input.properties.length === 1` + `targetDate = assessmentDateStr` 전달 → **2024·2025 + 1세대1주택 단일주택**이면 v3로 FMR이 0.60→0.44 등으로 바뀌어 재산세 determinedTax 감소 → 종부세 §9③ 재산세공제 피산입 재산세액 변동.

### 경로 2 — §9③ 안분공제 FMR factor (`getPropertyFmrForProration` → v3 **불변**)
`comprehensive-tax.ts:490`·`comprehensive-prior-year.ts:104`가 `getPropertyFmrForProration(assessmentYear, isOneHouseSingle)`(comprehensive-historical.ts:198)를 호출. 이 함수는 **2022만 0.45·그 외(2023~·2026 포함) 0.60**을 명문 반환하며, 주석에 "2026년도 구간별 43/44/45는 종부세 안분에서 비대상(12억 공제로 비과세 영역) — 본문 60% 유지"로 **의도적 결정**을 기록. v3는 이 함수를 건드리지 않으므로 **안분 FMR factor는 60% 유지**.

### 핵심: 이 비대칭은 **현행 2026이 이미 채택·수용** 중
- 현재도 2026 1세대1주택은 calcTaxBase=구간별(43/44/45) **AND** getPropertyFmrForProration=60%로 **비대칭이 코드상 존재**하며, 이 비대칭을 포함한 상태로 전체 종부세 스위트가 green(회귀 0)이다.
- v3는 그 **기존 2026 패턴을 2024·2025로 복제**할 뿐 → **신규 dual-truth 아님**. "재산세 실세액"(경로1)과 "안분 FMR factor"(경로2)는 서로 다른 물리량이라 비대칭이 설계상 정당.

### Do 진입 전 필수 측정 (회귀 vs 정확도 개선 구분)
- **변동 후보 케이스**: 종부세 `assessmentYear ∈ {2024,2025}` + `isOneHouseOwner` + `properties.length===1` + 주택분(특히 §122 cap 트랙 B `priorAssessedValue` 입력). 이 조합만 경로1 determinedTax가 변한다.
- 종부세 테스트 전수 실행 → 깨지는 anchor를 **법령 정합값(정확 FMR)으로 재산정**(memory `feedback_anchor_correction_legal_priority`) — 0.60 기반 기존값 유지 금지. 단 대부분 종부세 사례는 공시 12억↑(과세 영역)이라 1세대1주택 특례 FMR 구간(주로 9억↓·12억대)과 겹치지 않아 **실제 변동 anchor는 소수일 것으로 예상**(측정으로 확정).
- getPropertyFmrForProration(경로2) 주석을 "2024·2025·2026 구간별 비대상"으로 갱신(§9 단계 7).
