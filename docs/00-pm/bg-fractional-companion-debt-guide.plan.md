# 함께 부담부증여 — 공유지분 컴패니언 카드의 채무 안내 문구 정리 (Q-3)

> 선행: #2758(브라우저 확인 BV-1 — 현재 동작 기록) · #2750(컴패니언 채무는 축 B 에서만 지분 안분). 사용자 지시: 「단건 지분 담보 승, 기준시가 모드 채무 초과 500, 안내 문구 정리 순서로 진행해」 중 셋째.
> 같은 지시의 앞 두 건은 #2766(`bg-single-fractional-and-debt-excess.plan.md`).

## 1. 사실 (실측 — #2758 BV-1)

지분 50% 컴패니언 카드(자산 2)에 채무 안내가 **두 문단**으로 떴다.

- 축 A 문단(`isFractional`): 「공유지분(50%) 부담부증여 — … **이 지분에 대응하는 인수분**을 입력하세요. … 평가액은 물건 전체로 입력하면 엔진이 지분분으로 환산합니다」
- 컴패니언 문단(`isCompanionBundle`): 「여러 물건 함께 부담부증여 — … **이 물건에 설정된 금액**을 입력하세요. 채무가 없는 물건은 비워 둡니다 … 채무 합계를 자산별 평가액 비율로 재배분합니다」

두 문장은 서로 다른 지시처럼 읽힌다(「인수분」 vs 「이 물건에 설정된 금액」). 그러나 모순이 아니다 — #2750 이후 컴패니언의 채무는 **그 물건에 설정된 금액 중 본인 지분 인수분**이다(채무를 지분율로 줄이는 것은 축 B 만).

## 2. 수정

`BurdenedGiftBlock.tsx` — 세 문단을 조합으로 가른다.

| 조합 | 문단 |
|---|---|
| 단건 지분(축 A) | 축 A 문단만(종전) |
| 컴패니언 100% | 컴패니언 문단만(종전) |
| **컴패니언 × 지분(축 A)** | **합친 한 문단**: 「…이 물건에 설정된 금액 중 이 지분에 대응하는 인수분을 입력하세요. 채무가 없는 물건은 비워 둡니다. 평가액은 물건 전체로 입력하면 엔진이 지분분으로 환산하고, 시스템이 채무 합계를 자산별 평가액 비율로 재배분합니다」 |
| 축 B | 물건 전체 문단만(종전) |

필드 라벨(「담보차입금 (지분 인수분)」 등)·계산은 그대로다(표시 전용 · 세액 불변).

## 3. 검증

- 단위 `bg-debt-guide-fractional-companion.anchor.test.tsx` GD-1(합친 문단 1건 · 옛 두 문단 없음 · 라벨 유지)·GD-2(나머지 3개 조합은 종전 그대로) 4건. 컴포넌트를 되돌리면 GD-1 red(뮤테이션).
- 브라우저 e2e `bg-browser-verify.spec.ts` BV-1 을 새 문구로 갱신(Playwright 5건 통과): 지분 카드에 합친 문단 1건, 「이 물건에 설정된 금액을 입력하세요」는 100% 카드(자산 1)에만(종전 2건), 옛 축 A 단독 문단 없음.
- 회귀 `__tests__/calc`·`components` 1,443 파일 통과. 이 문구를 직접 보는 다른 e2e(`transfer-companion-burdened-gift` · `transfer-burdened-gift-fractional`)는 100% 자산 카드라 영향 없다.
