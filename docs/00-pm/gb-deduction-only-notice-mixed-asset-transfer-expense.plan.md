## 1. 요약

- **환산 파트가 반영되는 경계**(F1, 양도비 **1,500,000,000**): 환산 토지 + 감정 건물 → 토지 6,150,000 → **1,220,313,270**, 건물 4,500,000 (불변) · 세액 302,075,519 → 26,605,749. 감정 토지 + 환산 건물 → 건물 4,500,000 → **279,686,730**, 토지 불변 · 231,774,001. 즉 **환산 파트로도 몫이 반영될 수 있다**(단서 발동 시) — 「다른 파트가 환산이면 반영 안 됨」이라고 단정하는 문구도 틀린다.

## 3. 원인 · 데이터 흐름

1. 양도비는 자산 단위로 한 번 입력된다(`AssetSectionExpense.tsx:155-182` 칸, 분리 ON 에서도 숨기지 않는다). ④ 가 그대로 싣고 엔진이 **공통 양도비용**으로 카드(토지·건물·증축분)에 가액 비례로 나눈다 — 법문 §100② 후문 그대로다(§4).
2. 감정·매매사례 카드의 몫은 §97②2호 본문(취득가액 + 개산공제)에 양도비가 들어갈 자리가 없어 버려지고, 실가 카드의 몫은 §97②1호로 가산되며 환산 카드의 몫은 단서 비교에 들어간다. 엔진은 이미 이렇게 계산한다(엔진 설계서 §4.1 :165 「실가 파트에 안분된 몫은 `swap.addition` 으로 유지」).
3. 안내 컴포넌트는 **파트 단위 사실**(「이 파트는 개산공제만」)과 **자산 단위 결론**(「입력해도 세액 불변」)을 한 문장에 섞었다. 분리 OFF 에서는 두 파트가 같은 모드라(`transfer-tax-split-acq-mode.ts:180-184` `gbPartModes`) 결론이 참이지만, 분리 ON 파트 카드(`GeneralBuildingAcquisitionCardsParts.tsx:249-252`)는 **다른 파트·증축분이 다른 모드일 수 있다**.
4. 증축이 있을 때만 건물 파트 문구가 「증축분 몫은 증축분 취득방식대로 반영」을 덧붙인다(`GbDeductionOnlyNotice.tsx:22-23`, `extension={!isLand && asset.gbHasExtension}`). 토지 파트 카드는 증축이 있어도 이 문장이 없다 — 같은 결함의 일부다.

## 4. 법령 근거 (해석 쟁점 없음)

- 「소득세법」 제100조 제2항 **후문**: 「이 경우 **공통되는 취득가액과 양도비용은 해당 자산의 가액에 비례하여 안분계산한다.**」 — 토지·건물을 함께 양도하면 공통 양도비는 자산(토지·건물) 가액 비례로 나뉜다.
- 「소득세법」 제97조 제2항 제1호: 「취득가액을 실지거래가액에 의하는 경우의 필요경비는 … **제1항제2호 및 제3호의 금액을 더한 금액**」 — 실가 파트는 자본적지출·양도비를 가산한다.
- 같은 항 제2호 **본문**: 「그 밖의 경우의 필요경비는 … 제114조제7항(…)의 금액에 자산별로 대통령령으로 정하는 금액을 더한 금액」 — 감정·매매사례 파트는 양도비 가산이 없다. **단서**: 환산취득가액인 경우 가목(환산취득가액 + 위 금액)이 나목(제1항제2호·제3호의 합)보다 적으면 나목을 필요경비로 할 수 있다 — 환산 파트는 비교.
- 따라서 법문이 정하는 결론은 「**자산 단위 양도비 중 감정·매매사례 파트 몫만 산입되지 않는다**」이다. 법문이 명확하므로 해석례·질의가 필요 없다(메모리 `feedback_clear_statute_needs_no_ruling`). 인용은 법령명 + 「법」 + 조항호 형식(`feedback_law_citation_must_name_statute_and_tier`).
- 조문 상수·`manifest/additions-transfer.ts` 등록: Do 에서 새 문구가 §100② 후문을 인용하므로 기존 등록 여부를 확인한다(§8 V-5).

## 5. 수정안

### 5.1 문구 (조건부)
- **모든 다른 카드가 감정·매매사례**(또는 분리 OFF) → 종전 문구 그대로(§2.4 에서 맞다).
- **다른 파트 또는 증축분이 양도비 몫을 받을 수 있다** → 둘째 문장을 바꾼다.
  - 종전: 「자본적지출·양도비는 필요경비에 산입되지 않으므로 입력해도 세액이 바뀌지 않습니다 (「소득세법」 §97②2호 본문).」
  - 변경: 「이 파트의 자본적지출은 필요경비에 산입되지 않으므로 입력해도 세액이 바뀌지 않습니다 (「소득세법」 §97②2호 본문). 자산 전체 양도비는 토지·건물 가액에 비례해 나뉘고(「소득세법」 §100② 후문) 이 파트 몫만 산입되지 않으며, 다른 파트·증축분 몫은 그 취득방식대로 반영됩니다(실지거래가액이면 가산, 환산취득가액이면 개산공제와 비교 — §97②).」
  - 기존 증축 문장(「증축 후 지출과 양도비 중 증축분 몫은 …」)은 이 문장에 흡수한다(증축 후 **자본적지출**은 건물 파트 칸의 별도 안내와 `capexHint` 가 이미 다룬다 — 중복 방지는 Do 에서 문구 대조).
  - 납세자 유리·불리·절감 표현 금지(법령 정확성 원칙).

### 5.2 판정 leaf (새 파일 1개)
- `gbOtherCardsReceiveTransferExpense(asset, part)` — 후보 위치 `lib/calc/` 신규 파일(`transfer-tax-split-acq-mode.ts` 는 778줄이라 거기에 더하면 800줄 트리거에 근접 — File Size Policy). 입력은 이미 ④·⑧·⑤ 가 공유하는 `gbPartModes(asset)`(`:180`)의 반대 파트 모드와 `asset.gbHasExtension`.
- 반환 `true` ⇔ 분리 ON ∧ (반대 파트 모드 ≠ appraisal·salesCase ∨ 증축 있음). 증축분은 모드가 실가·환산 둘뿐이라(`GeneralBuildingExtensionSection`) 증축이 있으면 항상 몫을 받는 카드가 하나 더 있다.
- 상속·증여·이월과세 파트의 유효 모드는 `gbPartModes` 가 `actual`/`estimated` 로 돌려주므로(`lib/calc/transfer-tax-gb-toggle-patches.ts:34-38` `gbPartAllowedModes`) 별도 분기 불요 — §2.2·§2.3 에서 상속·이월과세 파트가 몫을 받는 것을 실측했다.
- 분리 OFF 자산 단위 안내(`AssetSectionExpense.tsx:77-78,107`)는 **변경하지 않는다**(두 파트 모드가 같다). 단 이 불변식을 anchor 한 줄로 고정한다.

### 5.3 컴포넌트
- `GbDeductionOnlyNotice` 의 `extension?: boolean` prop 을 `shareToOtherCards?: boolean` 으로 대체(호출부 2곳: `GeneralBuildingAcquisitionCardsParts.tsx:251` 만 값 전달, `AssetSectionExpense.tsx:107` 는 생략 = 종전 문구). 호출부는 컴포넌트 안에서 계산하지 않고 leaf 결과를 내려준다(⑤ 표시 = 판정 leaf 단일 소스).
- 문서 정정 동반: `gb-part-appraisal-salescase.ui.design.md` §3.7(:254 문구 · :257 「⑧ V-8 이 안내·차단」 가정 — 자본적지출 한정으로 정정) · 엔진 설계서 :213 요약 · 컴포넌트 주석 `GbDeductionOnlyNotice.tsx:8`.

### 5.4 건드리지 않는 것
엔진·⑧ 검증·④·세액식·`capexHint`·분리 OFF 안내·명세서 산식. (14 동기화 지점 중 ⑤ 표시 문구 한 곳만 바뀐다 — 필드·API 변경 없음.)
