## 1. 요약

상속개시일이 1985.1.1. 이후인 상속받은 자산은 상속개시일 현재 상증법 평가액이 취득 당시 실지거래가액이다(소득세법 시행령 §163⑨). 그래서 법 §97①1호 단서의 나목 — 환산취득가액·매매사례가액·감정가액 — 을 쓸 수 없다.
⑧ 은 BG 시가 평가에서 이 셋을 모두 막는다 (`transfer-tax-validate-bg.ts` 의 `converted` 분기와 `isBgPresumedMethod` 분기의 `bgPresumedBlock` 상속 사유 — `burdened-gift-presumed-acquisition.ts:61-67`).
⑫ 는 #2735 가 `converted` 만 막았고 **감정가액·매매사례가액은 200** 이었다.

화면 도달: 불가능하다 (⑧ 차단). API 직접 호출에서만 생긴다.

## 2. 측정

환경: vitest + `makeMockRates`, 단건·BG 쌍(주 자산·컴패니언), 일자 1988·1995·2005 × 분리 OFF·ON × 평가액 4수준.

- 72셀(위치 3 × 24): 감정가액·매매사례가액은 **전부 ⑧ 차단 · ⑫ 200**, 올바른 경로(`actual` + 평가액)는 ⑧ 통과 · 200.
- 두 방식의 세액은 같다 (칸이 같다).
- 세액 — 상속 평가액 205M/150M, 감정/매매사례가액을 바꿔 넣을 때 (단건 · 1988 · 분리 OFF):

| 감정·매매사례가액(토지/건물) | 수정 전 | 올바른 경로 64,895,000 과의 차 |
|---|---|---|
| 100M / 75M | 87,418,550 | +22,523,550 |
| 205M / 150M | 63,478,550 | −1,416,450 |
| 400M / 300M | 13,695,881 | −51,199,119 |
| 800M / 600M | 0 | −64,895,000 |

세액이 **상속 평가액이 아니라 입력한 감정가액을 따른다.** 평가액과 같은 값을 넣어도 −1,416,450(감정가액·매매사례가액은 필요경비가 개산공제뿐이라는 ⑧ 주석 `transfer-tax-validate-bg.ts` K-6/K-7 과 부합하나, 차이의 구성은 분해해 보지 않았다 — 「확인 필요」) 가 남는다.

## 3. 구현

`lib/api/transfer-tax-schema-gb-bg-refines.ts` — #2735 의 `bgInheritConvertedBlocked` 를 `bgInheritNonActualBlocked` 로 바꾸고 방식 집합을 `converted`·`appraisal`·`salesCase` 로 넓혔다. 조건·제외(담보 승·기준시가 평가·축 B·기준시가 4칸 누락)는 그대로다. 메시지는 「환산취득가액·감정가액·매매사례가액을 쓸 수 없습니다」.
(`bgPresumedBlock` 의 둘째 사유 재개발 완공 아파트는 일반건물이 아니라 이 규칙의 대상이 아니다.)

## 4. 기준일 정정 — #2735 의 거짓 차단 (이 PR 이 함께 닫는다)

이 PR 의 첫 구현은 #2735 와 같이 **자산 취득일**(`acquisitionDate`)로 상속개시일을 판정했는데, 회귀(`transfer.route.bg-pre-deemed-gb-market-ui` S-4b — 토지만 1983 상속 · 건물 감정가액)가 **⑧ 통과 입력을 ⑫ 가 400 으로 막는 것**을 잡았다.
⑧ 은 `deriveSec163_9BaseDate` — 상속개시일 칸(`inheritanceStartDate`)을 읽고, 일반건물 payload 에는 그 칸이 없다. 토지만 상속받고 건물을 다른 날 취득하면 자산 취득일(건물)은 1995 이지만 상속개시일(토지)은 1983 이다.

실측(토지 1983-07-26 상속 · 건물 1995-05-01 취득 · 분리 ON · 위치 3):

| 방식 | #2735 (master) | 이 PR |
|---|---|---|
| `converted` | ⑧ 통과 · **⑫ 400** (3/3, 거짓 차단) | ⑧ 통과 · 200 |
| `appraisal` | ⑧ 통과 · 200 | ⑧ 통과 · 200 |

즉 **#2735 에는 이 입력을 막는 결함이 있었다** (V-1 구현의 정합 격자가 `inheritanceStartDate` 를 비워 둔 채 ⑧ 이 자산 취득일로 판정하게 해서 놓쳤다 — 화면은 항상 그 칸을 채운다). 기준일을 **토지 파트 취득일**(`generalBuildingValuation.landAcquisitionDate`, 없으면 자산 취득일)로 바꿔 닫았고, 정합 격자는 `inheritanceStartDate = 토지 취득일` 로 화면과 같게 고쳤다. 앵커 EC-6 이 이 입력을 고정한다. 기준일 변형(자산 취득일로 되돌림)은 적색 3건이다.
