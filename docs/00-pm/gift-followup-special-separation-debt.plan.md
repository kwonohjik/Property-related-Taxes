## Track A — 조특법 특례 분리과세 구조 재설계 (§30의5⑪·§30의6⑤ 준용)

### A-1. 법문 요건 (검증 완료 — 재조회 불필요)

§30의5⑪: "창업자금에 대하여 증여세를 부과하는 경우에는 「상속세 및 증여세법」 **제47조제2항에도 불구하고**
동일인(그 배우자를 포함한다)으로부터 증여받은 **창업자금 외의 다른 증여재산의 가액은 창업자금에 대한
증여세 과세가액에 가산하지 아니하며**, … 제69조제2항에 따른 신고세액공제를 적용하지 아니한다."
(§69 배제는 PR #114 D5로 구현 완료. §47② 배제가 본 트랙.)

§30의5① 후단: "창업자금을 **2회 이상 증여받거나 부모로부터 각각 증여받는 경우에는 각각의 증여세
과세가액을 합산**하여 적용한다." — 창업자금끼리는 기간 무관 합산.

§30의5⑧⑨ (상속 연계): 창업자금은 §3의2① 상속재산 가산 증여재산으로 보며, §13①1호 적용 시
**기간 무관** 상속세 과세가액 가산, §24 3호 적용 시 가산 증여재산가액으로 보지 않음.

§30의6⑤: 위 ⑧~⑬을 가업승계 주식에 준용 ("창업자금"→"주식등").

### A-3. 설계 방향 (Plan 단계 합의 필요 — 구현 디자인은 별도 .engine.design.md)

**핵심 결정: "절감액 공제" 폐기 → 2-스트림 분리 계산.**

```
giftItems → 특례 대상 자산 표시(isSpecialTreatmentAsset? 또는 specialTreatment 선택 시 자산-수준 라디오)
  ├─ 일반 스트림: 일반 자산만 — §47 합산(일반 prior만) → §53·§53의2 공제 → §56 누진 → §57 → §58 → §69
  └─ 특례 스트림: 특례 자산만 — 과거 특례 prior 합산(①후단, 기간 무관) → 5억/10억 공제 → 10%(/20%) → §69 배제
최종 = 일반 스트림 세액 + 특례 스트림 세액
```

- **입력 확장**:
  - 자산-수준: `EstateItem`(증여 모드)에 특례 귀속 표시 — 혼합 증여 케이스 매트릭스 전수 후 결정
    (단순안: specialTreatment 선택 시 "특례 대상 자산 선택" 멀티선택. 자산 1개면 자동 귀속)
  - `PriorGift.specialTreatmentType?: "startup" | "family_business"` — 과거 특례 회차 구분.
    §47 일반 합산에서 제외(G3) + 특례 스트림 합산(①후단)에 사용
- **기존 결과 호환**: `specialTreatmentCredit`(절감액) 필드는 echo 호환을 위해
  `일반화 후 가상 산출세액 − (일반+특례 합산세액)`으로 재정의하거나 deprecated — 결과뷰·별지10호 영향 전수 조사 필요
- **별지 10호**: 특례 신고는 별도 서식(창업자금 특례신청서 §30의5⑫)이 실무 — 현행 18행 표가 특례 케이스에서
  어떤 표시가 정합인지 Design 단계에서 결정 (특례신청 ⑫ 미신청 시 특례 배제 게이트도 검토)
- **상속 연계(G5)**: `PriorGift.specialTreatmentType` 재사용 — 상속세 §13 가산 시 cutoff 무시 +
  §24 3호 공제한도 분모 제외. **별도 PR 분리 권장** (상속 엔진 영향 — `computePriorGiftDeductionForLimit` 등)

### A-4. 케이스 매트릭스 골격 (Design에서 전수 확장)

| 케이스 | 일반 스트림 | 특례 스트림 |
|---|---|---|
| 특례 자산만 단독 증여 | 없음 (세액 0) | 5억/10억 공제 → 10% |
| 혼합 증여 (특례+일반) | 일반분만 §47·§53 | 특례분만 |
| 과거 일반 prior + 신규 특례 | 일반 prior는 특례에 미가산(⑪) — 일반 스트림 없으면 미사용 | 특례분만 |
| 과거 특례 prior + 신규 특례 | — | ①후단 합산 (기간 무관) + §58 유사 기납부 공제 |
| 과거 특례 prior + 신규 일반 | 특례 prior 제외(⑪ 역방향) | — |
| 특례 미적격 폴백 (투자미완료 등) | 전체 일반 과세 (현행 PR #114 폴백 유지) | — |

### A-5. 작업 규모·순서

1. **A-Phase 1** (증여세 엔진): G1~G4 — 2-스트림 분리 + PriorGift 필드 + UI(자산 귀속 선택·prior 특례 토글) + 14지점. 규모: §57/§53의2 사이클(PR #111)보다 큼 — 엔진·UI 시니어 병렬 Plan 필수
2. **A-Phase 2** (상속 연계): G5 — §13 기간 무관 가산 + §24 3호. 상속세 anchor 영향 전수
3. Pre-Do anchor 후보: 혼합 증여(창업자금 30억 + 일반 5억) / 특례 prior 2회차 합산 / 일반 prior 10억 + 특례 신규(⑪ 미가산 확인)

## Track B — 부담부증여 채무인수 차감 (§47①, 별지 10호 ②)

### B-1. 법문 요건

상증법 §47①: 증여세 과세가액 = 증여재산가액 합계 − "그 증여재산에 담보된 채무(그 증여재산에 관련된
채무 등 대통령령으로 정하는 채무를 포함한다)로서 **수증자가 인수한 금액**".
(배우자·직계존비속 간 부담부증여는 §47③ 채무 인수 추정 배제 — 객관적 입증 시만 인정. Design에서 안내 문구 처리.)

### B-2. 현행 갭 (실측)

| # | 갭 | 현행 코드 |
|---|---|---|
| B-G1 | 채무인수 입력 자체 없음 — 과세가액 차감 미지원 | `gift-tax.ts:258` `debtAmount: 0 // 현행 증여세는 채무 미지원` |
| B-G2 | 별지 10호 ② 행은 존재하나 항상 0 | `gift-filing-form-rows.ts` ② 행 (PR #112에서 ⑤ formula에 ② 이미 포함) |

### B-3. 설계 방향

- **입력**: 자산-수준 채무 (`EstateItem` 증여 모드 — 상속의 담보채무 §14 자동 반영 패턴
  `deriveCollateralDebts` 참조, memory `project_inheritance_collateral_66_max`) 또는 폼-전역 단일 금액.
  **자산-수준 권장** — §47①이 "그 증여재산에 담보된 채무"로 자산 귀속을 요구 + 평가(§66 MAX)와 교차
- **엔진**: STEP 2~3 사이 `netCurrentGiftValue` 산정에 채무 차감 추가 + `debtAmount` 별지 ② 연동
  (⑤ formula는 PR #112 수정으로 ② 이미 표기 — 자동 정합)
- **§66 교차 주의**: 저당권 설정 재산은 평가액이 `MAX(보충평가, 임대료환산, 담보채권액−신용보증)`
  (memory `project_inheritance_collateral_66_max`) — 같은 저당 채무가 평가 MAX와 §47① 차감에 이중 관여하는
  케이스 매트릭스 필수
- **양도세 연계 안내**: 채무인수분은 증여자의 유상양도 — transfer 탭 `burdened_gift`(기구현) 안내 카드만,
  자동 연동은 스코프 외
- **§47③ 추정 배제**: 배우자·직계존비속 증여 시 기본 미인정 + 입증 토글(중립 문구) — 법령 정확성 원칙

### B-4. 작업 규모

PR #111 수준 (입력 1~2개 + 엔진 차감 1지점 + 14지점 + 별지 ② 연동). Track A와 독립 — 선행 가능.
