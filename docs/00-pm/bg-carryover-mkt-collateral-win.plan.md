# 이월과세 × 부담부증여 × 시가 모드 × 담보 승 — 화면 개방 (2단계)

1단계(`bg-carryover-std-uniform-bundle.plan.md`, #2783)는 기준시가 모드 이월과세만 풀었다. 이 문서는 남은 **시가 모드 담보 승**을 푼다.

## 1. 배경 — 무엇이 막고 있었나

시가 모드(상증법 §60)에서 담보평가(상증법 §66)가 시가보다 크면 증여가액은 담보평가액이고, 「소득세법 시행령」 제159조 제1항 제1호 괄호에 따라 취득가액은
산정방식과 무관하게 **취득시 기준시가 × 채무비율**이다(엔진 `resolveBgAcquisitionBasis`의 `collateralForcedStdInMarketMode`).
이월과세(「소득세법」 제97조의2)이면 두 시나리오가 모두 기준시가를 쓴다 — A는 당초 증여자, B는 양도인. 기준시가 모드와 같은 구조다.

막고 있던 곳(모두 ⑧·⑤·⑫의 **화면·검증 쪽**이고 엔진 값은 이미 맞았다):

| 곳 | 종전 |
|---|---|
| ⑧ 단건 `transfer-tax-validate-bg.ts` | 이월과세 담보 승을 「취득가액 산정 기준을 확인하지 못해」 차단 |
| ⑧ 묶음 `bgNonSupplementaryWinnerUnsupported` | 시가 모드 이월과세의 비보충 승자를 「함께 양도와 같이 계산하지 않습니다」로 차단 |
| ⑤ `bgCollateralForcesStdAcq` | 이월과세를 제외 → 당초 증여자 기준시가 칸이 열리는 조건(`bgCoDonorNeedsStdPrice`)에 담보 승이 없었다 |
| ⑫ Zod `collateralForcesStdAcquisition` | 이월과세(`carryoverDonorBasis`)를 제외 → 매매사례·감정가액 요구가 그대로 걸렸다 |
| ⑫ 엔진 `assertCarryoverDonorBasis` | 담보 승이어도 방식별로 쓰이지 않는 당초 증여자 값(실지·매매사례·감정)을 요구 |

## 2. 실측 (probe → anchor)

- **시가 모드의 임대 승은 존재하지 않는다.** `computeSangjeungbeopValuation`은 시가 모드에서 임대 환산을 비교하지 않는다(`burdened-gift-valuation.ts:300` `rentalEligible`). 그래서 이 단계의 범위는 담보 승 하나다.
- **엔진 값은 이미 맞았다.** ⑧을 건너뛰고 직접 호출하면 주택 단건 A 150,000,000 · B 500,000,000, 일반건물 A 50,000,000 · B 200,000,000, 묶음 2건 합은 단건 합과 ±0.
- **방식별 값은 읽히지 않는다.** 산정방식(실지·환산·매매사례·감정)을 바꿔도 A·B·양도차익·결정세액이 같다(주택 결정세액 270,387,000 · 일반건물 418,539,000).
- **그런데 ⑫가 읽지 않는 값을 요구했다.** 실지 → 당초 증여자 실지취득가액 필수 · 매매사례·감정 → 당초 증여자 매매·감정가액 필수(없으면 「입력값이 올바르지 않습니다」). 화면이 그 칸을 숨기면 막다른 길이다.

## 3. 변경

- ⑤ `bgCollateralForcesStdAcq`: 이월과세 제외 삭제. 이 술어를 쓰는 소비처(취득시 기준시가 칸·산정방식 칸 숨김·필요경비 라벨·의제취득·재개발 등)는 기준시가 모드와 같은 경로를 탄다.
- ⑤ `bgCoDonorNeedsStdPrice`: 담보 승을 추가(인자를 `AssetForm`으로 넓힘). 이월과세 박스에서 담보 승이면 쓰이지 않는 당초 증여자 매매·감정가액 입력과 환산 안내를 숨기고, 담보 승 안내에 「당초 증여자 기준시가도 이월과세 칸에 입력」을 덧붙인다.
- ⑧ 단건: 이월과세 담보 승 차단 삭제(조합원입주권은 유지). 당초 증여자 요구(`missingCoDonorBasisLabel`)는 담보 승이면 매매·감정 요구를 건너뛰고 기준시가 두 칸만 요구한다.
- ⑧ 묶음: `bgCarryoverWinnerUnsupported` 삭제. 이월과세는 더 이상 비보충 승자 차단 사유가 아니다. 지분·입주권·겸용은 그대로 막는다.
- ⑫ Zod: `collateralForcesStdAcquisition`에서 이월과세 제외 삭제. 판정 함수는 `required-refines`와 `donor-built`가 서로 import하지 않도록 리프 `transfer-tax-schema-collateral-win.ts`로 옮겼다.
- ⑫ Zod 당초 증여자 건물 기준시가 0 거부(`needsDonorStdPrice`)에 담보 승을 추가. 실측: 담보 승 일반건물에서 ⑧은 0을 막는데 ⑫는 200으로 받아 A가 건물 0(1천만 원)으로 계산됐다(같은 입력을 기준시가 모드로 넣으면 ⑫가 400). ⑧↔⑫ 불일치라 맞췄다.
- ⑫ 엔진: 담보 승이면 증여받은 파트의 당초 증여자 **기준시가만** 요구한다(`assertCollateralForcedDonorStd`). 미입력은 `?? 기존값`이 양도인 값으로 대신해 A = B가 되므로 여전히 차단한다. §114조의2 × 이월과세 × 감정가액 가드는 함수로 빼내 담보 승에서도 그대로 적용한다.

- 옛 차단을 단언하던 기존 칸 3개(1단계 CU-2 · UW-2 · `bg-collateral-win-ratio-one` CW-2의 이월과세 칸)는 반전하지 않고 삭제했다 — 열린 동작은 이 anchor가 고정하고, 같은 `it.each`의 지분·입주권·겸용 칸이 차단 안전망을 유지한다.

- 시나리오 채택은 법대로다: 이월과세 적용 시 결정세액이 적용하지 않을 때보다 **크면** 적용(A), **더 적으면** 적용하지 않는다(B)(소득세법 §97조의2②3호).

## 5. 확인 필요 · 고치지 않은 것

- 브라우저 확인은 **주택 · 둘 다 이월과세 · 단건**만이다. 일반건물과 첫/둘째 자산만 이월과세인 조합은 API anchor로만 확인했다.
- §114조의2(신축·증축 5년 이내) × 이월과세 × 감정가액 가드는 담보 승에서도 유지했다. 그 조합의 시료는 측정하지 않았다.
- 지분 보유 · 조합원입주권 · 겸용주택의 비보충 승자는 그대로 막는다.
