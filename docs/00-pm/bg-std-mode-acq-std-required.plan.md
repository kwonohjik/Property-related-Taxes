# 부담부증여 기준시가 모드 — 양도인 취득시 기준시가 필수 (⑫ 침묵 취득가액 0 차단)

> 선행: 「이월과세 담보·임대 승 ⑧↔⑫ 격자」 측정(2026-10-30)에서 발견한 별건(결함 2). 사용자 지시: 「결함 2번 진행해」.

## 1. 사실 (실측)

기준시가 모드 부담부증여는 양도가액을 양도시 기준시가로, 취득가액을 「취득시 기준시가 × 채무비율」로 정한다(「소득세법 시행령」 §159①1호 괄호).
양도인의 취득시 기준시가를 비우면 ⑧(`transfer-tax-validate-bg.ts` (5-c))은 막지만 **⑫·엔진은 200** 이고 취득가액이 0이다.

| 셀 | ⑧ | ⑫ 종전 | 양도차익 |
|---|---|---|---|
| 기준시가 모드 주택 단건 · 채움 | 통과 | 200 | 194,000,000 |
| 기준시가 모드 주택 단건 · **비움** | 차단 | **200** | **400,000,000** |
| 기준시가 모드 토지 단건 · 비움 | 차단 | **200** | **400,000,000** |
| 주택 묶음 · 주 자산 / 컴패니언 비움, 토지 묶음 컴패니언 비움 | 차단 | **200** | (취득가액 0) |
| 시가 모드 담보 승 · 비움 (주택·토지) | — | 400 | 엔진이 이미 막는다 |

양도시 기준시가의 짝 가드(`isStandardMode && supplementary === 0`)는 있었고 취득시 쪽만 없었다. 일반건물은 ⑫ `requireStd`(`transfer-tax-schema-gb-bg-refines.ts`)가 4칸 모두 요구해 이미 막힌다.
화면에서는 ⑧이 먼저 막아 **API 직접 호출에서만** 도달한다. 이월과세와 무관하다.

## 2. 수정

`lib/tax-engine/burdened-gift-apportionment.ts` — 양도시 기준시가 가드 바로 아래에 짝 가드를 추가한다.
조건: `isStandardMode ∧ acqStdPriceForced ∧ ¬preDeemed ∧ 취득시 기준시가(토지+건물) ≤ 0` ⇒ `TaxCalculationError(INVALID_INPUT)` → 400.

- 의제취득일 전 자산(`preDeemed`)은 의제취득일 기준시가를 요구하는 자기 안내가 `resolveWholeBgAcquisition`에 따로 있어 제외한다(안내가 가려지지 않게).
- 입주권은 `acqStdPriceForced`가 false라 영향 없다(괄호 미발동 · K-4).
- 시가 모드는 건드리지 않는다 — 담보 승은 기존 가드가, 보충적평가 승은 괄호 미발동이다.

## 3. 검증 (`transfer.route.bg-std-mode-acq-std-required.anchor.test.ts` 10건)

- SA-1 주택·토지 단건 — 비움 ⇒ 400(「취득시 기준시가」 안내, 종전 200), 채움 ⇒ 200 ∧ 양도차익 194,000,000.
- SA-2 함께 양도 묶음 — 주 자산·컴패니언 어느 쪽이든 비움 ⇒ 400, 둘 다 채움 ⇒ 200.
- SA-3 시가 모드 보충적평가 승 — 취득시 기준시가 없이 200(과차단 없음).
