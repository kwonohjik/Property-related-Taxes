## 1. 측정 방법 [직접]

throwaway probe(`calculateStockTransferTaxAggregate(inputs, "aggregate")`, 시드 고정 의사난수, 삭제함 · 복사본은 세션 스크래치패드).

- **시료:** 3,000건. 종목 2~3건. 각 종목은 «단독 대주주(비상장·장기, 주당 양도가·취득가 1원 단위 무작위)» 또는 «분할 로트 대주주(장기 lot + 단기 lot, `costAllocationMethod: "fifo"`, 양도가 1원 단위 무작위)». 비중소기업·기본공제 250만 그룹 1회.
- **기준(단일 절사값):** `floorTen( f(Σ 장기분 과세표준) + Σ 단기분 30% 세액 )`, `f(B) = 0.2B (B ≤ 3억) / 0.25B − 15,000,000`. 단기분·장기분 분할은 `calcSplitModeTax`와 같은 식으로 재구성(`shortBase = floor(과세표준 × 단기이익 / 전체이익)`).
- 한 건을 손으로 검산했다(§2.1).

## 3. 원인 [직접: 코드 + 시료 재현]

`stock-transfer-aggregate.ts` 합계는 `floorTen( Σ 행 + adjustment )`이고 `adjustment = floorTen(f(ΣL)) − Σ floorTen(f(Lᵢ))`(`stock-transfer-aggregate-major-bracket.ts:68-70`)다. 두 곳의 절사 단위가 다르다.

- **행:** `floorTen(단기세액ᵢ + 장기세액ᵢ)` — 단기와 장기를 **합쳐서** 절사.
- **보정의 종목별 합:** `Σ floorTen(장기세액ᵢ)` — 장기분만 **따로** 절사.

단독 종목(단기분 없음)은 두 절사가 같은 수라 상쇄돼 정확하다. 혼합 종목에서는 `floorTen(s+l) ≠ floorTen(s) + floorTen(l)`이라 종목당 최대 9원씩 어긋난 채 보정이 더해진다. 이 어긋남이 «종목 행이 이미 내린 몫»과 «보정이 되돌리는 몫»이 달라서 생기며, 부호가 한쪽으로 고정되지 않아 합계가 정확값을 넘을 수 있다.

## 4. 후보 F3 [직접: 같은 3,000건]

**군 단위 한 번 절사.** 보정을 «대주주 군의 법정 세액과 행 합의 차»로 정의한다.

```
groupTax   = floorTen( f(Σ장기분) + Σ(혼합 종목의 단기분 30% 세액) )
adjustment = groupTax − Σ(대주주 군 소속 종목의 행 산출세액)
합계       = floorTen( Σ 모든 행 + adjustment )
```

- 3,000건 전부 **오차 0** (히스토그램 `{0: 3000}`) [직접].
- 군 소속 종목만 이 식으로 묶이므로, 비대주주·기타자산 등 **군 밖 종목은 종전 규약(행 절사 합)** 그대로다 — 이 시료는 군 밖 종목을 넣지 않았다 → V-2.
- 보정이 0 이하일 때 echo를 숨기는 규칙(`adjustment ≤ 0 → undefined`)은 그대로 둘 수 있다 — 같은 식에서 `adjustment`만 새 정의 → V-3.

## 5. 영향 범위 [직접: grep] · 미측정 후속

- `computeMajorProgressiveGroupTax`(`stock-transfer-aggregate-major-bracket.ts`) — 입력에 «종목별 단기분 30% 세액»과 «행 산출세액»이 더 필요하다. 지금은 `bases`(장기분 과세표준)와 `items`(`isExempt`)만 받는다.
- 세율 계산이 돌려주는 값에 `shortTermTax`(혼합 종목의 단기분 세액)를 추가해야 한다 — `calcSplitModeTax`가 이미 `shortTax`를 갖고 있다(`lot-allocation-tax.ts`).
- echo `majorProgressiveGroupTax`의 의미가 바뀐다: `aggregatedTax`는 «누진 합산 세액 + 단기분»이 되고 `itemSumTax`는 «군 소속 종목 행 합»이 된다. 결과 카드(`StockAggregateSummaryCard.tsx`)와 신고서 행 24-3 문구 확인 필요 → V-4.
- 기존 anchor: `MB-5-2`는 `ten(Σ 행 + adjustment)`을 단언하므로 새 정의에 맞게 갱신해야 한다(정의 변경이지 값 오류가 아님).
