# 판정 메뉴 — 명부의 「장기임대」 행 × §155⑳ 충족인데 과세 — 수정 계획서

> 작성 2026-10-25 · 검증 깊이 **L2**(판정 메뉴 결론이 바뀐다 — 계산기 세액·엔진 불변) · 선행: `rental-155-20-merge-temp-composition.plan.md` §5 별건 R-1 · `rental-155-20-unmet-blocks-155-1.plan.md`(F-1 Q-3)

## 0. 배경

판정 메뉴는 「§155⑳ 특례로 선언한 임대주택은 보유 주택 명부에 넣지 않는다」가 전제다(`lib/tax-engine/one-house/rental-housing-verdict.ts:90-103`).
그래서 ⑳ 판정 결과를 반영하는 `applyRentalHousingVerdict`(`:127-136`)는 **충족이면 판정을 그대로 둔다**.

그런데 사용자가 임대주택을 명부에도 「장기임대 등록주택」으로 넣으면, 판정 엔진은 그 행을 세어 「1세대 2주택 이상」으로 판정한 상태다.
⑳이 충족돼도 그 판정이 남아 **⑳ 카드는 「요건 충족」인데 판정 결과는 「과세」**가 된다. 같은 입력을 넘겨받은 계산기는 0이다.

⑧은 경고만 낸다(`lib/calc/one-house-exemption-validate.ts:376` 「…명부에 다시 넣지 마세요…」 — 차단 아님). 불성립 쪽은 F-1 Q-3이 명부 행을
지원하게 했지만(`judgment-pipeline.ts:64-65`) 충족 쪽은 빠져 있었다.

## 2. 원인과 법령 근거

- 원인: `app/api/calc/one-house-exemption/judgment-pipeline.ts:45-65` — 판정(`judgeOneHouseExemptionFromInput`)은 명부 전체로 한 번만 하고, ⑳ 충족이면 `applyRentalHousingVerdict`가 그 판정을 그대로 돌려준다.
- 계산기는 STEP 1a(다른 특례 비과세면 조기 반환) → STEP 2.5(⑳ 충족이면 특례 결과로 반환 — `transfer-tax.ts:477-506`)라 이 결함이 없다.
- 영 §155⑳: 「장기임대주택 … 과 그 밖의 1주택을 국내에 소유하고 있는 1세대가 … 거주주택을 양도하는 경우에는 **국내에 1개의 주택을 소유하고 있는 것으로 보아 제154조제1항을 적용한다**」(MST 286211 · 290841 원문 — `lib/tax-engine/transfer-tax-rental-housing-judge.ts:312-313`).
  ⑳이 충족되면 임대주택을 뺀 주택 수로 §154①을 판정하는 것이 조문 문언이다. 해석이 갈리는 쟁점은 없다.
- 세대 구성 판정(`resolveRentalResidenceComposition`)은 이미 명부의 `isLongTermRental` 행을 전부 임대주택으로 본다(`transfer-tax-rental-residence-composition.ts:172`). 아래 수정은 같은 술어로 그 행들을 뺀다.

## 3. 설계

### D-1 — ⑳ 충족 + 명부 「장기임대」 행 + 비과세 안 섬 → 그 행을 빼고 다시 판정 (pipeline)

```ts
const rentalRowIds =
  builtRentalVerdict?.passed && !roster.judgment.isExempt && !roster.judgment.isPartialExempt
    ? (engineInput.houses ?? []).filter((h) => h.isLongTermRental === true).map((h) => h.id)
    : [];
const { exclusion, judgment: coreJudgment } =
  rentalRowIds.length > 0 ? judgeRoster(withoutRosterRows(engineInput, rentalRowIds, isRightSale)) : roster;
```

- 재판정은 **판정 엔진을 다시 부른다** — 보유 2년·거주 요건은 엔진이 그대로 본다. `applyRentalHousingVerdict` 주석의 「비과세를 «주면» 거주·보유요건을 두 번째 경로로 우회」 우려에 해당하지 않는다.
- 세대 주택 수는 route와 같은 `deriveHouseholdHousingCount`로 다시 도출한다.
- 그 뒤 단계(⑳ 반영 · §89①4호 · 비거주자 · 잔금 전 멸실)는 그대로 돈다. 양론 표시·같은 날 권리 고지의 파이프라인 재실행도 같은 규칙을 탄다(`judgment-request.ts:219·251`).

### D-2 — 다른 특례로 이미 비과세·부분 비과세가 서면 재판정하지 않는다

P4(임대 행이 일시적 2주택 신규 주택)는 엔진이 임대주택을 센 채 ①로 비과세를 냈다. 계산기도 STEP 1a에서 그 판정으로 조기 반환한다(사유 「일시적 2주택 비과세」).
재판정하면 사유가 「1세대1주택 비과세」로 바뀌어 계산기와 갈린다 — 그대로 둔다.

### D-3 — 주택 수 카드에 뺀 행을 보인다

재판정만 하면 카드가 「2채 중 2채」인데 결론은 비과세다(실측). `buildOneHouseCountBreakdown`에 `rentalDeemedHouseIds`를 넘겨 제외 목록에 한 줄을 싣는다.

- 문구: 「장기임대주택 — 거주주택 특례 요건 충족으로 거주주택을 1주택으로 봄」 · 근거 `TRANSFER_RENTAL_HOUSING.PIT_RD_155_20`.
- 명세의 `exclusion`은 재판정 입력의 것을 쓴다 — 임대 행이 다른 제외(상속 등)에도 걸려 있으면 두 번 빼지 않게.

### D-4 — ⑧ 경고 문구는 그대로 둔다

「명부에 다시 넣지 마세요」는 메뉴 전제를 알리는 입력 안내다. 수정 후에도 불성립이면 그 행은 주택 수에 들어가고(P3·P9·P10), 충족이면 결론이 「명부 없음」과 같아진다 — 안내가 결론을 틀리게 만들지 않는다.
