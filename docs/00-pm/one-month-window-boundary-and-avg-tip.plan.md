## B-1 ✅ 「이전 N개월이 되는 날」은 구간에 **포함**된다

### 판정 근거

상증령 §52의2②2호:

> 「평가기준일 **이전 2월이 되는 날부터** 동 사유가 발생한 날의 전일까지의 기간」

같은 항 1호·3호는 경계를 **뺄** 때 「사유가 발생한 날의 **다음날**부터」라고 **명시**한다.
⇒ 조문이 뺄 때는 그렇게 적는데 정상 구간의 시작은 「~되는 날**부터**」이므로 **포함**이다.

소득세법 시행령 §165③이 「"평가기준일 전후 2개월"은 "양도일·취득일 **이전 1개월**"로 한다」로
**치환**하므로 1개월 창에도 같은 규칙이 적용된다.

### 반대 근거도 있었다 — 사용자 결정으로 종결

「이미지 13」의 실제 사례 3건은 **경계일을 제외**한다(`listed-stock-valuation-anchor-shift-fix.plan.md:11`
「시작 = anchor − 2개월 **+ 1일**」):

| 평가기준일 | 이미지 13 시작일 | `−2개월` | `−2개월 +1일` |
|---|---|---|---|
| 2022-12-02 | 2022-10-03 | 10-02 | **10-03** |
| 2022-12-15 | 2022-10-16 | 10-15 | **10-16** |
| 2001-12-28 | 2001-10-29 | 10-28 | **10-29** |

⇒ **조문 문언(포함) vs 교재 사례(제외)** 의 충돌. 세액이 바뀌는 판정이라 조용히 고르지 않고
사용자에게 물었고, **「1개월·2개월 모두 경계일 포함」** 으로 확정됐다(2026-09-01).
이미지 13을 고정하던 anchor(AS-01·02·03 등)는 그 결정에 따라 갱신했다.

> ⛔ **재제안 금지**: 「이미지 13 사례대로 되돌리자」는 이미 판정된 사항이다. 되돌리려면
> 조문 해석을 뒤집을 **새 근거**(예규·심판례)를 먼저 제시할 것.

### 구현

`lib/kiwoom/calendar.ts`:

- `addMonthsClamped(date, delta)` **신설** — 민법 §160② 말일 클램프의 일반형.
  종전에는 1개월 쪽(`monthBeforeClamped`)만 클램프가 있고 **2개월 쪽은 맨 `setUTCMonth(±2)`** 라
  월말에서 달을 넘겼다(2023-04-30의 −2개월이 3월 2일로 밀렸다). 한 파일 안에서 두 방향이
  갈려 있던 것을 합쳤다.
- `buildOneMonthBeforeSlots` — `start`의 `+1일` **제거**.
- `buildSurroundingSlotsFromAnchor` — `start`의 `+1일`·`end`의 `−1일` **제거** + 클램프 적용.
- `monthBeforeClamped` → `addMonthsClamped(a, -1)` 위임(단일 소스).

⚠️ **`buildOneMonthAfterListingSlots`(§165⑤)는 건드리지 않았다** — B-4 참조.

### 결과

| | 종전 | 변경 후 |
|---|---|---|
| 양도일 2026-02-26 (제보) | 2026-01-27 ~ 02-26 (31일 · 거래일 20) | **2026-01-26 ~ 02-26** (32일 · 거래일 21) |
| 양도일 2024-06-03 | 2024-05-04 ~ 06-03 | **2024-05-03 ~ 06-03** |
| 양도일 2023-03-31 | 2023-03-01 ~ 03-31 | **2023-02-28 ~ 03-31** (말일 클램프) |
| 평가기준일 2022-12-02 | 2022-10-03 ~ 2023-02-01 | **2022-10-02 ~ 2023-02-02** |

⚠️ **「1개월 = 31일」이 아니다.** 말일 클램프 때문에 달마다 **29~32일**로 달라진다.
길이를 상수로 단언하는 테스트를 새로 쓰지 말 것 — **경계 두 날짜**를 단언한다.

## B-2 ✅ 같은 팁이 두 번 뜨고 **두 값이 갈렸다**

### 실측 위치

`PostListingValuationCard.tsx`가 `<TransferDate1MonthClosingPriceTable>`을 렌더하는데,
**그 표가 이미 자기 요약줄을 갖고 있었다.** 카드가 같은 필드의 요약을 하나 더 붙였다.

| | 값 출처 |
|---|---|
| amber (표 안) | `preview.avg` — **매 렌더 재계산** |
| green (카드) | `form.transferDatePriceAvg1Month` — **저장 값** |

### 🔴 중복보다 심각했던 것 — 저장값이 낡는다

```
amber : 거래일 16일 · 종가합계 264,970 · 1개월 종가평균 16,560   (현재 입력 상태)
green : 자동 산정 평균 = 16,559 원                                (직전 자동조회 20거래일 — stale)
```

저장 필드는 **셀 편집(`handleChange`)·키움 자동조회(`onFill`)** 때만 쓰인다.
표시만의 문제가 아니다 — **저장값이 곧 §99①3 환산 분모로 엔진에 간다.**

### 근본 원인 — 리셋 조건이 모드로 한정돼 있었다

`Step1.tsx`는 양도일 변경 시 `transferPriceDates`·`transferPriceClosing`·
`transferDatePriceAvg1Month`를 리셋하는데, 그 조건이 **`transferStdInputMode === "daily"`** 였다.
⇒ **direct 모드에서 양도일을 바꾼 뒤 daily로 전환**하면 배열이 낡은 채 살아남아,
`displayDates`(양도일 파생)와 인덱스가 어긋나고 저장 평균만 옛 값으로 남는다.

### 수정

1. **`Step1.tsx` 리셋에서 모드 조건 제거** — 잔재는 어느 모드에서 생겼든 양도일이 바뀌면 무효다.
2. **카드의 green 요약줄 삭제** — 표시는 **실시간 재계산 쪽 한 곳**으로 모은다
   (stale이 구조적으로 불가능한 쪽).

> ⛔ `useEffect → store` 미러링으로 해결하지 않았다(프로젝트 정책 · 무한 루프).
> ⛔ 리셋 조건을 다시 좁히지 말 것 — 이 결함이 되살아난다.

### 검증

- anchor `one-month-avg-stale-mirror.anchor.test.tsx` **3건** — SM-1(daily 회귀 가드) ·
  **SM-2(제보 경로 · direct)** · SM-3(같은 일자 재입력 시 불필요한 삭제 없음)
- **수정 전 SM-2가 적색**임을 먼저 확인했다(결함 재현 → 그 다음 수정)

## B-4 ✅ §165⑤ 상장일 이후 1개월도 같은 off-by-one이었다

초판에서는 승인 범위 밖이라 미변경으로 두고 **PDF 원본의 확인을 요청**했다. 저장소 기록이
서로 어긋났기 때문이다:

| 출처 | 2009-08-21 상장 시 종료일 |
|---|---|
| `docs/00-pm/recent-completions.md:52` — 「PDF 일자 2009-08-21~2009-09-21 일치」 | **09-21** |
| 코드 `calendar.ts` + anchor `stx-venue-and-month-clamp.anchor.test.ts:130` | **09-20** |

**사용자 확인 (2026-09-01): PDF는 09-21이다.** ⇒ B-1과 같은 방향(경계일 포함)으로 확정.

### 🔑 종전 구현은 자기 자신과 모순이었다

`monthAfterClamped`의 두 분기가 같은 규칙을 다르게 구현하고 있었다:

| 분기 | 예 | 종전 결과 | 경계일 |
|---|---|---|---|
| **오버플로**(해당일 없음) | 2023-01-31 + 1개월 | 2023-02-28 | **포함** |
| **정상**(해당일 있음) | 2009-08-21 + 1개월 | 2009-09-**20** | **제외** |

민법 §160③의 「최종의 월에 해당일이 없는 때에는 **그 월의 말일로 기간이 만료한다**」를
오버플로 분기에서는 「말일 = 종료일」로 옳게 읽고, 정상 분기에서만 하루를 뺐다.

⇒ 이 모순이 **결함의 위치를 스스로 가리킨다**. 두 분기를 「1개월이 만료하는 날 = 종료일」로
통일하면 **오버플로 케이스는 값이 그대로**여야 하는데, 실제로 그랬다(PL-CLAMP-1~3 무변경).

### 구현

- `monthAfterClamped` **삭제** — `addMonthsClamped(a, +1)`과 동일해져 고아가 됐다.
  (내 변경이 만든 고아만 제거 — Surgical Changes)
- `buildOneMonthAfterListingSlots`의 `end` → `addMonthsClamped(anchor, 1)`.
  ⇒ 1개월 전·2개월 전후·1개월 후 **세 창이 모두 같은 소스**를 쓴다.

### 미확인으로 남기는 것

`recent-completions.md:52`는 같은 줄에서 사례 48을 「**21 거래일** 종가표」라고도 적는다.

행 수는 화면 문구·상수로 쓰지 않는다.
