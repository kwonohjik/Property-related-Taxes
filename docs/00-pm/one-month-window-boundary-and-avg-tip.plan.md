## B-1 ✅ 「이전 N개월이 되는 날」은 구간에 **포함**된다

### 판정 근거

상증령 §52의2②2호:

> 「평가기준일 **이전 2월이 되는 날부터** 동 사유가 발생한 날의 전일까지의 기간」

같은 항 1호·3호는 경계를 **뺄** 때 「사유가 발생한 날의 **다음날**부터」라고 **명시**한다.
⇒ 조문이 뺄 때는 그렇게 적는데 정상 구간의 시작은 「~되는 날**부터**」이므로 **포함**이다.

소득세법 시행령 §165③이 「"평가기준일 전후 2개월"은 "양도일·취득일 **이전 1개월**"로 한다」로
**치환**하므로 1개월 창에도 같은 규칙이 적용된다.

### 반대 근거도 있었다 — 사용자 결정으로 종결

「이미지 13」의 실제 사례 3건은 **경계일을 제외**한다(`listed-stock-valuation-anchor-shift-fix.plan.md:11`
「시작 = anchor − 2개월 **+ 1일**」):

| 평가기준일 | 이미지 13 시작일 | `−2개월` | `−2개월 +1일` |
|---|---|---|---|
| 2022-12-02 | 2022-10-03 | 10-02 | **10-03** |
| 2022-12-15 | 2022-10-16 | 10-15 | **10-16** |
| 2001-12-28 | 2001-10-29 | 10-28 | **10-29** |

⇒ **조문 문언(포함) vs 교재 사례(제외)** 의 충돌. 세액이 바뀌는 판정이라 조용히 고르지 않고
사용자에게 물었고, **「1개월·2개월 모두 경계일 포함」** 으로 확정됐다(2026-09-01).
이미지 13을 고정하던 anchor(AS-01·02·03 등)는 그 결정에 따라 갱신했다.

> ⛔ **재제안 금지**: 「이미지 13 사례대로 되돌리자」는 이미 판정된 사항이다. 되돌리려면
> 조문 해석을 뒤집을 **새 근거**(예규·심판례)를 먼저 제시할 것.

### 구현

`lib/kiwoom/calendar.ts`:

- `addMonthsClamped(date, delta)` **신설** — 민법 §160② 말일 클램프의 일반형.
  종전에는 1개월 쪽(`monthBeforeClamped`)만 클램프가 있고 **2개월 쪽은 맨 `setUTCMonth(±2)`** 라
  월말에서 달을 넘겼다(2023-04-30의 −2개월이 3월 2일로 밀렸다). 한 파일 안에서 두 방향이
  갈려 있던 것을 합쳤다.
- `buildOneMonthBeforeSlots` — `start`의 `+1일` **제거**.
- `buildSurroundingSlotsFromAnchor` — `start`의 `+1일`·`end`의 `−1일` **제거** + 클램프 적용.
- `monthBeforeClamped` → `addMonthsClamped(a, -1)` 위임(단일 소스).

⚠️ **`buildOneMonthAfterListingSlots`(§165⑤)는 건드리지 않았다** — B-4 참조.

### 결과

| | 종전 | 변경 후 |
|---|---|---|
| 양도일 2026-02-26 (제보) | 2026-01-27 ~ 02-26 (31일 · 거래일 20) | **2026-01-26 ~ 02-26** (32일 · 거래일 21) |

⚠️ **「1개월 = 31일」이 아니다.** 말일 클램프 때문에 달마다 **29~32일**로 달라진다.
길이를 상수로 단언하는 테스트를 새로 쓰지 말 것 — **경계 두 날짜**를 단언한다.

## B-2 🟠 같은 팁이 두 번 뜬다 — 그리고 **두 값이 다르다**

### 실측 위치

`PostListingValuationCard.tsx:180-188`이 `<TransferDate1MonthClosingPriceTable>`을 렌더하는데,
**그 표가 이미 자기 요약줄을 갖고 있다**. 카드가 같은 필드의 요약을 하나 더 붙인다.

| | 위치 | 값 출처 |
|---|---|---|
| amber | `TransferDate1MonthClosingPriceTable.tsx:180-187` | `preview.avg` — **렌더 시점에 입력칸에서 실시간 재계산** |
| green | `PostListingValuationCard.tsx:181-188` | `form.transferDatePriceAvg1Month` — **저장된 값** |

### 🔴 중복보다 심각한 것 — 값이 갈린다 (dual-truth)

제보 이미지 13에서 두 줄의 값이 **다르다**:

```
amber : 거래일 16일 · 종가합계 264,970 · 1개월 종가평균 16,560
green : 자동 산정 평균 = 16,559 원
```

264,970 ÷ 16 = 16,560.6 → **16,560**(amber, 현재 입력 상태)
331,180 ÷ 20 = **16,559**(green, 직전 키움 자동조회 20거래일 결과 — **stale**)

원인: 저장 필드는 **셀 편집 시(`handleChange`)** 와 **키움 자동조회 시(`onFill`)** 에만 쓰인다
(`TransferDate1MonthClosingPriceTable.tsx:92-105`). 반면 amber의 `preview`는 **매 렌더 재계산**된다.
⇒ 셀 편집 없이 `displayDates`가 바뀌는 경로(양도일 변경 등)에서 저장값만 낡는다.

> 🔴 **B-1이 이 위험을 키운다.** 창이 31→32슬롯으로 바뀌므로, 기존 입력이 남은 상태에서
> 일자 집합이 재생성되는 경로에서 divergence가 더 잘 드러난다. B-2를 B-1 직후에 처리할 것.

### 수정 방향 (착수 전 확인 필요)

- **표시는 한 곳만** — 표 안의 amber 요약줄을 정본으로 두고 카드의 green 줄을 제거하는 쪽이
  자연스럽다(값의 출처가 실시간 재계산이라 stale이 없다).
- 다만 **저장 필드가 낡는 문제 자체는 표시를 지워도 남는다.** 저장값이 곧 §99①3 환산 분모로
  엔진에 가므로, `displayDates`가 바뀌는 모든 경로에서 평균이 다시 쓰이는지 **입력 경로 전수
  열거**가 선행돼야 한다(memory `feedback_enumerate_all_write_sites_before_fixing`).
- ❌ `useEffect → store` 미러링으로 해결 금지(프로젝트 정책 · 무한 루프).

### anchor 필수

착수 전 안전망 실측 결과를 적을 것. 최소 2건:
1. 표와 카드가 **같은 값**을 보인다(또는 요약이 1개만 렌더된다)
2. `displayDates`가 바뀐 뒤 저장 평균이 **재계산된 값과 일치**한다 ← 진짜 결함을 잡는 쪽

## B-3 🟠 사용자가 알 수 없는 문구 — 내부 식별자·전문용어 노출

나가면 안 된다(memory `feedback_no_internal_id_in_result`).

### 수정 방향

- 변수명 → **화면에 실제로 보이는 라벨**로 대체. 예: 「양도일 이전 1개월 종가평균」 칸.
- `mirror` → 「자동으로 채워집니다」·「자동 입력됩니다」 같은 평이한 한국어.
- 법조문 인용(§99①3 등)은 **유지**한다 — 이 앱의 사용자는 세무 실무자이고 근거 표시는 자산이다.
- 1·2번은 B-2에서 줄 자체가 통합·삭제될 수 있으므로 **B-2 결론 후** 문구를 확정한다.

## B-4 🟡 §165⑤ 상장일 이후 1개월도 같은 off-by-one인가 — 판단 요청

승인받은 범위는 「1개월·2개월」이었고 `buildOneMonthAfterListingSlots`는 **건드리지 않았다.**
다만 같은 축이고, 저장소 기록이 **서로 어긋난다**:

| 출처 | 2009-08-21 상장 시 종료일 |
|---|---|
| `docs/00-pm/recent-completions.md:52` — 「**PDF 일자 2009-08-21~2009-09-21 일치**」 | **09-21** |
| 코드 `calendar.ts` + anchor `stx-venue-and-month-clamp.anchor.test.ts:130` | **09-20** |

- 09-21로 보면 B-1과 **같은 방향**(경계일 포함)이고 조문 해석과 정합한다.
- 09-20으로 보면 사례 48 PDF의 **「21 거래일 종가표」** 와 맞는다 — 2009-09-20은 일요일이라
  09-21(월)을 넣으면 거래일이 **22**가 되기 때문이다.

⇒ **PDF 원본의 표 행 수(21 vs 22)를 직접 확인해야 갈린다.** 확인 전에는 바꾸지 않는다.
바꾼다면 세액(§165⑤ 취득 후 상장 환산)이 움직이므로 B-1과 같은 절차(anchor + 뮤테이션)를 밟는다.
