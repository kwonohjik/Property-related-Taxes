# 분리 OFF 증여 × 고시 전(단서 구간) — ⑧ 은 막고 ⑫ 는 일괄 신고가액으로 계산한다 (V-5)

- 상태: 실측 완료 · 구현 전 (Q-1·Q-2 결정 대기)
- 앵커: `__tests__/api/transfer.route.gb-gift-off-sec164-unsplit.anchor.test.ts` (12건, 현행 동작 고정)
- 선행: `gb-sec164-substitutes-blank-reported.plan.md` §8 (#2725 구현 중 드러난 V-5)

## 1. 요약

「소득세법 시행령」 §163⑨ 단서 1호·2호는 **증여받은 토지(1990.8.30. 전)·건물(기준시가 고시 전)** 의 취득가액을 **신고가액과 §164 가액 중 많은 금액**으로 정한다. 비교는 **파트별**이다.
분리 OFF 는 증여 신고가액이 **자산 단위 일괄값**으로만 들어와 파트별 비교가 성립하지 않으므로 ⑧ 이 막는다 (`lib/calc/transfer-tax-validate-gb.ts:308-318` — 「증여일이 기준시가 고시 전이라 토지·건물의 증여 신고가액을 파트별로 나누어 입력하세요」).
**⑫ 에는 이 조건이 없다.** ④ 가 파트 슬롯을 비워 보내면(#2725 `compareSec164`) 최상위 `acquisitionPrice`(일괄 신고가액)가 §166⑥ 으로 안분되어 200 이 나온다. 일괄 신고가액이 §164 합계보다 작으면 **§164 가액이 채택돼야 하는데 일괄 신고가액이 쓰여 세액이 과대**하다.

화면 도달: 불가능하다 (⑧ 차단). API 직접 호출·⑧ 우회 입력에서만 생긴다.

## 2. 측정

환경: vitest + `makeMockRates`, 함께 양도 묶음 두 위치(컴패니언·주 자산)와 단건. 취득시 기준시가는 토지 205,000,000(㎡당 1,000,000 × 205㎡) · 건물 150,000,000, 합계 S = **355,000,000**.

### 2.1 ⑧ ↔ ⑫ 격자 (72셀: 증여일 4 × 구성 3 × 일괄 신고가액 입력·비움 × 위치 3)

| ⑧ | ⑫ | 셀 |
|---|---|---|
| 차단 | **200** | **18** |
| 차단 | 400 | 42 |
| 통과 | 200 | 12 |

⑧ 차단·⑫ 200 의 18셀 = 일괄 신고가액을 **입력한** 셀 중 단서 구간 증여 파트가 있는 것: 1980 토지·건물 증여(3) · 1988 세 구성 전부(9) · 1995 토지·건물 증여와 토지 매매+건물 증여(6). 일괄 신고가액을 **비우면** ⑧ 도 ⑫ 도 400 이다. 단서 밖(2005, 1995 토지 증여+건물 매매)은 ⑧ 이 통과시키고 ⑫ 도 200 — 거짓 차단이 아니다.

### 2.2 세액 이탈 — 판별 시료 (오라클 = 같은 신고가액을 취득시 기준시가 비율 205:150 으로 나눈 분리 ON)

앞선 시료(P = 400,000,000)는 **판별력이 없었다** — P > S 면 두 파트 모두 신고가액이 §164 가액을 넘어 비교가 의미를 잃고 세액이 같다. 파트 비율이 기준시가 비율과 같으면 P ≥ S 일 때 두 파트가 함께 신고가액 쪽, P < S 일 때 함께 §164 쪽이다.

| 증여일 | P (일괄 신고가액) | 컴패니언·주 자산 Δ | 단건 Δ |
|---|---|---|---|
| 1988 | 355,000,000 (= S) | 0 | 0 |
| 1988 | 284,000,000 | **+22,365,000** | +20,874,000 |
| 1988 | 213,000,000 | **+44,730,000** | +41,748,000 |
| 1988 | 1,000,000 | **+111,510,000** | +107,580,000 |
| 1995 (건물만 단서) | 284,000,000 | +9,450,000 | +8,820,000 |
| 1995 | 213,000,000 | +18,900,000 | +17,640,000 |
| 1980 (의제취득일 전) | 284,000,000 · 1,000,000 | 0 | 0 |

Δ = 분리 OFF 세액 − 오라클 세액 (항상 **분리 OFF 쪽이 크다**). 1980 은 ③ 환산 경로가 신고가액과 무관하게 같은 값을 내므로 이탈이 없다. 대표: 1988 P=284,000,000 분리 OFF 444,675,000 · 오라클 422,310,000 (단건 349,914,000 · 329,040,000).

### 2.3 #2725 이전과의 관계

#2725 이전에는 같은 입력이 §164 가액을 **파트 슬롯에 직접 채워** 사용자의 일괄 신고가액을 무시했다(329,040,000). #2725 가 그 대체를 없애 일괄 신고가액이 쓰이게 됐다(315,810,000). 어느 쪽도 단서 비교를 하지 못한다 — 이 계획은 #2725 의 되돌림이 아니라 그 위의 별건이다.

## 3. 법령

새 해석 없음. 시행령 §163⑨ 단서 1호(토지 §164④)·2호(건물 §164⑤)의 「많은 금액」은 ⑧ 의 기존 문구가 그대로 인용한다. 단서는 **파트별 두 값의 비교**이며 일괄값은 비교 대상이 아니다 — 일괄값을 §166⑥ 으로 나눠 비교하는 것은 **자동 안분 fallback** 으로, 이 저장소는 금지한다 (`CLAUDE.md` 「자동 안분 fallback 금지(예외: PHD §164⑦)」 · memory `feedback_no_silent_apportion_fallback`). 미입력은 검증 오류로 차단한다.

## 4. 설계안

⑫ 에 ⑧ 과 **같은 조건**의 규칙을 둔다: 증여 파트가 단서 구간인데 그 파트의 가액 슬롯이 비면 400.

```ts
// transfer-tax-schema-required-refines-gb.ts — refineGbPropertyRequired (주 자산·컴패니언 공용), actualPriceMode 안
if (v.landAcquisitionCause === "gift" && v.landAcquisitionDate < LAND_PRICE_NOTICE_START && !positive(v.landAcquisitionPrice))
  issue(["landAcquisitionPrice"], …);
if (v.buildingAcquisitionCause === "gift" && isBeforeBuildingStdPriceNotice(v.buildingAcquisitionDate) && !positive(v.buildingAcquisitionPrice))
  issue(["buildingAcquisitionPrice"], …);
```

- 상수·함수는 ⑧ 이 쓰는 `LAND_PRICE_NOTICE_START`(`lib/calc/transfer-pre1990-commercial-bridge.ts`) · `isBeforeBuildingStdPriceNotice`(`lib/calc/commercial-164-6-proviso.ts`)를 그대로 쓴다(단일 소스). `lib/api` 는 이미 `lib/calc` 에서 상수를 가져온다(`transfer-163-9-base-date`).
- 필드(`landAcquisitionCause` · `landAcquisitionDate` · `buildingAcquisitionDate` · 파트 가액 슬롯)는 ⑫ 서브객체에 이미 있다.
- 분리 ON 은 ⑧ V-7 이 파트 가액을 요구하므로 슬롯이 채워져 이 규칙에 걸리지 않는다. 부담부증여는 함수가 `transferType` 으로 이미 면제한다.
- 새 법령 인용 없음 — 메시지는 ⑧ 문구를 그대로 쓴다(manifest 등록 대상 아님).

## 6. 미검증 (V)

- **V-1** 축 B 지분(`generalBuildingShares[].valuation`)은 측정하지 않았다 — 같은 규칙이 지분 카드에도 필요한지(지분별 ⑧ 조건)는 확인 필요. 이 설계는 주 자산·컴패니언 공용 함수에 두므로 지분 카드는 건드리지 않는다.
- **V-2** 이월과세(`carryover_gift`) 파트의 증여 단서는 이 규칙의 `gift` 조건에 해당하지 않는다 — 별도 경로이며 측정하지 않았다.
- **V-3** 오라클은 「일괄 신고가액을 기준시가 비율로 나눈 값」이다. 사용자가 실제로 입력할 파트별 신고가액은 임의이므로 Δ 는 이 가정 아래의 크기다 — 부호(분리 OFF 쪽이 큼)는 P < S 에서 항상 성립한다.
- **V-4** 1980(의제취득일 전) 파트의 `landPreDeemedClauseA` echo 가 슬롯 빈 입력에서 어떻게 보이는지는 확인하지 않았다(규칙은 1980 도 400 으로 만든다).
