## 4. 결정 대기

- **Q-1 (쌍 1: §97의3 × §97의4)** 선택 순서에 따라 갈리고 한쪽이 버려지는 동작을 어떻게 하나.
  - **a (권장)**: ⑧·⑫에서 막는다. 문구는 조문을 맞게 가리킨다 — «§97의3과 §97의4는 중복하여 적용할 수 없습니다 (조특법 §97의3②). 하나만 선택하세요.» UI 라디오가 이미 같은 결과를 강제하고 있어 ⑤ 변경이 없다. 법이 승자를 정하지 않고(§2) 선택 주체가 거주자(§127⑦ 취지)이므로 자동으로 고르지 않는다.
  - b: 엔진이 둘을 모두 평가해 공제액이 큰 쪽을 채택한다. 법에 선택 규칙이 없고 §97의3③ 신청 구조와 맞지 않아 자동 선택이 되며, 결과 표시(어느 쪽이 적용됐는지)도 만들어야 한다.
  - c: 현행 유지 + 고지. 순서에 따라 세액이 바뀌는 동작이 남는다.
- **Q-2 (쌍 2: ×§97의5)** ⑧만 막고 ⑫는 통과시키는 동작을 어떻게 하나.
  - **a (권장)**: ⑫도 ⑧과 같은 단일 소스 술어·문구로 막는다. ⑧↔⑫ 정합이고, 직접 호출에서 부적격 §97의5 때문에 §97의3이 조용히 빠지는 손실(41,066,668)을 없앤다.
  - b: 현행 유지. 엔진이 `OVERLAP_EXCLUDED_BY_97_5` 사유를 응답에 남긴다.
- **Q-3 (쌍 3: §97 본문·단서·§97의2 × §97의3/4)** 일반 규정 §127⑦ 충돌에 넣나.
  - **a (권장)**: 넣는다. `RENTAL_97_SERIES_IDS` 제외를 명문 배제 3쌍의 id(§97의3·§97의4·§97의5)로 좁힌다. 문구는 기존 §127⑦ 문구(`track127_7ConflictMessage`). §98·§98의2·신축주택·수용 감면과 같은 취급이다(#3118 Q-1 a·Q-2 a).
  - b: 현행 유지. 이중 적용(§3.4)이 직접 호출에 남는다.

## 5. 미검증 · 확인 필요

- V-1: §3.4는 합성 시료다. §97(2000.12.31 이전 임대 개시)과 §97의4(민간임대주택특별법 등록)가 같은 주택에서 동시에 적격인 현실 사례가 있는지 **확인 필요**. 없다면 쌍 3의 실제 도달 가능성은 낮다(그래도 분류 일관성 때문에 Q-3 a를 권장).
- V-2: 엔진은 §97의5가 부적격이어도 선택 사실만으로 §97의3/4를 배제한다. §97의5②가 «적용받는» 경우만 배제하는지는 조문상 «세액감면은 … 중복하여 적용하지 아니한다» 이상은 알 수 없다 — 해석례 미확인. 이번 계획은 ⑧의 현행 기준(선택 사실)을 ⑫에 맞출 뿐이며 이 기준 자체는 바꾸지 않는다.
- V-3: 다건 `properties[]`·컴패니언에 ⑫ 차단이 닿는지는 #3118과 같은 구조(같은 refine 호출 2곳)라고 코드로 보았으나 anchor로만 확정한다.
- V-4: 폼 마이그레이션 전 저장분 legacy id `long_term_rental`은 현재 임대 범주 제외 목록에 있다. Q-3 a로 목록을 좁히면 이 id와 §97의3/4의 병용도 §127⑦로 막힌다 — 의도이나 도달 여부는 **확인 필요**.
- V-5: 저장된 이력·정규화(`normalize`)로 UI에서도 임대 조문이 둘 이상 담길 수 있는지는 확인하지 않았다. 라디오는 선택 시에만 작동한다.
- V-6: §97 단서(`rental_97_proviso`)는 측정하지 않았다. §97 본문과 같은 분류 경로(세액감면형)라고 코드로 보았다.
