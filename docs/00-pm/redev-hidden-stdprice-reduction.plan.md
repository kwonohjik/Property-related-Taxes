# 재개발·입주권(§166) 자산의 감면 계산이 화면에 없는 기준시가 칸을 읽는 문제 수정 계획서

> 상태: **v0.2 (2026-10-21) 사용자 결정 반영** — Q-1 = **(a) ④·⑧·⑤ 한 leaf**, Q-2 = **(a) 안분 키 계속 인정**, Q-3 = **(a) ⑧에서 막지 않음**(Do 1단계 실측에서 엔진이 명시 사유 없이 0을 내면 (b)로 재검토).
> 계기: #2336(§166 표시 취득가액 역산 통일) 보고의 남은 확인 필요 «§166 엔진이 감면 판정에 일반 기준시가 칸을 넘긴다 — 숨은 옛 값의 감면 영향».
> 검증 방식: throwaway probe(워크트리 `-rhsp`, 커밋 안 함)로 폼 → ④ → route → 엔진 결과를 실측했고, 화면에 칸이 있는지는 Playwright로 셌다. 인용 file:line은 base `56a4e42ae`(master) 기준.

---

## 0. 한 줄 요약

원조합원 §166 자산(입주권 · 비승계 완공APT)은 일반 「취득시·양도시 기준시가」 칸이 **화면에 없다**. 그런데 환산 모드면 ④가 그 칸의 값을 엔진에 보내고, 감면 카드의 기준시가 칸이 비어 있으면 감면 계산이 **그 값으로 대신 계산**한다. 자산 종류를 바꾸기 전에 넣은 옛 값이 남아 있으면 **세액이 바뀐다**(같은 입력에서 330,990,000 대 181,170,000). ⑧도 그 숨은 값을 「입력됨」으로 인정해 차단하지 않는다.
수정안은 «화면에 없는 칸은 보내지도, 입력으로 인정하지도 않는다»를 한 leaf로 정해 ④·⑧·⑤가 함께 쓰게 하는 것이다.

### 1.4 같은 폴백인데 ⑧ 가드가 없는 조문

§99(`income-deduction-router.ts:289`) · §98의8(`:345`) · 미분양 하이브리드 §98의3·§98의5·§98의6·§98의7·§99의2(`unsold-hybrid*.ts`)는 감면 카드의 양도시 기준시가가 «선택 — 미입력 시 자산값 폴백»이고(`ReductionStdPriceSection.tsx:40-42`), ⑧이 그 칸을 요구하지 않는다. 감면 자산 종류 게이트는 완공APT·입주권에 이 조문들을 허용한다(`asset-kind-gate.ts:43-48`, §98의2만 제외). ⇒ §166 자산에서 감면 카드 양도시 칸을 비우면 숨은 옛 값이 **⑧ 차단 없이** 쓰인다. **적격 입력으로 세액 차이는 재지 않았다 — 확인 필요**(Do 1단계).

### 1.5 결함이 아닌 것 — 의도된 설계

일반 자산(주택 등) **실가 모드**도 기준시가 칸이 화면에서 숨는다(`CompanionAcqStdPriceSection.tsx:93` — 환산·분리 모드에서만 렌더). 옛 값이 남으면 ⑧은 통과하고 엔진은 `MISSING_PRORATION_PRICES`로 감면을 뺀다(probe C — 세액 480,628,500 세 경우 동일). 이 «⑧ 통과 → 엔진의 명시 오류»는 **의도된 설계**로 문서화돼 있다(`transfer-tax-validate-reductions.ts:269-273` — «조용한 오계산이 아니라 분명한 오류다»). 이번 범위에 넣지 않는다.

## 2. 원인

«화면에 없는 칸» 규칙이 ⑤(렌더 게이트)에만 있고 ④·⑧에는 없다. #2330(V5)·#2336이 같은 자산의 `fixedAcquisitionPrice`(숨은 상단 취득가액 칸)에 대해 이미 같은 문제를 한 leaf(`lib/calc/redev-acquisition-price-source.ts`)로 막았는데, 기준시가 두 칸은 그 leaf 밖에 남았다.

## 3. 수정안 (Q-1 추천안 기준)

### 3.1 leaf 1개 — 「§166 자산의 일반 기준시가 칸이 화면에 있는가」

`lib/calc/redev-acquisition-price-source.ts`에 함께 둔다(같은 자산, 같은 «숨은 칸» 규칙).

```ts
/** 원조합원 §166 자산은 일반 기준시가 칸이 화면에 없다(CompanionAcqPurchaseBlock 게이트) — 보이는 예외만 돌려준다. */
export function redevGeneralStdPriceVisibility(asset, ctx: { apportionedBundle: boolean }): { acq: boolean; transfer: boolean }
```

- 숨김 대상 = `isRedevelopmentSec166Asset(asset)` && 승계조합원 아님(`redevIsSuccessorMember !== "yes"`) && 부담부증여 아님.
- 보이는 예외: 안분 모드 함께 양도의 양도시 기준시가(안분 키) → `transfer: true`.
- 부담부증여 §166 자산은 「② 양도정보」에 기준시가 칸이 있다(`transfer-tax-validate-bg.ts:303-318` 주석) — 숨김 대상에서 뺀다. **두 칸이 모두 보이는지는 확인 필요**(Do 1단계 Playwright).

### 3.2 세 지점이 같은 leaf를 쓴다 (3중 패턴)

| 지점 | 변경 |
|---|---|
| ⑤ `CompanionAcqPurchaseBlock.tsx:361-368` | 렌더 게이트를 leaf로 바꾼다(동작 동일 — 술어 사본 제거) |
| ④ 주 자산 `transfer-tax-api.ts:371-409` · 컴패니언 `transfer-tax-api-companion-payload.ts:366-398` | 보이지 않는 칸은 `undefined`로 싣는다. 안분 키 `standardPriceAtTransferForApportion`은 그대로 |
| ⑧ `transfer-tax-validate-reductions.ts:419-423` · `:278-280` | 자산 값은 보이는 칸일 때만 「입력됨」으로 인정한다 → 감면 카드 칸을 요구한다 |
| ⑤ 안내 문구 `RentalCommonFields.tsx:345-349` · `ReductionStdPriceSection.tsx` «미입력 시 자산값 폴백» | §166 숨김 자산이면 «이 자산은 자산 카드에 기준시가 칸이 없어 이 칸을 입력해야 합니다»로 바꾼다 |

엔진은 바꾸지 않는다 — 엔진은 화면을 모르고, API를 직접 부르는 입력은 자산 기준시가를 정당하게 줄 수 있다.

### 3.3 세액 영향 (수정 후 예상 — Do에서 실측으로 확정)

- 감면이 없는 §166 자산: **변화 없어야 한다**. §166 경로는 일반 기준시가를 감면에만 넘긴다(§1.2). 단, 컴패니언 양도시 기준시가는 함께 양도 안분·사후 환산(`app/api/calc/transfer/bundled-apportionment.ts:166` · `:199-215`)도 읽는다 — 실가 거래 모드에서 이 값이 빠질 때 세액이 그대로인지 **확인 필요**(Do 1단계 — #2336 때 «§166 사후 환산 세액 영향 0» 실측이 있지만 그것은 값이 있을 때다).
- 감면 카드 칸을 채운 사용자: 변화 없음(감면 카드 값이 이미 우선).
- 감면 카드 칸을 비우고 숨은 옛 값에 기대던 계산: ⑧이 막고 감면 카드 입력을 요구한다(§97의3·§97의5·§99의3). ⑧ 가드가 없는 조문(§1.4)은 Q-3에 따른다.

## 6. 범위 밖 · 확인 필요

- **승계조합원 입주권**: ④가 일반 기준시가 대신 §165①(납입액 + 프리미엄) 값을 `standardPriceAt…`로 싣는다(`transfer-tax-api.ts:375-378`). §99 계열 감면 폴백이 이 값을 «기준시가»로 읽을 수 있다 — 확인 필요(별건).
- **§166 자산의 §97의3⑤ «취득 당시 기준시가»가 무엇인가**(종전 주택 취득 당시인가 등): 법령 해석 문제라 이번에 정하지 않는다. 이번 수정은 «사용자가 감면 카드에 넣은 값»을 쓰게 할 뿐이다 — 확인 필요.
- 일반 자산 실가 모드의 숨은 옛 값(§1.5): 의도된 설계 — 범위 밖.
