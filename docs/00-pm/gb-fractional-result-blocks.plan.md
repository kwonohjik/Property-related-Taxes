- 🔑 **환산 분기도 맞지 않다** — 블록이 **첫 지분의 재료**로 뜬다.
  - §100③ 금액이 지분 1 몫이다(A2: 사용자가 적은 9억이 4.5억으로 보인다).
  - §163⑨는 지분 1의 파트 값만 보이고, 지분 1이 상속이 아니면 블록이 사라진다(I6 ↔ I7 — 순서만 바꿔도 표시가 갈린다).
- 지분별 §100③ 판정은 지분율만큼 축소된 같은 판정이다. 단건 60%와 40%(A1′과 같은 축소)를 쟀다:
  - 구분 기재 780,000,000·180,000,000 / 520,000,000·120,000,000 → 합 13억·3억 = 계약서 기재액
  - 안분 781,000,493·178,999,507 / 520,666,995·119,333,005 → 합 1,301,667,488·298,332,512
  - 단건 100% 안분은 1,301,667,489·298,332,511 — 지분 합과 1원 차이(반올림)
  - 이탈률 12bp·55bp는 두 지분과 100%가 같고, 판정(30% 미만 → 구분 기재 적용)도 같다.

## 2. 원인

- 지분 분할 경로(`general-building-fractional.ts:253`)가 **첫 지분의 `detailBase`를 물건 전체 상세로 쓴다** — `if (detailBase === undefined) detailBase = built.detailBase`.
  - 실가 분기 `detailBase`에는 §100③ 판정·§163⑨ 표지가 원래 없다. #2469가 이를 `actualBlockEcho` 별 필드로 뺐고, 지분 경로에는 일부러 싣지 않았다(Q-3 a).
  - 환산 분기 `detailBase`(`gbOut` 전체)에는 있지만 **첫 지분 것**이다.
- 의제취득일 전 ①②③ 비교는 같은 이유로 일부러 비웠다(`:299-300` — 「첫 지분 값만 실으면 다른 지분의 비교로 오독된다(PR-4 한계: 블록 미표시)」).
- 결과 카드 §163⑨ 블록의 파트 값은 안분 표에서 첫 `land`/`building` 행을 집는다(#2469 단건 뷰 — `gb-result-block-views.ts`). 축 B의 안분 표 행은 지분×파트(`land#0`·`building#0`·`land#1`·`building#1`)라 **지분 1 행**이 잡힌다.

## 4. 설계

- **D-1 (⑭ 지분별 echo)**
  - `calculateGeneralBuildingFractional`이 지분마다 블록 재료를 모아 슬롯에 `shareBlockEcho: Record<지분 인덱스, …>`로 싣는다.
    - 재료: §100③ 판정 · §163⑨ 토지·건물 표지 · ①②③ 비교.
    - 기존 `shareActualExpenseEcho`(지분별 필요경비 echo)와 같은 모양이다.
    - 실가 분기는 `built.actualBlockEcho`를 쓴다(#2469). 환산 분기는 `built.detailBase`의 같은 키를 쓴다. ①②③은 두 분기 모두 `detailBase.preDeemedAcquisition`이다.
  - 슬롯 최상위의 첫 지분 판정·상속 표지는 지운다(`preDeemedAcquisition: undefined`와 같은 처리 — C-4·C-5).
- **D-2 (⑭ 물건 전체 §100③ 판정 — Q-1 a)**
  - 지분 판정의 구분 기재·안분·적용 가액을 **합산**한다.
  - 판정 여부·이탈률은 엔진 함수 `judgeDeemedUnclearSplit`(`sale-split-deemed-unclear.ts`)를 합산값으로 다시 불러 얻는다. 표시 계층이 판정 규칙을 다시 구현하지 않는다.
  - 결과를 슬롯 `saleSplitJudgment`에 싣는다. 그러면 단건과 같은 블록이 「계약서 기재액 13억·3억」으로 뜬다.
  - 🔴 지분 판정 중 하나라도 합산 판정과 다르면(30% 경계 반올림), 합산 판정을 싣지 않는다. 블록이 계산과 다른 결론을 말하게 두지 않는다.
    - 대신 지분별 판정을 그대로 남긴다(`shareBlockEcho`).
    - 이 경우의 화면은 Q-1 b와 같다. 구현 때 경계 시료로 실측한다(확인 필요).
- **D-3 (⑦ 표시 — Q-2 a)**
  - 뷰 헬퍼가 축 B(슬롯에 `shareBlockEcho`가 있음)를 알아본다.
  - 단건 블록과 같은 위치에 물건 단위 블록을 한 번 그린다(§100③ · 미입력 안내 · 환산주택가격 · §97②2호 swap).
  - §163⑨는 **블록 하나에 지분별 행**을 둔다:
    - 「자산 1 (지분 50%) 토지분 취득가액(상속개시일 평가액) {그 지분 카드 값}」 꼴.
    - 상속 파트가 있는 지분만, 그 지분의 토지·건물 두 행(단건과 같은 규칙 — 상속 아닌 파트는 「(상속 아님 — 종전 산정)」).
    - 값은 그 지분 카드(`#idx`)에서, 라벨은 그 지분 ①②③ 채택에서 읽는다.
    - 「다만 1985.1.1. 전 …」 문장은 상속 지분 중 하나라도 ③ 채택이 있으면 붙인다.
  - ①②③ 블록은 Q-3에 따른다.
  - 지분 이름은 카드 라벨의 자산 머리(`tagGbCards`가 붙인 `shareLabel` — 「자산 1」), 지분율은 폼 소유 지분이다.
- 저장된 옛 축 B 결과(`shareBlockEcho` 없음)는 지금과 같다(회귀 0).
- 입력·계산 불변 — ①~⑥·⑧~⑬ 변경 없음.
