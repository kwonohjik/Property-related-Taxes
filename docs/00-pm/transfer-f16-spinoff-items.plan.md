## N-2 · `splitCompanionIntoTwo` dead code — 🔴 **고치기 전에 안분이 먼저다**

**위치**: `bundled-split-helpers.ts:463-465` (미전달) · `:499-545` (분할 로직)

**메커니즘(확정)**: `resolveCompanionSplit`은 `:455`에서 `companion.landNature === "appurtenant_to_housing"`을
**이미 확인**하고도, `:463`에서 `resolveCompanionLandRate`에 `{ assetKind: "land", area }`만 넘긴다.
수신부 `appurtenant-land-rate.ts:213`이 `landNature`를 보고 `applied:false`를 반환 ⇒
`:476`에서 `{applied:false}` ⇒ `splitCompanionIntoTwo`가 **한 번도 실행되지 않는다**.
⇒ 영 §167의5 한도초과 분리가 **도달 불가**.

수정 자체는 `landNature: companion.landNature` **1줄**로 보인다. 그러나:

> ### 🔴 이 1줄이 검증되지 않은 코드 경로를 통째로 켠다
>
> `splitCompanionIntoTwo`는 금액 **5필드만** 분할하고 나머지는 `{...base}`로 **양쪽에 복제**한다
> (`:521`·`:539`). **F16이 컴패니언에 `carryoverTaxation`을 도달 가능하게 만들었으므로**,
> 지금 활성화하면 증여자 취득가액·증여세 상당액·증여 당시 평가액이 **두 파트에 각각 전액**
> 들어간다 ⇒ **2배 계상**.
>
> F16 시점에는 「dead code라 F16이 만든 위험은 0」이었다. **N-2를 고치는 순간 그 전제가 사라진다.**
> `carryoverTaxation` 말고도 `{...base}`에 실려 복제되는 금액 필드가 더 있는지 **전수 열거**가 필요하다
> (`reductions`·`burdenedGiftInfo`·`preHousingDisclosure` 등 — **확인 필요**).
>
> **안전망 0건**이라 복제가 켜져도 아무 테스트도 울리지 않는다.

**착수 순서 (강제)**
1. `{...base}`로 복제되는 **금액·이월과세 필드 전수 열거** → 표로
2. 각 필드의 분할 규칙 판정 — 안분인가, 한쪽 귀속인가, 복제가 정답인가.
   ⚠️ 「자동 안분 fallback 금지」에 걸리는 필드가 있는지 확인
3. characterization anchor — **현행(미발동) 상태**를 먼저 고정
4. `landNature` 전달 + 안분 구현을 **함께** 커밋 (1줄만 먼저 넣지 말 것)
5. 활성화 후 세액 격자로 2배 계상 부재 확인

**verify**: 한도 내 + 한도 초과 두 파트의 각 금액 **합 = 분할 전 원값**(floor 잔차 허용치 명시).
