# §155⑳ 세대 구성 불성립이 임대주택을 센 다른 특례 비과세까지 거두는 결함 — 수정 계획서

- 작성: 2026-10-24
- 출처: `rental-155-20-unmet-blocks-155-1.plan.md` §12 별건(F-1 PR-2 중 발견) → 2026-10-24 검토 → 사용자 지시 「계획서 작성해」.
- 검증 깊이: **L3** — 세액이 바뀐다(과다과세 정정). 해석이 갈리는 지점은 Q-n으로 사용자 결정을 받는다.

## 0. 용어 — 「세대 구성」

영 §155⑳은 「장기임대주택 … 과 **그 밖의 1주택**을 국내에 소유하고 있는 1세대가 … 거주주택을 양도하는 경우」에 적용한다. 계산기는 세 축을 따로 판정한다.

| 축 | 내용 | 코드 |
|---|---|---|
| 호별 요건 | 임대주택마다 등록·임대개시 당시 기준시가 상한·임대기간 | `checkEligibility` 호별 판정 |
| 거주주택 요건 | 보유 2년·거주 2년 | `checkEligibility` 거주 판정 |
| **세대 구성** | 세대가 「장기임대주택 + 그 밖의 1주택(=거주주택)」만 가졌는가. 다른 주택은 ⑳과 겹쳐 적용해도 된다는 해석이 있는 특례(일시적 2주택·상속주택·합가·귀농 등)로 빠질 때만 허용 | `resolveRentalResidenceComposition` (`met` / `exceeded` / `undetermined`) |

「세대 구성 불성립」은 `exceeded`다. 이 말은 코드·계획서 용어이고, 화면 문구는 「세대 구성 요건(「장기임대주택과 그 밖의 1주택」)」으로 조문 문구를 함께 적는다. `exceeded`가 되는 경우는 셋이다.
- 다른 주택이 어느 특례로도 빠지지 않는다.
- 다른 특례를 둘 이상 겹쳐야 빠진다(3중첩 — 사전-2016-법령해석재산-0584 등).
- ⑳과 겹쳐 적용한 해석이 확인되지 않은 특례로만 빠진다(조특법 §98 · §155⑦1·2호 — 「모름 = 불리」).

## 1. 요약

- 세대 구성이 서지 않으면 ⑳은 적용되지 않는다. 여기까지는 맞다.
- 그 뒤 임대주택은 일반 주택이다. 판정 엔진은 임대주택을 센 채로 다른 특례(예: 임대주택이 신규 주택인 일시적 2주택)를 판정한다.
- 그런데 회수 단계 D12(`revokeExemptionOnRentalCompositionExceeded`)가 「임대주택을 주택 수에서 뺀 전제의 비과세」라며 그 비과세까지 거둔다.
- ⇒ §155⑳을 **선언했다는 이유만으로**, 선언하지 않은 같은 사실보다 세금이 많다.
  - 10억: 0 → 124,366,000
  - 15억: 14,124,000 → 282,711,000
- 시나리오 B는 D12를 거치지 않지만 결과는 같다. 조기 반환이 막히고 STEP 2.5가 「적용 불가」로 일반 경로에 넘긴다. 일반 경로는 전액 비과세를 처리하지 않아 F-1과 같은 자기모순이 난다(60,621,000 · 사유 「일시적 2주택 비과세」).
- 판정 메뉴도 같다. F-1 PR-2(#2514)가 계산기 D12에 맞춰 「구성 불성립은 거둔다」를 남겼다.
- D12의 세대 구성 회수는 지금 **지키는 테스트가 0건**이다(끄고 31,266건 통과). 원래 사례(0584형 3중첩)는 이후 넓어진 STEP 0.96(판정 전 임대 호수 되돌림)과 판정 엔진이 이미 과세로 낸다(§2.3).

## 5. 설계안

### D-1 (엔진 · 계산기) D12의 세대 구성 회수를 없앤다 — Q-1

- `revokeExemptionOnRentalCompositionExceeded`에서 세대 구성 분기(A · `exceeded` → 회수)를 지운다.
- §154⑩ 표준 경로(B · 임대 0호 · `prhpStandardPathTransitionUnmetNotice`) 회수는 별개 축이라 남긴다. 함수 이름은 남은 역할에 맞게 바꾼다(예: `revokeExemptionOnStandardPathUnmet`). 호출부는 `transfer-tax.ts` 한 곳이다.
- 근거: 계산기 입력 관례상 판정이 임대주택을 세지 않은 입력은 STEP 0.96이 모두 되돌린다. 원인이 세대 구성이어도 같다(`judgeRentalHousingUnmet`).
  - 따라서 D12에 남은 입력의 비과세는 임대주택을 센 판정이다.
  - 0584형(C5)은 판정 엔진이 과세를 낸다.

### D-2 (엔진) 「⑳ 불성립」에 세대 구성 불성립을 포함한다

- 새 술어 `prhpUnmetCause(effectiveInput, parsedRates, date)` → `{ kind: "requirement", eligibility } | { kind: "composition", reason } | undefined`.
  - 호별·거주 요건 불성립이 우선이다(사유 문장이 더 구체적이다).
  - 다음이 세대 구성 `exceeded`다.
  - `resolveRentalResidenceComposition`은 판정 1회당 한 번만 부른다. `transfer-tax.ts`에서 구해 넘긴다.
- `canEarlyReturnPrhp`: 불성립(어느 원인이든)이면 허용하고, B 성립 + 구성 성립만 막는다(C3).
- `rentalNoticesForEarlyReturn`: 불성립이면 ㉒ 안내를 싣지 않는다. 확인 필요 고지(`eligibility.notices`)는 F-1 정정대로 유지한다.
- `prhpUnmetOtherExemptionNotice`: 세대 구성 원인이면 다음 문장을 쓴다.
  > 장기임대주택 거주주택 특례(소득세법 시행령 §155⑳)는 세대 구성 요건(「장기임대주택과 그 밖의 1주택」)을 충족하지 못해 적용하지 않았습니다 — {구성 사유}. 임대주택을 세대 주택 수에 넣어 판정했고, 적용한 비과세는 「…」입니다.
  - {구성 사유}는 `composition.reason`이다. 그 문장 끝의 「…을 적용하지 않았습니다」와 겹치지 않게 사유 문장을 다듬는다. 임시 수정에서 「적용하지 않았습니다 — … 적용하지 않」으로 겹쳤다.
- 구성 `confirmNotice`(「확인 필요」 — §98·⑦1·2호 겹침 해석 미확보)는 **결론을 가를 때만** 싣는다. ⑳이 서지 않아도 다른 특례로 비과세가 서면 그 해석은 결론을 가르지 않으므로 싣지 않는다. 그것이 종전 규칙(「`rhe.applied`일 때만」)과 같은 취지다.

### D-3 (판정 메뉴) 명부에 「장기임대」 행이 있으면 세대 구성 불성립이어도 유지한다 — Q-2

- `applyRentalHousingVerdict`: `rosterCountsRental`이면 원인과 관계없이 판정 결과를 유지한다(PR-2의 `!verdict.compositionFailReason` 조건 삭제).
- 명부에 장기임대 행이 없으면(메뉴 전제) 종전대로 거둔다(MS3).
- 결과 카드 한 줄(「적용한 비과세는 「…」입니다」)은 PR-2 그대로 뜬다. 조건이 `!rental.passed && 비과세`라서다.
