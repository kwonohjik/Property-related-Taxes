# 부담부증여 취득가액 칸을 비워 0으로 계산되던 틈 (입주권 밖)

> 상위: [bg-rtmi-actual-acq-failfast.plan.md](bg-rtmi-actual-acq-failfast.plan.md)(입주권 #2841). 사용자 지시: 「k-4 틈 수정해」(2026-11-02).

## 1. 측정 (수정 전)
K-4 시료: 시가 10억 · 채무 4억(채무비율 0.4) · 실지 2.5억(일반건물은 토지 1억 + 건물 1.5억). 오라클: 4억 − 2.5억 × 0.4 = 300,000,000.

틈 없음: 단건·축 A·축 B 첫 카드 전부 비움(⑧·⑫ 차단) · 축 B 둘째 카드(첫 카드 값 병합) · 담보 승(금액을 읽지 않음) · 산정방식 미선택 · 이월과세 K-4 당초 증여자(이미 두 칸 요구).

한쪽 입력 허용의 근거는 찾지 못했다(2026-06-20·10-14 도입 커밋, 관련 계획서). 주택·건물 토지·건물 분리 입력과 이월과세 K-4 당초 증여자는 이미 두 칸을 요구한다. 기존 anchor 1셀이 「하나만 있어도 통과」를 단언했으나 근거 인용은 없었다.

## 2.1 주택·건물 토지·건물 분리 (`bgHouseSplitActive`) — 직접 API만
⑧은 전부터 `transfer-tax-validate-bg-house-split.ts`가 전부 막았다. ⑫는 본인 K-4만 엔진 `assertBgSplitInputs`가 막고 나머지는 200이었다(실측: K-7 토지만 355,200,000 · 정상 295,200,000 / 이월과세 K-7 시나리오 A 토지만 결정세액 84,520,480 · 정상 72,664,480 / 시나리오 B 한쪽은 이 시료에서 세액 불변).
시나리오 B는 양도인 토지·건물 취득일이 같아 `assertBgSplitInputs`가 돌지 않으므로 엔진 함수를 넓혀도 막히지 않는다 ⇒ ⑫ `requireBgAcquisitionParts`로 한 곳에서 막았다. 주택·건물 총액 입력은 총액 면제로 걸리지 않는다.
