- 입력 «누락»이라는 이름과 달리, 앞의 2곳은 ⑫가 같은 조건(`mixedPartAcqNeedsOf`·4부분 안분 게이트 공유 leaf)으로 이미 막고 있어 **500이 나오지 않는다** [직접].
- 마지막 1곳은 **입력 누락이 아니라 계산된 0**이다. ⑧·⑫ 둘 다 «원 입력이 0 초과»만 보므로 극단값(상가 기준시가 1원 · 주택 면적 1㎡ 대 상가 99,999㎡)에서 500이 난다 [직접].

## 1. 범위

- 측정: 겸용 단건 주 자산 × 취득시 상가 기준시가(건물 0 · 공시지가 0 · 둘 다 0) × 취득 방식·용도변경 7종 = 21칸 + PHD 4부분(Case A) 3칸 + 상가→주택 극단값 3칸 + 컴패니언 겸용 3칸.
- 측정하지 않은 것: `mixedPartAcqNeeds.commercialStdAtAcq=false`(양쪽 실가 + 계약액 + 취득측 경비 없음)인 파트 모델 입력(⑫·엔진이 같은 leaf를 쓴다는 것은 코드로만 확인) · 다건(`multi`) route · ⑧의 상가→주택 `stdAtAcq` 검사 유무.

## 2. 측정 방법 [직접]

throwaway probe(미커밋): 기존 route anchor의 겸용 폼으로 ④ 본문을 만든 뒤 `mixedUse` 필드를 바꿔 직접 POST. 세 throw의 조건은 코드로 읽었다 [코드: `commercial.ts:171-196` · `housing-acq.ts:212-232`].

## 3. 측정 결과 [직접]

### 3.1 취득시 상가 기준시가 0 — 단건 주 자산 (21칸)

| 취득 방식 | 상가건물=0 | 공시지가=0 | 둘 다 0 |
|---|---|---|---|
| 환산 기본 · 실거래가 · 감정가액 · 상속 · 주택→상가 · 상가→주택 · PHD | 400 | 400 | 400 |

- 21칸 **전부 400 `INVALID_INPUT`** — 메시지 «겸용주택은 취득시 상가건물 기준시가가 필요합니다» / «… 개별공시지가가 필요합니다»(⑫ refine, `transfer-tax-schema-mixed-use.ts:268-274`).
- PHD 4부분 안분(Case A: 용도변경 + 상가 기준시가 3시점 + 총액): 값을 0으로 둬도 **200** — ⑫도 엔진도 이 경로에서는 요구하지 않는다(일치).
- 컴패니언 겸용: 상가건물=0 · 공시지가=0 모두 400(`companionAssets.0.mixedUse.acquisitionStandardPrice.…`), 대조 200. refine이 `mixedUseAssetSchema` 자체의 `superRefine`(`:151`)이라 주 자산·컴패니언이 공유한다 [코드].

### 3.2 상가→주택 용도변경 — 계산된 0

| 입력 | 결과 |
|---|---|
| 주택 1㎡ · 상가 99,999㎡ · 취득시 상가건물 1원 · 공시지가 1원/㎡ · 토지 0.01㎡ | **500 `INTERNAL_ERROR`** «용도변경(상가→주택): 취득시 상가 기준시가(건물+토지)가 0이거나 미입력…» |
| 같은 입력에서 상가건물=0 / 공시지가=0 | 400(⑫ refine) |

- 엔진은 `취득시 상가 기준시가 합 × 주택 면적 ÷ 전체 면적`을 정수 내림해 0이면 던진다 [코드: `housing-acq.ts:215-232`]. 원 입력은 모두 양수이므로 ⑫를 통과한다.
- 현실 입력(상가 기준시가가 수백만 원 이상)에서는 안분 값이 0 아래로 내려가지 않는다 — 극단값 시료로만 재현했다. **현실 입력에서의 도달 여부는 확인 필요**.
