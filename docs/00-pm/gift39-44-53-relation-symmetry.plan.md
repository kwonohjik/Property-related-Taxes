## 1. 결함 (실측 — 현행 master `4fbfab5a`)

엔진은 **수증자 행의 `relatedTo`만** 읽는다(`capital-increase-allocation.ts:222`
`relatedSets.get(b.id)?.has(donorId)`). 화면은 모든 행에 같은 칩을 그리고, 라벨은
「특수관계인 (이 주주에게 증여한 자)」(`capital-forms.tsx:348`)다. 누가 수증자인지는
**계산 결과(delta 부호)가 나와야** 정해진다.

E2E 사례4 입력(고가 · ㉮ 10,000 · ㉰ 30,000 · 갑 50,000/50,000/80,000/30,000 · 을 10,000/10,000/20,000/10,000
· 병 30,000/30,000/0/0 · 정 10,000/10,000/0/0), 엔진 직접 호출 probe:

| 칩 표시 위치 | 병 | 정 | 합계 |
|---|---|---|---|
| 수증자 행(병·정 → 갑·을) | 300,000,000 (225M+75M) | 100,000,000 (75M+25M) | **400,000,000** |
| 증여자 행(갑·을 → 병·정) | 0 | 0 | **0** |
| 혼합(병→갑 · 을→병·정) | 225,000,000 | 0 | 225,000,000 |
| 없음 | 0 | 0 | 0 |

**같은 관계**를 어느 행에 표시했는지에 따라 400,000,000과 0으로 갈린다.

## 2. 법령 — 특수관계는 **대칭**이다 (전 시기 본문 직접 확인)

| 시기 | 근거 | 본문(verbatim) |
|---|---|---|
| 2016.1.1.~ 현행 | 「상증법」§2제10호 후단 (MST 276123 · 2016.1.1. 시행본 법률 제13557호에도 동일) | 「이 경우 본인도 특수관계인의 특수관계인으로 본다.」 |
| 2012~2015 | 「국세기본법」§2제20호 후단 (2012.7.1.·2013.1.1.·2014.1.1. 시행본 확인) | 「이 경우 이 법 및 세법을 적용할 때 본인도 그 특수관계인의 특수관계인으로 본다.」 |
| 2015.2.3. 시행 상증령 | 「상증령」§29① → §12의2① (2014.2.21. 개정) | 「신주 또는 실권주를 **인수하거나 인수하지 아니한 자와** 제12조의2제1항 각 호의 어느 하나에 해당하는 관계에 있는 자」 / §12의2① 후단 「이 경우 본인도 「국세기본법」 제2조제20호 각 목 외의 부분 후단에 따라 특수관계인의 특수관계인으로 본다.」 |
| 2011.1.1. 시행 상증령 | 「상증령」§29① | 「신주 또는 실권주를 **인수하거나 인수하지 아니한 자와** 제19조제2항 각호의 1의 관계에 있는 자」 — 정의 자체가 **양쪽 어느 당사자를 기준으로 해도** 성립한다 |

⇒ 「갑 행에 병을 표시」와 「병 행에 갑을 표시」는 **법적으로 같은 사실의 기재**다. 시기 게이트는 필요 없다.

> ⚠️ 리뷰 원문은 「저장소가 금지하는 자동 안분 fallback으로 대칭 보정을 넣을 수 없다」고 했다.
> **이 전제를 정정한다** — 금지 대상은 입력되지 않은 **금액·비율을 추측해 채우는 것**이다.
> 여기서는 사용자가 입력한 관계 사실을 법이 정한 대칭성대로 읽는 것뿐이며, 추측이 없다.

> 📌 **형제 리뷰 F-helpers-types.md:249와의 관계** — 같은 결함을 다른 렌즈로 본 기록이다. 그 결론
> 「엔진 **방향을 뒤집는** 수정은 금지(`[CI-S39-C6]` 비대칭 픽스처와 충돌)」는 이 설계와 충돌하지 않는다.
> 안 A는 방향을 뒤집지 않고 **양방향의 합집합**을 읽는다 — C6(수증자 행에만 표시)는 종전 그대로
> 200,000,000/50,000,000이다(구현 후 실측 통과). F가 제안한 ⑧·⑫ 「A가 B를 지정하면 B도 A를 지정」
> 차단은 합집합 읽기로 **불필요**해진다(두 기재가 같은 사실이므로 한쪽만 적어도 모순이 아니다).

## 3. 설계 — 안 A(권장 · **2026-09-28 사용자 채택**): 엔진이 관계를 대칭으로 읽는다

| 지점 | 변경 |
|---|---|
| 엔진 (`capital-increase-allocation.ts:222`) | `isRelatedTo(d) = b.relatedTo ∋ d **또는** d.relatedTo ∋ b` — 주석에 §2제10호 후단·구 §29① 인용 |
| 타입 주석 (`gift-deemed-input-types.ts:292`) | 「어느 쪽 행에 표시해도 같은 관계」 |
| ⑤ 칩 표시 | 켜짐 = 두 행 중 **어느 쪽이든** 표시(대칭 폐포). 한 번 누르면 두 행 모두 켜진 것으로 보인다 |
| ⑤ 칩 끄기 | 두 행의 표시를 **한 번의 `set`으로** 함께 제거(다중키 patch stale spread 방지) |

| ④ API · ⑫ Zod · ⑧ validate | **변경 없음** — `relatedTo`를 그대로 싣고, 엔진이 해석한다(API 직접 호출·이력 재계산도 같은 답) |

**왜 엔진인가**: UI만 고치면(칩을 누를 때 양쪽 행에 기록) 이미 저장된 비대칭 이력과 API 직접 호출이
종전 답(0원)을 그대로 낸다. 단일 진실은 엔진 한 곳이어야 한다.

### 영향 (probe 실측)

- 엔진을 대칭 폐포로 바꾸고 `__tests__/tax-engine/gift-deemed/`·`__tests__/calc/`·`__tests__/components/calc/deemed-gift/`
  **424파일 4,411건 전건 통과** — 깨지는 기존 단언 0건. 반대로 말하면 **증여자 행 표시를 고정한 테스트가 0건**이다.
