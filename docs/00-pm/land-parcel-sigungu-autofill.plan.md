### 0.4 세액 영향 — 엔진 직접 실측(2024, 종합합산, 필지 2개 각 1,000㎡ × 5,000,000원)

| 시군구 | 재산세 합산 그룹 | 종부세 토지분 결정세액 | 농특세 | 총세액 |
|---|---|---|---|---|
| 강남구 + 송파구(정상) | 2개 | 191,989,209 | 38,397,841 | **230,387,050** |
| 강남구 + 강남구(잔존) | 1개 | 191,750,000 | 38,350,000 | **230,100,000** |

재산세는 관할 시군구별로 합산해 계산한다(`lib/tax-engine/comprehensive-land-parcels.ts:93~131`). 그룹이 바뀌면 공제할 재산세 상당액이 달라져 결정세액이 바뀐다. 이 사례에서 차이는 287,050원이다.

## 1. 원인

- `LandParcelEditor`는 `deriveSigunguFromAddress(v.road || v.jibun)`(`:53`)으로 **도로명이 있으면 도로명만** 본다. 지번 검색 결과는 도로명이 짧아 `null`이 된다.
- 근거 주석이 응답 형식을 한쪽만 적었다.
  - `:51` 「Vworld 지번(parcel)은 "석촌동 276-1"로 시군구 없음」
  - `derive-sigungu.ts:10` 「반드시 도로명 주소(시도·시군구 포함)를 전달할 것」
  - 기존 렌더 테스트 mock(`__tests__/components/comprehensive-land-parcel-address.test.tsx:17~19` 「Vworld 실제 포맷: road=전체 도로명, jibun=짧은 지번」)
  - 실제로는 검색 방식에 따라 어느 쪽이든 짧게 온다(§0.1).
- 파생에 실패한 선택이 칸을 건드리지 않아, 주소를 바꾸면 옛 주소의 시군구가 남는다(§0.3).

## 2. 수정안

- **R1. 도로명과 지번을 각각 파생해 먼저 나오는 값을 쓴다.**
  - `deriveSigunguFromAddress(v.road) ?? deriveSigunguFromAddress(v.jibun)`
  - 도로명에서 뽑히던 경우(도로명 검색)는 결과가 그대로다. 지번 검색은 지번의 전체 주소에서 뽑힌다(§0.2 — 같은 주소면 두 형식의 결과가 같다).
- **R2. 주소가 바뀌었는데 시군구를 뽑지 못하면 칸을 비운다**(Q-1).
  - 이 칸의 `onChange`는 #2352 뒤 주소 선택·「입력한 주소 그대로」·「지우기」에서만 온다(`disableUnits`). 셋 다 주소가 바뀌는 경우다.
  - 빈 칸은 계산 전에 막힌다(`comprehensive-api.ts:49`). 사용자가 새 주소의 시군구를 직접 넣게 된다.
  - 같은 원칙의 선례: 소재지를 바꾸거나 지우면 옛 주소에서 파생한 `regionCode`를 함께 비운다(`lib/calc/house-region.ts:53~64` 주석, S14a-2·S14a-3).
- 근거 주석 3곳을 실측 형식에 맞게 고친다(`LandParcelEditor.tsx:51~52` · `derive-sigungu.ts:10~12` · 기존 렌더 테스트 mock 주석).
- 엔진·API·store는 바꾸지 않는다.

## 3. 영향·위험

| 항목 | 내용 |
|---|---|
| 지번으로 검색해 고른 필지 | 시군구가 채워진다(종전 빈 칸) |
| 도로명으로 검색해 고른 필지 | 변화 없음 |
| 세종 · 입력한 주소 그대로 · 지우기 | 칸이 빈다(종전 옛 값 유지). 계산 전에 「모든 필지에 시군구를 입력하세요」로 막힌다 |
| 손으로 넣은 시군구 | 주소를 다시 고르면 새 주소 기준 값(또는 빈 칸)으로 바뀐다. 주소를 건드리지 않으면 그대로다 |
| 계산 결과 | 주소와 다른 옛 시군구로 계산되던 경우만 바뀐다(§0.4) |
| 저장된 필지(세션·이력) | 불러오기만으로는 바뀌지 않는다 — 주소를 다시 고를 때만 적용된다 |
| 기존 테스트 | `comprehensive-land-parcel-address.test.tsx`(도로명 형식 → 송파구)는 그대로 통과해야 한다 |
