## 1. 배경·문제

`§118`(세 부담 상한의 계산방법) 본문은 직전 재산세액 상당액을 **본세(§112①1호)·도시지역분(§112①2호·②) 각각** 산출하도록 명령한다. v1은 본세만 상한 적용했고 **도시지역분은 현행대로 `과세표준 × 0.14%`**(상한 미적용, `property-tax-surtax.ts` `calcSurtax`).

실측(용인 기흥 구갈동 아파트): 도시지역분 앱 312,250 vs 실제 302,480 — **연 9,770원 과다**. §118 본문을 본세·부가 양쪽에서 충족하려면 도시지역분도 세부담상한이 필요하다.

## 2. 법령 근거 확정 (KoreanLaw 검증)

| 조항 | 내용 | 출처 |
|---|---|---|
| **§118 본문** | "§112①1호 산출세액과 §112①2호·② 산출세액 **각각에 대하여 각각 산출**" → 도시지역분은 본세와 **분리된 독립 상한 계산 대상** | 시행령 mst=286395 |
| **§118 1·2호 가목 괄호** | "직전 연도의 과세표준"이 본세는 §110 과세표준, **도시지역분은 §110 토지등 과세표준**으로 자동 치환 → 도시지역분 전용 별도 규정 없이 동일 산식 골격 적용 | 시행령 §118 |
| **§118 2호 가목 단서** | "직전 연도에 해당 납세의무자에게 과세된 세액이 있으면 **그 세액으로 한다**" → 통상(계속보유)은 **직전 실제 부과 도시지역분** = 직접입력 (v1 본세와 동형) | 시행령 §118 |
| **§112①2호** | 도시지역분 = "§110에 따른 **토지등의 과세표준** × 1천분의 1.4". ②=조례로 0~2.3‰ 변형 | 법 mst=282559 |
| **§110③** | 주택 과세표준 **자체**를 상한액으로 치환 → 본세·도시지역분이 **동일 과표 공유**. 도시지역분 별도 과표상한 없음 | 법 §110③ |
| **부칙 §15 → 종전 §122** | 부칙 제15조 "종전의 규정에 따른다"(2024~2028). 종전 §122 = "산출세액(**§112①각 호 및 §112② 각각의 세액**)이 직전 상당액의 105/110/130%(주택 공시구간) 초과 시 그 금액" → **도시지역분(§112①2호) 명문 포함**, 상한율 본세와 동일 | 행위시법 §122@2023 + 부칙 §15 |

**결론: 도시지역분 세부담상한 = `min(당해 도시지역분 산출, floor(직전 도시지역분 × capRate))`, capRate는 본세와 동일 종전 §122 구간율(공시 3억↓105/3~6억110/6억↑130%).** 직전 도시지역분 상당액은 §118 2호 가목 단서로 **직전 실제 부과 도시지역분 직접입력**이 정석.

> ⚠️ 워크플로 R1·R2는 부칙 §15 본문을 consolidated MST에서 직접 미조회해 "확인 필요"로 남겼으나, 부칙 §15(사용자 제공 이미지) + 종전 §122(행위시법 @2023-07-01 KoreanLaw 확인, §112①각 호 포함)로 **도시지역분 포함이 확정**됨. v1과 동일 법적 경로.

## 3. 미해결 쟁점 — 실측 도시지역분 미스터리 (R4 결론)

실측 도시지역분(역산값)이 법령·세부담상한으로 설명되지 않는다:

| 연도 | 도시지역분(역산) | ÷0.0014 환산과표 | 재산세 과표 | 비율 |
|---|---|---|---|---|
| 2023 | 259,880 | 185,628,571 | 187,880,000 | 0.988 |
| 2024 | 274,680 | 196,200,000 | 198,462,000 | 0.988 |
| 2025 | 302,480 | 216,057,143 | 223,036,000 | 0.969 |

- **법령상 본세 과표 = 도시지역분 과표 명문**(§112①2호 "§110 토지등 과세표준") → 환산 과표가 재산세 과표보다 작을 수 없음 → **비율 0.969~0.988은 법령으로 설명 불가**.
- **모순1**: 2024 도시 실제(274,680) < 산출(198,462,000×0.14%=277,847) < 상한(직전259,880×110%=285,868) — 상한 안 걸렸는데 실제가 산출보다 작음.
- **모순2**: 2025 도시 실제(302,480) > 상한(직전274,680×110%=302,148) — 세부담상한이면 불가능한 한도 초과.
- **★정정(2026-06-25 검증)**: 도시지역분 세액은 **역산 오차가 아니라 정확값**이다. 지방교육세가 본세의 정확히 20%로 떨어진다(47,360 = 236,800 × 0.2) → 본세 236,800 정확 → 도시 = 539,280 − 236,800 = 302,480 정확. **도시지역분 세액 분리값은 이미 정확히 보유** — 위택스 추가 조회 불필요.
- **진짜 미스터리는 과세표준**: 도시 환산과표 216,057,143이 재산세 과표 223,036,000과 다른 이유(법령상 §112①2호 동일해야). 세부담상한(직전 274,680 × 110% = 302,148)으로도 실제(302,480)와 **332원** 어긋남 — 역산 오차가 아니라 실제 차이.
- **확인 결과(WebFetch 2026-06-25)**: 위택스 납부대상조회는 세목별 **세액(금액)만** 표시하고 과세표준 산출 내역은 분리 조회 불가. 서초구 등 공식 안내도 도시지역분 세부담상한 적용 여부 미기재. → 사용자 경험("분리값 조회 안 됨") 확인됨. ★앞선 "위택스에서 분리값 조회"는 검증 없는 추정이었음(철회).

**→ 결론: 332원 미스터리(도시지역분 과세표준·직전 세액 상당액 정의 = 실제 부과 vs 재산정)는 위택스·고지서·공식안내로 풀리지 않는다. 확실한 경로는 ①관할 구청(용인 기흥구) 재산세과 산출 내역 직접 문의 또는 ②지자체 공식 계산기(서울ETAX 지방세미리계산 등)에 동일조건 입력해 도시지역분 정밀값 재현.** 통합 anchor는 그때까지 유보, 설계는 §118 법문(직전 도시지역분 × capRate)으로 진행.

## 5. 신규 input/result + 엔진 설계

### input (`PropertyTaxInput`)
```typescript
/** [부칙 §15] 직전연도 주택 도시지역분 세액(§112①2호) — 도시지역분 세부담상한 직접입력. housing 전용. */
previousYearHousingUrbanTax?: number;
```

### 엔진 (`property-tax-housing-cap.ts` 확장)
v1 `applyHousingTransitionalCap`(본세)와 **동일 capRate**(`resolveHousingCapRate`)를 공유하는 도시지역분 상한 함수 추가:
```typescript
export function applyHousingUrbanTransitionalCap(
  urbanCalculatedTax: number,   // 당해 도시지역분 산출(taxBase × 0.14%)
  publishedPrice: number,       // 구간 판정 (본세와 동일)
  taxYear: number,
  previousYearHousingUrbanTax?: number,
): { applied: boolean; determinedUrbanTax: number; capRate?: number; capLimit?: number; warnings: string[] }
// 게이트: 2024≤taxYear≤2028 + previousYearHousingUrbanTax 입력 + isUrbanArea
// min(urbanCalculatedTax, floor(직전도시 × capRate))
```

### 적용 지점 (`property-tax.ts` Step3/Step4)
- v1 본세 분기와 같은 housing 블록에서 도시지역분 산출(`effectiveTaxBase × 0.14%`)을 먼저 계산 → `applyHousingUrbanTransitionalCap` → 결과를 `calcSurtax`에 **주입**.
- `calcSurtax`에 `overrideUrbanTax?` 파라미터 추가(v1 engine.design.md D-4-3에서 이미 검토된 하위호환 방식).

### result (`housingTransitionalCap` 확장)
```typescript
// 기존 housingTransitionalCap에 도시지역분 필드 추가
urbanCalculatedTax?: number;   // 상한 전 도시지역분 산출
urbanCapLimit?: number;        // floor(직전도시 × capRate)
urbanDeterminedTax?: number;   // = surtax.urbanAreaTax (상한 후)
previousYearUrbanTax?: number; // 입력값
```

## 7. anchor 계획 (분리값 확보 전략)

- **순수함수 (선구현 가능)**: `applyHousingUrbanTransitionalCap` 법문 단위 테스트 — 예 `(312250, 700000000, 2025, 274680)` → `min(312250, floor(274680×1.30))` 등 구간율·게이트·만료. FMR·역산 무관.
- **통합 anchor (유보)**: 실측 도시지역분 302,480은 역산 ±오차라 `toBe` 고정 불가 → **위택스 항목별 분리 고지값(도시지역분 직접) 확보 후** 작성.
- **확보 전략 (정정)**: 위택스/고지서는 세목별 **세액만** 제공(과표 산출 내역 분리 불가 — WebFetch 확인). 도시지역분 세액(302,480 등)은 이미 역산 정확. 332원 미스터리(과표·직전 상당액 정의) 규명은 ①관할 구청 재산세과 산출 내역 문의, 또는 ②서울ETAX 지방세미리계산 등 공식 계산기에 동일조건(공시 518,000,000·1세대1주택·직전공시 481,000,000·2025) 입력해 도시지역분 정밀값 재현.
