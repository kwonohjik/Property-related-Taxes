# 함께 양도 묶음의 조합원입주권 담보·임대 승 ⑧ 게이트 해제 (X-1)

## 1. 변경 (⑧ 한 곳 + 문구)
- 묶음 ⑧ 승자 게이트(`lib/calc/transfer-tax-validate.ts` — `bgNonSupplementaryWinnerUnsupported` 직후)가 `bgRtmiBundleWinnerComputable`(`lib/calc/bg-rtmi-std-acq.ts`)이 true인 자산을 건너뛴다.
- 술어: 입주권 ∧ 지분 100% ∧ 양도일 있음 ∧ (열거 이전 ∨ 승계). 게이트가 이미 정한 묶음 승자 `mode`(담보·임대)를 받아 시기를 본다.
  - 열거 이전: 취득가액이 실지라 승계·원조합원 모두 계산한다 — 엔진 값이 단건 합과 ±0.
  - 열거 이후 승계: 취득시 기준시가 2칸을 자산별 (5-c‴)이 요구하고, ⑤ 칸은 companion 카드가 `transferDate`를 넘겨 이미 열려 있다.
  - 열거 이후 원조합원: 계속 막는다(H-2 대기). 지분 < 1: 계속 막는다(X-2·X-3).
- `parenEraStarted(mode, date)`를 `bgRtmiParenEnumerated`와 공유한다(동작 불변).
- 문구 `BG_RTMI_SUCCESSOR_SINGLE_ONLY_CAUSE`: «단독 소유 단건만 … 함께 양도 묶음·지분은 확인하지 못했습니다» → «지분 100%(단독 소유)만 합니다 — 지분을 가진 입주권은 확인하지 못했습니다». 묶음이 풀려 앞 문구가 틀려졌다.
- ⑤⑥⑦·⑫·엔진 변경 없음. 14지점 중 ⑧만(⑫는 이미 200 — 측정 C1).

## 3. 확인 필요 (이번에 고치지 않았다)
- **⑫가 쓰이지 않는 값을 «있어야 한다»고 요구하지 않는 쪽은 맞지만, 반대로 실지 취득가액이 필요한데 비어 있어도 막지 않는 틈이 있다.** 열거 이전 승계 입주권에서 승계취득가액·추가분담금·실지취득가액을 모두 비웠을 때:
  - 단건 시가 모드: ⑫ 400(정상) · 단건 기준시가 모드: ⑫ **200, 양도차익 3,000,000,000(취득가액 0)** · 묶음 시가 모드: ⑫ **200, 합 5,485,000,000(입주권 취득가액 0)**.
  - ⑧은 세 경우 모두 막아 화면으로는 도달하지 못한다. 직접 호출만 해당(침묵 0 취득가액). I-1 이전부터인지는 측정하지 않았다 — 별건 후보.
- 묶음에서 입주권 카드의 «승계취득가액»·기준시가 칸 노출은 E2E로 확인했다. 지분(X-2)·축 B(X-3)는 아직 열지 않았다.
