## 1. 배경

- **결함 (#3272 전):**
  - 부담부증여 자산에서 「토지·건물 소유자 다름」을 켜도 엔진은 **물건 전체 값**으로 「소득세법 시행령」 §159를 계산했다.
  - 원인은 두 가지다. ④ `isSplitPayloadActive`가 부담부증여면 분리 payload를 끈다(`lib/calc/transfer-tax-api-split.ts:98` · 사유 주석 `:88-97`). 엔진 양도차익은 `splitDetail`이 있을 때만 `selfOwns`를 쓴다(`lib/tax-engine/transfer-tax.ts:374-376`).
  - 설계서 `bg-house-building-split.design.md:116` V-3이 이 조합을 「재지 않았다 — 별건」으로 남겨 두었다.
- **실측 (2026-11-12, 기준시가 모드 · 채무 1억 · 모의 세율):**
  - 건물 비중이 양도 20% · 취득 50%일 때, 물건 전체 값 → 양도차익 48,500,000 · 결정세액 **4,039,500**.
  - 같은 조건에서 건물분 값을 직접 넣으면 → −28,750,000 · **0**.
  - 건물 비중이 양쪽 같으면 결과가 같다. §159 식이 A·C를 같은 비율로 줄여도 변하지 않기 때문이다.
- **현재 상태:** #3272가 ⑤(토글 켜는 방향 잠금)·⑧·⑫로 **막고 있다**(`lib/calc/bg-owner-split-scope.ts`). 이 계획은 그 차단을 실제 계산으로 바꾼다(사용자 결정 b).

## 3. 조사로 확인한 엔진 구조 (설계의 전제)

1. **비소유 파트를 0으로 보내면 기존 §159 계산이 본인 몫을 낸다.**
   - 기준시가 모드: 토지 양도가액 = `safeMultiplyThenDivide(토지 기준시가, B, 기준시가 합)`이고, 건물이 나머지를 흡수한다(`lib/tax-engine/burdened-gift-apportionment.ts:189-198`).
   - 시가 모드: 기준시가 비율로 시가를 나눈다(같은 파일 `:203-211`).
   - 따라서 **새 §159 산식은 필요 없다.** 입력(양도·취득 기준시가 4칸, 시가, 실지취득가)을 본인 몫으로 만들면 `buildBurdenedGiftBreakdown`이 맞는 값을 낸다.
   - 증여세 쪽 echo(무상분 = C − B)도 함께 바로잡힌다.
2. **초과부담부 검사가 본인 몫 기준으로 바뀐다.** `burdened-gift-eligibility.ts`는 B > Max(보충적, 담보, 임대)이면 던진다. 지금은 물건 전체 값이라 통과하던 「채무가 증여한 부분 가액보다 큰」 입력이 이제 걸린다(앵커 A4).
3. **④ `single` 슬롯 구조:** 공시가격 총액을 `buildingStdPriceAtTransfer`에, 토지에는 0을 싣는다(`lib/calc/transfer-tax-api-burdened-gift.ts:584-591`). 날짜 분리는 `bgHouseSplitInfoPatch`(`:592`)가 파트 값으로 덮는다 — 소유자 분리도 같은 형태의 패치로 본인 몫만 싣는다.
4. **`splitDetail` 의존:** 양도차익(`transfer-tax.ts:374-376`)·장특공제·임대 장특 파트·비사업용 분리·표시 echo는 모두 `splitDetail.selfOwns`를 읽는다. 날짜 분리 결과 `bgSplitGainResult`는 `selfOwns: "both"`를 하드코딩한다(`lib/tax-engine/burdened-gift-split-parts.ts:127`).
5. **두 분리는 함께 켜지지 않는다.** `bgHouseSplitMode`는 소유자 분리면 undefined를 돌려준다(`lib/calc/bg-house-split.ts:20`). 날짜 분리 모델은 두 파트를 모두 증여해 **채무를 나누고**, 소유자 분리는 한 파트만 증여해 **채무 전부가 그 파트**에 붙는다 — 날짜 분리 모델을 그대로 쓸 수 없다.

## 5. 엔진 설계

- **새 leaf** `lib/tax-engine/burdened-gift-owner-split.ts`(순수 함수):
  - 판정: 부담부증여 ∧ 주택·건물 ∧ `selfOwns ≠ both`. `bgPartDatesDiffer`가 `selfOwns === both`를 요구하는 것과 짝이다.
  - 입력 계약 검사: 비소유 파트 기준시가(양시점) = 0, 소유 파트 기준시가 > 0, 비소유 파트에 값이 있으면 던진다(⑫의 거울 · 엔진이 자동으로 0으로 바꾸지 않는다).
- **`splitDetail` 경유 (Q-2 a 채택안):** `bgSplitGainResult`가 입력의 `selfOwns`를 돌려주게 한다(현재 `"both"` 하드코딩). 보유연수는 소유 파트 취득일로 센다. 비소유 파트 값을 하류가 읽지 않는지는 V-6에서 뮤테이션으로 확인한다.
  - 기각안: `splitDetail` 없이 합계만 넘기기. 양도차익은 맞지만 토지만 본인일 때 세율 기산(`transfer-tax.ts:662`)·장특공제가 서로 다른 가정으로 돌아 기산일이 어긋난다.
- **채무:** 증여자의 채무 B 전액이 증여한 부분에 속한다는 전제다. 공동담보는 v1에서 막고, 「채무가 증여한 부분만 담보한다」는 확인을 받는다(Q-3).
- **§66 담보 승:** 기존 `resolveBgAcquisitionBasis`의 §159①1호 괄호(2023.2.28.~)를 그대로 쓴다. 담보 승이면 B/C = 1이 되어 취득가액이 취득시 기준시가 전체가 된다 — 결과 카드에 안내한다(A3).
- **정수 연산:** 기존 `safeMultiplyThenDivide` · `apportion*`만 쓴다. `Math.round`는 쓰지 않는다. 개별주택가격 가목:나목 분할은 `bgHouseSplitTransferStd`와 같이 토지를 floor하고 건물이 잔액을 흡수한다(`bg-house-split.ts:46-47`). 날짜는 `lib/api/date-coerce.ts`를 거친다.
