# 일반 주택 × §155⑳ 불성립이 다른 특례 비과세까지 막는 결함 — 수정 계획서

- 작성: 2026-10-24
- 출처: `redev-apt-rental-residence-155-20.plan.md` §11 별건 F-1. 완공APT 경로는 #2506에서 이미 바르게 처리한다(RR-10).
- 검증 깊이: **L3**. 세액이 바뀐다(과다과세 정정). 해석이 갈리는 지점은 Q-n으로 사용자 결정을 받는다.
- 이 문서의 수치는 2026-10-24 master(c7f9006ac)에서 throwaway probe로 실측했다. probe 파일은 지웠다.

## 0. 요약

- 세대가 거주주택과 임대주택을 가진 경우를 본다. 임대주택이 거주주택 취득 1년 뒤에 산 「신규 주택」이고 거주주택을 3년 안에 판다면, 영 §155⑳ 특례가 서지 않아도 **일시적 2주택 비과세(영 §155①)는 그 자체로 선다**.
- 계산기는 §155⑳을 선언한 입력에서 그 특례가 서지 않으면, 공유 판정 엔진이 낸 일시적 2주택 비과세를 **결과에 싣지 않고 전액 과세**한다.
- 원인은 게이트 `isPrhpScenarioAIneligible`(시나리오 A)·`isPrhpScenarioB`(시나리오 B)다(`lib/tax-engine/transfer-tax-rental-housing-judge.ts:111` · `:38`). 둘 다 STEP 1a 전액 비과세 조기 반환을 막는다. 정상 경로 STEP 3은 전액 비과세를 처리하지 않는다(부분 비과세만 안분한다). 그래서 같은 사실에서 결과가 갈린다.
  - **10억 양도: 과세 60,621,000**
  - **15억 양도: 과세 14,124,000**(12억 초과분만 과세)
- 화면에서 도달한다. 계산기 화면과 판정 메뉴 →「계산기로 보내기」 두 경로 모두 ⑧이 막지 않는다(§1).
- A 게이트의 원래 목적은 「주택 수 1(임대 제외)로 입력 + 요건 미충족」의 과다 비과세 차단이었다. 지금은 STEP 0.96(`restoreRentalUnitsToHouseCount`)이 같은 입력을 판정 **전에** 바로잡는다. 게이트를 떼어도 그 과다 비과세는 되살아나지 않는다(§1.3 실측).

## 3. 원인

### 3.1 조기 반환 게이트

`transfer-tax.ts:280` STEP 1a의 조건은 `exemptionResult.isExempt && canEarlyReturnPrhp(effectiveInput) && …`이다.

`canEarlyReturnPrhp`(`transfer-tax-rental-housing-judge.ts:197`) = `!isPrhpScenarioB && !isPrhpScenarioAIneligible`. 두 게이트의 원래 목적은 다르다.

| 게이트 | 원래 목적 | §155⑳ 불성립일 때 |
|---|---|---|
| `isPrhpScenarioB` | B가 **성립**하면 §161① 안분이 필요하다. 전액 비과세로 끝내면 안 된다. | 성립하지 않았으므로 §161 안분은 없다. 막을 이유가 없는데 막는다. |
| `isPrhpScenarioAIneligible` | 「주택 수 1(임대 제외)로 입력 + 불성립」이면 판정 엔진이 1주택 비과세를 잘못 낸다. 그 비과세를 막는다. | 그 입력은 이제 STEP 0.96이 판정 **전에** 임대 호수를 되돌린다. 남은 입력(명부에 임대 행 · 명부 없음 + 주택 수 2 이상)은 판정 엔진이 이미 임대주택을 센 결과다. 막으면 정당한 다른 특례까지 지운다. |

### 3.2 정상 경로가 전액 비과세를 처리하지 않는다

`resolveTaxableGain`(`transfer-tax-taxable-gain.ts:29`)은 `isPartialExempt`만 안분한다. `isExempt`는 조기 반환이 전제라서 전액 과세로 떨어진다(같은 파일 `:73-77` 주석이 「§155⑳ B·A 미충족은 `isExempt=true`인 채로 과세돼야 한다」고 그 전제를 적어 두었다). 그래서 P2(전액 과세)와 P3(12억 초과분만 과세)가 역전한다.

### 3.3 조기 반환 안내가 「⑳ 성립」을 전제한다

`rentalNoticesForEarlyReturn`(`transfer-tax-rental-housing-judge.ts:167`)은 A이면 다음을 그대로 싣는다. 모두 ⑳이 성립할 때의 문장이다.
- `eligibility.notices`(예: 부칙 마목·바목 「…인정했습니다」)
- ㉒ 사후 추징 안내
- 거주 통산 문장

이 함수는 불성립 입력에 닿은 적이 없다. A 게이트가 막았기 때문이다. 게이트를 떼면 불성립에 틀린 문장이 실린다(§1.3).

### 3.4 STEP 0.96 고지가 판정 전에 결론을 단정한다

`restoreRentalUnitsToHouseCount`의 고지는 판정 **전에** 만들어진다. 문장이 「1세대1주택 비과세·12억 초과분 안분·장기보유특별공제 표2를 적용하지 않습니다」로 결론을 미리 말한다.

STEP 0.96으로 되돌린 입력은 명부가 없어 일시적 2주택 사실이 없다. 그래서 지금은 결론이 대개 맞는다. 다만 다른 특례(상속주택 등 명부 없이 판정되는 사실)로 비과세가 서면 이 문장이 거짓이 된다.

또 안내의 처방 「주택 수로 직접 입력」이 그대로는 판정되지 않는다(P7).

## 4. 설계안

### D-1 (엔진 · 계산기) 조기 반환 게이트를 「§161 안분이 필요한가」 하나로 좁힌다

```ts
// transfer-tax-rental-housing-judge.ts
export function canEarlyReturnPrhp(effectiveInput: TransferTaxInput): boolean {
  const eligibility = judgeRentalHousingEligibility(effectiveInput);
  // 불성립(A·B) — 임대주택은 일반 주택이다. 판정 엔진이 그 주택을 센 결과(STEP 0.96 · 명부)가 정본이다.
  if (eligibility && !eligibility.passed) return true;
  return !isPrhpScenarioB(effectiveInput); // B 성립 → §161① 안분(STEP 2.5)
}
```

- `isPrhpScenarioAIneligible`는 쓰는 곳이 없어지므로 지운다. 그 이름을 인용한 주석 2곳을 고친다(`rental-housing-verdict.ts:93` · `__tests__/api/one-house-exemption-rental-housing.route.anchor.test.ts:13`).
- 세대 구성 불성립(D12 `revokeExemptionOnRentalCompositionExceeded`)과 §154⑩ 표준 경로(B · 0호 `prhpStandardPathTransitionUnmetNotice`)는 **판정 직후 이미 비과세를 거둔다**. 그래서 이 게이트에 닿지 않는다. 손대지 않는다.
- 부수토지 G-2·G-3 게이트(`hasHousingLandExemptExclusion`)는 별개 조건이다. 그대로 둔다.
- 부담부증여(증여세 경로)도 같은 엔진을 탄다. 따로 손대지 않는다. 한 건을 실측해 확인한다(V-4).

### D-2 (엔진) 조기 반환 안내를 성립·불성립으로 가른다

`rentalNoticesForEarlyReturn(effectiveInput, exemptReason)`:
- **성립:** 현행 그대로다(㉒ · 통산 · `eligibility.notices`).
- **불성립:** 성립 전제 문장을 싣지 않는다. 대신 한 문장을 싣는다.
  - > 장기임대주택 거주주택 특례(소득세법 시행령 §155⑳)는 요건을 충족하지 못해 적용하지 않았습니다 — {사유}. 임대주택을 세대 주택 수에 넣어 판정한 결과 {exemptReason}을 적용했습니다.
  - {사유}는 STEP 2.5 「적용 불가」 단계와 **같은 소스**(`eligibility.failReasons`·`residenceFailReasons`)에서 만든다. 정상 경로(P3)와 조기 반환(P2)이 같은 사유를 말하게 한다.

### D-3 (엔진) STEP 0.96 고지를 판정 뒤에 확정한다 — Q-4

`restoreRentalUnitsToHouseCount`가 되돌린 경우:
- **판정 결과가 과세:** 종전 문장을 쓴다. 처방은 「세대 보유 주택 명부에 임대주택(취득일 포함)을 넣어야 판정합니다」로 바꾼다. 주택 수만으로는 판정되지 않는다(P7).
- **비과세·부분 비과세:** 「적용하지 않습니다」 단정을 빼고 D-2 문장으로 대체한다.

### D-4 (판정 메뉴) 같은 규칙 — Q-3

`applyRentalHousingVerdict`는 불성립이면 무조건 거둔다. 다음으로 바꾼다.

- 불성립이면서 **명부에 장기임대 행이 있으면 거두지 않는다.** 그 행이 판정 엔진의 주택 수에 이미 들어 있기 때문이다. 계산기 `rentalUnitsToRestore`의 「명부에 장기임대 행 = 이미 센 것」 술어와 같다.
- 명부에 장기임대 행이 없으면(메뉴 전제 M2) 종전대로 거둔다. 임대주택 취득일을 몰라 다른 특례를 판정할 수 없기 때문이다.
- 메뉴 ⑧ 경고(`one-house-exemption-validate.ts:376`)는 「특례가 서면 이중 계상」만 말한다. 「특례가 서지 않을 때 임대주택이 일시적 2주택의 신규 주택 등에 해당하는지 보려면 명부에 넣어 판정한다」를 덧붙인다.
