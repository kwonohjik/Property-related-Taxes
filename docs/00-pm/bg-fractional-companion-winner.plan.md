# 함께 부담부증여 × 지분 있는 컴패니언 — ⑧ 과 ⑫ 가 승자를 다르게 읽는다 (측정 · 계획)

- 앵커: `__tests__/api/transfer.route.bg-fractional-companion-winner.anchor.test.ts` (FC-1~FC-4, 7건)
- 선행: #2745(균일/혼합 승자 측정) · #2746(`bgBundleMixedWinner` — ⑫ 가 혼합 승자 400). 그 PR 의 CB-3 이 이 건을 「확인 필요」로 남겼다.
- 상태: **구현 완료** — Q-1 a 채택(2026-10-30 「권고안으로 진행해」). §7 에 결과.

## 1. 질문

#2746 이 막는 것은 「자산별 상증법 평가 승자가 서로 다른 묶음」이다. 그런데 ⑧ 이 막는 지분 쌍(주 100% + 컴패니언 50%, 컴패니언 시가 1.0B · 채무 0.6B)을 ⑫ 는 200 으로 통과시킨다
(#2745 CB-3). 이것이 ① 계산이 맞는데 ⑧ 만 과차단하는 것인지, ② ⑫ 가 틀린 값을 내보내는 것인지 가린다.

## 2. 방법 — 이미 맞게 도는 경로를 오라클로

지분 r 인 자산 F(시가 V · 채무 D)는 경제적으로 「지분율 100% · 시가 r×V · 취득가액 ×r · 채무 D」 자산 F' 와 같다(`scaleBurdenedGiftInfo` 가 평가액만 r 로 줄이고 채무는 그대로 두는 축 A 규약 —
`BurdenedGiftBlock.tsx:119-134`, `transfer-tax-api-burdened-gift.ts:591`). F' 쌍은 #2745 가 확인한 100% 경로(균일 승자 ±1원)다.
보충 승 파트너(시가 1.0B · 채무 0.4B)와 묶어 역할(F 가 컴패니언 / 주 자산) × 채무 D 를 훑고 증여가액·증여세·양도차익·총세액을 대조했다.

## 3. 결과 (앵커 실측)

| D (F 의 인수분 채무) | F 지분 시가 | F 가 컴패니언 | F 가 주 자산 | 100% 오라클 |
|---|---|---|---|---|
| 2억 · 3억 · 5억 | 5억 이상 | 200 · 증여가액 1.5B — **오라클과 ±0**(증여세·양도차익·총세액 포함) | 같음(±0) | 200 |
| 6억 | 5억 < D (담보 승) | ⑧ 게이트 · **⑫ 200** · 증여가액 1.5B · 증여세 77,600,000 | ⑧ 게이트 · ⑫ 400 | 혼합 → ⑫ 400. 같은 ΣA(1.6B)를 보충 승으로 만든 쌍: 증여세 101,850,000 |
| 7억 | 〃 | ⑧ 게이트 · **⑫ 200** · 증여가액 1.5B · 증여세 58,200,000 | ⑧ 게이트 · ⑫ 400 | ΣA 1.7B 쌍: 증여세 101,850,000 |

- **FC-1**: 보충 승 영역(D ≤ 지분 시가)은 컴패니언·주 자산 모두 오라클과 같다 — 지분 컴패니언 처리 자체는 맞다.
- **FC-2 (결함)**: D > 지분 시가인 컴패니언은 ⑫ 를 통과해 **증여가액이 ΣA 보다 작다**(1.5B vs 1.6B / 1.7B). 증여세 **24,250,000 / 43,650,000 과소**.
  양도차익·총세액도 오라클보다 작다(645,000,000 vs 667,187,500 · 709,500,002 vs 755,441,179; 총세액 169,026,000 vs 175,859,750 · 188,892,001 vs 203,620,677) —
  단 오라클의 취득가액이 실가 그대로라(담보 승이면 취득시 기준시가로 강제되는 값과 다름) **양도세 쪽은 근사**다(확인 필요). 증여세 쪽은 증여가액만 같게 만든 오라클이라 확정이다.
- **FC-4**: 둘 다 지분이면 같은 비대칭이 두 방향으로 나온다.
  - 50/25, D=3억: 컴패니언 인수분 3억 > 지분 시가 2.5억 → 담보 승인데 ⑫ 200(증여가액 7.5억, ΣA 8.0억, 증여세 9,700,000) — 과소. 오라클은 혼합이라 ⑫ 400.
  - 50/50·50/25, D=6억: 둘 다 담보 승(**균일** — 오라클 ⑫ 200)인데 ⑫ **400**(거짓 차단). 주 자산은 6억 그대로, 컴패니언만 3억으로 읽혀 혼합으로 보인다.

## 4. 원인 (코드 + 인과 확인)

- ④ 가 같은 폼 채무를 주 자산과 컴패니언에서 **다르게** 싣는다. 주 자산: `buildBurdenedGiftInfo(primary, fractionalBundleMerge ? ratio : undefined, …)` — 축 B 일 때만 지분 안분
  (`transfer-tax-api-primary-context.ts:226-232`). 컴패니언: `buildBurdenedGiftInfo(asset, fractional ? ratio : undefined, …)` — 지분이면 **축과 무관하게** 안분
  (`transfer-tax-api-companion-payload.ts:514`; `fractional = ratio < 1` `:178`, `axisB` 는 `:185` 에 이미 있다).
- 그 외 모든 곳은 채무를 지분 인수분 그대로 읽는다: ⑧ `transfer-tax-validate.ts:352-360`(`buildBurdenedGiftInfo(a)` 무안분) · 합산 info `buildCompanionBurdenedGiftWholeInfo` · 채무 재배분 `apportionCompanionBurdenedGiftDebt`
  (`transfer-tax-api-primary-context.ts:243`) · UI 안내(`BurdenedGiftBlock.tsx:265-272` — 지분 인수분을 입력).
  실측 payload: 컴패니언 F 채무 3억(폼 6억), 주 자산 F 채무 6억, 합산 info 채무 10억 · 시가 15억(FC-3).
- 그래서 ⑫ `bgBundleMixedWinner`(payload 를 읽는다)는 컴패니언 F 를 보충 승으로, ⑧ 과 합산 info 는 담보 승으로 읽는다.
- **인과 확인**: `:514` 를 `axisB && fractional ? ratio : undefined` 로 임시 변경(원복·`diff -q` 확인)하면 FC-2 두 셀이 ⑫ 400 으로 뒤집히고 FC-1 은 그대로다.

## 5. 결정 (Q-1) — a 채택

- **a (권고)**: 컴패니언 payload 의 채무 안분을 축 B 에서만 한다(`:514` 한 줄). 주 자산과 같은 규약(축 A 인수분)이 되고 ⑫ 는 ⑧ 과 같은 값을 읽어 #2746 규칙이 지분 쌍에도 닿는다.
  FC-4 의 거짓 차단도 함께 사라진다. 구현 때 확인: ① 카드 표시용 담보평가(카드 `giftValuation.mortgage` 3억→6억)가 어디에 쓰이는지 ② 채무 재배분 B 값 불변 ③ FC-1 ±0 유지 ④ 비일반건물 컴패니언(같은 줄이 모든 자산 종류에 닿는다).
- b: ⑫ 규칙이 payload 채무를 지분율로 나눠 되돌려 읽는다 — 역산이라 반올림·축 B 와 섞이면 깨진다. 권고하지 않는다.
- c: 컴패니언도 「물건 전체 입력」으로 규약을 바꾼다 — UI 안내·⑧·합산 info 가 모두 바뀐다. 권고하지 않는다.
