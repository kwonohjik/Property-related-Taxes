## 0. 한 줄 요약

- **사이드바만의 문제가 아니다.** 원인이 세 층에 있다.
  1. ⑥ 사이드바: 부담부증여 자산의 취득가액·필요경비를 화면에 없는 자산 일반 칸에서 읽는다(단건·묶음 모두).
  2. **엔진 표시 echo**(`resolveDisplayAcquisitionAndExpense`): §159를 모른다. 묶음의 자산별 취득가액이 route 입력(숨은 값)이고, 필요경비는 역산이라 **음수**가 된다. 이 echo를 합산 신고서·명세서·합산 요약 카드·PDF가 읽는다 — 결과 화면에서 「양도가 − 취득가 − 필요경비 = 차익」이 깨진다(실측 800,000,000 − 600,000,000 − 0 ≠ 388,000,000).

- 단건 주택 부담부증여의 **결과 화면**은 이미 엔진 값과 맞다(200,000,000 · 6,000,000). 틀린 곳은 사이드바다.

## 1. 실측

fixture는 PR-1 anchor(`__tests__/api/transfer.route.burdened-gift-bundle-apportion.anchor.test.ts`)와 같다. 부담부증여 주택 = 취득시 기준시가 500,000,000 · 양도시 1,000,000,000 · 채무 4억(보증금 2억 + 담보 2억) → 채무비율 40%. 숨은 값 = 일반 거래 때 입력한 `fixedAcquisitionPrice` 300,000,000(부담부증여 화면에서 사라진 칸).

### 1.2 사이드바(⑥) — 단건

| 경우 | 취득가액 계산 전 / 후 | 필요경비 계산 전 / 후 | 엔진(§159 명세) |
|---|---|---|---|
| 기준시가 · 숨은 취득가 3억 | **300,000,000 / 300,000,000** | 「-」 / 6,000,000 | 200,000,000 · 6,000,000 |
| 기준시가 · 숨은 값 없음 | **「-」 / 「-」** | 「-」 / 6,000,000 | 200,000,000 · 6,000,000 |
| 기준시가 · 자본적지출 5천만 | 300,000,000 / 300,000,000 | **50,000,000** / 6,000,000 | 200,000,000 · 6,000,000 |
| 시가 모드 · 실지취득가 3억 | 300,000,000 / 300,000,000 | 「-」 / 「-」 | **75,000,000** · 0 |
| 시가 모드 · 환산 | 300,000,000 / 300,000,000 | 「-」 / 2,250,000 | **120,000,000** · 2,250,000 |
| 원조합원 입주권 | 「-」 / 200,000,000 | 「-」 / 「-」 | §166 역산 200,000,000(양도 600,000,000 − 차익 400,000,000) |

- 「-」는 값 0 · pending 아님(`TransferSidebarSummary.tsx:30-36`).
- 필요경비 계산 후는 엔진 `expenses`라 맞다(`transfer-per-asset-summary.ts:626-634`). 계산 전은 화면의 `capitalExpenditure`를 그대로 보인다 — 기준시가 모드 필요경비는 개산공제(소득세법 시행령 §163⑥)이고, 자본적지출은 §97②2호 단서가 발동할 때만 채택된다. 계산 전에는 엔진만 안다.
- 입주권 계산 후 200,000,000은 §166 역산 leaf(`redevFilingTotals` — 양도가액 인자는 #2377의 §159 양도가액)라 차익과 맞다. §159 명세의 `perAsset` 취득가액 합(120,000,000)은 인가 전 분(실지취득가 3억 × 40%)만이고, 인가 후 청산금 분(80,000,000)은 §166 분기가 따로 낸다(결과 화면 장특 표 실측: 120,000,000 · 80,000,000).

### 1.3 사이드바 · 결과 화면 — 전 자산 부담부증여 묶음

부담부증여 주택 A(위) + B(취득시 300,000,000 · 양도시 600,000,000 · 채무 4억), 안분 16억(실가 거래 모드도 같은 값).

| | A 취득가액 · 필요경비 | B 취득가액 · 필요경비 |
|---|---|---|
| 엔진 단건 결과(§159 명세 — 집계 안 `r.result`) | 250,000,000 · 7,500,000 | 150,000,000 · 4,500,000 |
| 엔진 표시 echo(`aggregated.properties[]`) | **300,000,000 · −42,500,000** | **300,000,000 · −145,500,000** |
| 사이드바 계산 후 | 300,000,000 · −42,500,000 | 300,000,000 · −145,500,000 |
| 사이드바 계산 전 | 300,000,000 · 「-」 | 300,000,000 · 「-」 |

- echo 양도가액은 확정 가액 Bᵢ(500,000,000 · 300,000,000 — #2365)라 맞다. 차익(242,500,000 · 145,500,000)도 맞다. 취득가액만 route 입력이고, 필요경비는 `양도가 − 취득가 − 차익` 역산이라 음수다.
- **결과 화면(Playwright)**: 합산 표 「취득가액 600,000,000 300,000,000 300,000,000 · 필요경비 0 0 0 · 전체 양도차익 388,000,000」. 필요경비 음수가 UI clamp에 잘려 0이 되고(`transfer-tax-aggregate-display-echo.ts:29-31` 주석의 그 clamp), 정본은 취득가액 400,000,000 · 필요경비 12,000,000이다.
- 주택 + 입주권 묶음: echo [[300,000,000, −94,000,000], [200,000,000, 0]] · 사이드바 계산 후 [[300,000,000, −94,000,000], [0, 0]]. 입주권 echo는 §166 역산 leaf라 맞고, 사이드바만 0이다(`bundledMatch.allocatedAcquisitionPrice`).

### 1.4 결과 화면 — 단건 원조합원 입주권 부담부증여

신고서 표(Playwright): 「취득가액 **−400,000,000** 120,000,000 80,000,000 · 필요경비 0 0 0 · 전체 양도차익 400,000,000 240,000,000 160,000,000」. 합계 열만 틀렸다(분할 열은 맞다).

## 3. 수정안

leaf 하나 — 「부담부증여 자산의 §159 합계」 `burdenedGiftPerAssetTotals(brkd)` → `{ transferPrice, acquisitionPrice, estimatedDeduction }`(토지·건물 합). Layer 2(`lib/tax-engine/`)에 두고, #2377의 `burdenedGiftTransferPrice`(lib/calc)·결과 카드·신고서 resolver가 이것을 쓴다.

**D1 엔진 표시 echo (C2)** — `resolveDisplayAcquisitionAndExpense`에 §159 분기를 둔다. 위계: 이월과세 → §166 → 분리 → **§159** → swap → 종전.
- 취득가액 = `burdenedGiftPerAssetTotals(r.result.transferBurdenedGiftBreakdown).acquisitionPrice`.
- 필요경비는 종전 역산 그대로(`양도가 − 취득가 − 차익`) — §159 취득가액이면 역산값 = 엔진 `expenses`(7,500,000 · 4,500,000 실측)라 항등식이 성립한다.
- §166 자산(입주권)은 §166 분기가 먼저라 그대로다(정본 200,000,000).
- 세액 경로는 이 echo를 읽지 않는다(파일 머리 주석) — anchor에서 결정세액 불변을 함께 단언한다.

**D2 사이드바 (C1)** — 부담부증여 자산(`usesSelfComputedTransferPrice`, 겸용 × 부담부증여 `bgMixed`는 종전 분기 유지):
| | 취득가액 | 필요경비 |
|---|---|---|
| 계산 전 | 「계산 후 표시」 | 「계산 후 표시」 |
| 묶음 계산 후 | `bundledProperty.acquisitionPrice`(D1 echo) | 종전(`bundledProperty.necessaryExpense` — D1로 양수) |
| 단건 계산 후 | §166 자산 = 종전 `redevResultTotals`, 그 밖 = §159 명세 취득가액 | 종전(엔진 `expenses`) |

**D3 신고서 표·계산명세서 §166 역산 (C3)** — 부담부증여 §166 자산의 역산 양도가액 인자를 §159 양도가액(`burdenedGiftPerAssetTotals(...).transferPrice`)으로 준다. 사이드바는 #2377에서 이미 그 값을 넘긴다(입주권 계산 후 200,000,000이 맞는 이유). 양도가액 행도 같은 값으로 채운다(지금은 `bgSingle`이 §166을 빼서 폼 값 0 → 빈칸 — Do 1단계 실측).

**세액 영향**: 없음. 결과 화면 합산 표·건별 신고서·명세서·PDF·사이드바의 표시값만 바뀐다.

### 7.2 구현

- **신규** `lib/tax-engine/burdened-gift-totals.ts`:
  - `burdenedGiftPerAssetTotals(brkd)` — §159 명세 토지·건물 합(양도가액·취득가액·개산공제).
  - `redevInverseTransferPrice(result, fallback)` — §166 역산 양도가액 인자. §166 + 부담부증여면 §159 양도가액, 아니면 fallback.
  - #2377의 `burdenedGiftTransferPrice`(lib/calc)는 이 leaf에 위임한다.
