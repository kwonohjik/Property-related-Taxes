# 의제취득일 전(1980) ①② echo · §163⑨ 근거 echo × `compareSec164` — 실측 (결함 없음)

- 상태: 측정 완료 — 소스 변경 없음 (앵커 + 이 문서만)
- 앵커: `__tests__/api/transfer.route.gb-pre-deemed-echo.anchor.test.ts` (3건)
- 선행: `gb-sec164-substitutes-blank-reported.plan.md` V-2·V-4 (#2725) · `gb-gift-off-sec164-unsplit.plan.md` V-4 (#2729)

## 1. 질문

#2725 가 파트 슬롯을 `compareSec164(①, 적용, ②)` 로 바꿨다 (`transfer-tax-api-gb-sec163-9.ts:100`). 의제취득일(1985.1.1.) 전 상속·증여 파트는 ①② 를 슬롯과 **따로** `landPreDeemedClauseA {reported, sec164}` 로 싣고(`gb-pre-deemed.ts:56-63`) 엔진이 ③ 환산과 비교해 경로를 고른다(`general-building-pre-deemed.ts` `resolveGbPreDeemedRoute`).
1. 그 ①② echo · ③ 비교가 `compareSec164` 변경과 어긋나는가? (#2725 V-2)
2. 파트 카드의 `sec1639Basis` echo (`adopted: reported | sec164`) 가 규칙과 맞는가? (#2725 V-4)
3. 1980 파트의 슬롯이 비면 echo 가 어떻게 되는가? (#2729 V-4)

## 2. 측정

환경: vitest + `makeMockRates`. 취득시 기준시가 토지 205,000,000 · 건물 150,000,000. 상속·증여 × 증여·상속일 4(1980·1988·1995·2005) × 분리 OFF·ON(증여는 ON 만 — OFF 는 ⑧ 이 막는다) × 토지·건물 신고가액 5조합(§164 의 0.5배·1배·2배, 서로 엇갈린 둘) × 위치 3(컴패니언·주 자산·단건) = **180셀**, 양도가액 1.6B·1.0B 두 번.

**시료를 갈랐다.** 양도가액 1.6B 는 ③ 환산이 ①② 를 이기는 셀 36을, 1.0B 는 ③ 채택 0 · **② §164 채택 90파트**(1.6B 는 54파트)를 만든다. 비교 채널이 모두 갈리는 셀이 있어야 어긋남이 보인다.

오라클(이미 동작하는 채널, ±0):
- ⓐ 멱등 — 파트 가액을 max(①,②,③) 로 미리 넣은 같은 자산의 세액이 같다 (③ 채택 셀 제외).
- ⓑ 증여 — 같은 날짜의 **매매(실가) 채널** 세액이 같다 (③ 채택 파트는 추계 모드로).

- 1980 파트가 비는 입력은 echo 까지 가지 못한다 — 비-BG 는 ⑧ 이 막고 ⑫ 도 400 이다 (`gb-sec164-substitutes-blank-reported` SU-1~3 · `gb-gift-off-sec164-unsplit` S-2 의 1980 셀). 즉 「빈 슬롯의 echo」 는 도달하지 않는다.
- **BG(부담부증여) 시가 평가 × 의제취득일 전 × 파트 ① 비움은 ⑧ 차단 · ⑫ 200 이지만 의도된 비대칭**이다 — `bg-gb-residuals.plan.md` §2.2 · Q-2 a (PR-7b-6a 계약 R-0·R-2, 앵커 5건). 이 측정의 BG 시료(1980 증여·상속 × OFF·ON 12셀)도 같은 결과(64,895,000, ① 이 max(②,③) 이하일 때 lt 와 동일)였고 **결함으로 세지 않는다**. (초안에서 결함으로 읽었다가 코드 주석 `transfer-tax-validate-bg.ts:421` 의 계약 주석과 계획서로 정정했다.)

## 4. 새로 확인된 한 건 (V-1)

**BG 상속 × 취득방식 「converted」 × 상속개시일 1985.1.1. 이후** — ⑧ 은 막는다(`transfer-tax-validate-bg.ts:380-384` — 상속개시일 현재 상증법 평가액이 실지거래가액이라 환산 불가, 소득세법 §97①1호 단서). ⑫ 에는 같은 조건이 없어 **30셀(1988·1995·2005 × OFF·ON × 평가액 5조합) 전부 200**이고, 평가액을 바꿔도 세액이 76,712,292 로 같다(평가액이 쓰이지 않고 환산으로 계산된다).
- 앵커 EC-2 가 **현재 동작을 기록**한다 (고쳐지면 반전).
- 의도된 비대칭인지는 근거 문서를 찾지 못했다 (`bg-gb-residuals.plan.md` §2.2 는 ① 비움만 다룬다) — 「확인 필요」.
- 세액 영향(올바른 경로 = 「실지취득가액 안분 + 평가액」과의 차)은 **측정하지 않았다.**
