## 1. ① 비교과세와 `Σ건별 산출`

### 1.1 측정 (집계 엔진, 주택/토지 2~5건)

| 시료 | `comparedTaxApplied` | 합산 산출 | Σ건별 산출 | 차 |
|---|---|---|---|---|
| A 일반 누진 주택 2건 | `none` | 310,770,000 | 278,320,000 | **32,450,000** |
| B 단기(70%) + 일반 | `groups` | 309,110,000 | 309,110,000 | 0 |
| C 단기2년(60%) + 일반 | `groups` | 289,360,000 | 289,360,000 | 0 |
| D 미등기(70%) + 일반 | `groups` | 449,860,000 | 449,860,000 | 0 |
| E 토지 2건 (한쪽에 `isNonBusinessLand`를 넣었으나 mock 세율표에 중과가 없어 둘 다 `progressive` — **사실상 일반 누진 2건**) | `none` | 265,410,000 | 235,360,000 | **30,050,000** |
| F 다주택 중과(70%) + 일반 | `groups` | 423,170,000 | 423,170,000 | 0 |
| G 단기 + 자경농지 감면 + 일반 (3건) | `groups` | 364,454,000 | 334,550,000 | **29,904,000** |
| H 토지 3건 (한 건 `isNonBusinessLand` — 위와 같이 `progressive`) + 자경 감면 + 일반 | `none` | 385,725,000 | 324,350,000 | **61,375,000** |
| I 감면 2 + 일반 2 (4건) | `none` | 445,125,000 | 354,870,000 | **90,255,000** |
| J 감면 3 + 단기 + `isNonBusinessLand` 한 건(`progressive`) (5건) | `groups` | 548,600,000 | 457,610,000 | **90,990,000** |

- 어긋난 6개(A·E·G·H·I·J)는 모두 `rateGroup = progressive`인 자산이 **2건 이상**(E·H·J의 «비사업용» 한 건도 `progressive`로 집계됐다)이고, 같은 세율군의 과세표준이 합쳐져 누진 구간이 올라간다. 정확히 맞은 4개(B·C·D·F)는 progressive 자산이 **1건**뿐이고 나머지는 고정 세율군(단기·미등기·중과)이다.
- 비교과세(`groups`)가 걸린 G·J는 어긋남이 있지만 progressive 2건 이상이 원인이다 — 같은 조건에서 `none`인 A·H·I도 똑같이 어긋난다.
- 이 시료에서 `Σ배분 = 합산 감면`(G·H·I·J 모두 100,000,000)과 `refDet = max(0, refCalc − 배분)`이 전부 성립했다.

### 1.2 화면 고지는 이미 이 경우를 덮는다

신고서 합산 표는 자산 세액 칸이 2개 이상이면 `REF_TAX_FOOTNOTE`를 붙인다(`FilingFormTableAggregateHelpers.ts:478-486`, 2026-11-09 사용자 결정 a) — 위 어긋난 6개 시료는 모두 자산 칸 2개 이상이라 고지가 뜬다. 고지 문구는 «합계 칸은 과세표준을 모두 더한 뒤 세율을 적용하므로 자산별 칸을 더한 값과 다를 수 있습니다»라 ①과 일치한다.

## 2. ② 분할(GB) 자산 × §97·§99 [직접: route 400 문구]

일반건물 1건, 일반건물 + 토지 2건에 감면을 실어 다건 route를 호출했다(감면 본문은 주택 폼 → ④ 변환으로 얻은 실제 API 본문을 그대로 이식).

| 감면 | 결과 |
|---|---|
| §97 본문 · §97의3 · §97의5 · §99 · §99의3 · §98의3 | 모두 **400** `properties.0.reductions.0.type` — «…감면은 주택 양도에만 적용됩니다. 자산 종류를 확인하거나 감면 선택을 해제하세요.» (일반건물 1건·+토지 모두 동일) |

- 따라서 일반건물 분할 카드의 `reductionAggregated`·`refDeterminedTax`는 §77 등 비주택 감면에서만 생긴다. 그쪽은 #3170 조사(§77, `Σ배분 = 합산 감면` 성립)로 이미 확인했다.
- 막는 지점은 ⑫(Zod, NH-54 자산 종류 게이트)다. 엔진 직접 호출 경로는 측정하지 않았다 — route 밖 호출은 이 앱에 없다(확인 필요: 라우트 전수는 하지 않았다).
- 측정하지 않은 것: 겸용주택·주택 분리(§164)와 같은 **주택** 분할 자산의 §97·§99 감면(이번 «GB»는 일반건물만).

## 3. ③ 4건 이상

§1.1의 I(4건)·J(5건)가 근거다. 건수가 늘어도 규칙은 동일하며, 어긋남의 크기는 progressive 자산 수와 과세표준 크기에 따른다(I 90,255,000 · J 90,990,000). 6건 이상·같은 날 양도 다수·기본공제 `annualBasicDeductionUsed > 0`은 측정하지 않았다.
