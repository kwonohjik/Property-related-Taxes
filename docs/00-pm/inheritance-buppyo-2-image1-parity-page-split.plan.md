> ★ **핵심**: 1쪽 나 칸은 데이터를 채우지 않고 `"별첨"` 한 단어만 기재. 재산 상세는 별지(2쪽)에 「상속인별 상속재산명세」로 작성. 1차 구현은 1쪽 나에 실제 데이터를 넣고 2쪽을 만들지 않음 → "한 페이로 만들고 제목 삭제".

| 사용자 발언 | 의미 |

## 4. 작업 항목 (단일 출처 우선 — 화면·PDF 동시)

### 4-1. 상수 (`besshi-buppyo-2-constants.ts`)
- `BP2_GA_LABELS` ①~⑧ 번호 부착 (relation~actualValue)
- `BP2_NA_LABELS` ⑨⑩⑪⑫⑬⑭⑮⑯ 번호 부착 (overseas·country 번호 없음)
- `BP2_KYE_ROWS` ⑰~㉘ 번호 + 그룹 메타(group·groupSize) 부착. **⑳ 라벨 §6 결정 의존** (이미지=문화재 / 현행코드=공공단체유증)
- 신규: `BP2_NA_SECTION_TITLE = "상속인별 상속재산명세"` · `BP2_ATTACHMENT_MARK = "별첨"`

### 4-2. 어댑터 (`lib/calc/besshi-buppyo-2-data.ts`) — 계 행 1필드
- `Buppyo2HeirData`에 `itemRowsTotal: number` = `Σ itemRows[].valuatedAmount` (UI 무산술)
- 엔진/타입/Zod/validate 무변경. 기존 `sectionTotal`(계 ⑰~㉘)·`itemRows`(2쪽)·`sectionA`(가) 그대로.

### 4-3. 1쪽 컴포넌트 (`Buppyo2GaSection` + 계 + `Buppyo2KyeSection`)
- 가: ①~⑧ 헤더 번호 (상수 반영)
- 나(1쪽): ⑨~⑯ 헤더 + **"별첨" 1행** + 빈행 (실제 데이터 미표시). 신규 소형 컴포넌트 `Buppyo2NaAttachmentStub` 또는 NaTable에 `mode="stub"` prop
- 계: ⑰~㉘ 번호 + 그룹 라벨 rowSpan(비과세 ⑲⑳㉑ / 불산입 ㉒㉓㉔ / 가산증여 ㉕㉖㉗). 좌측 "계" rowSpan 12

### 4-4. 2쪽 컴포넌트 (`Buppyo2NaTable`)
- 상단 독립 제목 「상속인별 상속재산명세」 (`text-center text-base font-bold`)
- ⑨~⑯ 헤더 (상수)
- 실제 itemRows + 빈행
- **계 행** 추가: `<td colSpan>계</td>…<td>{itemRowsTotal}</td>` (⑮ 열). testid `buppyo2-na-total-{idx}`

### 4-5. 페이지 분리 (`Buppyo2HeirSheet` · `BesshiBuppyo2Section`)
- HeirSheet = [1쪽 블록] `print:break-after-page` + [2쪽 블록] `print:break-inside-avoid`
- 1쪽 블록: 상속인번호 헤더 + 가 + 나"별첨" + 계
- 2쪽 블록: NaTable(독립 제목·실제 데이터·계행)

### 4-6. PDF (`InheritanceBuppyo2PdfDocument`) — 상속인당 2 Page
- Page1: subtitle + 전체제목 + 상속인번호 + GaBlock(①~⑧) + 나"별첨" + KyeBlock(⑰~㉘ 그룹)
- Page2: 「상속인별 상속재산명세」 제목 + NaBlock(⑨~⑯ + 실제행) + 계행
- 칸번호·제목·계행 = constants 동일 출처

### 4-7. anchor
- `besshi-buppyo-2-data.test.ts`: `itemRowsTotal` = Σ valuatedAmount (이미지 4,210,000,000) · ㉘합계 = ⑰+⑱+㉕ 정합
- UI: 가 ①~⑧·나 ⑨~⑯·계 ⑰~㉘ 번호 존재 · 1쪽 나 "별첨" · 2쪽 제목·계행 `buppyo2-na-total` · 기존 testid 동결
