### F-1 🔴 과다과세 — 스칼라가 정본인데 ⑥ 행이 그 수에 들어 있지 않다

엔진은 `max(주택 수 − 제외 수, 0)`(`transfer-tax-house-exclusion-step.ts:205-208`)으로 뺀다. 스칼라 1(= 양도
주택뿐)에서 ⑥ 1채를 빼면 **0채**가 되고, 1세대1주택 비과세를 잃는다.

- 스칼라가 정본인 두 경우: 옛 이력 표식(`resolveHouseholdHousingCount` — `legacyPrecedence`) · 대표 자산이
  주택이 아닌 경우(F1 — 재개발 아파트는 ⑥ 게이트 `countExclusionRowsInScope` 안이다).
- **D는 평범한 조작으로 생긴다**: 재개발 아파트는 명부가 정본이 아니라 스칼라 버튼이 잠기지 않는다
  (`houseCountScalarLocked`) → 「2채 → 행에 ⑥ 지정 → 1채로 낮춤」.
- **명부가 보여도 틀린다**: C·D의 양도일(2024-06-01)은 한시배제 창 안이라 명부가 **보이는** 상태에서 잰
  값이다(렌더 probe: 행 편집 버튼 1개). 화면 축(F-2)과 별개다.
- 두 입력이 모순이다 — 스칼라 1은 「양도 주택 외 주택 없음」, ⑥ 행은 「다른 주택 r이 있다」.
  어느 쪽이 사실이든 법령상 답은 과세가 아니다(1채뿐이면 비과세, r이 있으면 2−1=1로 비과세).

### F-2 🟠 화면 — 창 밖에서는 값이 있어도 명부가 숨는다

2026-09-07 수정(`house-count-inputs-scope.ts` — 「값이 남아 있으면 그 값을 고칠 화면도 남는다」)은
**섹션 바깥 게이트**에만 걸렸다. 비한시배제 분기는 `SurchargeJudgmentSection.tsx:61`에 안쪽 게이트
`isHousingLike && 스칼라 ≥ 2`가 따로 남아, 섹션은 열려도 `HouseCountExemptionInputs`가 숨는다.

- 렌더 probe: 창 밖(2026-06-01) · 스칼라 1 · 행 있음 → 행 편집 버튼 **0개**(C′·D′), 창 안 → 1개.
- 숨은 행은 ④가 계속 싣고 ⑧이 계속 검증한다 → E처럼 **보이지 않는 행**의 오류로 막힌다(09-07이 고친 것과
  같은 dead-end가 이 분기에 남아 있다).

### F-3 🟠 화면 — 창 안에서는 분양권 목록이 두 벌 뜬다

창 안 + 값 있음 + 스칼라 < 2이면 `HousesListSection`(명부 안 `PresaleRightsSection`)과 ② 섹션의
`PresaleRightsSection`(`Step4.tsx` `스칼라 < 2` 게이트) **둘 다** 렌더된다 — 렌더 probe에서 「분양권·입주권」
제목 2개. 같은 `form.presaleRights`를 두 컴포넌트가 patch한다(last-write-wins). 09-07 수정이 만든 잠복 결함이고,
F-2를 같은 방식으로 고치면 창 밖 분기에도 복제된다.

## 2. 결정

### Q-1 F-1을 어떻게 막나 — ✅ (a) ⑧ 차단으로 결정 (2026-09-30)

| 안 | 동작 | 장단 |
|---|---|---|
| **(a) ⑧ 차단 (추천)** | 정본 주택 수 − ⑥ 행 수 < 1이면 「세대 보유 주택 수(N채)가 주택 수 제외로 지정한 명부 주택 M채를 포함하지 않습니다 — 주택 수를 늘리거나 지정을 해제하세요」 | 어느 쪽이 사실인지 사용자가 고른다. C6 결정(Q-1 — 자동 배정 금지)과 같은 방향. 주택 수는 ④와 같은 leaf(`resolveHouseholdHousingCount`) |
| (b) ④에서 조용히 제외 | 정본 주택 수 < 2이면 ⑥을 싣지 않는다 | C·D는 비과세로 맞지만 사용자 모르게 입력을 버린다 |
| (c) 엔진 하한 1 | `max(주택 수 − 제외 수, 1)` | 모든 경로·API 직접 호출까지 막지만 공유 엔진 변경. 「양도 주택은 제외 대상이 아니다」 근거는 명확하나 모순 입력을 조용히 흡수한다 |

- (a)가 못 잡는 것(기록): 스칼라 2(양도 + N)인데 명부에 N과 r(⑥)이 따로 있는 경우 — 실제 3채 − 1 = 2(과세)인데
  2 − 1 = 1(비과세). 스칼라와 명부의 **전체** 정합성은 재개발 아파트에서 의도적으로 보지 않는 축(F1)이라 이 계획 범위 밖이다.

### Q-2 F-2·F-3 — 선례 적용 (결정 불필요)

- 안쪽 게이트를 09-07 leaf와 같은 술어로: 값이 있으면 `HouseCountExemptionInputs`를 연다.
- ② 섹션의 분양권 목록은 **명부가 렌더되지 않을 때만** 연다 — 두 게이트가 같은 술어의 부정이 되게 한다(F-3 해소).
