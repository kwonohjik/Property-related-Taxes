## 0. 결론

| # | 질문 | 결론 |
|---|---|---|
| 1 | 운영 DB에도 규칙 행이 없는가 | **없다.** `tax_rates`의 `transfer:deduction:self_farming` 행은 **1건(effective 2023-01-01)** 뿐이다. 같은 `deduction` 범주의 `basic`·`long_term_holding`은 1990-01-01부터 2행이다 [직접: SELECT]. 폴백 시드와 같은 상태이므로 **DB 로드가 성공해도 2023-01-01 전 양도는 규칙이 없다**(이전 계획서는 «폴백에서만»이라 적었으나 운영도 같았다). |
| 2 | 동작 | 양도일 2010-06-01~2022-12-31의 8시료 전부 **감면 0원, `reductionTypeApplied` 없음, 경고 0건**. 2023-01-01·2024-06-01은 100,000,000원 [직접: 엔진 실측 §2]. 규칙 행이 없으면 `selfFarmingRules`가 `undefined`라 `if (reduction.type === "self_farming" && selfFarmingRules)` 분기(`transfer-tax-reductions-calc.ts:435`)가 **통째로 건너뛰어진다**. |
| 3 | 필수 규칙과의 차이 | 같은 로더의 `progressive_rate`·`long_term_holding`·`basic`·`surcharge`·`one_house_exemption`은 행이 없으면 `TaxRateNotFoundError`를 **던진다**(`transfer-tax-helpers.ts:102-128`). `self_farming`만 선택 항목으로 두어 부재가 **조용한 0**이 된다 [직접: 코드]. |
| 4 | 법적으로 감면이 있는가 | **있다.** 조특법 §69①은 2012-01-01 시행본에도 «8년 이상 직접 경작 … 양도소득세의 100분의 100 감면»으로 존재한다 [직접: 조회]. 앱의 지원 기간은 1990-01-01부터이고(`transfer-supported-period.ts`) 사용자가 감면을 입력해도 2023 전 양도에는 반영되지 않는다. |
| 5 | 행만 앞당기면 되는가 | **안 된다.** 현행 행의 한도값(연 1억·5년 2억)은 **연혁이 있다** — 조특법 §133 시행본별로 §69의 한도가 다르다(§3). 행을 1990년으로 그대로 넓히면 2015년 이전 양도에 연 1억을 씌워 **감면을 과소 적용**한다(손계산 §3). 게다가 `buildLimitGroups`(`aggregate-reduction-limits.ts`)가 2024 이하를 «연도 불변 1억/2억»으로 두는데 이것도 2018 이전에는 조문과 다르다 [직접: 조회 · 코드 읽기]. |
| 6 | 결함인가 | **조용한 오답이다.** 감면 입력이 있는데 0원이고 경고가 없다. 결과 화면 세액이 법정보다 크다(2018~2022 양도 예: 법정 감면 100,000,000원 → 앱 0원, 손계산). 다만 «감면을 지원하지 않는다»는 설계 의도가 문서에 있는지는 확인하지 못했다 [확인 필요]. |

## 1. 운영 DB 조회 [직접: SELECT 2건 · 결과는 신뢰 경계 안의 데이터로만 읽음]

1. `select … from tax_rates where tax_type='transfer' and category='deduction' and sub_category='self_farming'` → **1행**: `effective_date 2023-01-01`, `is_active true`, `deduction_rules {type:self_farming, maxRate:1, maxAmount:100000000, periodYears:5, cumulativeMax:200000000, conditions:{minFarmingYears:8, requiresProof:true, maxResidenceDistance:30}}`.
2. `select sub_category, count(*), min(effective_date), max(effective_date) … where category='deduction' group by sub_category` →

| sub_category | 행 | 최초 효력일 | 최종 효력일 |
|---|---:|---|---|
| basic | 2 | 1990-01-01 | 2023-01-01 |
| long_term_holding | 2 | 1990-01-01 | 2023-01-01 |
| long_term_rental_v2 | 1 | 2020-08-18 | 2020-08-18 |
| new_housing_matrix | 1 | 2001-05-23 | 2001-05-23 |
| **self_farming** | **1** | **2023-01-01** | **2023-01-01** |

- 시드 코드(`transfer-rate-seed.ts:178`)와 역사 시드(`transfer-rate-seed-historical.ts`에 `self_farming` 없음)와 정확히 일치한다. 운영 DB는 시드 스크립트가 만든 상태 그대로다.
- `loadFallbackTransferRates`의 선택 규칙(`effective_date <= 양도일` 중 최신 1건)은 `preload_tax_rates` RPC와 같은 의미론이라고 주석에 적혀 있다 — 따라서 §2의 폴백 실측은 운영 DB 동작과 같다 [해석: RPC 본문은 조회하지 않음].

## 7. 결정 · 구현 결과 (2026-11-11)

결정: **Q-1 a · Q-2 a**(모두 권장안), Q-3 운영 DB 쓰기 없음. **세액·감면액·DB는 바뀌지 않는다.**

- **엔진:** `transfer-tax-reductions-calc.ts`에 순수 함수 `selfFarmingRuleMissingNotice({isUnregistered, reductions, selfFarmingRules})` — 자경농지 감면이 입력됐는데 규칙이 없으면 고지 문구를 돌려준다(미등기·규칙 있음·감면 없음·자경 외 감면은 `undefined`). 문구는 법령 상수 `TRANSFER.REDUCTION_SELF_FARMING`(조특법 §69)·`TRANSFER.REDUCTION_ANNUAL_LIMIT`(조특법 §133)로 인용하고 «확인 필요»를 붙인다. `unregisteredReductionNotice`와 같은 패턴이다.
- **배선:** `transfer-tax.ts` — 메인 `warnings`에 싣고, 다필지 조기반환 경로가 쓰는 `withUnregisteredNotice`의 `extra`에도 넣었다. 파일은 785줄(800 미만).
- **의도적 미배선:** 겸용주택 사후 세액 경로(`transfer-tax-mixed-use-totals.ts`)는 **고지를 싣지 않는다.** 이 경로의 픽스처는 기준시가 입력이 무거운 데다 «농지 자경 감면 + 겸용주택»이 현실적 조합이 아니고, 테스트 없는 배선을 남기지 않기 위해 되돌렸다. 거기서는 조용한 0이 그대로 남는다(V-7).
