## 1. 현행 사실 (실측)

### 1.1 사건 모델과 «직전 재산세 구분»의 의미

- 사건 종류는 `"building_built" | "building_removed"` 둘뿐(`lib/tax-engine/non-business-land/land-usage.types.ts:308`). 행 모양 `{kind, date, propertyTaxTypeBefore}`(`lib/stores/calc-wizard-asset-nbl-other.ts:41-45`).
- `propertyTaxTypeBefore` = «그 사건이 닫는 건축물 구간의 재산세 구분». 철거 행에서만 뜻이 있다(`land-usage.types.ts:315`). 건축물 구간의 구분은 **그 구간을 닫는 철거 사건의 값**(`other-land-state-history.ts:197-201`), 신축 전 나대지는 **종합합산 고정**(V-6, 같은 파일 `:168` 주석 · 조립 `:197-199`), 꼬리(양도일 현재) 구분은 현행 입력 `nblOtherPropertyTaxType`(`:202`, 미리보기 `nbl-other-state-history-preview.ts:61`은 `|| "comprehensive"`).
- ⇒ M12(건물 불변 · 별도합산 → 종합합산)는 **«변경 직전 구분 = 별도합산»을 가진 행이 있으면** `[소유 시작, 사건일)` 구간이 별도합산이 되고 꼬리가 현행 선언(종합합산)이 되어 표현된다. **철거 행의 의미(직전 구분)를 그대로 확장한 것이 (A)다.**

### 2.2 사용자가 «언제 이 입력이 필요한지» 인지하는 경로 (발견성)

- 현행 질문은 «건축물이 새로 생기거나 없어진 적»만 묻는다 → 건축물이 그대로인 M12 사용자는 «바뀐 적 없습니다»를 고르고 지나간다. **질문 문구를 확장해야 입구가 열린다**(UQ-2).
- **질문 문구(제안)**: 「소유기간 중 이 토지 위 건축물이 새로 생기거나 없어진 적, 또는 재산세 과세 구분(고지서의 과세구분)이 바뀐 적이 있습니까?」
- 옵션 설명(제안 — 덧붙이기만):
  - 바뀐 적 없습니다: 「소유기간 내내 양도일 현재와 같았습니다(건축물이 계속 있었거나 계속 없었고, 재산세 과세 구분도 같았습니다).」
  - 바뀐 적 있습니다: 「건축물을 새로 지었거나 철거·멸실된 적, 또는 재산세 과세 구분이 바뀐 적이 있습니다 — 아래에 사건을 입력합니다.」
  - 모름: 현행 문구 + 「재산세 과세 구분 이력」 포함(UQ-2).
- **위험**: 기존 저장·세션의 `unchanged`는 «건축물 불변»이라는 좁은 질문에 답한 값이다. 확장 후 그 답이 «재산세 구분도 불변»으로 **읽힌다**. 판정은 byte-identical(엔진은 `unchanged`를 현행으로 처리)이라 숫자는 안 바뀌고, 엔진 고지 `NBL_STATE_HISTORY_UNCHANGED_NOTICE`(`lib/tax-engine/nbl-confirm-notices.ts:47-50`)가 이미 «재산세 분류는 양도일 현재 값을 소유기간 전체에 적용»을 말한다 → 그 문장을 **지우지 말고 유지**(UQ-2 · §5 R-5).
