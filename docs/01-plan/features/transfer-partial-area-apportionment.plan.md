## 1. 결함 — `partial`에 면적/가액 안분 로직이 없다

`areaScenario === "partial"`(일부 양도)은 취득·양도 면적을 각각 받지만(validate 불변식: 취득 ≥ 양도), **엔진에 안분 로직이 없다**. `areaScenario`는 API까지 전달되지만(`transfer-tax-api-helpers.ts:341`) 엔진이 소비하지 않는다.

결과: 취득측 값은 **취득 전체**, 양도측 값은 **양도분**으로 계산돼 환산취득가 비율이 왜곡된다.

### 1.1 영향 경로 (실측)

| 경로 | 취득측 면적 | 양도측 면적 | 근거 | 왜곡 |
|---|---|---|---|---|
| `building` 일괄 (축 B 연면적) | `acquisitionArea` | `transferArea` | `CompanionAcqPurchaseBlock.tsx:621,645` | 🔴 → **F1 β-2가 소멸시킴** |
| `land` 일괄 (축 A 토지) | `acquisitionArea` | `transferArea` | `StandardPriceInput` `isAreaMode`(`toPropertyKind("land")→"land"`) | 🔴 |
| `housing` 토지·건물 분리 (축 A) | `acquisitionArea` | `transferArea` | `LandBuildingSplitSection.tsx:141` ↔ `TransferStdPriceCards.tsx:56~57,67` | 🔴 |
| 다필지 (환지 아님) | `parcel.acquisitionArea` | `parcel.transferArea` | `multi-parcel-transfer.ts:349~350` | 🔴 |
| **다필지 감환지** | **의제취득면적 안분** | `parcel.transferArea` | `multi-parcel-transfer.ts:326` | ✅ **대조군** |
| `housing` 일괄 | — | — | `toPropertyKind("housing")→"house_individual"` → `isAreaMode=false`(총액 직접) | ✅ 해당 없음 |

**대조군이 결정적이다** — 다필지 **감환지**는 이미 안분한다:
```ts
// multi-parcel-transfer.ts:326
acqArea = (priorLandArea * allocatedArea) / entitlementArea;   // 의제취득면적
```
코드베이스는 이 패턴을 이미 알고 있고, 일반 `partial`에만 없다.

### 1.2 수치 — 축 A (취득 300㎡ · 양도 100㎡ · 취득 ㎡당 50만 · 양도 ㎡당 150만 · 양도가액 9억)

| | 취득 기준시가 | 양도 기준시가 | 환산비율 | 환산취득가 | 양도차익 |
|---|---|---|---|---|---|
| **현행** | 150,000,000 (300㎡) | 150,000,000 | **1.0** | **900,000,000** | **0** 🔴 |
| 안분 시 | 50,000,000 (100㎡) | 150,000,000 | 1/3 | 300,000,000 | 600,000,000 |

**양도차익 6억 차이.** 면적비가 단가비를 상쇄해 두 기준시가가 우연히 같아지는 것이 문제의 본질이다.

### 1.3 환산 모드는 왜곡이 자동이고 회피가 어렵다

`StandardPriceInput.tsx:129~152` — `handlePricePerSqmChange`·`handleAreaChange` **둘 다** 총액을 자동 재계산한다(`onTotalPriceChange(String(Math.floor(sqm * areaNum)))`). 사용자가 총액을 수동 편집하지 않는 한 왜곡을 피할 수 없다.

### 1.4 선행 설계 문서 주장 정정

[`transfer-asset-area-basic-info.engine.design.md:213`](../../02-design/features/transfer-asset-area-basic-info.engine.design.md):

> **함의**: 면적이 안분 키로 직접 쓰이는 곳은 **다필지(`parcels[]`) 경로 단독**이다. … 자산-수준 `partial` 불변식이 없어도 그동안 안분 왜곡이 드러나지 않았다.

🔴 **부정확하다.** 자산-수준에서도 면적이 **기준시가 총액의 곱셈 인자**이고 그것이 환산취득가 비율을 만든다. "안분 비율"로 직접 쓰이지 않을 뿐, 세액에 도달하는 경로는 있다.

## 2. 두 모드는 성격이 다르다 (U-9)

| | 환산(기준시가) 모드 | 실거래가 모드 |
|---|---|---|
| 취득측 값 산출 | **시스템 자동** — `floor(단가 × acquisitionArea)` | **사용자 직접 입력** — `fixedAcquisitionPrice` |
| 엔진 면적 안분 | 없음 | 없음 (`transfer-tax-api-helpers.ts:474` — 지분 `applyRatio`만) |
| 사용자가 정답을 넣을 수 있나 | ❌ 총액 수동 편집해야 | ✅ 양도분 대응 가액을 넣으면 정답 |
| 안내 존재 | 없음 | **없음** — 라벨 "취득가액 (원)" · hint `undefined`(`CompanionAcqPurchaseBlock.tsx:509~527`) |

수치(취득 300㎡·양도 100㎡, 취득가액 3억, 양도가액 2억): 전체 취득가액을 그대로 넣으면 양도차익 **−1억(손실)**, 안분 시 **+1억** → **2억 차이**.

**대조**: 다필지 경로는 라벨에 "**총** 취득면적"을 명시한다(`transfer-tax-validate-asset.ts:77`). 자산-수준은 "취득 당시 면적"이라 총량인지 대응분인지 알 수 없다.

### 2.1 코드베이스의 자동 스케일 허용 기준

| 선례 | 처리 | 근거 |
|---|---|---|
| 지분: `applyRatio(fixedAcqRaw, ratio)` (`transfer-tax-api-helpers.ts:492`) | **자동 스케일** | 같은 물건의 지분이므로 가액이 지분에 **정의상 비례** |
| 부담부증여 채무: ×지분율 (`BurdenedGiftBlock.tsx:101`) | **자동 금지** | 주석 원문: "물건 전체 채무를 ×지분율로 쪼개면 **자동 안분 fallback 정책 위반**" — 채무는 당사자 약정이라 비례 보장 없음 |

→ 「자동 안분 fallback 금지」는 무조건 금지가 아니라 **비례 근거 없는 안분을 금지**하는 규칙이다.

## 3. 법령·심판례 (U-10·U-11) — KoreanLaw 실측 2026-07-30

### 3.1 조문 — 「소득세법 시행령」 제176조의2 제2항 제2호 (MST 286211, 시행 2026-07-01)

> 환산가액 = 양도당시의 실지거래가액 × (**취득당시의 기준시가** / 양도당시의 기준시가)

조문은 **면적을 언급하지 않는다.** "취득당시의 기준시가"는 「소득세법」 제114조 제7항 문맥상 **양도자산의** 것이며, 일부양도에서는 양도한 부분이 그 자산이다.

관련: 「소득세법」 제100조 제2항 후문 — "공통되는 취득가액과 양도비용은 해당 자산의 **가액에 비례**하여 안분계산한다."

### 3.2 심판례 3건 — 채택·배척이 갈린다

| 재결 | **채택된** 안분 기준 | 배척된 것 |
|---|---|---|
| **국심1992서2655** (1992.09.09, 기각) | **면적비** — 이유: "**기준시가가 동일하므로** 면적비율로 안분" | 청구인의 감정가액 안분(그 감정가액이 "합리성을 결여하고 비현실적") |
| **국심2005구1458** (2005.08.31, 기각) | **감정가액** — 법원 토지매각허가 감정, 신빙성 有. "2002년도 **개별공시지가보다는 감정가액으로** 안분계산하는 것이 타당" | 청구인의 **면적** 안분 |
| **조심 2018부0572** (2018.05.03, 기각) | **취득 당시 기준시가** — "각 필지별 실지취득가액이 **불분명한 경우**, 전체 토지의 실지취득가액을 **각 필지의 취득 당시 기준시가 비율로 안분**하는 것이 합리적" | 청구인의 **양도 당시** 감정평가액 안분 |

조심 2018부0572 사실관계: 분할전토지 1,134㎡를 2005년 취득 → 2017년 분할된 **644㎡를 양도(수용)**. 매매계약서에 쟁점토지·잔여토지 가액이 구분되지 않았고, 취득 당시 공시지가가 **동일**했다.

### 3.3 도출 제약

| # | 제약 |
|---|---|
| **L-1** | 안분 기준은 **면적비가 아니다.** 1992서2655가 면적비를 인정한 것은 "**기준시가가 동일하므로**"이고, 2005구1458은 면적 안분을 **부인**했다. 면적비는 독립 기준이 아니라 기준시가가 동일할 때의 특수 케이스다 |
| **L-2** | 안분은 **실지취득가액이 불분명한 경우의 보충 방법**이다(2018부0572 "불분명한 경우"). 계약서에 구분 기재돼 있으면 그 값을 쓴다 → **무조건 자동 안분 금지** |
| **L-3** | **양도 당시** 가액을 취득가액 안분 기준으로 쓰는 것은 배척된다(2018부0572 — "토지조서상 평가가액은 취득 당시의 가액이 아닐 뿐만 아니라") |
| **L-4** | 환산 분자는 **양도한 부분의** 취득 당시 기준시가다("각 필지의 취득 당시 기준시가"). 부분별 단가가 같으면 면적비 적용과 수학적으로 동치(anchor 고정) |
| **U-11** | **필요경비도 취득가액과 동일 기준**으로 안분한다 — 2005구1458이 "취득가액 **및 필요경비**를 감정가액으로 안분"을 인정. 「소득세법」 제100조 제2항 후문("가액에 비례")과 정합 |

**종합 원리**: 안분 기준은 고정 서열이 아니라 **「취득 당시 각 부분의 상대가치를 가장 신빙성 있게 반영하는 값」**이다. 취득 당시 신빙성 있는 감정가액이 있으면 그것, 없으면 취득 당시 기준시가, 기준시가가 동일하면 결과적으로 면적비.

## 4. UI 설계 방향

```
취득가액이 양도분·잔여분으로 구분되는가?          ← 반드시 물어야 한다 (C-7)
  ├ 예   → 양도분 취득가액 직접 입력 (우선 — L-2)
  └ 아니오 → 안분 기준 선택
       ├ 취득 당시 감정가액 (있는 경우 — L-1·C-3 ①)
       └ 취득 당시 기준시가 (기본 — C-3 ②)
              ※ 부분별 단가가 동일하면 결과가 면적비와 같다

※ 양도 당시 가액(감정가·실거래가) 기준 안분은 제공하지 않는다 (L-3·C-4)
```

환산 모드에서는 취득 기준시가 산정 시 **양도한 부분의 면적·단가**를 쓴다(L-4·C-6).

**지분과의 합성 주의**: 취득 기준시가·취득가액에 부분 비율을 적용하면 지분 `applyRatio`와 **곱셈 합성**된다(지분 × 부분비). 이중 적용·순서 오류가 나기 쉬우므로 anchor로 두 축의 합성을 고정해야 한다.

## 5. 단계 제안 (미착수)

```
B4-1  환산 모드 — 취득 기준시가를 양도분 기준으로 산정 (L-4)
      영향: land 일괄 · housing 토지·건물 분리 · 다필지(환지 아님)
      (building 경로는 F1 β-2가 이미 소멸시킴)

B4-2  실거래가 모드 — "취득가액 구분 여부" 2-state + 안분 계산기 (L-1·L-2·C-3)
      + 필요경비 동일 기준 안분 (U-11)

B4-3  지분 × 부분비 합성 anchor + 회귀
```

**채택하지 않은 안**: UI 파생(표시·계산 이원화를 만든다) · `partial` 폐지(`land` 일부양도라는 실제 거래 형태를 표현 불가로 만든다).
