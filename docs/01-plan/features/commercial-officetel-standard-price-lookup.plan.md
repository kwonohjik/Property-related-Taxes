## 2. 목표 / 비목표

**목표**
1. 자산 카드의 기존 `addressPnu` 하나로 해당 필지의 호 목록을 조회한다.
2. 호를 선택하면 **3시점 고시가 + 전용면적 + 공유면적**을 한 번에 채운다.
3. 로컬 파일로 동작하되, 나중에 원격 저장소로 옮길 때 변환 파이프라인을 재사용한다.

**비목표 (이번 범위 아님)**
- 수기 입력 필드 제거 — **금지**. 고시 대상이 전수가 아니므로 조회 실패가 정상 동작이다(§7-C).
- 엔진 산식 변경. 이 작업은 **엔진 무변경**이다(§5).
- `standard_prices` Supabase 테이블 사용. 미사용 상태 유지, 재설계는 배포 시점 과제.
- 상속·증여세 보충적평가 연동. 후속 별건.

`2-1/2-2` 분할, xlsx 5시트(50만행씩) 구조는 전부 **Excel 상한 1,048,576행** 때문이다(2019 2-1 = 1,048,576줄, 2023 각 시트 1,048,575행으로 상한에 정확히 걸림). 공공데이터포털 파일데이터 게시분은 **CSV와 함께 JSON 다운로드**를 제공하므로(2020-08-04 게시분에서 확인), 연도별로 JSON 경로가 있으면 분할본 병합 없이 전량을 받을 수 있다. Phase 1 착수 시 연도별로 확인해 **JSON 우선, 없으면 분할 CSV 병합**으로 처리한다.

**파서 강제 규칙 (실측 근거)**
1. **헤더명으로 코드/라벨을 판별할 수 없다** — 2019는 헤더가 `상가종류코드`인데 값은 코드다. **값 sniffing 필수**.
2. **번지·호는 `parseInt` 정규화 후 비교** — 2022의 zero-pad(`0080`)를 그대로 두면 §4-1 PNU 조인이 깨진다.
3. 컬럼명은 단위 접미사(`(원)`·`(m2)`)를 제거한 정규화 이름으로 매칭한다.

**분류코드표**(`상업용건물 및 오피스텔 기준시가 분류코드표(2018년).csv` 실측):
- 건물구분: `1`=상가 `2`=오피스텔 `3`=복합건물
- 특수지: `0`=일반지번 `1`=산 `2`~`9`=확정예정지번/구획정리/블록/구역/단지/무번지 `A`=해당없음
- 층구분: `1`=지하 `4`=지상 `5`=옥탑

### 3-6. 원본 데이터 오염 — 호 값 Excel 날짜 변환

전 연도 20,422,320행 중 **12,359행(0.061%)** 의 `호` 값이 Excel 날짜로 변환돼 있다 — `3-2` → `03월 02일`, `6-1` → `06월 01일`.

## 4. 아키텍처

### 4-1. 조인 키 — PNU 직행 (인덱스 불필요)

`AssetForm.addressPnu`가 **이미 존재**한다(`CommercialBuildingBlock.tsx:63`에서 건물 기준시가 모달에 전달 중). PNU 19자리 분해는 프로젝트 표준이 확립돼 있다 — `lib/geo/pnu-building-register.ts:30-34`:

```
PNU[0:10]  = 법정동코드   → CSV 법정동코드
PNU[10]    = 필지구분      → CSV 특수지코드 (1=일반 ↔ 0, 2=산 ↔ 1)
PNU[11:15] = 본번          → CSV 번지 (parseInt 정규화 후 비교)
PNU[15:19] = 부번          → CSV 호   (parseInt 정규화 후 비교)
```

⚠️ **`decomposePnuForBuildingRegister`의 `platGbCd` 사용 금지** — 그 값(`'0'`/`'1'`)은 건축HUB 규약 전용이며 CSV 특수지코드(0=일반/1=산)와 **값이 우연히 일치**해 더 위험하다. **raw `pnu[10]` 를 직접 읽어라** (memory `feedback_gov_site_lookup_weak_tls_pnu_params` 항목2).

### 4-2. 물건(호) 식별 키 — **층구분 필수 포함**

```
물건키 = (법정동코드, 특수지, 번지, 호, 건물명, 동, ★층구분★, 층, 호수)
```

⚠️ **층구분(지하/지상/옥탑)을 키에서 빼면 서로 다른 물건이 섞인다.** 2021년 전수 실측: 층구분 제외 키 1,560,153개 중 **5,772개(0.370%)** 가 같은 층·호에 층구분 2종 이상을 갖는다. 그 첫 사례가 이 계획서의 anchor 건물이다 —

```
적선현대빌딩 1층 1호 → 지상층(639.47㎡, 5,898,000원) · 지하층(7.18㎡, 2,485,000원)
```

단가가 **2.4배** 차이 나므로 층구분 누락은 환산취득가·세액에 직결된다.

⚠️ **건물명도 같은 이유로 키에서 뺄 수 없다.** 한 필지에 동(棟)이 다른 건물이 여럿 등록된다 — 건물명 제외 키 1,560,322개 중 **3,517개(0.225%)** 충돌:

```
필지 1126010200 129-19 · 지상층 2층 201호 · 동 "1(단일)"
  → 스마트빌A동 3,065,000원/61.15㎡  ·  스마트빌B동 3,063,000원/62.08㎡
```

`상가건물동주소`가 둘 다 `1(단일)`이라 **동으로 구분되지 않는다** — 건물명이 유일한 판별자다. 응답·목록 표시·선택 키 **전부**에 층구분과 건물명을 포함한다.

**✅ 키 안정성 실측 (층구분 포함, 전수)**

| 간격 | 기준 연도 키 | 공통키 | 매칭률 | 공통키 중 면적 동일 |
|---|---|---|---|---|
| 2년 (2019→2021) | 1,215,885 | 1,141,303 | **93.9%** | 99.67% |
| 8년 (2013→2021) | 823,331 | 544,180 | **66.1%** | 98.44% |
| 16년 (2005→2021) | 407,673 | 218,415 | **53.6%** | 96.67% |

적선현대빌딩: 2019 63키 **전부** 2021에 존재, 면적 100% 일치, 소멸키 0.

⚠️ **"호 1회 선택 → 3시점 전부 자동 채움"은 성립하지 않는다.** 실제 보유기간(8~16년)에서는 호 재편·건물 멸실·신축으로 **1/3~1/2이 매칭되지 않는다**. 특히 C-01 경로(2005 최초고시 ↔ 양도)의 매칭률이 가장 낮다.

**설계 요구**: 3시점 조회는 **시점별로 독립적으로 성공/실패**한다.
- 매칭된 시점만 채우고, 매칭 실패 시점은 **빈 값 + "해당 고시분에 이 호가 없습니다 — 수기 입력" 안내**
- **인접 호·유사 면적으로의 자동 대체 금지** (memory `feedback_no_silent_apportion_fallback` — 다른 호의 단가가 침묵 유입되면 환산취득가·세액 직결 오류)
- 응답 스키마는 이미 `prices: Record<noticeDate, {...} | null>`로 시점별 null을 표현한다(설계 §3-2)

층구분을 키에서 빼면 여기에 더해 지하↔지상 혼입이 겹친다(§4-2 상단).

**gitignore 패턴** — `/data/stdprice/*`는 상위 디렉터리 자체를 제외해 `!` 재포함이 불가능하다(기존 `/data/raw/*` + `!/data/raw/.gitkeep`이 동작하는 건 `.gitkeep`이 직속 자식이기 때문). 따라서:

```gitignore
/data/stdprice/
```
전체를 제외하고, **manifest도 커밋하지 않는다**(빌드 산출물). 클론 환경에서 실재하지 않는 데이터를 있다고 기술하는 모순을 피한다. UI가 필요로 하는 "이용 가능 고시일자"는 **API 응답으로** 제공한다.

**파티션 = 시군구 × 고시일자** 근거 (2021년 실측 gzip):

| 후보 | 파일 수 | 평균 | 중앙값 | 최대 |
|---|---|---|---|---|
| 법정동 × 고시일자 | ≈30,200 | ≈8KB | — | ≈230KB |
| **시군구 × 고시일자** | **≈2,550** | **98KB** | **73KB** | **354KB** (41135) |
| 시군구 × 전 연도 | 116 | 2.2MB | — | 7.8MB |

법정동 단위는 파일이 12배 많은데 최대 fetch는 별 차이가 없다(최대 법정동이 사실상 해당 시군구 전체). 시군구 단위가 균형점.

**총량 실측**: 2021년 1개 고시분 gzip **11.6MB**(행당 7.42B) → 22개 고시분 외삽 **≈255MB**.
포맷 4종 비교 결과 사전 인코딩은 10%만 절감(7.42→6.69B/행)하므로 **자기서술형 객체배열 JSON을 유지**한다.

파티션 레코드:
```jsonc
{ "b":"1111010700", "s":0, "bn":80, "jn":0, "nm":"적선현대빌딩",
  "dg":"1(단일)", "fc":4, "fl":"1", "ho":"1",
  "p":5898000, "ea":639.47, "sa":357.74, "k":1 }
```
`fc`=층구분(1지하/4지상/5옥탑), `k`=건물구분(1상가/2오피스텔/3복합). `bn`·`jn`은 parseInt 정규화 값.

### 4-4. 읽기 어댑터 (배포 대비 단일 교체 지점)

```ts
// lib/stdprice/load-partition.ts
export async function loadPartition(sigungu: string, noticeDate: string): Promise<StdPriceUnit[] | null>
```
구현체가 하나뿐이므로 interface + class 2단 구성은 만들지 않는다(Simplicity First). 내부에서 로컬 FS(`fs` + `zlib.gunzip`) + LRU 캐시로 처리하고, **원격 전환 시 이 파일 1개만 교체**한다. ≈255MB는 Vercel 번들에 못 들어가므로 배포 시 원격 전환은 필수다.

### 4-5. 조회 API

```
GET /api/address/commercial-standard-price?pnu={19자리}&dates=2005-01-01,2013-01-01,2021-01-01
```

```ts
export const runtime = "nodejs";   // fs·zlib 사용 — 형제 라우트 building-standard-price-etax/route.ts:9 선례
```

- 시군구 = `pnu.slice(0,5)` → 요청 고시일자별 파티션 로드 → 법정동·특수지·본번·부번 필터
- 응답 형식은 형제 라우트 규약(`building-standard-price-etax/route.ts:17-24`)에 맞춘다:
  `{ success, parcelReason?, dateStatus, units, availableDates, error? }` — 상세 스키마·판정 순서는 설계 문서 §3-2.
  형제 라우트의 `warnings: string[]`로는 3시점 각각의 상태를 표현할 수 없어 **의도적으로 확장**한다(HTTP 200·비차단은 동일).
- **strict-match-or-null 불변식**: 필터 매치 0건이면 **임의 fallback 금지 → 빈 결과 + 사유 반환**. 기존 구현에 확립된 패턴(`app/api/address/standard-price/route.ts:183-185` — "임의 세대로 fallback하지 않고 조회 실패(null) 반환"). 상가는 한 필지 최대 5,371행이라 동일 위험 (memory `feedback_apart_stdprice_dong_ho_required`).
- **사유 4종 분리 안내**: `no_notice`(고시 자체 없음 — 정상) / `partial_data`(자료 부분 결손 — 현재 해당 연도 없음, 향후 대비) / `partition_missing`(미변환) / `unit_not_found`(해당 호 없음). 병합 금지 — 부분 결손을 "고시 없음"으로 안내하면 침묵 오안내다.

**고시일자 선정 규칙 — ✅ 확정 (Phase 0-3 GREEN)**: 기준일(양도일·취득일) 이하 고시일자 중 **최대**.

법령 근거 (KoreanLaw MCP 원문 검증):
> **소득세법 시행령 §164③** — "법 제99조제1항제1호가목부터 라목까지의 규정을 적용함에 있어서 **새로운 기준시가가 고시되기 전에 취득 또는 양도하는 경우에는 직전의 기준시가에 의한다.**"

(오피스텔·상업용 건물은 법 §99①1호**다목** — §164⑩이 "법 제99조제1항제1호다목에서 '대통령령으로 정하는 오피스텔 및 상업용 건물'"로 확인)

**"고시" 시점 = 시행일 = 1월 1일**임을 국세청 고시문으로 확정했다:
> 「2025년 오피스텔 및 상업용 건물에 대한 기준시가 고시」 **국세청고시 제2024-39호, 2024. 12. 31. 제정, [시행 2025. 1. 1.]**

공포는 전년 12월 31일이나 **시행일이 1월 1일**이므로, §164③의 "고시되기 전" 경계는 기준일(1/1)과 일치한다. 따라서 `고시일자 ≤ 기준일 중 최대` 규칙이 §164③에 정합한다.

⚠️ **`recommendLandPriceYear()` 재사용 금지 (확정)** — `lib/utils/land-price-year.ts:22-36`은 `month <= 5 → year - 1`이다. 이는 **개별공시지가**가 기준일 1/1 · 공표 5/31 · **시행 6/1**이기 때문이다(memory `feedback_standard_price_year_164_3_prior`). 기준시가는 **시행 1/1**이라 보정이 없어야 한다. 그대로 쓰면 기준일이 1~5월인 **전건에서 1년 이전 고시분을 오선택**한다(양도일 2021-03-15 → 2020년분, 정답 2021-01-01분). 신규 `pickNoticeDate(availableDates, refDate)`를 별도 작성한다.

### ⑧ validation — §164⑥ 8필드 all-or-nothing 충돌 (Critical)

`lib/calc/transfer-tax-validate-asset.ts:110-127`은 상속 §164⑥ 경로(상속개시일 < 2005-01-01)에서 **8필드 all-or-nothing** 검증을 한다:

```
면적 3: cbExclusiveArea, cbSharedArea, cbLandArea
금액 5: cbUnitPriceAtFirstOrAcq, cbLandPricePerSqmAtAcq, cbLandPricePerSqmAtFirst,
        cbBuildingStdPriceAtAcq, cbBuildingStdPriceAtFirst
→ filled > 0 && filled < 8 이면 차단
```

모달이 채우는 건 이 중 **3개뿐**(`cbExclusiveArea`·`cbSharedArea`·`cbUnitPriceAtFirstOrAcq`)이다. 빈 상태에서 조회·적용하면 `filled = 3` → **즉시 검증 차단**된다. CLAUDE.md ⑧ "UI 통과 ↔ validate 차단 모순 금지" 정면 위반.

**대응**: 상속 배치 모달에 *"§164⑥ 적용에는 대지면적·개별공시지가 2시점·건물 기준시가 2시점을 추가로 입력해야 합니다"* 안내를 넣고, §8 성공 기준에 8필드 완성 시나리오를 포함한다. validate 로직 자체는 변경하지 않는다(법령상 all-or-nothing이 맞다).

## 7. 리스크 · 미해결

**A. 자료 상태 — 전 연도 완전본 확보 (조치 불요)**
1. ~~**2020년 결손**~~ — **✅ 해소. 결손이 아니었다(2026-07-28 정정).**

   `상업용건물_오피스텔 기준시가(2020년1월1일기준).zip`은 **zip이 아니라 CSV 텍스트**다(`file` 판정). 확장자만 `.zip`인 채 배포·저장된 파일이며, 그 실체가 바로 "없다"고 판단했던 **2-2 파트**다.

   | 2-1 | `…_2-1(재추출).csv` | 721,849 | 50 ~ 21232 |
   | 2-2 | `…(2020년1월1일기준).zip` (실체 CSV) | 721,852 | **21233** ~ 46196 |
   | **병합** | | **1,443,701** | 연속 확인 |

   **오진 원인**: 확장자를 신뢰해 zip으로 열다 `File is not a zip file`을 파일 손상으로 단정했다. → **§6 Phase 1 S1에 "확장자 불신, `file`/매직바이트로 실체 판별" 규칙을 추가**했다.
