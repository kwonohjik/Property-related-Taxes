## 1. 법령 확인 (KoreanLaw MCP 본문 · 2026-11-25 조회 — 확인)

### 1.1 영 §103의2 — 현행 본문 (MST 290815 · 시행 2026.10.1. · 조문 최종 개정 2025.12.31.)

> 제103조의2(철거ㆍ멸실된 건축물 또는 주택의 범위) 법 제106조제1항제2호다목에서 "대통령령으로 정하는 부속토지"란 **과세기준일 현재** 다음 각 호의 어느 하나에 해당하는 건축물 또는 주택의 부속토지를 말한다. 이 경우 「건축법」 등 관계 법령에 따라 허가 등을 받아야 하는 건축물 또는 주택으로서 허가 등을 받지 않은 건축물 또는 주택이거나 사용승인을 받아야 하는 건축물 또는 주택으로서 사용승인(임시사용승인을 포함한다)을 받지 않은 건축물 또는 주택의 부속토지는 제외한다.
> 1. 건축물 또는 주택이 사실상 철거ㆍ멸실된 날(사실상 철거ㆍ멸실된 날을 알 수 없는 경우에는 공부상 철거ㆍ멸실된 날을 말한다)부터 1년이 지나지 않은 건축물 또는 주택의 부속토지(건축물 또는 주택의 건축을 위한 용도 외의 다른 용도로 사용하는 부속토지는 제외한다). 이 경우 **건축물의 부속토지는** 철거ㆍ멸실되기 전 건축물의 바닥면적(건축물 외의 시설의 경우에는 그 수평투영면적을 말한다)에 제101조제2항에 따른 용도지역별 적용배율을 곱하여 산정한 면적 범위의 토지를 말한다.
> 2. 「빈집 및 소규모주택 정비에 관한 특례법」에 따른 빈집정비사업 또는 「농어촌정비법」에 따른 생활환경정비사업(빈집의 정비에 관한 사업만 해당한다)의 시행으로 빈집이 사실상 철거된 날(…)부터 3년이 지나지 않은 빈집의 부속토지. 다만, 건축물 또는 주택의 건축을 위한 용도 외의 다른 용도로 사용하는 부속토지는 제외하되, 법 제109조제2항 단서에 따른 재산세의 부과대상이 되는 부속토지로서 국가, 지방자치단체 또는 지방자치단체조합이 1년 이상 공용 또는 공공용으로 사용(1년 이상 사용할 것이 계약서 등에 의하여 입증되는 경우를 포함한다)하는 경우에는 그 공용 또는 공공용으로 사용하는 기간 동안의 그 부속토지는 포함한다.

(확인) 면적 범위 문장은 **«건축물의 부속토지»**에만 있다 — 주택 부속토지는 이 문장의 대상이 아니다(§1.4). 법 §106①2호 다목(확인): «철거ㆍ멸실된 건축물 또는 주택의 부속토지로서 대통령령으로 정하는 부속토지»가 별도합산과세대상.

> ① … 다음 각 호의 어느 하나에 해당하는 건축물의 부속토지를 말한다. 다만, 「건축법」 등 관계 법령에 따라 허가 등을 받아야 할 건축물로서 허가 등을 받지 아니한 건축물 또는 사용승인을 받아야 할 건축물로서 사용승인(임시사용승인을 포함한다)을 받지 아니하고 사용 중인 건축물의 부속토지는 제외한다. <개정 2010.12.30, 2016.12.30>

### 1.4 판단이 갈리는 법문 읽기 (이 계획서의 해석 — 확인 필요 아님, 법문 그대로)

- **주택 철거 부속토지**는 법 §106①2호 다목으로 **별도합산**이다(재산세 3분류에서 «주택분»이 아니다 — 주택은 철거돼 없다). 1호 «건축물 또는 주택»·2호 «빈집(주택)» 모두 **별도합산 한시 지위**를 준다.
- 1호 후단 면적 범위 문장은 «건축물의 부속토지»에만 → **주택 철거는 배율 한도가 없다.** 주택 부속토지 범위는 법 §106②·영 §105(경계 불명 시 바닥면적 10배 — 확인: 현행 본문)가 정한다. 양도세 쪽도 같은 결론(주택 행 면적 칸 없음 — NBL v4 §5.7).
- 2호 «빈집» = 빈집법 §2①1호(확인): «시장ㆍ군수등이 거주 또는 사용 여부를 확인한 날부터 1년 이상 아무도 거주 또는 사용하지 아니하는 **주택**(미분양주택 등 제외)». → **빈집은 주택만**(비주택 건축물 철거에는 3년 연장이 없다). 빈집정비사업 = «빈집을 개량 또는 철거하거나 효율적으로 관리 또는 활용하기 위한 사업»(§2①2호 — 확인). 현행(2026.7.1. 시행본) 정의만 열람(V-5).
- 법 §109② 단서(확인): 국가 등이 1년 이상 공용·공공용으로 사용(계약서 등 입증 포함)하는 재산은 **재산세 비과세**, 단 **유료 사용 · 소유권 유상이전 약정 선사용**은 부과. → 영 §103의2 2호 단서의 «법 제109조제2항 단서에 따른 재산세의 부과대상» = **유료 사용 등**이라 «공용 사용 ∧ 유료»일 때만 단서로 포함. **무상 공용 = 비과세**(별도합산도 아님 — 재산세 0).

1. **허가·사용승인·건축 외 용도·빈집·단서 = 없음.** 무허가 건축물을 철거해도, 철거 후 주차장으로 써도 별도합산으로 계산된다.

### 5.3 판정 모델 — 과세기준일 한 점

양도세는 «철거일부터 일 단위 창»이지만 재산세는 **과세기준일 `s`에서 한 번** 판정한다(법문 «과세기준일 현재»).

```
judgePropertyDemolishedLand({ taxBaseDate: s, removedOn: r, kind, facts, landArea, floorArea?, zone? })
  0) r > s            → 호출자 차단(Q-11) — 철거 전 건축물이 현존하므로 본 경로 판정 대상
  1) W = demolishedStatusPeriodMonths(s, vacantYes)        // 0이면 한시 규정 없음
       W == 0         → fold "not_yet"                      // s < 2016.6.1. (기존 동작 유지)
  2) isWithinPeriodMonths(r, W, s) 아니면 → fold "period"   // 만료일 당일 포함(민법)
  3) s ≥ 2019.6.1.:  permit == "yes" 아니면 → fold "permit"          // no/unknown/"" 
  4) s ≥ 2024.6.1.:  otherUse == "no" 이거나(아래 단서) 아니면 → fold "other_use"
       단서(2호 · kind=house ∧ vacantHouse=yes): otherUse=="yes" ∧ publicUse=="yes" ∧ publicUsePaid=="yes" → 통과
       publicUse=="yes" ∧ publicUsePaid=="no" → fold "other_use" + 비과세(§109②) 가능성 고지
  5) 면적: kind=="building" ∧ s ≥ 2024.6.1.  → recognized = min(landArea, floorArea × 배율), excess = landArea − recognized
           그 외(주택 · 2024.6.1. 전 건축물)       → recognized = landArea(전체), excess = 0  + 부속토지 범위 확인 필요 고지
  6) holds {recognizedArea, excessArea, periodMonths: W, notes}
```

- **«모름»·«아니오»·미충족 = 혜택 불성립**(종합합산 이관 + 확인 필요). 단 **빈집정비 «아니오»·«모름»은 접힘이 아니라 일반 W 적용** + «3년 연장 불인정 — 확인 필요» 고지(NBL v4 §5.7 — 1호는 «빈집정비사업» 요건이 없으므로 빈집 여부를 몰라도 1호는 성립).
- **엔진 직접 호출에서 요구 칸이 `""`(미선택)이면 `yes`가 아니므로 접힘**(throw 없음) — 입구 차단은 Zod ⑫·⑧이 맡는다(UI 문서 E-9와 같은 읽기).
- 판정 순서(접힘 사유 우선순위): 기간 → 허가 → 건축 외 용도 → (면적은 접힘이 아니라 분리). 사유별 고지 문구가 다르다.
- 면적(5): 재산세 법문이 **«면적 범위의 토지»**(= 범위 안 별도합산 + 초과분 종합합산)라 NBL처럼 «부분이면 구간 전체 접힘»이 **아니다**(Q-4). 이는 «자동 안분 fallback»이 아니라 법문이 정한 분할이며 현행 동작과 같다.
- 2호 단서는 **한 점**으로 본다: 현행 문언 «그 공용 또는 공공용으로 사용하는 기간 동안의 부속토지»는 과세기준일 `s`가 사용 기간 안일 때 성립하므로 «과세기준일 현재 국가 등이 사용 중 + 1년 이상(또는 계약서 입증)» · «유료·유상이전 약정 선사용(재산세 부과)» 2칸으로 충분하다(Q-6).
- 단서 2칸·허가·건축 외 용도·빈집정비의 «yes/no» 의미는 §5.5.

### 5.4 요구 술어 — 단일 소스

```ts
propertyDemolishedRequired({ taxBaseDate: s, removedOn: r, kind })
  → { permit, otherUse, vacantHouse, floorArea /*= zone 포함*/ } : boolean
```
- `r` 없음·Invalid Date·`kind` 없음·`r > s` → 전부 `false`(날짜·종류 결함이 먼저 — ⑧이 «철거일/종류를 입력하세요»를 말한다).
- **한시가 가능한 과세기준일일 때만** 칸을 묻는다: `s`가 «최대 W»(주택: 빈집 3년 가능 시 36개월, 건축물: `demolishedStatusPeriodMonths(s,false)`) 안에 없으면 모든 사실이 판정을 못 바꾸므로 4칸 전부 `false`(= 기간 초과면 요건을 묻지 않는다 — «엔진이 읽는 칸만 요구»). `W == 0`(2016.6.1. 전)도 `false`.
- `permit` = `demolishedPermitClauseApplies(s)` · `otherUse` = `demolishedOtherUseClauseApplies(s)` · `vacantHouse` = `kind==="house" ∧ demolishedVacantHouseClauseApplies(s)` · `floorArea` = `kind==="building" ∧ demolishedAreaClauseAppliesOn(s)`(zone도 함께 — Q-8).
- `propertyDemolishedPublicUseAsked(need, facts)` = 답 의존 사슬: `need.otherUse ∧ need.vacantHouse ∧ otherUse=="yes" ∧ vacantHouse=="yes"` → `publicUse` 칸 열림 → «yes»이면 `publicUsePaid` 칸 열림(NBL `demolishedPublicUseAsked`와 같은 구조 — 날짜 칸 2개가 없다).
- **이 두 함수가 ⑤ 표시 · ⑧ 차단 · ⑫ 400 · ④ 운반 · 엔진 읽기의 유일한 술어**다. 엔진은 요구되지 않은 칸을 **읽지 않는다**(숨은 stale 값이 판정을 바꾸지 못함).
- 과세기준일 `s`: `resolvePropertyTaxBaseDate(targetDate?, now)` 1개(엔진 `property-tax.ts:376-377` · route `:89` · ⑧이 각자 `new Date().getFullYear()`로 따로 구해 서버 시간대에 흔들릴 수 있다 — `lib/tax-engine/CLAUDE.md` UTC 달력 규칙) — 세 곳이 같은 함수를 부른다. 화면은 `targetDate`를 안 보내므로 `s` = 올해 6.1.(Q-10).

- 본 경로 허가 칸(Q-2 채택 시): 비철거 `buildingPermit`(`yes`/`no`/`unknown`) — 요구 조건 `s ≥ 2011.6.1.` ∧ 별도합산 건축물 부속토지(`!demolished`). 의미: `yes` = 허가·사용승인(임시 포함)을 받았거나 불요 · `no` = 받아야 하는데 받지 않고 **사용 중**(영 §101① 단서 «사용승인을 받지 아니하고 사용 중인»). 판정: `s ≥ 2011.6.1.`에서 `buildingPermit != "yes"` → 종합합산 접힘 + 확인 필요(공장용·영업용 공통).

### 13.2 합산 단위 — 법문 정정 (확인: 법 §113① MST 282559)

> ① … 1. 종합합산과세대상: 납세의무자가 소유하고 있는 **해당 지방자치단체 관할구역에 있는** 종합합산과세대상이 되는 토지의 가액을 모두 합한 금액을 과세표준으로 하여 제111조제1항제1호가목의 세율을 적용한다. 2. 별도합산과세대상: … 해당 지방자치단체 관할구역에 있는 별도합산과세대상이 되는 토지의 가액을 모두 합한 금액 … 나목의 세율 …

→ **재산세 합산은 «인별 전국»이 아니라 «납세의무자 × 해당 지방자치단체 관할구역»**이다(전국 합산은 종부세). 코드의 «인별 전국 합산» 서술(`separate-aggregate-land.ts` 머리 주석 · `PROPERTY_SEPARATE.PERSONAL_AGGREGATION` · `property-tax-comprehensive-aggregate.ts` 머리 주석)은 이 법문과 어긋난다 — 종부세 쪽 `comprehensive-land-parcels.ts`는 «재산세 합산 단위(과세권자) … 관할구역별 그룹»으로 **맞게** 구현돼 있다(확인). 이 계획의 입력 칸 라벨·고지는 «**같은 지방자치단체 관할구역**»을 쓴다(Q-13·Q-17).

### 13.3 설계

**(a) 새 순수 leaf** `lib/tax-engine/property-land-split-tax.ts` (DB 없음 · `property-tax.ts` 800줄 정책상 배선 ≤ 40줄만 본체에):

```ts
calculateLandClassTax(i: {
  taxYear: number;                       // 과세기준일 연도 → 세율 세트·FMR
  separateOwnValue: number;              // 이 필지의 별도합산 인정 공시가액(원)
  comprehensiveOwnValue: number;         // 이 필지의 종합합산(이관분 + 직접 선택) 공시가액
  otherSeparateValue?: number;           // 같은 관할구역 타 별도합산 토지 공시가액 합계 (필수 여부는 술어)
  otherComprehensiveValue?: number;
  rates?: TaxRatesMap;                   // FMR — DB tax_rates 우선 · 상수 fallback (calcTaxBase)
  cap?: { mode: "direct"|"recompute"; previousYearTax?: number; previousYearTaxBase?: number; priorYear: number };
  isUrbanArea: boolean; publishedPrice: number;
}): LandClassTaxResult
```
분류 `c ∈ {separate, comprehensive}`마다 같은 4단계:
1. **합산 가액** `V_c = own_c + other_c` → **합산 과세표준** `B_c = calcTaxBase(V_c, "land", rates, {taxYear})`(FMR 70% — DB 행 우선 · `applyFairMarketRatio` 정수 분수 · 절사 규정 없음).
2. **합산 산출세액** `T_c` = 별도합산: 영 §111①1호 나목 3구간(`rateSet.landSeparateAggregate`) · 종합합산: 가목 3구간(`rateSet.landComprehensive`) — `getPropertyRateSet(taxYear)`(연도 키 · 현재 2005 세트). 구간표: 별도합산 2억/10억 · 0.2/0.3/0.4% · 공제 20만/120만, 종합합산 5천만/1억 · 0.2/0.3/0.5% · 공제 5만/25만(확인 — `property-rate-history.ts:55-90`).
3. **이 필지 몫** `S_c = floor(T_c × own_c / V_c)`(`own_c = 0`이면 0 · `other_c = 0`이면 `S_c = T_c` 그대로). 마지막 잔여 귀속 없음 — 잔여는 합산에 포함된 «다른 토지»의 몫이다.
4. **세부담상한**(Q-15) — 이 필지 합계 `S = S_sep + S_comp`에 적용(아래 (d)).
- 합계: `determinedTax = S(상한 후)`. **부가세는 현행 `calcSurtax`를 그대로 호출**(Q-18): `calcSurtax(determinedTax, ownTaxBase = floor-FMR(own_sep) + FMR(own_comp), publishedPrice, "land", isUrbanArea)` — 지방교육세 = `determinedTax × 20%`(`applyRate`) · 도시지역분 = 이 필지 **자기 과세표준** × 0.14%(선형이라 합산 무관). 분납(`calcInstallment`)·`buildTaxpayerOutcome`(공유지분·납세의무자)는 **합계 `determinedTax`·`totalPayable` 기준으로 그대로**(변경 없음).

**(b) 결과 타입** `PropertyTaxResult.landSplit?`(optional echo — 판정·합계는 최상위 필드가 유지):
```
landSplit: {
  separate?:     { ownValue, otherValue, combinedTaxBase, combinedGrossTax, share, appliedRate, progressiveDeduction, ownTaxBase },
  comprehensive?:{ ownValue, otherValue, combinedTaxBase, combinedGrossTax, share, appliedRate, progressiveDeduction, ownTaxBase,
                   transferReasons: Array<"no_building"|"demolished_period"|"permit"|"other_use"|"area_excess"|"public_use_unpaid"|"direct_type"> },

  jurisdictionBasis: "관할구역 합산"    // 라벨

```
최상위 `taxBase` = 이 필지 자기 과세표준(별도합산분 + 종합합산분 — 현행 별도합산 단독 경로에서는 별도합산분만이었다), `calculatedTax`·`determinedTax`·`totalPayable` = **합계**. `appliedRate`는 누진이라 0 유지. 이관 사유 echo는 §5.6 `demolishedVerdict.foldReason`·`excessArea` 사유(`area_excess`·`no_building`)를 분류 매핑 1곳에서 만든다.

**(c) 입력(와이어) — Q-13 추천**
| 칸 | 값 | 요구 술어 `propertyLandSplitRequired(verdict, landTaxType)` |
|---|---|---|
| `otherSeparateAggregateValue` | 원, **0 이상 정수**(0 = «없음» 명시) | `separateOwnValue > 0`(= 이 필지가 별도합산분을 가질 때) — 철거·면적 접힘으로 전량 이관이면 **비요구** |

- 둘 다 **«같은 지방자치단체 관할구역에서 이 필지 외 소유한 해당 과세대상 토지 공시가액 합계»**. 기본값 0 금지(빈칸 = ⑧ 차단 + ⑫ 400 — 자동 안분·자동 0 fallback 금지). 요구되지 않은 칸은 엔진이 **읽지 않는다**(stale 무해).

**(d) 세부담상한(§122 · 영 §118) — Q-15 추천**
- 상한 = `floor(직전 연도 세액 상당액 × 150%)`, 합계 본세가 이를 넘으면 상한액을 징수세액으로 한다(현행 `applyBurdenCap` 의미 그대로).
- **직전 기준**: ① **recompute**(`taxCapMode = "recompute"` + `previousYearTaxBase`): 직전 과세표준을 **분류 면적 비례**로 나누고(`prior_c = previousYearTaxBase × area_c / landArea` — 개별공시지가가 필지 내 균일하므로 면적 비례는 정확) 영 §118①1호 다목에 따라 **이 연도 분류의 직전 연도 세율**로 재산정(`rate_c(prior_c)`; `getPropertyRateSet(priorYear)`). ② **direct**(`previousYearTax`): 분류 변경이 없는 일반 입력(이관 0)에서만 현행 그대로. **이관분 > 0 + direct**이면 상한 미적용 + 고지(영 §118①1호 다목 — 직전 실제 세액이 이 연도 분류의 기준이 아닐 수 있음 — **확인 필요**).
- 현행 UI는 `isRecomputeTarget`(건축물·선박·항공기·**종합합산 토지**)만 recompute를 제공한다(`Step3.tsx:62-70`) — 별도합산 토지는 direct만. 이관 가능 입력(별도합산 선택)에도 recompute를 열려면 UI Step3 조건 확장이 필요하다(UI 문서 §).
- 합산 입력이 있을 때 직전 기준에 «타 토지 합산 효과»를 넣는지는 **확인 필요**(V-18) — 이 설계는 **이 필지 단독** 직전 세액(합산 효과 제외)으로 비교하고 `other*Value > 0`이면 «직전 기준은 이 필지 단독 계산 — 확인 필요» 고지.

**(e) FMR·세율·연도(과세기준일 기준)** — `taxYear` = `resolvePropertyTaxBaseDate`(§5.4) 연도. FMR = `calcTaxBase(…, rates, {taxYear})` 하나로 **두 분류 통일**(현행 별도합산의 상수 0.70은 DB 행이 0.70일 때 값이 같고 DB가 바뀌면 달라지는 이중 소스 — V-19). 세율 = 연도 키 상수 세트(DB `tax_rates`가 아님 — «DB tax_rates 또는 기존 상수»의 후자). **DB 마이그레이션 없음.**

**(f) `calculateSeparateAggregateTax` 변경 없음** — 반환값 `totalExcessOfficialValue`(+필지별 `landChecks`)를 새 leaf가 입력으로 받는다. 다필지 합산·지자체 안분 내부 로직은 손대지 않는다(Q-17 (가)).

### 13.8 종합부동산세 영향 (확인)

- 종부세 토지분은 **이 계산기의 별도합산·이관 판정을 읽지 않는다.** `comprehensive-tax.ts`가 `calculatePropertyTax`를 부르는 곳은 **`objectType: "housing"` 두 곳**(`:248` · `:292`)과 주택 세부담상한 모듈뿐이고, 토지는 `comprehensive-land-adapter.ts` → `comprehensive-land-parcels.ts`(`calcLandParcelsPropertyTax`)의 **자체 필지 모델**(`LandParcelInput` — 사용자가 필지별 `kind: aggregate | separate`를 직접 지정, 관할구역별 그룹·표준세율·§122 Min)이다. `landTaxType`·`separateAggregateItem`·`isSeparateAggregateLand`는 `comprehensive*` 파일에서 **0건**(grep).
- 따라서 이 계획(요건 판정 + 이관분 세액 + 합산 입력)은 **종부세 입력·결과·종합합산 5억 공제에 영향이 없다.** 종부세에서 철거 토지·무허가 건축물의 분류를 어떻게 입력하는지는 사용자 선택에 달려 있어 별도 문제(V-13).
- 한 방향 의존(comprehensive → property)도 지킨다: 새 leaf는 `property-tax.ts`가 소비하고 `comprehensive-*`는 import하지 않는다.
