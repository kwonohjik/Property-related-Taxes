### 1.3 «과세기간 단위 판정 × 일 단위 기간기준» — 무엇이 정해져 있고 무엇이 없는가

**정해져 있다**: ① 수입금액비율은 과세기간(역년)별로 판정(영 §168의11②) ② 연환산은 «사업을 영위한 기간»으로(③3호) ③ 비사업용 기간은 일수로 센다(영 §168의6) ④ 임대한 기간은 사업용에서 빠진다(서면4팀-1048).
**정해져 있지 않다(본문·해석례 0건)**: 비율을 통과한 과세기간을 **일수로 어떻게 환산하는지**. 가능한 읽기 3가지 — Q-2:
- (가) **통과한 과세기간 ∩ 영위일** — 영위하지 않은 날은 사업용이 아니다. ③3호(영위기간 개념)·서면4팀-1048(기간 소거)·E3-①의 일 단위 사건 모델(V-1)과 일관.
- (나) **통과한 과세기간 역년 전체** — 법 §5의 «과세기간»을 단위로 읽음. 개시 전·폐업 후 같은 해의 날도 사업용. 근거 문언은 없다(v2의 «과세기준일 접기»가 철회된 이유와 같은 종류의 해석 선택).
- (다) (가) + 직전 비율② 통과 시 개시 전 보정 — 현행 DM-01의 `priorPass` 휴리스틱(`other-land-merge.ts:143`)을 일반화. 개시일을 입력해도 ②가 통과하면 전 기간을 사업용으로 읽는다 — M9′에서 과소가 그대로 남는다.

세 읽기는 **판정이 갈린다**(실측 `zz-probe2`): M9′(개시 2022-12-01 · 양도 2024-06-30) (가) 영위 577일 → **비사업용**(직전 3년 중 비사업 519 > 365) · (나) 2022-01-01~ 911일 → **사업용**(직전 3년 중 비사업 185) · (다) 3,832일 → **사업용**. 계획은 (가)를 추천하되 **사용자가 정한다**(Q-2 — V-1 직접 해석 부재).

## 3. 모델안 3개 비교와 추천

### 3.1 공통 전제

- 구간은 `[start, end)` 반열린, **사건일 = 새 상태의 첫날**(E3-① V-1과 동일 — 개시일 = 처음 영업한 날 · 폐업일 = 영업하지 않게 된 첫날). 폐업일을 사업자등록상 폐업일자(마지막 영업일)로 입력해도 그 날이 사업용 → 유예 구간으로 넘어갈 뿐 **합집합이라 일수가 달라지지 않는다**; 영향은 ③3호 연환산 영위일수 1일뿐(V-3).
- 날짜는 `lib/tax-engine/utc-date`·`toOptionalDate`(⑭ 주입 `parseDate`)만 — 신규 코드 `new Date(x)` 금지. 금액·일수 정수, `Math.floor`(연환산은 기존 `annualizeRevenue`), `Math.round` 금지.
- 과세기간 = 역년(법 §5①). 폐업·개시로 단축되지 않는다. 연도 y의 영위일수 = **초일산입 일수**(양도일 포함 — 기존 `deriveBusinessDays` 규약), 사업용 **구간** 일수 = 반열린 `[start,end)`(양도일 제외 — 기존 `meetsPeriodCriteria` 규약). 두 규약은 현행이 이미 공존한다(DM-01 `businessDays`).
- 업종은 **하나로 고정**(현행 `nblRevenueBusinessType`) — 업종 변경 이력은 받지 않는다(Q-7).

### 3.2 (A) 과세기간 표 단독 — `rows[{taxYear, revenue, landValue, opStart?, opEnd?}]`

연도마다 영위 시작·종료일을 행이 갖는다. 사건이 없어 모델은 단순하나 ① 영위 연속성(개시 → 휴업 → 재개)이 행마다 흩어져 **겹침·공백·연도 경계 검증이 행×날짜로 늘어난다** ② 계속 영업 연도마다 날짜 2칸이 의미 없이 반복 ③ 폐업 후 «영업 없음» 연도를 행으로 표현할 방법이 없어 V-7 전제(영위 통산)와 10호 앵커링이 분리된다. 입력 칸 ≈ 연도 × 4.

### 3.3 (B) 업종 사건 + 과세기간 표 — **추천**

```ts
type BusinessEventKind = "business_started" | "business_closed";           // 휴업·폐업·이전은 하나(규칙 §83의5①10호가 같이 취급)
interface BusinessEvent { kind: BusinessEventKind; date: Date }             // 사건일 = 새 상태 첫날
interface RevenueYearRow { taxYear: number; revenue?: number; landValue?: number }  // 미입력 = 모름(Q-4)
interface RevenueHistoryInput { mode: StateHistoryMode; events: BusinessEvent[]; rows: RevenueYearRow[] }
// NonBusinessLandInput.revenueHistory?: RevenueHistoryInput   (landStateHistory와 평행한 optional 입력)
```

- 영업 구간은 건축물 이력(`deriveOtherLandStateIntervals`)과 같은 방식의 **replay**: 첫 사건이 `business_closed`이면 소유 첫날 영업 중, `business_started`이면 영업 없음에서 시작 · 개시/폐업은 번갈아 · 사건일 엄격 증가 · 마지막 사건일 < 양도일 · 양도일 현재 영업 여부 = 마지막 사건(없으면 §4.4의 `unchanged`/현행). 소유 시작 전 사건은 클립(축 B 지분 · 이월과세 배제 시나리오 B — E3-① Q-11과 같다).
- **연도 행은 사건이 정한다** — 영업일이 1일이라도 있는 과세기간만 행이 필요하다(UI가 파생 목록을 보여준다). 당해(양도연도 T)·직전(T−1) 행은 **기존 `nblRevenue*` 칸이 그대로 말한다**(§3.5 — 중복 입력 없음). 새 행은 **T−2 이전**만 받는다.
- 장점: 취득일·양도일 중복 입력 없음 · 개시/폐업이 한 곳(사건)에서 일 단위로 정해져 ③3호 연환산 영위일수·사업용 구간·V-7 전제·DM-01 대체가 **같은 leaf**를 쓴다(3중 패턴). 단점: 새 ⑫ 칸 3개(strip 위험).

### 3.4 (C) 현행 DM-01 확장 — 개시일 + 폐업일 칸 추가

`currentBusinessStartDate` 옆에 `currentBusinessEndDate`를 두고 당해·직전 2행으로 판정. 입력은 최소이나 **M11(폐업 2021-06-01 후 나대지)을 표현하지 못한다** — 폐업 뒤 양도연도의 당해·직전 수입은 0이라 비율 통과가 불가하고, 그 이전 8년의 비율을 말할 칸이 없다. 연도별 비율 없이 «영업 기간 선언»만 받으면 법정 요건(비율 이상)을 건너뛰는 근거 없는 혜택이다. **기각**(DM-01은 (B)의 `changed`가 대체 — Q-6).

### 3.6 판정 산식 (추천 (B) + Q-2 (가))

입력: `revenueHistory.mode = changed` · 사건 → 영업 구간 `O`(일 단위) · 행(과거) + 기존 당해·직전 칸 · 업종 임계 `th`(규칙 §83의4) · 소유기간 `[acq+1, pjDate)`.

1. **영업 구간 `O`** = replay 결과 ∩ 소유기간. 연도 y의 **영위일수** `od(y)` = `O`의 날 중 y에 속하는 날(초일산입 — 양도연도는 양도일 포함 · 폐업일은 비영업).
2. **연도 판정** — 영위일이 있는 모든 과세기간 y에 대해 **`computeRevenueTest`를 연도 y 입력으로 한 번씩**(현행 함수 재사용 — 연환산·윤년·max(①,②)·간주임대료·공통수입 로직을 복제하지 않는다): `currentRevenue/LandValue = 행(y)` · `currentBusinessDays = od(y)` · `currentTaxYear = y` · `prior* = 행(y−1)` · `priorBusinessDays = od(y−1)` · `priorTaxYear = y−1`. 양도연도 T와 T−1은 기존 `revenueTest` 칸으로 같은 입력을 만든다(T−1은 `prior*`를 `current*`로 한 칸씩 당기고 `prior*`는 T−2 행). 행이 없거나 수입·토지가액이 빈 연도는 **모름 → 불통과**(+확인 필요 고지, Q-4). 비율 ②는 직전 행이 없으면 계산하지 않는다(현행 `hasPrior`와 같음).
3. **사업용 구간** `B` = 통과한 y마다 `O ∩ [y.1.1., (y+1).1.1.)`(Q-2 (가)). 통과 연도 사이의 불통과 연도는 비사업(영업 중이어도). 도소매업 `wholesaleItemIssue`가 «불인정»이면 경로 전체가 막힌다(현행과 동일 — 이력이 우회하지 않는다).
4. **판정** = `meetsPeriodCriteria(B, 취득일, 의제양도일, "other_land", rules, 유예)` — 유예는 **합집합**(이중 계상 없음). 건축물 이력이 있으면 `B`는 **core 자체 사업기간**으로 `markOwn(trace, B)` → `applyStateHistory`가 `소유기간 ∩ B`를 이전 구간 사업용과 합집합(Q-15 (가′) 그대로).
5. `periodEvaluation.basis = "state_history"`, 신규 optional echo `periodEvaluation.revenueHistory`(영업 구간 · 연도별 `{taxYear, operatingDays, yearDays, annualizedRevenue, ratioCurrent, ratioCombined, threshold, pass, foldReason?}` · 사업용 구간 · V-7 전제 결과) — 없으면 키 없음(종전 echo와 바이트 동일).

**연산 정밀도**: 비율은 현행 `computeRevenueTest`와 같은 방식(부동소수 `>=` 비교 — 현행 계약 유지, 경계쌍 `3,000,000 / 2,999,999`로 고정 — P6 실측은 현행 안전망이 이 경계를 **간접 1건**만 지킴을 보인다). 연환산 `floor(수입×총일수÷영위일수)`.

## 4. V-7 해소 — 규칙 §83의5①10호 «2년 이상 사업에 사용한 토지»

**현행**: `business_closure_relocation` 유예행은 기산일 + 2년을 **무조건** 유예 구간으로 만든다(`grace-reason-period.ts:49`). «2년 이상 사업에 사용» 전제는 검사하지 않는다 — 입력 근거(영위 구간)가 없었다.

**제안 (Q-5 (가))**: `revenueHistory.mode = changed`일 때만 전제를 검사한다.
- 전제 일수 = `O`(영위 구간)의 **통산** 일수 중 `[소유 첫날, 유예 기산일)`에 속하는 날 ≥ **2년** (`differenceInDays(anchor, addYears(anchor, −2))` — 윤일 포함 730 또는 731). 비율 통과 여부와 **무관** — «사업에 사용한» 사실이고 다목 인정 여부는 별개다(통합 근거: 법에 없는 불리 요건 추가 금지). «통산 vs 계속» 직접 해석은 검색 0건(V-2) — 통산을 택하는 이유는 문언 «2년 이상 사업에 사용한 토지»에 «계속하여»가 없기 때문이다.
- 미충족 시 그 10호 유예 구간만 `meetsPeriodCriteria`에서 **제외** + `NBL_REVENUE_HISTORY_GRACE10_PREMISE_NOTICE`(전제 미충족으로 유예 미적용 — 확인 필요). 다른 호 유예는 건드리지 않는다.
- `changed`가 아니면 현행 + (검토 대상) 고지 없음 — **기존 입력의 고지·판정을 한 글자도 바꾸지 않는다**. 이력 없는 10호 유예 입력에 전제 «확인 필요» 고지를 새로 얹을지는 바이트 계약을 깨므로 별도 결정이다(Q-5 (나)에 포함).
- 기산일이 영위 사건과 일치하지 않아도 된다: 검사는 «기산일 이전 영위 통산 일수»만 본다(사건일과 결합하지 않는다 → 입력 모순 차단 규칙이 늘지 않는다).

실측 V7(손 유도 + 오라클): 취득 2022-07-01 · 개시 2022-09-01 · 폐업 2023-03-01(영위 181일) · 10호 유예 `[2023-03-01, 2025-03-01)` · 양도 2024-06-30 — **현행 B**(유예 단독 487/729 → 사업용) · 전제 미검사로 보면 B(668/729) · **전제 검사 시 N(181/729)** — 세액 +69,750,000. 소유기간 729일(<2년)이라 가목 미적용 · 다목 임계 floor(729×0.4)=291.

### 남은 확인 필요 (비차단)

- **V-1**: 과세기간별 판정 → 일 단위 사업용 기간 환산의 직접 규정·해석례 없음(Q-2 (가)는 사용자 결정 — 고지에 «확인 필요»).
