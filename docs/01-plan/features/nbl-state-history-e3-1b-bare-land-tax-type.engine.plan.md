### 4.1 공통 의미론 (E3-① Before 사슬 유지)

각 사건 행은 **그 행이 닫는 구간**을 기술한다. 닫는 구간이 건축물 있음이면 현행(종류 Before)대로, **나대지면 새 «선언»**(종류 + 근거 + 한도 이내 여부)을 읽는다. 꼬리(양도일 현재)는 기존 입력이 말한다. 나대지 구간의 선언은 V1-A 해석기로 `accepted`/`unconfirmed`/`partial`로 가른다.

| 입력 부담 | 해당 행에서만 3칸(나대지 구간을 닫는 행) | 행 1개 추가 + 3칸 | 0 |
| E3-① 차단 완화 | 규칙 삭제 | 규칙은 «건축물 구간용 `tax_type_changed`»로 유지 — 단 새 종류 신설 | 불필요 |

**추천 (a).** 이유: (1) **Before 사슬은 «구간을 닫는 행이 그 구간을 말한다»**이므로 신축 앞 나대지는 신축 행이 말할 수밖에 없다 — (b)는 이 한 점에서 모델이 성립하지 않는다. (2) ⑫·⑧·엔진의 순서 규칙(날짜 엄격 증가·같은 날 금지·교대)이 그대로다. (3) 해석기는 V1-A를 **재사용**해 «근거 없는 비종합합산 = 종합합산 접기»가 꼬리와 구간에서 같은 함수·같은 문구다. (c)는 실측 시료 C1·C3·C5를 표현하지 못해 기각한다(§5).

> **작은 변형 — 선언 칸을 1개로 합치기**: 나대지에서는 종류가 근거로 정해지므로(`statutory_exempt → exempt` · `separate_taxation → special_sum` · `vacant_state → separate`) 근거 1개 칸으로도 충분하다. 그러나 ① 꼬리 입력(종류 + 근거 2칸)과 같은 모양을 쓰면 `propertyTaxBasisOptions`·`isUsableBasis`·화면 선택지 필터를 **그대로 재사용**하고 ② 호환 불가(종류와 근거 불일치) 분기도 같은 `incompatible` 경로로 흡수된다. 따라서 2칸(종류 + 근거)을 유지한다 — 계약은 UI가 «종류를 고르면 호환 근거만 보인다»로 막고 엔진은 방어한다.

### 4.4 의미표 — 행의 «닫는 구간»이 나대지일 때

| 행 종류 | 닫는 구간 | `propertyTaxTypeBefore` | 근거 | 결과 구간 |
|---|---|---|---|---|
| `building_built` | **항상 나대지** | `""`·미전송·`comprehensive` = 종합합산(**종전과 동일 · 고지 없음**) / 비과세·분리·별도 | 필요(없으면 접힘 + 고지) | 해석기 결과 |
| `tax_type_changed`(직전 상태 건축물 없음) | 나대지 | `""` = **모름**(E3-① 동일 — 종합합산 + 확인 필요) / `comprehensive` / 비과세·분리·별도 | 필요 | 해석기 결과 |
| `tax_type_changed`(직전 상태 건축물 있음) | 건축물 있음 | E3-①대로(근거·한도 칸은 **무시**) | — | 변경 없음 |
| `building_removed` | 건축물 있음 | E3-①대로 | — | 변경 없음 |

**해석기(구간 단위, `resolvePropertyTaxBasis` 호출)**
- 선언 = `comprehensive`/`""`(built 행) → 종합합산 · 구간 비사업용 · 고지 없음.
- 선언 ≠ 종합합산 → `resolvePropertyTaxBasis({propertyTaxType, hasBuilding:false, propertyTaxBasis, demolishedFloorArea: undefined})`:
  - `unconfirmed`(미선택·모름·호환 불가·`demolished`) → 종합합산으로 접힘 + **새 고지**(구간별 «근거를 확인하지 못해 종합합산으로 보았다 — 확인 필요»).
  - `accepted` + 근거 `vacant_state` → `areaWithinLimitBefore`: `within` → 사업용 구간 · `exceeded` → **부분 면적(이력 미적용 + 고지)** · `unknown`·`""` → 접힘 + 고지.
  - `accepted` + 그 밖(비과세·분리과세) → 사업용 구간.
- 구간의 사업용 술어: `(hasBuilding ∨ basisOutcome === "accepted") ∧ type ∈ {exempt, special_sum, separate}` — `isStateIntervalBusiness`에 한 항만 추가.

### 4.6 면적한도·부분 면적 정책

| 선택지 | 내용 | 평가 |
|---|---|---|
| **(가) 3지선다(추천)** | `within`(전체 한도 이내) / `exceeded`(일부 초과) / `unknown`(모름 — `""`과 동일) | 호별 계산 없이 사용자가 호별 사실로 답한다. `exceeded` = 부분 면적 → **이력 미적용 + 고지**(확정 결정), `unknown` = 혜택 불성립 + 확인 필요 |
