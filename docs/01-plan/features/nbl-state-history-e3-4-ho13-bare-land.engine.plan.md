// StateHistoryIntervalEcho(구간표 한 행)에 optional `vacantLotDays?: number` — 그 구간 ∩ 13호 구간 일수(R-2 · 없으면 키 부재)

→ 식(UI 제안과 **동일 — 코드 대조로 확정**):

```
vacantLotHousePeriodsRead({ relatedBusinessType, tailHasBuilding, historyChanged, historyDeemedBlocked, landArea })
  = relatedBusinessType === "vacant_lot_1household"
    && ( !tailHasBuilding
         || ( historyChanged && !historyDeemedBlocked && !isAreaOver(landArea, NBL_AREA_MULTIPLIER.VACANT_LOT_1HOUSEHOLD) ) )
```

- `historyChanged` = `nblOtherStateHistoryApplies` ∧ 모드 `changed`(소비 지목이 `other_land`일 때만 — 13호는 기타토지 전용이라 자동 충족) · `historyDeemedBlocked` = `stateHistoryDeemedBlocks`(`house-prior-scope.ts:52`) · `tailHasBuilding` = `effectiveOtherHasBuilding`(⑫′가 쓰는 같은 함수 — `refines.ts:220`).
- **부분 면적 경로(E3-③ 후속 `otherLandAreaIsPartial` 선례 — `other-land.ts:104`)는 쓰지 않는다**: «꼬리 나지 + 660 초과»는 core가 행을 읽고 «꼬리 건물 + 660 초과»는 core가 부분 면적을 만들지 않아 `otherLandAreaIsPartial`이 거짓이라, 부분 면적 판정으로는 이 식을 못 낸다. 읽는 조건이 `tailHasBuilding`·`isAreaOver`·이력 모드·의제로 **닫히므로** core를 돌리지 않는 순수 입력 술어로 둔다(UI §5 교훈 — 렌더마다 core 실행 금지).
- 위치: 신규 `lib/tax-engine/non-business-land/other-land-vacant-lot-history.ts`(leaf와 같은 파일 — `vacantLotBusinessIntervals`와 함께 export). **엔진 자신도 이 술어를 부른다**: leaf의 `eligible`(=`!isAreaOver`) 분기와 `applyStateHistory`의 13호 분기 진입이 같은 함수의 인자 일부를 쓴다 → 3중 패턴(④⑤⑧ ↔ 엔진 동일 소스).
- 참이지만 행이 효과가 없는 경우(꼬리 건물인데 나지 구간이 아예 없는 이력 등)는 «읽지만 영향 없음»이다 — 요구해도 «엔진이 안 읽는 칸 요구»가 아니다.
- **parity anchor(E3-② 교훈)**: 인자 격자(호 × 꼬리 건물 × 이력 모드 × 의제 × 면적 ≤660/>660)마다 «행을 하나 넣어 판정이 실제로 달라지는 시료»를 만들어 **술어 참 ⟺ 행 투입 시 판정(또는 `vacantLot` echo)이 변함**을 단언한다. 술어와 엔진이 어긋나면 이 격자가 잡는다. 격자 표는 R-8 공용 표에 포함.
