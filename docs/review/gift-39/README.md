### 1.3 구조적 패턴

**패턴 A — 「상증령」§29② 「다목」 계열 비율 인자가 계통적으로 결손하고, 엔진·④·⑤·⑧·⑫ 전 계층이 같은 방향으로 닫혀 있다.**
저가 나목(§29②2호 다목)과 고가 가목(§29②3호 다목) 둘 다 원시 실권주수를 그대로 곱한다(`capital-increase.ts:65`·`:116→:121`). 그 비가중 base가 같은 함수 안에서 **3억 기준금액 판정에도 재사용**돼(`:72`) 금액 과다와 게이트 반전이 함께 난다. 입력 경로도 같은 방향으로 닫혀 있다 — ⑤ `needsRatio = isHigh && subType !== "forfeited_realloc"`(`capital-forms.tsx:232`) → ④ `needsRatio ? … : undefined`(`gift-deemed-api.ts:211-212`). **엔진이 안 읽으니 UI가 안 그리고, UI가 없으니 ④가 안 싣는 자기정합적 공백**이라 어느 한 층만 고치면 no-op이 된다. 전환주식(§29②6호)이 이 primitive를 2시점 호출하므로(`convertible-stock.ts:12-13`) 오염이 그대로 전파된다(#14 실측 99,990,000 vs 법정 33,330,000).

**패턴 B — 폼이 수집한 「축」이 ④/⑫/⑭ 중간에서 침묵 strip되어 엔진에 도달하지 않는다.**
증여일은 ⑧이 필수화까지 하는데(`gift-deemed-validate.ts:47`) `CapitalIncreaseInput`에 날짜 필드가 0개(`gift-deemed-input-types.ts:174-198`, `ConvertibleStockInput`은 `:248-253`)라 「상증령」§29③ 신설(2016-02-05)도 「상증법」 법률 제14388호 부칙 §5②(2017-01-01)도 분기할 수 없다(#5·#25). 증여자 축은 prefill이 아예 싣지 않고 ④가 재파생해 덮는다(#1). 수증자 법인격은 타입·Zod·UI 어디에도 없다(#21·#77). 공통점은 **TypeScript가 감지하지 못하는 ⑫⑬⑭ 층**이라는 것이고, `as unknown as` 캐스트(`app/api/calc/gift-deemed/route.ts:65`)가 22개 브랜치의 드리프트를 영구히 가린다(#91). 저장소 CLAUDE.md의 「⑫⑬⑭는 TS 미감지 — 누락 시 침묵 stripping」 경고가 §39에서 그대로 재현된 사례다.

**패턴 C — 세액을 결정하는 게이트 층에 회귀 안전망도 개정 감시도 없다.**
뮤테이션 실측에서 3억 arm 삭제·3억→100억·30%→40·`>=`→`>` 가 **전부 3,361건 전건 생존**한다(#20·#68·#76·#58) — 유일한 게이트 픽스처의 이익이 13,330,000원·25,000원이라 그보다 큰 어떤 값도 통과하기 때문이다. 동시에 `verify:legal` manifest 키워드는 §39 3개(`additions-inheritance.ts:285`)·§29 4개(`additions-inheritance-decree.ts:74`)가 **전부 ①항 본문·1호·조문 제목에서 와서**, 세액을 정하는 §29②(30%·3억·상장 단서)·§29③④⑤·§39①2호·3호·§39②·§28⑤가 감시 0건이다(#8·#42·#86·#96·#98·#99·#106 — 뮤테이션 PASS 실측). 커버리지 게이트는 모수가 `legal-codes` export 문자열이라 **인용 상수가 없는 조문은 uncovered에도 뜨지 않는다**(#43·#57 — coverageRate 1·uncovered 0건). 결과적으로 「현행은 맞다」는 판정이 「앞으로도 맞다」를 전혀 보장하지 못하는 층이 §39 전역에 깔려 있다.

## 2. 「상증법」§39 · 「상증령」§29 호·목별 구현 커버리지

**판정 기준** — 구현됨: 법문의 요건·산식 인자가 모두 코드에 있고 엔진 산식 자체의 결함이 이 리뷰에서 보고되지 않음(입력·표시·안전망 결손은 비고) / 부분구현: 산식·요건의 일부가 존재하나 법정 인자·단서·분기 중 하나 이상이 결손 / 미구현: 대응 코드 0건 / 확인필요: 이 리뷰의 증거로 판정 불가.
**충돌 처리** — 영역별 판정이 엇갈리면 **더 보수적인(주장을 부풀리지 않는) 「부분구현」** 을 쓰고 충돌을 각주로 남겼다. 각주가 붙은 행은 원 판정이 갈린 행이다. file:line은 본 리포트가 작업 디렉터리에서 직접 열어 대조했다.
