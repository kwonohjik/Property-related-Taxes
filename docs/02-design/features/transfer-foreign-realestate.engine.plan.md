## §0 요약 (결정 필요 항목은 §7 Q-n)

1. **현재 국외 부동산 경로는 없다.** 양도세 엔진 `transfer-tax*.ts` 계열(`lib/tax-engine/transfer-*` 파일 158개)에 국외 분기가 0건이고, 국외 처리는 주식 전용(`stock-transfer/foreign-stock*.ts`)뿐이다. 국외주식은 법 **§118②**(§118의2~4·6 준용)로 가지만, **부동산은 §118의2~§118의8 전체**가 적용된다 — 그래서 주식 트랙이 «준용 X»로 둔 **§118의5(세율 §55①)·§118의7(기본공제)·§118의8(장특 배제 단서)이 여기서는 본체**다(`legal-codes/stock.ts:391-398` 헤더와 정확히 대칭).
2. **권고 아키텍처(Q-1)**: 기존 양도세 route·엔진·Zod·마법사에 **얹지 않고** 별도 엔진(`lib/tax-engine/foreign-realestate/`) + 별도 route(`app/api/calc/transfer/foreign/`) + 별도 Zod(`lib/api/transfer-foreign-schema.ts`). 이유 — 국외는 **§118의8 준용 목록 밖의 국내 기계(§95 장특·§97①1호나목 환산·§97의2 이월·§102 통산·§104 중과·§104의3 비사업용·§99 기준시가)를 전부 쓰지 않는다**(§1.2). 기존 `transfer-tax-api.ts`는 756줄·`route.ts` 491줄이라 건드리면 800줄 정책 위험구간이다.
3. **교재 사례 정답(K-1)은 법문으로 재현된다**: 양도차익 437,000,000 = 양도 $900,000×1,100 − 취득 $400,000×1,300 − 양도비 $30,000×1,100. 장특 배제(§118의8 단서)·미등기여도 기본공제 250만원(§118의7①, 국내 §103①1호 단서와 다름) → 과세표준 434,500,000 → §55① 산출세액 **147,860,000** · 지방소득세 14,786,000.
4. **v1 범위(권고)**: 매매(유상) 취득 · 실지거래가액 · 외화+날짜별 기준환율 직접 입력 · 단건 + 다건(양도차손 없는 경우) · 외국납부세액 공제/필요경비산입 · 양도일 ≥ 2020-01-01. 상속·증여·시가 모드·장기할부·환차익 제외·가산세는 차단 또는 고지(Q-2·5·6·11·13).
5. 열린 법령 쟁점 중 **세액이 갈리는 것**: V-1(차손 통산 근거 — §102 미준용) · V-3(미등기 70% 비적용 확정 근거) · V-5(국내·국외 과세표준 합산 누진 여부 — 예시 30,630,000원 차이, §2 K-17) · V-7(지방소득세 base·절사). **근거 없이 불리/유리 어느 쪽으로도 단정하지 않는다** — 막고 «확인 필요»로 고지.

### 3.3 계산 순서 (§92②·§118의5·§118의7)

1. **적용 대상 판정**: 자산별 `양도일 ≥ addYears(domesticResidenceStartDate, 5)`(경계 V-2). 하나라도 미충족이면 그 자산은 `not_liable`로 **합산에서 제외**하고 사유를 싣는다(전부 미충족이면 §2 K-9).
2. **자산별 원화 환산**(§3.4) → `transferKrw · acquisitionKrw · capexKrw · costKrw`.
3. **양도차익** = 양도가액 − 취득가액 − 자본적지출 − 양도비 (자산별).
4. **장특** = 0(§118의8 단서). `longTermDeduction: 0`과 근거 코드를 echo.
5. **양도소득금액**(자산별) = 양도차익. 차손 자산: 단건이면 `incomeAfterOffset = 0` · `lossAmount` echo; 다건+차손은 V-1 해소 전 ⑧⑫ 차단이므로 엔진에는 **차손 ≥ 2건 조합이 도달하지 않는다**(방어적으로 `TaxCalculationError(INVALID_INPUT, path)` — `taxCalculationErrorResponse`가 400으로 매핑, `lib/api/tax-error-response.ts:15-23`).
6. **기본공제**(§118의7②): 합 = Σ양도소득금액(≥0). 공제 = `min(합, annualLimit)`. 배분은 **양도일 오름차순**으로 각 자산 소득금액에서 순서대로 차감(감면소득금액 구분 없음). `annualLimit`은 `basicDeductionRules.annualLimit`(seed `transfer-rate-seed.ts:102` = 2,500,000) — 코드에 2,500,000 하드코딩 금지(STOCK 상수 `STOCK_FOREIGN_BASIC_DEDUCTION`은 **쓰지 않는다**: 국내 §103 그룹 주식용).
7. **과세표준** = 합 − 공제. **천원 절사 없음**(`tax-utils.ts:245` 주석: 양도소득 과세표준에는 절사 규정이 없다 — 일반 설명서의 «과세표준 천원 절사»는 이 저장소에서 양도소득 과세표준에 적용하지 않는다).
8. **산출세액** = `calculateProgressiveTax(과세표준, brackets)`(과세기간 합산 1회). `appliedRate`·`progressiveDeduction`은 해당 구간 값을 echo.
9. **외국납부세액**: `credit`이면 `computeForeignTaxCreditLimits(rows)`(A=산출세액 — **기본공제 후**, B·C=**기본공제 전** 양도소득금액; 인자 이름이 단계를 박아 둠 `foreign-tax-credit-limit.ts` 서두) → `applied = min(외국세 원화, 한도)` 자산별 합. `expense`이면 **2~8단계 이전**에 해당 자산 양도차익에서 외국세 원화를 차감(필요경비 산입)하고 재계산(K-12). 두 방법 동시 적용 금지.
10. **결정세액** = 산출세액 − 공제. **지방소득세** = 결정세액의 10% — 절사 단위·base는 V-7(권고 Q-10). **합계**.
11. `appliedLawDate` = 가장 늦은 양도일(ISO), `warnings[]`·`appliedRules[]`.

### 3.4 정수 환산 (K-23 근거)

- 규약: 모든 금액 원 정수, **환율×외화액은 항목별로 floor**(원 미만 처리 무규정 → 선례 FX-4 `foreign-stock.ts:243` 서술 유지, V-13).
- 실측: `Math.floor(400000 * 1300.10)` = 520,039,999 ≠ 정확 520,040,000. 주식 엔진이 `Math.floor(perShare*count*rate)`(`foreign-stock.ts:199-204`, `:217`)를 쓰므로 **같은 1원 과소 위험이 거기도 있다**(별건 · §9 ②).
- 설계: `fx.ts` — `toKrw(amountForeign: number, exchangeRate: number): number`. 두 입력을 소수 ≤4자리 십진수로 보고 **정수 스케일**(`decimalizeRatio`(`tax-utils.ts:95`)와 같은 방식 — 문자열 파싱이 아니라 `round(x×10^k)` 복원)로 환산해 `BigInt(a)×BigInt(r)/10^(ka+kr)` floor. 소수 5자리↑·비유한은 `TaxCalculationError`. 이 함수는 `applyRatio`(`:131`)가 «amount가 안전정수» 전제라 직접 재사용 불가 → 신규.
- 음수 외화액·환율 ≤ 0 거부.

### 3.5 결과 타입 echo (`ForeignRealEstateResult`)

`taxCategory: "foreign_realestate" | "not_liable"`, `isLiable`, `ineligibleReason?`;
자산별 `rows[]`: `{ id, 환산 4항목(KRW)과 사용 환율 echo, gain, incomeAfterOffset, lossAmount, basicDeductionAllocated, foreignTax:{ paidKrw, limit, applied } }`;

`supportedFrom`(2020-01-01) · `appliedLawDate` · `warnings[]` · `appliedRules[]`(§5 상수).
**echo 규율**: 조기 반환(`not_liable`)에서도 입력 축을 그대로 싣는다(`foreign-stock.ts:143-158` 선례, skill echo-field-pattern).

### 3.6 날짜·권한 규칙

- 날짜는 route에서 `coerceDates`(`lib/api/date-coerce.ts:76`)로 변환 — 배열 경로 `assets[].transferDate` 표기가 같은 파일 `coercePath`에서 지원됨(`[]` 접미 처리 확인). **신규 코드 `new Date(x)` 직접 호출 금지**. 엔진 안 날짜 연산은 `lib/tax-engine/utc-date`(`addYears` :54 · `isBefore` :187).

## §9 이 계획이 건드리지 않는 것 / 별건 발견

**건드리지 않음**: 기존 양도세 엔진·route·`propertySchema`·`callTransferTaxAPI`·국외주식·국외전출세(§118의9~18, 2027-01-01 개정 시행분 별도)·UI(UI plan)·이력 저장(IndexedDB — UI plan)·비거주자(§121 이하).

**별건 발견 — 실측 근거 있음(수정하지 않음, 사용자 결정 대상)**:
1. **V-10** — 국외주식 FS-09 장기할부가 영 §178의5② 문언과 달리 «수령일별 환율»로 구현돼 있을 가능성(`foreign-stock.ts:77-84` 주석이 스스로 그렇게 서술). 문언상으로는 영 §162①3호의 양도일 1회 환율로 읽힘.
2. **환산 1원 과소** — `foreign-stock.ts:199-204·217`이 `Math.floor(외화×환율)`(부동소수)를 쓴다. 이 계획 K-23은 `Math.floor(400000 * 1300.10)` = 520,039,999(정확 520,040,000)를 실측했다. 주식은 외화액·환율이 어떤 소수 조합일 때 얼마나 나는지 **미측정**.
3. **환율 fallback** — `foreign-stock.ts:244-245·256-257`이 자본적지출·양도비·외국세 환율 미입력 시 양도일 환율로 떨어진다(3대 정책 #2 «자동 안분 fallback 금지»와의 부합 여부는 별도 판단 — 국외주식 이월과세 계획이 이미 `Q-4`로 인지, `foreign-stock-carryover-97-2.engine.plan.md:118`).
4. 지방소득세 규약 불일치(V-7).
