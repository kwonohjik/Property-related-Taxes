# 승계조합원 완공 아파트 — 「취득 당시 기준시가」 §164⑦ 계산 도우미

> **출처**: `redev-successor-apt-estimate.plan.md` §4 Q-3. 처음에 (a)로 정했다가 구현 중 (b)로 다시 정했고(§8.5 V-7), 이 문서가 그 별건이다. PR #2940(미머지) 위에 쌓은 브랜치다.
> **깊이**: L2. 화면 보조 도구만 바뀐다. 엔진에는 사용자가 확인한 「취득시 기준시가」 한 칸만 가고(종전과 같다), 세액 경로는 바뀌지 않는다.

## 0. 결론

1. **지금**: 매매로 승계한 완공 APT를 추계(감정가액·매매사례가액·환산취득가액)로 계산할 때, 「취득 당시 기준시가」는 **사용승인일 당시 공동주택가격**이다. 새 아파트는 그날 가격이 대개 아직 공시되지 않아 §164⑦로 계산해야 한다. 그런데 일반 주택 카드에 있는 계산 도우미(`PhdConvertedPriceFill`)가 승계 APT에는 뜨지 않는다. #2940은 산식을 안내 문구로만 알린다.
2. **막는 것**은 세 가지다.
   - ① 도우미의 노출 게이트 `phdFillAssistVisible`이 `assetKind === "housing"`만 받는다.
   - ② 도우미는 취득일로 `asset.acquisitionDate`를 읽는데, 승계 APT에서 이 값은 **입주권 취득일**이다. 취득일은 사용승인일이어야 한다(소득세법 시행령 §162①4호).
   - ③ 계산에 쓰는 「토지 면적」 칸이 재개발 APT 카드에 없다(`AssetAreaSection` 시나리오 표에 재개발 APT가 없다).
3. **실측**(1장): 기준일을 사용승인일로 바꿔 읽으면 기존 계산 함수가 그대로 맞는 값을 낸다(313,725,490). 면적 칸을 채워도 승계 분기 세액은 바뀌지 않는다(461,000,000 그대로).
4. **권장**: Q-1 (a) 면적 칸은 도우미 카드 안에만 둔다 · Q-2 (a) 환산 방식에서도 도우미를 보인다 · Q-3 (a) 주택 유형은 공동주택으로 고정한다.
5. **작업량**: 결정 후 약 반나절. 화면 3곳 + 판정 leaf 1곳 + 렌더 anchor·E2E 1건.

## 1. 실측 (2026-11-06 · probe `keep/probe-successor-phd-assist.test.ts`)

시료는 #2940 anchor와 같다: 입주권 승계 2020-04-15 · 준공 2022-12-02 · 양도 2023-02-16 920,000,000 · 감정가액 450,000,000 · 취득시 기준시가 300,000,000.

| 행 | 입력 | 결과 |
|---|---|---|
| P1 | 도우미 노출 판정 `phdFillAssistVisible`(승계 APT 그대로) | **false** — 화면에 없다 |
| P2 | 같은 자산을 `assetKind: housing` · 취득일 = 준공일로 바꿔 판정 | true |
| P3 | 도우미 입력: 최초 고시일 2023-04-28 · 최초 고시가격 320,000,000 · 토지 40㎡ · 취득시 토지 ㎡당 5,000,000 · 건물 100,000,000 · 최초 고시 시 토지 ㎡당 5,200,000 · 건물 98,000,000 | `computeConvertedHousingPrice` → **313,725,490** = ⌊320,000,000 × 300,000,000 / 306,000,000⌋ (취득일을 입주권 취득일로 읽어도 이 시료에서는 같은 값) |
| P4 | P3 입력이 저장된 채 route 계산 | ⑧ 이슈 0 · 본문 `acquisitionArea` 40 · `preHousingDisclosure` 없음 · 양도차익 **461,000,000**(P3 전과 같다 — 엔진 승계 분기는 면적을 읽지 않는다) |

- P3에서 두 날짜의 값이 같았던 것은 이 시료의 날짜가 우연히 맞았기 때문이다. 도우미 안의 판정 셋(`isPhdEligible` · `classifySameAdjustmentPeriod` · `phdAssistNeeds164_5`)이 `acquisitionDate`를 쓰므로, 날짜를 사용승인일로 바꿔야 할 경우는 다음과 같다(코드 확인 · 값 실측은 착수 시 anchor로).
  - 입주권은 최초 고시일 전에 샀지만 사용승인일은 그 뒤인 경우 — 그날 가격이 이미 있으니 도우미가 필요 없는데, 입주권 취득일로 읽으면 계산을 허용한다.
  - 2000년 이전 날짜의 §164⑤ 확인.
  - 같은 조정기간 판정.

## 2. 설계 (Q 권장안 기준)

1. **leaf** — `successorAptPhdAssistView(asset)`(신규 · `lib/calc/`). 매매 승계 완공 APT(`isRedevSuccessorAptEstimable`)이면 도우미에 넘길 **읽기용 사본**을 만든다.
   - 사본 값: `assetKind: "housing"` · `acquisitionDate: redevCompletionDate` · `phdHousingType: "apartment"` · 추계 플래그 false(환산이어도 도우미가 열리게 — Q-2).
   - 그 밖의 자산이면 사본 없이 원래 자산을 그대로 돌려준다.
   - 도우미가 쓰는 patch(`phd*` 칸 · `acquisitionArea`)는 원래 자산에 그대로 쓴다. 사본의 바꾼 키는 쓰지 않는다.
2. **⑤** — `CompanionAcqStdPriceSection`·`CompanionAcqAmountSection`의 도우미 렌더 게이트(`propertyKind === "house_individual"` · `assetKind === "housing"`)에 승계 APT를 더하고 사본을 넘긴다. 환산 칸(`useEstimatedAcquisition`)에서도 승계 APT는 보인다.
3. **⑤ 면적** — 승계 APT일 때만 도우미 카드 안에 「토지(대지권) 면적 (㎡)」 칸을 둔다. `PreHousingDisclosureSection` assist 모드에 prop 하나를 추가한다.
4. **④·⑧·엔진** — 바꾸지 않는다. 보조 칸은 싣지도 요구하지도 않는다(`phdFlagEffective`가 재개발 APT에서 false). `acquisitionArea`는 실리지만 승계 분기는 읽지 않는다(P4).
5. **안내** — #2940의 §164⑦ 산식 안내 문장은 「아래 계산 도우미로 채울 수 있습니다」로 바꾼다.

## 3. 결정 게이트

### Q-1 토지(대지권) 면적 칸 위치

- (a) **도우미 카드 안 · 승계 APT 전용**(권장) — 그 면적은 도우미 계산에만 쓰인다. 다른 카드와 원조합원 화면은 바뀌지 않는다.
- (b) ① 기본정보에 재개발 APT 면적 칸 — 원조합원 화면에도 생긴다. 원조합원 §166 경로가 그 값을 읽는지 별도로 실측해야 한다(범위 확대).

### Q-2 환산 방식에서도 도우미를 보이는가

- (a) **보인다**(권장) — 환산 분자(취득 당시 기준시가)도 같은 값이다. 일반 주택은 환산이면 §164⑦ 3-시점 토글이 대신하지만, 재개발 APT에는 그 토글이 없다(토글 게이트가 `assetKind === "housing"`).
- (b) 감정가액·매매사례가액에서만 — 환산 사용자는 직접 계산해야 한다.

### Q-3 도우미의 주택 유형 라디오(단독·공동)

- (a) **공동주택으로 고정하고 라디오를 숨긴다**(권장) — 재개발 완공 APT는 공동주택이다. 이름도 「환산 공동주택가격」(§164⑦ 용어 규칙)이 된다.
- (b) 라디오를 둔다 — 고를 이유가 없는 선택지가 남는다.
