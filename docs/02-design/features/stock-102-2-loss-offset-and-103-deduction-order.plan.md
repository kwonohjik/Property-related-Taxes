### 1.2a 🆕 **Phase 0 부수 발견 — PR #1212(국외주식 20% 단일세율)의 미포착 경로**

계획서 범위 밖이지만, **이미 머지된 코드**에 관한 것이라 여기 남긴다.

별지 제84호서식 부표 2 국외주식 코드표 각주(§2.4a):

> ※ **국외주식란의 중소기업**은 **우리나라 중소기업**이 해외에서 발행한 주식등으로서
> **외국의 시장에 상장된 주식**을 말합니다.

⇒ 국외주식 코드 **62 = 중소기업 10%** / **61 = 중소기업외 20%**.
PR #1212은 「외국법인에는 중소기업 규정을 적용할 수 없다」는 판정으로 §104①12호**가목 10%**를
도달 불가로 보고 `STOCK_FOREIGN_RATE = 0.2`를 **무조건** 적용했다. 그 판정은 **외국법인에
관해서는 맞다** — 그런데 서식이 가리키는 10% 경로는 **외국법인이 아니라 내국 중소기업**이다.

§94①3호다목은 「외국법인이 발행하였거나 **외국에 있는 시장에 상장된** 주식등」이라 **후단**으로
내국법인 주식도 들어온다. 엔진도 그 축을 이미 갖고 있다 —
`ForeignStockInput.isListedForeignCorp`(`types/foreign-stock.types.ts:66-72`,
`false` = 내국법인 발행 + 해외 상장). **UI 토글도 있다**(`ForeignStockBlock.tsx:215`).

| 확인 | 결과 |
|---|---|
| 2호(내국법인 해외상장) 선택 경로 | ✅ **있다** — UI 토글 |
| 발행법인 중소기업 여부 입력 | ❌ **없다** — `ForeignStockInput`에 SME 플래그 부재 |
| 현행 적용 세율 | 2호에서도 **20% 무조건** (`foreign-stock.ts` STEP 9) |
| 엔진 주석 | 「1·2호 모두 … 동일 과세」 — **서식과 어긋난다** |

⇒ **회귀는 아니다**(PR #1212 이전에는 §55① 누진이라 더 틀렸다). 다만 「가목 10%는 도달 불가」
라는 근거가 **불완전**했다. 우리나라 중소기업의 해외상장주식이면 10%가 맞고 현행은 20% —
**과대과세** 방향이다. SME 입력이 없어 지금은 표현할 수 없다(D-2·D-3과 같은 모양).
⇒ **별도 판단 필요.** 이 계획서에서 고치지 않는다.

> 1. 양도차익: … 양도가액에서 제97조에 따른 필요경비를 공제하여 계산
> 2. **양도소득금액**: 제1호의 양도차익에서 제95조에 따른 장기보유 특별공제액을 공제하여 계산

### 2.2 법 §102 — 구분계산 및 통산

> ① 양도소득금액은 다음 각 호의 소득별로 **구분하여** 계산한다. 이 경우 소득금액을 계산할 때
> 발생하는 결손금은 **다른 호의 소득금액과 합산하지 아니한다.**
> 1. 제94조제1항제1호ㆍ제2호 및 제4호에 따른 소득
> 2. **제94조제1항제3호에 따른 소득**
> 3. 제94조제1항제5호에 따른 소득
> 4. 제94조제1항제6호에 따른 소득
>
> ② 제1항에 따라 양도소득금액을 계산할 때 **양도차손이 발생한 자산이 있는 경우에는 제1항
> 각 호별로** 해당 자산 외의 다른 자산에서 발생한 양도소득금액에서 그 양도차손을 공제한다.
> 이 경우 공제방법은 양도소득금액의 세율 등을 고려하여 **대통령령으로 정한다.**

🔑 「제1항 **각 호별로**」 ⇒ 통산은 **호 내부에서만**. 주식(2호)과 기타자산(1호)은 통산 금지.
엔진의 `basicDeductionGroup`(`"stock"` / `"real_estate_and_other_asset"`)이 이 호 구분과
**정확히 일치**한다 — 새 축을 만들 필요가 없다.

### 2.3 영 §167의2① — 통산 방법 (위임 수령)

> ①법 제102조제2항의 규정에 의한 양도차손은 다음 각호의 자산의 양도소득금액에서 **순차로** 공제한다.
> 1. 양도차손이 발생한 자산과 **같은 세율을 적용받는 자산**의 양도소득금액
> 2. 양도차손이 발생한 자산과 **다른 세율을 적용받는 자산**의 양도소득금액. 이 경우 다른 세율을
>    적용받는 자산의 양도소득금액이 2 이상인 경우에는 각 세율별 양도소득금액의 합계액에서
>    당해 양도소득금액이 차지하는 비율로 **안분하여** 공제한다.

② 감면소득금액이 포함된 경우 순양도소득금액:감면소득금액 비율로 안분 (전문은 §6.4 참조).

### 2.4 법 §103 — 기본공제

> ① 양도소득이 있는 거주자에 대해서는 다음 각 호의 소득별로 **해당 과세기간의** 양도소득금액에서
> **각각 연 250만원**을 공제한다.
> 1. 제94조제1항제1호ㆍ제2호 및 제4호에 따른 소득. 다만, 제104조제3항에 따른 미등기양도자산의
>    양도소득금액에 대해서는 그러하지 아니하다.
> 2. **제94조제1항제3호에 따른 소득**
>
> ② 제1항을 적용할 때 … **감면소득금액 외의 양도소득금액에서 먼저 공제**하고, 감면소득금액 외의
> 양도소득금액 중에서는 **해당 과세기간에 먼저 양도한 자산의 양도소득금액에서부터 순서대로 공제**한다.

## §3 결함 상세 — 전부 프로브 실측

### 3.1 D-A — §102② 통산 미구현 (과대과세 1,000,000)

| 프로브 | 입력 | `totalTransferIncome` | `totalCalculatedTax` |
|---|---|---:|---:|
| P-A | 이익 단독 | 10,000,000 | 1,500,000 |
| **P-B** | **이익 + 손실** | **5,000,000** | **1,500,000** ← 이익 단독과 **동일** |

`stock-transfer-aggregate.ts:434`가 `totalTransferIncome`은 음수를 합산해 5,000,000으로 줄이는데,
`:439`의 `totalCalculatedTax`는 **종목별 `calculatedTax`를 그대로 더한다**. 손실 종목의
`calculatedTax`는 0이므로 세액이 전혀 줄지 않는다. **표시 소득과 세액이 어긋난다.**

법령대로면: 통산 후 소득금액 5,000,000 − 기본공제 2,500,000 = 과세표준 2,500,000 × 20% = **500,000**.
⇒ **1,000,000 과대과세**.

### 3.2 D-B — 음수 `totalTransferIncome` 노출

P-C(손실 단독): `totalTransferIncome = -5,000,000`.

부동산 정본은 clamp한다 — `multi-parcel-transfer.ts:478`:
```ts

const totalTransferIncome = Math.max(0, parcelResults.reduce((sum, r) => sum + r.transferIncome, 0));
```
주식 aggregate에는 이 clamp가 없다. 신고서식(`StockFilingFormTableHelpers.ts:459,470`)이
이 값을 그대로 쓰므로, 다종목 모드가 살아나면 **서식에 음수 소득금액**이 찍힌다.

### 3.3 D-C — `basicDeductionByGroup` 표시 ↔ 적용 불일치

P-E(이익 1건 + 손실 3건):

## §6 설계

### 6.1 §102② 통산 — 정본 재사용 (설계 A 권장)

**부동산에 이미 완전 구현체가 있다** — `offsetLosses`(`transfer-tax-aggregate-helpers.ts:173-260+`).
그룹 내(1호) → 잔여를 타군 pro-rata 안분(2호) → 잔여 차손 소멸(이월 불인정)까지 영 §167의2①을
그대로 따른다. [[feedback_sibling_path_already_implements_rule]]가 정확히 이 상황이다.

| 설계 | 내용 | 평가 |
|---|---|---|
| **A** | `offsetLossesCore`를 **무의존 leaf로 추출** — `{income, rateKey, exempt}[]` → `{fromSame[], fromOther[], incomeAfterOffset[], rows[], unusedLoss}`. 부동산 `offsetLosses`는 propertyId 매핑 **어댑터로 축소**, 주식 aggregate가 같은 코어 호출 | ✅ **권장** — 단일 소스. [[feedback_ui_engine_dual_truth_avoidance]] |
| B | 주식에 별도 구현 (~80줄 복제) | ❌ dual truth. 한쪽만 고쳐지는 드리프트가 이 저장소의 반복 실패 패턴 |

⚠️ **설계 A는 부동산 정본을 건드린다** — 회귀 위험은 §9.1에서 별도로 덮는다.

주식의 `rateKey`는 **Q-1 확정에 따라 세율 값 4종**(`"10" | "20_25" | "20" | "30"`)이다.
`(taxCategory, isSmallMediumEnterprise, isShortTermHolding)`을 이 4값으로 **매핑하는 함수**를
`applyStockTaxRate`와 **같은 파일**에 두어 세율 분기와 축 분기가 갈라지지 않게 한다
([[feedback_shared_predicate_argument_parity]] — 술어 공유만으로는 부족하고 인자 동일성까지 맞춰야
한다). 기타자산 그룹(51·52 누진)은 서식이 명시적으로 제외하므로 이 축에 넣지 않는다.

✅ **Q-3 확정에 따라 감면 분기는 코어에 올리지 않는다** — 영 §167의2②(감면분 안분)는
**부동산 어댑터에 남긴다**. 코어로 끌어올리면 주식이 쓰지 않는 분기를 떠안는다.

### 6.2 통산 삽입 위치 — 기본공제 배분 **앞**

§92②(§2.1)가 순서를 확정한다: 양도소득금액(통산 포함) → 기본공제 → 세율.

```
현행 aggregate 흐름                     수정 후
────────────────────────               ────────────────────────
STEP 1 rawItems (공제 최대 소진)        STEP 1 rawItems               (그대로)
                                        STEP 1.5 §102② 통산 ★신규
STEP 2 그룹별 소득 합산                 STEP 2 그룹별 소득 합산 (통산 후 기준)
STEP 3 기본공제 순차 배분 → 재계산      STEP 3 §103② 양도일 정렬 후 배분 ★D-D
```

`incomeAfterOffset[i]`가 STEP 3의 `income`을 대체한다. 종목별 세액은 이미
`applyStockTaxRate(taxBaseAfterDeduction, …)`로 **재계산**하는 경로가 있으므로(`:399-407`),
통산분을 과세표준에 반영하는 배관은 **새로 만들 필요가 없다** — `income`만 갈아끼우면 된다.

### 6.3 D-B — clamp 한 줄

```ts
// 통산 후 합계가 음수면 과세 소득은 0이다 (결손금 이월은 양도소득에 없다 — §102②).
const totalTransferIncome = Math.max(0, processedItems.reduce((s, r) => s + r.transferIncome, 0));
```
부동산 정본(`multi-parcel-transfer.ts:477-481`)과 **주석까지 대칭**으로 맞춘다.

⚠️ `aggregateCore`에는 **두 개의 return 경로**가 있다(`each_item`/단건 `:301`, `aggregate` `:434`).
**양쪽 모두** 고쳐야 한다 — 한쪽만 고치면 `deductionMode`에 따라 답이 갈린다.

### 6.4 D-D — 양도일 정렬

```ts
// §103② — 「해당 과세기간에 먼저 양도한 자산의 양도소득금액에서부터 순서대로 공제」.
// 입력 순서가 아니라 **양도일** 순서다. 동일 양도일은 법문에 규정이 없어 입력 순서로 안정 정렬(Q-2).
const order = inputs
  .map((inp, i) => ({ i, d: inp.transferDate.getTime() }))
  .sort((a, b) => a.d - b.d || a.i - b.i)
  .map((x) => x.i);
```
배분 루프를 `order` 순으로 돌되 **결과 배열은 입력 순서를 유지**한다(결과뷰·신고서식이
입력 순서를 전제하므로). 즉 순회 순서와 출력 순서를 분리한다.

⚠️ 감면소득금액이 있으면 §103② 전단이 **그것보다 먼저** 걸린다 — Q-3 확정 후 반영.

### 6.5 D-E — 부담부증여 루프

Q-4 확정 전에는 설계를 고정하지 않는다. 방향 후보만 기록:

  세액은 맞아지나 **오류 처리 계약이 바뀐다**(§4 Q-4).

  다음 호출에 넘김. 계약 변경은 없으나 **§102② 통산은 여전히 불가**(호출 간 손실 공유 불가).

⇒ (가)가 법령상 옳다. 다만 UI 시니어 판단이 선행되어야 한다.
