# 다건 계산 — 상속·증여 §164 기준시가(②)를 조용히 버린다

> **출처**: `redev-successor-inherit-right-no-sec164.plan.md` §4 V-2′(#2876) · `redev-companion-sec164-carry.plan.md` §4 V-2(#2882) — 「다건(`/api/calc/transfer/multi`) 측정 안 함」.
> **검증 깊이**: L3 — 세액이 바뀐다(또는 막힌다). 재개발은 다건이 이미 막는다 — 결함은 **일반** 상속·증여 주택·토지에서 나왔다.

## 0. 결론

| 축 | 답 |
|---|---|
| 재개발(원조합원·승계 완공 아파트·입주권) | **해당 없음.** 다건 ⑧ `validateMultiSupportedMode`(`lib/calc/multi-transfer-tax-validate.ts:127`·`:141`)가 「단건 계산기에서만 지원」으로 막고, ⑫ `MULTI_REJECT_RULES`(`lib/api/transfer-tax-schema-multi-refines.ts:57`·`:61`)가 `propertyType`을 400으로 거절한다(실측 §1.3). #2876·#2882의 규칙은 다건에 닿지 않는다 |
| 일반 상속·증여 주택(2005.4.30. 전) · 토지(1990.8.30. 전) | **②를 버린다.** 다건 ④ `buildPropertyPayload`(`lib/calc/multi-transfer-tax-api.ts:243`)는 상속이면 `fixedAcquisitionPrice ‖ publishedValueAtInheritance`(①)만 `acquisitionPrice`로 싣고 §163⑨ 운반(`inheritedAcquisition`·`inheritedHouseValuation`·`pre1990Land`)이 없다. ⑫는 앞의 둘을 거절한다(`:81`·`:82` 「상속 취득가액 평가(보충적평가·환산)는 단건 계산기에서만 지원됩니다」). 그런데 ⑧ 다건 가드는 ①이 있으면 통과시켜 **화면에 ② 칸이 보이고 채워도 계산에서 빠진다** |

- 법: 소득세법 시행령 §163⑨ 단서 1호(1990.8.30. 전 상속·증여 토지 = max(평가액, §164④))·2호(건물 기준시가 고시 전 상속·증여 건물 = max(평가액, §164⑤~⑦)). 다건·단건을 가리지 않는다.

## 3. 변경 계획 (Q 전부 a 기준)

1. ⑧ `validateMultiSupportedMode` — 상속·증여 ∧ ② 입력 있음(`sec164HouseStatus`·`sec164LandStatus`·`sec164CommercialStatus` 중 하나라도 `filled > 0` — 단건 ④·⑧과 같은 단일 소스 `lib/calc/sec164-required-fields.ts`) → 새 문구 상수(`multi-transfer-support-messages.ts`).
   - 상가(§164⑥ `sec164CommercialStatus`)는 다건이 `commercial_building`을 이미 막는다 — 조건에 넣어도 먼저 걸린다(구현 때 확인).
   - D2(건물 상속 + 토지 매매)·축 B 지분 카드의 ② 경로는 다건이 따로 막는지 구현 전에 잰다(확인 필요).
2. ⑫ — 변경 없음(`inheritedAcquisition`·`inheritedHouseValuation`는 이미 거절). `pre1990Land`는 1990 환산(매매) 경로가 쓰므로 거절하지 않는다 — 다건 ④가 §163⑨ 토지 ②로는 싣지 않음을 anchor로 고정한다.
3. 테스트 — anchor(주택 상속·증여 · 토지 · ② 비움 통과 · 재개발 기존 차단) → mutation → 회귀 → tsc/eslint → Playwright(다건 화면에서 ② 채운 상속 주택 → 계산 막힘 · 요청 없음).
