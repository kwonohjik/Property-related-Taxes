## 3. 결정 요청 (Q 레지스터)

**Q-1 증여 지분의 상한(D-1)** — **a) 일반 증여는 증여일(취득일)로 자른다(권장).** b) ⑫와 같은 넓은 상한을 유지한다.
- a 근거: 공제율 거주는 증여받은 날부터의 본인 거주다. 표2 대상 판정의 증여 전 통산은 별도 칸이 맡는다.
- 이월과세는 지금처럼 증여자 취득일 기준으로 둔다(법규과-1660).
- ⑫ 자체(API 입력 검사)는 바꾸지 않는다. 느슨한 것이 의도다(⑧ 통과 ⇒ ⑫ 통과).

**Q-2 취득 전 거주(D-2)** — 취득일이 다른 지분이 있을 때만의 문제다.
- 구간 입력: **④가 지분별로 겹친 개월을 계산해 컴패니언에 실어 보낸다(권장).** 서버는 직접 값을 우선하므로 추가 변경이 없다.
- 직접 입력: **a) ⑧로 구간 입력을 요구한다(권장).** b) 승계를 유지하고 「거주 시점이 지분별로 다를 수 있다 — 확인 필요」를 고지한다(세액 불변). c) 0개월로 계산하고 고지한다.
- a 근거: 사실을 물을 수 있으니 물으면 모름 자체가 없어진다. 취득일이 같은 지분(일반적인 경우)에는 아무것도 묻지 않는다.
- b는 `second-share-card` Q-1의 「복사 + 고지」 선례와 같고 입력 부담이 없지만, V-3에서 112,046,000 차이가 나는 값을 그대로 낸다.
- c는 「모름 = 혜택 불성립」 원칙에 맞지만, 사실을 묻지 않고 0을 정하는 셈이다.
- API 직접 호출에서 값이 없고 기산일이 다르면 0개월로 둔다(호출자가 값을 보낼 수 있다).

**Q-3 「그 보유기간」을 지분별로 읽는 판단(#2813 Q-2 a)** — **a) 유지하고, 취득일이 다른 지분 결과에 「지분별 보유기간으로 판정 — 정면 해석례 미확보, 확인 필요」를 고지한다(권장).** b) 유지하고 고지하지 않는다. c) 주택 전체 기준으로 바꾼다.
- a 근거: 근거가 없는 판단이 세액을 크게 가른다. c는 근거 없이 비과세 쪽으로 넓힌다.
