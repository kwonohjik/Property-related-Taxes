# 승계조합원 완공 아파트 — 결과 화면의 「권리가액」 문구 정정

> **출처**: `redev-successor-apt-estimate.plan.md`(#2940)의 별건 후보 1. 종전부터 있던 표시 결함이고, #2940은 추계 3종 경로만 고쳤다.
> **깊이**: L2. 결과 화면과 계산명세서의 문구만 바뀐다. 세액·엔진 값은 바뀌지 않는다.

## 0. 결론

1. **지금**: 승계조합원 완공 APT를 실거래가·증여·상속·부담부증여로 계산하면, 결과 화면과 계산명세서가 **§166 안분 구조의 문구**를 그대로 쓴다. 승계 계산은 안분이 아니라 단순 차감이다(`redevelopment-successor.ts`). 값은 맞고 문구만 틀리다.
2. **틀린 문구는 세 묶음**이다(1장 실측).
   - ① 결과 카드의 단순 차감 줄: 「− **권리가액(상속·증여 평가액)** 450,000,000」. 매매 승계에서는 상속·증여 평가액이 아니고, 어느 원인이든 권리가액이 아니다.
   - ② 결과 카드의 3분할 표(인가후 칸): 「§166②1호 안분 (**권리가액/분양가**)」 · 「안분 취득가액(**=권리가액**)」. 승계는 안분하지 않는다.
   - ③ 계산명세서의 양도가액·취득가액 행: 「920,000,000 × (**0 ÷ 0**) = 920,000,000 (분양가 안분 — 권리가액 비율)」 · 「의제 = **권리가액** = 450,000,000 (§166②1호 안분 분자)」 · 인가전 행 「의제 양도가액 = 권리가액 = 0」.
3. **이미 맞는 곳**: 추계 3종(감정가액·매매사례가액·환산)은 #2940에서 고쳐서 카드의 줄과 명세서의 취득가액·필요경비 행이 승계용 산식이다. 명세서의 행 이름(「② 승계조합원 신축APT (단순 차감)」)과 필요경비·양도차익·총차익·장기보유공제·소득금액 행의 산식은 맞다.
4. **권장**: Q-1 (a) 원인 불문 중립 문구 · Q-2 (a) 3분할 표는 두고 승계용 문구로 교체 · Q-3 (a) 명세서 양도가액·취득가액 행도 승계용 산식으로.
5. **작업량**: 결정 후 약 반나절. 카드 1곳 + 명세서 빌더·오버라이드 2곳 + anchor.

## 1. 실측 (2026-11-06 · probe `keep/probe-v34.test.tsx`)

시료는 #2940 route anchor와 같다: 입주권 승계 2020-04-15 · 준공 2022-12-02 · 양도 2023-02-16 920,000,000 · 승계 취득가액 450,000,000. 실제 route 응답의 `redevelopmentDetail`을 결과 카드와 명세서 빌더에 넣어 문자열을 모았다.

| 취득 원인 | 양도차익 | 카드 단순 차감 줄 | 카드 3분할 표 인가후 칸 |

| 행 | ② 승계조합원 신축APT 칸의 산식 | 판정 |
|---|---|---|
| 양도가액 | 「920,000,000 × (0 ÷ 0) = 920,000,000 (분양가 안분 — 권리가액 비율, 1원 미만 절사)」 | 🔴 틀림 |

| 취득가액 ① 인가전 / ③ 청산금 | 「실제 취득가액 = 0 (실가 모드)」 · 「의제 = 청산금 = 0 (§166②1호 안분 분자)」 | 🔴 틀림 |

- 양도가액·취득가액 행의 **합계 줄 설명**(「분할 표시는 §166 — 인가전(권리가액 의제)·인가후(분양가 안분)·청산금(분양가 안분)이며…」)은 `DetailedStatementRedevOverrides.ts:304·326`의 상수 문구다. 승계 게이트가 없다(코드 확인 · 호출부 `DetailedStatementLateStages.ts:272` 조건은 `redevelopmentDetail` 존재뿐). 이 합계 줄 문구를 화면에서 실제로 읽은 것은 아니다 → V-1.
- 엔진은 값을 정확히 낸다. `apportionedAcquisition = successorAcquisitionPrice`(`redevelopment-successor.ts:187`)는 매매 실지거래가액 · 증여 신고가액 · 상속개시일 평가액 · 부담부증여 채무비율 안분액이고, 엔진 주석도 「§166④ 평가액(권리가액)으로 대신하지 않는다 … 승계인의 취득가액(§97①1호 가목 · 시행령 §163⑨)」이라고 적는다.

## 2. 설계 (Q 권장안 기준)

1. **카드 단순 차감 줄**(`RedevelopmentDetailCard.tsx:289`): 「− 권리가액(상속·증여 평가액)」을 「− **취득가액**」으로 바꾼다. 줄 제목 「단순 차감 산식 (§166 안분 우회)」은 그대로 둔다. 한 줄 풀어쓰기 규칙(변수 약어 금지)은 지킨다.
2. **카드 3분할 표**: 승계일 때만 인가후 칸 안내문을 「소득세법 시행령 §162①4호 (안분 없음)」으로, 행 이름을 「양도가액」 · 「취득가액」으로 바꾼다. 인가전·청산금 칸의 행 이름 「의제 양도가액(=권리가액)」도 승계에서는 「미적용」 안내로 바꾼다(값 0은 그대로).
3. **명세서**: 승계일 때 `buildRedevTransferFormula` · `buildRedevAcquisitionFormula`가
   - 인가후 칸: 양도가액 「920,000,000 (승계조합원 — 단순 차감, 안분 없음)」 · 취득가액 「승계 취득가액 = 450,000,000」(추계면 이미 있는 승계 산식 그대로).
   - 인가전·청산금 칸: 「미적용 — 승계조합원은 §166 안분을 하지 않는다」.
   - `DetailedStatementRedevOverrides.ts`의 합계 줄 설명도 승계용 한 문장으로 갈아 끼운다.
4. **엔진·④·⑧·⑫**: 바꾸지 않는다(문구만). 원인별 라벨이 필요하면(Q-1 b) 엔진 echo에 `acquisitionCause` 한 필드를 더한다.

## 3. 결정 게이트

### Q-1 「취득가액」 줄의 이름을 원인별로 가르는가

- (a) **원인 불문 중립 이름 「취득가액」**(권장) — 매매는 실지거래가액, 증여는 신고가액, 상속은 평가액, 부담부증여는 채무비율 안분액이라 한 이름으로 어긋남이 없고 엔진 echo 추가가 없다.
- (b) 원인별 이름(「실지거래가액」 · 「증여 신고가액」 …) — 엔진 결과 타입에 `acquisitionCause`를 더해야 하고(⑦ 타입 1필드), 부담부증여의 안분액 이름이 따로 필요하다.

### Q-2 카드 3분할 표를 승계에서 어떻게 하는가

- (a) **표는 두고 승계용 문구로 교체**(권장) — 표가 보여 주는 장기보유공제(보유기간·율)가 단순 차감 상자에는 없다. 표를 숨기면 그 정보가 사라진다.
- (b) 표를 숨긴다 — 상자만 남아 화면은 단순해지지만 장기보유공제 표시가 없어진다.

### Q-3 명세서의 양도가액·취득가액 행

- (a) **승계용 산식으로 교체**(권장) — 위 2.3.
- (b) 행 이름만 두고 산식은 비운다 — 산식 없는 행이 생긴다.
