## 0. v1 → v2 개정 요지

v1은 **"§94①1호가 토지와 건물을 병렬 열거하므로 취득일이 다르면 세율도 파트별"** 을 전제로
주택 케이스에서 9,594만원 과대과세를 주장했다. 이 전제는 **조세심판원이 정면으로 기각**했다.

> **조심 2024인3140 (2024.09.03) — 기각.** 청구인이 "§94①1호가 토지·건물을 별개 과세대상으로
> 구분하므로 세율도 구분 적용해야 한다"고 주장했으나, "§104①3호가 1년 미만 주택에 70%를
> 적용하도록 하고 **같은 항 2호가 주택에 '이에 딸린 토지로서 대통령령으로 정하는 토지'를
> 포함하도록 명시**"함을 근거로 배척.

⇒ **주택 + 배율 내 부수토지에 대해서는 현행 엔진(주택 보유기간 단일 세율)이 정답이다.**
v1 §1.1 케이스 A의 "9,594만원 과대"는 **오류**였다. 아래 §4에 폐기 내역을 남긴다.

다만 심판례를 정독하면 **다른 갭 3건이 드러난다**(§3). v2는 그 3건으로 범위를 재정의한다.

### 1.1.1 배율 3축 — 조문은 다르고 수치는 같다

같은 "주택 정착면적 × 배율"이 **세 개의 독립된 축**에서 각각 위임된다. 축을 섞어 인용하면 안 된다.

| 축 | 근거 조문 | 위임(배율) | 초과분의 취급 |
|---|---|---|---|
| **비과세** | §89①3호 | 영 **§154⑦** | 1세대1주택 비과세 **제외** |
| **세율** | §104①2·3호 괄호 | 영 **§167의5** | 주택 단기세율 **미적용** |
| **비사업용 토지** | **§104의3①5호** | 영 **§168의12** | **비사업용 토지 → 누진 +10%p 중과(§104①8호)** |

배율 수치는 세 조문 모두 **3/5/5/10로 동일**하므로 **판정은 1회, 소비는 3축**이면 된다.
엔진에도 이미 세 구현이 흩어져 있다 — `appurtenant-land-rate.ts:appurtenantLandMultiplier`(세율 축) ·
`non-business-land/urban-area.ts:getHousingMultiplier`(비사토 축, §168의12 명시).

**도출 규칙**

1. **주택 + §167의5 배율 내 부수토지** → 세율 보유기간은 **주택부수토지로서의 보유기간**.
   토지를 아무리 오래 보유했어도 주택이 신축된 날부터 기산한다.
2. **배율 초과 토지** → 주택부수토지가 아니다. 나아가 **§104의3①5호가 이를 명문으로
   비사업용 토지로 규정**한다 ⇒ 토지 자체 보유기간 + **누진 +10%p 중과** + 1세대1주택 비과세 제외.
   ⚠️ 단 §104의3① 본문이 "해당 토지를 소유하는 기간 중 **대통령령으로 정하는 기간** 동안"이라
   **정의요건(배율 초과) + 기간요건(영 §168의6) 2단**이다. 배율 초과만으로 곧바로 비사토가 아니다.
   조심 2024서2826도 두 요건을 각각 판단했다.
3. **용도변경**(건물의 동일성 유지)은 취득이 아니므로 **당초 취득일** 기준 — (8)(9).
   신축(자산의 신규 생성)만 기산일이 새로 잡힌다.
4. 위 1은 **주택 전용 규칙**이다 — §104①2호 괄호가 "주택"만 지목한다. 상가·일반건물의 부속토지에는
   대응 규정이 없다.

### 1.3 🔶 여전히 미검증

- **G-3**(§3) — "주택부수토지**로서의** 보유기간"이 `max(토지 취득일, 주택 취득일)`인지, 아니면
  주택 보유기간을 그대로 승계하는지. 확보한 해석·재결례는 **전부 "토지가 먼저, 주택이 나중"** 사안뿐이라
  반대 방향(토지를 나중에 취득)에 대한 직접 판단이 없다. 문언상 `max`가 자연스럽지만 단정 금지.
- 조심 2024인3140에서 **배율 초과 60㎡의 처리**는 처분청 경정 내역(표1이 `ㅇㅇㅇ` 마스킹)에서
  직접 확인되지 않는다. 처분청 의견이 "쟁점토지 **중 600㎡에 대해서는** 70%"라고 한정한 데서
  초과분은 별도 취급으로 추론되나, **명시 판단은 아니다**. (다만 초과분이 §104의3①5호에 따라
  비사업용 토지라는 점은 **법문 자체로 명확**하므로 이 재결례에 의존하지 않는다.)
- ~~③ 영 §168의12 1호 각목 원문 미확인~~ → **✅ 해소 (2026-07-30)**. 법제처 API는 여전히 표를
  반환하지 않지만, **조심 2024서2826(2025.5.13)이 관련법령 절에 전문 인용**한 것으로 확보했다:
  가.수도권 주거·상업·공업 3배 / 나.수도권 녹지 5배 / 다.수도권 밖 5배. 엔진 구현
  (`urban-area.ts:getHousingMultiplier`)과 일치하며, 같은 재결례가 **개정 연혁·부칙 경과조치**까지
  인용해 **G-5**를 낳았다.

## 5. 설계

### 5.1 G-1 — 비주택 파트별 세율

**진입 게이트** (전부 참일 때만, 하나라도 거짓이면 기존 단일 경로)

1. `splitDetail != null`
2. **`propertyType !== "housing"`** ← v2 신설. 주택은 §104①2호 괄호가 지배하므로 진입 금지
3. `selfOwns === "both"` (단독 소유 파트는 `transfer-tax.ts:652`가 이미 처리)
4. `!forceFlatRate20 && !suppressShortTermRate` (조특법 §98①1호·P3 특칙 세율 강제)
5. 부담부증여 아님 (§159 안분으로 총액 override — `transfer-tax-api-split.ts:38-44`와 동일 사유)
6. **파트별 확정세율이 서로 다름**

> 게이트 6은 "세율**군** 상이"가 아니라 **확정세율·누진공제쌍 상이**로 판정한다. 세율군으로 두면
> 1년미만(50%)+1~2년(40%) 조합이 둘 다 `short_term` 그룹이라 누락된다.
> 게이트 6이 **회귀 0의 핵심**이다 — 세율이 같으면 분해해도 결과가 같으므로 진입하지 않는다.

**계산** (`computeSplitPartTax`)

```
① 파트별 양도소득금액 = max(0, part.gain) − part.longTermDeduction     // splitDetail 기존 값
   ※ 자산 단위 감면 소득공제(§99의3 등)가 걸리면 잔액을 partIncome 비율로 안분,
     floor 잔액은 마지막 파트 흡수 (memory `feedback_floor_residual_absorption`)
② 기본공제 배분 = allocateBasicDeduction(파트 2건, basicDeduction, "MAX_BENEFIT")  // 기존 헬퍼
③ partTaxBase = max(0, partIncome − allocatedBasic)
   ※ 불변식 Σ partTaxBase === taxBase — 어긋나면 throw (조용한 오답 금지)
④ §104⑤2호 = Σ calcTax(partTaxBase, rates, { ...taxRateInput, acquisitionDate: 파트 기산일 })
⑤ §104⑤1호 = applyGeneralProgressive(taxBase, rates)                   // 기존 헬퍼
⑥ 산출세액 = MAX(④, ⑤)
```

파트 기산일: 건물 = 현행 자산 단위 로직 그대로 / 토지 = `landAcquisitionDate` (G-4에서 통산 확장).

`splitDetail.holdingYears`는 **연 단위**라 24개월 경계에 못 쓴다 — `calculateHoldingPeriod`를
파트별로 새로 호출한다(민법 초일불산입 동일).

### 5.2 G-2 — 주택 배율 초과 토지를 비사업용 토지로 분리 (경로 B)

**진입 게이트**

```
propertyType === "housing" && splitDetail != null
  && buildingFootprintArea > 0 && acquisitionArea(토지면적) > 0
  && excessArea > 0     // 토지면적 − 정착면적 × 배율(3/5/5/10)
```

**분리 후 3파트 모델** — 기존 2파트(토지·건물)를 **3파트**로 확장한다.

| 파트 | 세율 | 비과세 | 장특 |
|---|---|---|---|
| 건물(주택) | 주택 보유기간 — 2년 미만 시 단기 70%/60% | 1세대1주택 대상 | 표1/표2 |
| 토지 — 배율 내(부수토지) | **건물과 동일**(§104①2호 괄호) | 1세대1주택 대상 | 건물과 동일 |
| **토지 — 배율 초과** | **누진 + 10%p**(§104①8호, 토지 본래 보유기간) | **제외** | 표1(토지 본래 보유기간) |

그 후 §5.1 ④⑤⑥ 동일 — §104⑤ 후단("한 필지의 토지가 비사업용 토지와 그 외의 토지로 구분되는
경우에는 **각각을 별개의 자산으로 보아** 산출세액을 계산")이 **이 3파트 분해의 직접 근거**다.

**배율 판정 헬퍼는 신규로 만들지 않는다** — `non-business-land/urban-area.ts:getHousingMultiplier`
(§168의12 명시 구현)를 재사용한다. memory `single-source-engine-helper` ·
`feedback_sibling_path_already_implements_rule`.

**필요 입력**: `buildingFootprintArea` · `appurtenantLandZone`(또는 `zoneType`+`isMetropolitan`) ·
토지면적. 셋 다 **엔진 입력·API 전송 경로에 이미 존재**(`transfer-tax.types.ts:551·566·579`,
`transfer-tax-api.ts:683-691`) ⇒ 신규 엔진 필드 0.
**단, 주택 split 모드 UI에서 이 칸들이 노출되는지 Design 단계 실측 필요** — 미노출이면 ⑤UI 추가
(memory `feedback_ui_gate_removes_sole_input_path`).

**미입력 시 분리하지 않는다** — 배율 판정 불가 시 전량 부수토지로 두는 현행 fallback
(`appurtenant-land-rate.ts:267-281`)과 같은 방향. 다만 이는 **납세자 유리 방향**이므로
자동 안분 fallback 금지 정책과의 정합을 Design에서 재확인할 것.

**선결 과제 — 자산 내부 비사토 부분 분리 표현**: 현행 `isNonBusinessLand`는 자산 단위 boolean이라
"주택 자산 안의 토지 일부만 비사토"를 표현할 수 없다(§3 구조적 장애물). 3파트 모델을
`splitDetail`에 담을지, 별도 결과 타입을 둘지가 설계의 핵심 결정 지점이다.

초과분 자산에 `primaryContextForCompanionRate: undefined`를 넣어 일반 경로로 흘려보낸다
→ 토지 본래 보유기간 기준 §104①이 적용된다. `excessRate` 참조처는 테스트
(`new-construction-bundled-case-28.test.ts` T-18·T-21)뿐이다.

⇒ `excessRate`는 죽은 필드이고 그 값(40% 고정)은 소비되면 오답이 된다. G-2 착수 시
**필드 삭제 또는 실사용** 중 택일. 관련 테스트 2건도 함께 정리 대상.

⚠️ **다만 이것으로 "경로 A가 정확하다"고 결론지으면 안 된다**(v2 초판의 오류). 세율은 누진이
적용되지만 **§104의3①5호 비사토 중과(+10%p)는 자동 적용되지 않는다** — 초과분 자산의
`isNonBusinessLand`가 사용자 입력값을 그대로 상속하기 때문이다. 어차피 경로 A는 잘못된
입력 방식(§3 G-2 방침)이므로 이 경로를 정답 기준으로 삼지 않는다.
