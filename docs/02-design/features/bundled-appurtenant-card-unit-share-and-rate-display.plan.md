## 0. 요약

- **O-8(역방향 12억 단위 재배분 `h1`)은 «독립 재도출 불가»가 아니다.** 이전 세 계획서가 한계로 남긴 `h1` 값을 **정수까지** 손 계산으로 도출했고 엔진과 일치했다(V-1~V-3). 법에 정해진 것은 «단위 합»(재산세제과-915 방식)이고, 카드별 분배(비례 · 잔액은 마지막 양수 조각)는 **구현 규약**이라는 점을 구분해 고정하면 한계가 풀린다. **코드 변경 없음 — anchor만 추가.**
- **O-10(중과 카드 줄 표시 vs 합계)은 실재한다.** 합계는 합쳐 입력한 값과 정수까지 같지만(V-4) **카드 줄의 세율 · 조항 · 산출세액(그리고 신고서 세율구분 코드)이 합계에 실제로 적용된 세율과 다르다**(V-5·V-6). 짝 주택이 단기(2년 미만)일 때 카드 줄이 «58% · 104-7-1»(또는 «40% · 104-1-2»)로 나오는데 합계는 주택 단기 60%를 걸었다. 합계(세액)는 정확하고 어긋나는 것은 **표시 필드**다.
- 근본 원인은 아직 **추적하지 않았다**(V-7 ⏳) — 구현 첫 단계. 합계가 흔들리면 중단하고 b안으로 전환한다(§5 Q-2).

## 1. O-8 — 역방향 12억 단위 재배분 값 (V-1~V-3)

시료는 `bundled-merge-date-appurtenant-card` anchor의 역방향 `SAM_REV`다: 첫 자산 = 부수토지 4억(200㎡ · 취득 2억), 짝 주택 `h1`(토지만 본인 · 같은 세대)의 토지 8억(200㎡ · 엔진 실측 취득가 2억), 건물 8억은 다른 세대원 소유, 총 양도가 20억, 정착면적 100㎡(한도 300㎡), 양도 2026-02-16.

| ID | 항목 | 결과 | 상태 |
|---|---|---|---|
| V-1 | **단위 구성** | 한도 내 토지 조각 = `h1` 토지분(양도차익 600,000,000) + `primary__appurtenant`(100㎡ · 100,000,000), 배율 초과분 `primary__excess` = 100,000,000(X). K1 규칙대로 짝 주택 토지가 한도를 먼저 쓴다(200㎡ + 100㎡ = 300㎡) | ✅ 실측 |
| V-2 | **독립 산식**(재산세제과-915 방식 + `allocateUnitExcessShares` 규약) | 안분율 = (총 양도가 20억 − 12억)/20억 = **40%**. 몫: `h1` = floor(100,000,000 × 600/700) = 85,714,285 · `primary__appurtenant` = floor(100,000,000 × 100/700) = 14,285,714 · 합 99,999,999 → 잔액 1원은 **마지막 양수 조각**에 → 14,285,715. 조각 과세 양도차익 = floor((조각 + 몫) × 40%) − 몫: `h1` = floor(685,714,285 × 0.4) − 85,714,285 = **188,571,429** · `primary__appurtenant` = floor(114,285,715 × 0.4) − 14,285,715 = **31,428,571** | ✅ 산식 |
| V-3 | **엔진 실측 대조**(과세 양도차익 = 장특 + 소득) | 합가 없음/2012: `h1` 113,142,857 + 75,428,572 = **188,571,429** · `primary__appurtenant` 18,857,142 + 12,571,429 = **31,428,571**. 합가 2020-01-01: 82,971,428 + 105,600,001 = **188,571,429** · 13,828,571 + 17,600,000 = **31,428,571**. 합가 2023-06-01: 45,257,142 + 143,314,287 = **188,571,429** · 7,542,857 + 23,885,714 = **31,428,571**. **합 = 220,000,000** = 안분(8억) 320,000,000 − X 100,000,000(**915 방식의 단위 합 — 몫 규약과 무관한 법 근거 오라클**). 합가 2025-01-01(합가 후 2년 미만): `primary__appurtenant`가 부분과세에서 빠져 단위 밖(100,000,000 전액 과세 · 장특 24,000,000 · 소득 76,000,000) → 조각은 `h1` 하나, 몫 = X 전부 → `h1` = floor(700,000,000 × 0.4) − 100,000,000 = **180,000,000** · 엔진 43,200,000 + 136,800,000 = **180,000,000** | ✅ 전부 일치 |

→ 이전 계획서의 V-10(«`h1` 값이 부수토지 카드 변화에 따라 바뀐다 — 독립 재도출하지 못했다»)의 답: **규칙대로**다. 2025에서 `h1`이 188,571,429 → 180,000,000으로 바뀌는 것은 부수토지 조각이 단위에서 빠지며 X 전부가 `h1` 몫이 되기 때문이다.

## 2. O-10 — 카드 줄 표시와 합계 (V-4~V-8)

| ID | 항목 | 결과 | 상태 |
|---|---|---|---|
| V-4 | **합계는 맞다** | `T_both`(주택·카드 모두 2025-01-01 취득 · 2주택 중과 · 양도 2026-06-15 · 한 장 100㎡): 합계 **724,350,000** = (900M + 200M − 2,500,000) × 60% × 1.1 = **합쳐 입력 단일 결과와 같다**(`appliedRate` 60% · `104-1-2` · 산출세액 658,500,000). `U_two`(카드 2014 옛 토지 · 주택 2025-01-01 · 2주택)도 724,350,000 | ✅ 독립 산식 일치 |
| V-5 | **카드 줄은 합계와 다르다 — 중과 카드** | `T_both`: `primary` 60% · 104-1-2 · 산출 538,500,000(합쳐 입력과 같은 종류) / **`c1` 58% · 104-7-1 · 산출 96,059,999**(= 누진 38% + 20%p). 그룹은 `short_term` 하나(`primary`+`c1`, 과표 1,097,500,000 · 60% · 658,500,000). 합쳐 입력은 한 줄 60%·104-1-2인데 카드 줄은 «중과 58%»다 | ✅ 실측 |
| V-6 | **카드 줄은 합계와 다르다 — 분리 배치 · 그룹 행** | `T_both_split`(200㎡ 카드 → `c1__appurtenant` + `c1__excess`): 합계 702,350,000(그룹 `short_term` 638,500,000 = 538,500,000 + **60,000,000(이내분 60%)** + 40,000,000(초과분 40%))인데 **`c1__appurtenant` 카드 줄은 40% · 104-1-2 · 산출 40,000,000**. `U_two`: 그룹 행이 **`multi_house_surcharge`(`c1`) appliedRate 0.58 · surchargeRate 0.2 · 산출세액 120,000,000**(= 200,000,000 × 60%) — 행 라벨은 «58% +20%p»인데 세액은 60%다 | ✅ 실측 · 행 라벨 렌더 ⏳ |
| V-7 | **근본 원인** | 카드는 단독 계산에서 **토지 단기 세율(40%)과 중과를 비교**하고(`transfer-tax-rate-calc.ts:594` §104⑦ 후단 비교 — `surchargeTaxST > shortTermTax`) 짝 주택이 중과면 일체과세(주택 단기) 분기를 끈다(`appurtenant-card-surcharge.ts`). 반면 합계는 집계가 호 버킷을 다시 합산해 주택 단기 60%를 건 값이다. 정확히 어느 단계가 카드 줄을 단독 값으로 두는지는 **추적하지 않았다** — 구현 첫 단계 | ⏳ 미확인 |
| V-8 | **합계 밖 표시면 — 이미 «참고값»이라는 설계가 있다** | 자산별 산출세액 `refCalculatedTax`는 «자산 단독 참고값이고 Σref ≠ 합계는 비교과세의 본질이라 설계상 의도»(`FilingFormTableAggregateHelpers.ts:326-330` · `transfer-tax-aggregate-helpers.ts` — ❌역안분 재제안 금지). **그러나 같은 줄의 세율·세율구분 코드까지 참고값은 아니다** — 신고서 자산 열이 `p.appliedRate`(58%)와 `resolveFilingRateCode(rateClause)`(`104-7-1` → `1-47` 중과 코드)를 그대로 싣는데(`FilingFormTableAggregateHelpers.ts:341-350`) 합계는 단기 60%(코드 `1-39`)다 | ✅ 코드 확인 |

**불변 사실(V-4 외)**: A1(중과만 · 단기 없음) 카드 줄은 합계와 같은 종류다(58% · 104-7-1) — 어긋나는 것은 **단기가 중과를 이기는 조합**뿐이다.

## 3. 판단과 설계

### O-8
D-1 **anchor만 추가**(코드 변경 없음) — `transfer.route.bundled-merge-date-appurtenant-card.anchor.test.ts`의 AN-5 «`h1` 값은 측정 일치만» 주석을 V-3 값으로 교체하고 `h1`·`primary__appurtenant`의 **과세 양도차익(장특 + 소득)** 을 4개 합가 시나리오에 정수로 고정, 그리고 **단위 합 = 220,000,000(법 근거 오라클)** 과 2025의 `h1` = 180,000,000. 세 계획서의 «한계 명시» O-8 행에 «해소 — 본 계획서» 표기.

### O-10 (Q-2 a 가정)
D-2 **카드 줄을 합쳐 입력과 같게** — 짝 주택이 단기(§104①2·3호 보유기간 2년 미만)면 부수토지 카드의 §104⑦ 후단 비교(및 분리 배치 이내분의 단기 세율)는 **주택 단기 세율(60%/70%)** 로 한다(부수토지는 «주택(이에 딸린 토지를 포함한다)»이라 §104⑦·① 후단 모두 주택 단기 세율 — 이미 합계가 이렇게 계산한다). 합계는 불변이고 카드 줄(세율 · 조항 · 산출세액 · 신고서 코드)만 합쳐 입력과 같아진다. 구현 위치는 V-7 추적 뒤 확정(후보: 카드가 단독 계산에 넘기는 입력의 단기 세율 기준).
D-3 **그룹 행 라벨** — 카드가 단기 호로 정합되면 `U_two`의 `multi_house_surcharge` 행이 `short_term`으로 옮겨 라벨도 따라간다(V-6). 따라가지 않으면 별도 항목으로 올린다(O-18).
D-4 **고지** — 카드 줄 값이 바뀌는 조합에서 기존 부수토지 카드 고지(`APPURTENANT_CARD_SURCHARGE_NOTICE`)의 «중과 규정(§104⑦ 세율·보유기간 2년 미만 세율 비교)을 적용했습니다»와 모순이 없는지 확인한다(문구 변경 필요 시 최소로).

**하지 않는 것**: 합계(세액) 변경 · `refCalculatedTax`의 합계 정합(역안분 — 재제안 금지) · 집계 호 버킷 합산 규칙 · 입력 필드 · Zod · API. 14 동기화 지점: 엔진 결과 필드 값만 바뀌고 필드는 늘지 않아 해당 없음(UI 표시는 기존 필드를 읽는다).

### 9.2 O-10 — 근본 원인 추적과 **계획 전제 붕괴** (Q-2 a 중단)

**V-9 근본 원인 확정(코드 읽기)**: 집계는 «해당 호 집합이 같은 자산»을 한 버킷으로 묶어 합산 과세표준에 대해 `calcTax`를 **한 번** 하되 **대표 단위(`members[0]`)의 입력**(`rateInput`)으로 한다(`transfer-tax-aggregate-group-tax.ts` — `calcTax(bucketBase, …, members[0].rateInput, members[0].mhResult)`). 부수토지 카드는 `propertyType: "land"`라 §104⑦ 후단 비교의 «단기세율»이 **토지 40%**(주택 60%가 아니다) — 중과를 따르는 카드는 일체과세(주택 단기) 분기를 끈다(`transfer-tax-rate-calc.ts:261`).
- **순방향**(주택이 첫 자산): 대표 = 주택 → 버킷이 주택 단기 60%로 계산되어 합계가 맞고, 카드 줄(단독 계산)만 어긋난다 = 이미 측정한 **표시 불일치**.
- **역방향**(부수토지가 첫 자산): 대표 = **부수토지 카드** → 버킷 전체가 카드 입력(토지 40% vs 중과)으로 계산되어 **합계가 달라진다**.

**V-10 순·역 총세액 불일치 실측**(`bundled-appurtenant-card-multi-house-surcharge` anchor의 A7 시료 — 주택 16억(취득 8억) · 주택 토지 200㎡ · 부수토지 4억(취득 2억) 200㎡ · 2주택 · 조정 · 양도 2026-06-15 — 에서 취득일만 바꿈. 순·역 입력은 같은 사실):

| 취득일(주택 · 카드) | 순방향 | 역방향 | 차 |
|---|---|---|---|
| 2014 · 2014 (장기) | 594,649,000 | 594,649,000 | **같다**(A7) |
| **2025 · 2025 (둘 다 단기)** | **636,350,000** | **616,561,000** | **19,789,000** |
| **2025 · 2014 (주택 단기 · 카드 옛 토지)** | **614,438,000** | **594,649,000** | **19,789,000** |

**V-11 어느 쪽이 맞는가 — 독립 산식**(2025 · 2025): 양도차익 주택 800,000,000 · 이내분 100,000,000 · 초과분 100,000,000, 과세표준 997,500,000(기본공제 2,500,000을 주택에). 주택 + 이내분은 §104⑦ 후단 «중과 vs 단기 큰 세액»: **단기 60%** = (800,000,000 + 100,000,000 − 2,500,000) × 60% = **538,500,000** · 중과 = 897,500,000 × 42% − 35,940,000 + 897,500,000 × 20% = **520,510,000** → 큰 쪽 538,500,000. 초과분(배율 초과 토지 · 1~2년) 100,000,000 × 40% = 40,000,000 → 산출 **578,500,000** → ×1.1 = **636,350,000 = 순방향**. 역방향 산출은 560,510,000 = 520,510,000(**중과로 계산**) + 40,000,000 → 단기 60%가 중과보다 큰데도 중과가 걸렸다 = **역방향 과소 19,789,000**. 주택 단기 · 카드 옛 토지도 같은 구조(순방향 614,438,000이 독립 산식과 같다).

**V-12 영향 범위**: 주택이 2년 미만이고 중과 대상이며 **부수토지가 첫 자산(역방향)** 이고 이내분이 있는 조합. 장기 보유(2년 이상)는 단기 후단 비교가 없어 순·역 같다(A7). 순방향은 값이 맞고 카드 줄 표시만 어긋난다(V-5·V-6).
