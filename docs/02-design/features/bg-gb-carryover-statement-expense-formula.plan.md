## 1. 현상 (실측)

시료: 일반건물(토지 + 건물 파트 둘 다 증여받음) · 부담부증여 시가 10억 · 채무 5억(채무비율 0.5) · 이월과세 · 당초 증여자 취득시 기준시가 토지 10,000,000 · 건물 40,000,000 · 양도일 2026-03-01. 시료는 `transfer.route.gb-bg-carryover-presumed-scenario-b.anchor.test.ts`를 따랐다. 모든 시료에서 ⑧ 이슈 0건 · 결과 A 채택.

### 1.1 방식 × 증여세 상당액 — 상세 명세서 「필요경비」 파트별 산식 (`perAsset`)

| 방식 | 증여세 상당액 | 슬롯 토지 / 건물 | 산입분 토지 / 건물 | 명세서 토지 줄 (적힌 값) | 적힌 산식의 값 |
|---|---|---|---|---|---|
| 감정가액(K-7) | 0 | 150,000 / 600,000 | — | 150,000 | 150,000 (정상) |
| 감정가액 | 2,000,000 | 650,000 / 1,100,000 | 500,000 / 500,000 | **650,000** | 150,000 |
| 감정가액 | 5,000,000 | 1,400,000 / 1,850,000 | 1,250,000 / 1,250,000 | **1,400,000** | 150,000 |
| 환산(K-5) | 2,000,000 | 650,000 / 1,100,000 | 500,000 / 500,000 | **650,000** | 150,000 |
| 실지(K-4) | 2,000,000 | 500,000 / 500,000 | 500,000 / 500,000 | 「필요경비 = 채무비율 안분 실비 (자본적지출·양도비) = **500,000**」 | 실비는 0 — 전부 산입분 |

- 산식 문구(감정가액 · 증여세 2M · 토지): 「필요경비 = 취득시 기준시가 × 채무액 / 증여재산 평가액 × 3% (개산공제, 소령 §163⑥) = 10,000,000 × 500,000,000 / 1,000,000,000 × 0.03 = **650,000**」 — 산식은 150,000을 만들고 적힌 값은 슬롯(개산공제 + 산입분). 건물 줄도 같다(40,000,000 × 0.5 × 0.03 = 600,000인데 1,100,000).
- 실지(K-4)는 산입분 500,000이 「자본적지출·양도비」로 라벨링된다.
- 필요경비 **합계**(감정가액 · 2M: 1,750,000)와 증여세 상당액이 없을 때(0)는 맞다. 방식(감정·환산·실지)과 무관하게 같은 함수가 같은 결함을 낸다.

### 1.2 원인 (코드로 확정)

- 파트별 산식은 `buildBgExpenseFormula(bg, a)`(`DetailedStatementBgFormulas.ts`)가 만든다. `a.estimatedDeduction`(= 개산공제 + 그 파트의 이월과세 증여세 산입분 — STEP 5.7 `burdened-gift-apportionment.ts`)을 마지막 값으로 그대로 적는다. 산입분(`bg.carryoverGiftTax.landApplied`·`buildingApplied`)을 읽지 않는다.
- 호출처는 두 곳뿐이다(전수 grep): `DetailedStatementGbFormulas.ts:577`(일반건물 파트 — **이월과세가 닿는 곳**)와 `buildBgSingleExpenseFormula`(단건 — `resolveBgSingleDisplay`가 이월과세를 제외하므로 닿지 않는다).
- 호출은 `cardBg(burdenedGift, p.propertyId)`가 고른 breakdown의 `perAsset.land`/`building`을 `a`로 넘긴다. 그래서 `a === bg.perAsset.land`로 어느 파트인지 알 수 있다.
- 같은 결함이 이미 고쳐진 곳: 카드(단건 #2679 · 묶음 #2669·#2674) — 파트별 순액 + 산입 줄. 이월과세 단건 상세 명세서는 자체 문구(「양도비 등 … + 증여세 상당액 800,000 — 이월과세 §97의2①3호·시행령 §163의2② = 1,700,000」)로 정상이다(#2679 측정).

## 2. 사용자 결정 (대기)

### Q-1 고칠 곳

- **(a) `buildBgExpenseFormula` 한 곳 (권장)**: 호출처 전부(일반건물 파트·단건)가 같은 함수를 쓰므로 한 번에 닫힌다. 파트 산입분이 없으면(`carryoverGiftTax` 없음) 출력이 종전과 문자 그대로 같다 → 기존 단언(`bg-presumed-acquisition-ui` 등)이 변하지 않는다.
- (b) 일반건물 호출처(`DetailedStatementGbFormulas.ts:577`)에서 따로 후처리: 함수가 둘이 되어 산식 단일 소스가 깨진다.

### Q-2 산식 모양

- **(a) 파트 순액으로 종전 산식을 그대로 적고, 뒤에 산입분을 더해 슬롯으로 맺는다 (권장)** — 이월과세 단건 명세서와 같은 문구 틀(「… + 증여세 상당액 N — 이월과세 §97의2①3호·시행령 §163의2② = 합계」):
  ```
  필요경비 = 취득시 기준시가 × 채무액 / 증여재산 평가액 × 3% (개산공제, 소령 §163⑥)
          = 10,000,000 × 500,000,000 / 1,000,000,000 × 0.03 = 150,000
          + 증여세 상당액 500,000 — 이월과세 §97의2①3호·시행령 §163의2②
          = 650,000
  ```
  실지(K-4)는 「채무비율 안분 실비 (자본적지출·양도비) = 0 + 증여세 상당액 500,000 … = 500,000」. 산입이 없으면 종전 문구 그대로.
- (b) 산입분이 0인 파트는 산입 줄을 생략하고, 실지에서 실비가 0이면 「필요경비 = 증여세 상당액 500,000 …」 한 줄로: 문구가 짧아지지만 경우가 하나 더 늘어난다.

## 3. 설계 (Q-1 a · Q-2 a 기준)

`buildBgExpenseFormula(bg, a)`:

1. 파트 산입분 `part = a === bg.perAsset.land ? cgt.landApplied : a === bg.perAsset.building ? cgt.buildingApplied : 0`(`cgt = bg.carryoverGiftTax`, 없으면 0).
2. `net = a.estimatedDeduction − part`. 기존 세 분기(실비 · 기준시가 모드 · 환산·매매사례·감정)는 **슬롯 대신 `net`** 으로 마지막 값을 적는다(분기 판정은 그대로 — 환산 단서 나목 `swapDirect`도 같다).
3. `part > 0`이면 끝에 두 줄을 더한다: 「+ 증여세 상당액 {part} — 이월과세 §97의2①3호·시행령 §163의2②」 · 「= {a.estimatedDeduction}」.
- 순수 함수의 문자열만 바꾼다. 엔진·API·타입·카드 변경 없음 → 14동기화 지점 중 ⑦ 결과(상세 명세서)만 해당. 줄 수는 `DetailedStatementBgFormulas.ts` 약 +10줄(파일 크기 문제 없음).
- 카드와 같은 이유로 leaf `bgPartExpenseNet`(`burdened-gift-totals.ts`)을 재사용할 수 있으면 쓴다 — 단, 그 leaf는 `perAsset`을 파트 키로 읽으므로 `a` 객체가 아니라 파트 키가 필요하다. 구현 때 `a` 동일성 비교와 leaf 중 단순한 쪽을 고른다(둘 다 엔진 echo의 뺄셈뿐).
