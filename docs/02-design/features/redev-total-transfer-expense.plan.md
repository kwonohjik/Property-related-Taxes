# 재개발·입주권(§166) 자산 — 폼 상단 총 양도비 소실 (측정 + 계획)

> 출처: `project_receive_only_guideline_100_166_10` 메모 「총 양도비가 재개발 payload에 닿지 않는다」.
> 규칙: 추정 금지 — 세액은 throwaway probe(폼 → ④ → ⑫ → route)와 브라우저로 읽었다. probe는 커밋하지 않는다. 측정 기준 코드 = master `2d12d8d5a`. 금액은 표시가 없으면 mock 세율표 값이다. 이번 커밋은 문서만 바꾼다.

## 0. 결론

| 질문 | 결과 |
|---|---|
| 결함인가 | **그렇다.** 자산 2건 이상에서 총 양도비를 넣으면 §166 자산 몫이 필요경비에서 빠진다. 안내 문구는 「자산별 양도가액에 비례하여 안분합니다」라고 적고 있다(V-1·V-3). |
| 범위 | 함께 양도·축 B, 완공 APT·입주권, 납부·수령·단독 신고, 실가·환산, 승계 APT, 부담부증여, 이월과세 전부(V-2). |
| 세액 차이 | 총 양도비 1천만 기준 화면에서 필요경비 3,000,000 ↔ 10,000,000, 차감납부세액 130,895,310 ↔ 128,817,517(V-3). |
| 단순 수정으로 맞는가 | **맞는다.** route에서 자산 몫을 인가 후 필요경비에 더하는 시험 적용으로 다시 잰 17칸 전부 자산 칸 입력과 ±0이다(V-4). |
| 함께 찾은 별건 | 옛 필요경비 칸(`directExpenses`)도 §166 자산에서 소실된다(V-5). 이번 범위에서 제외를 권장한다(Q-3). |

요청 본문 `commonTransferExpense = 10000000`, `redevelopment.postApprovalExpenses` 없음. ⑧·⑫ 모두 통과(응답 200). 화면에 필요경비 일부가 빠졌다는 안내는 없다. 입력 칸 안내(`AssetSectionExpense.tsx`)는 「자산별 양도가액에 비례하여 안분합니다」이다.

⑧: V-2 시료 중 APT·입주권 함께 양도와 축 B 행은 `collectStepIssues`에 이 축의 차단이 없음을 확인했다(남은 지적은 시료의 소재지·명부 확인뿐). 축 B 단독 신고는 시료 양도일 지적 1건이 있어 ⑫·route까지만 확인했다. 부담부증여·이월과세 행은 ⑧을 돌리지 않았다(V-7).

**V-4 시험 적용 (커밋 안 함, 측정 후 원복)**

`bundled-route.ts:221` 주 자산, `bundled-split-helpers.ts:343` 컴패니언에 `postApprovalExpenses += allocatedCommonExpense`만 더했다.

- V-2 19행 중 17행을 다시 재서 전부 오라클과 **±0**이다. 부담부증여 행은 채무비율 0.4가 곱해져 카드당 2,000,000으로 일치한다.
- 다시 재지 않은 2행은 「토지 + 완공 APT(컴패니언)」·「토지 + 입주권(컴패니언)」이다. 컴패니언 APT 경로는 「토지 + APT + 토지」 행으로 확인했고, 컴패니언 입주권은 구현 anchor에서 확인한다.
- 대조군(승계 입주권)도 다시 재지 않았다. 코드상 `redevelopment`가 있을 때만 더하므로 닿지 않아야 하며, 구현 anchor에서 고정한다.
- 전체 회귀는 아직 돌리지 않았다(V-6).

**V-5 별건 — 옛 필요경비 칸**

`directExpenses` 7백만 + 토지(자산 칸 없음): 세액 145,067,241로 0 입력과 같고, 양도비 칸 7백만이면 142,781,668이다. 안분 몫 `allocatedExpenses`에는 들어가지만 §166 산식이 읽지 않는다. 이 칸은 이전 저장값이 있을 때만 보인다. 단건 경로는 측정하지 않았다(V-7).

**법령**

「소득세법」 §100②(MST 280405) 후문: 「공통되는 취득가액과 양도비용은 해당 자산의 가액에 비례하여 안분계산한다.」 안분 자체는 이미 구현되어 있다. 몫을 §166 산식에 넣는 칸은 기존 자산 칸과 같은 인가 후 분이다(`AssetSectionExpense.tsx:89` 주석, `transfer-tax-api-redev.ts:117`).

단독 신고는 #2851의 규칙대로 `postApprovalExpenses`까지 청산금 비율로 안분된다. 시험 적용에서 960,000 · 640,000으로 자산 칸과 일치했다.

## 2. 결정 필요 (Q 레지스터)

**Q-1 고치는 층**
- **a. route (권장)**: 함께 양도 「기준시가 안분」은 자산별 양도가액을 서버만 안다. `withBundledCommonExpense`와 같은 위치다.
- b. ④: 축 B는 지분율로 계산할 수 있지만 함께 양도를 못 고친다.

**Q-2 귀속**
- **a. 인가 후 분 (권장)**: 자산 칸 양도비와 같다. 오라클 ±0의 전제다.
- b. 인가 전·후 안분: 양도비에 그렇게 나눌 근거를 찾지 못했고, 자산 칸과 값이 갈라진다.

**Q-3 옛 칸(V-5)**
- **a. 이번 범위에서 제외, 별건으로 남김 (권장)**: 총 양도비와 원인 위치가 다르다. 단건까지 측정해야 판단할 수 있다.
- b. 함께 수정.
