## 0. 이미 정해진 것 (재제안 금지)

- Q-24·Q-25(2026-10-23): 1985 전 상속·증여 부담부증여 — 시가 평가 = 3자 max × 채무비율, 기준시가 평가 = 의제취득일 기준시가 × 채무비율(3자 max 없음).
- A안(2026-10-24): 1985 전 상속·증여 상가의 ③ 분자 = §164⑥ 값. 양도시 기준시가가 비면 ⑧·⑫가 막는다(V-1 가드) — 기준시가 평가 부담부증여는 그 가드에서 뺐다(③이 없다).
- 「자동 안분 fallback 금지」: 빠진 값을 다른 값으로 메우지 않고 입력을 요구한다.

## 1. 법령 확인 (KoreanLaw MCP · 소득세법 시행령 MST 290841, 2026-10-01 시행본 · 2026-10-25 조회)

| 조문 | 본문(발췌) | 의미 |
|---|---|---|
| §159①2호 | 「양도가액 = A × B / C · A: 「상속세 및 증여세법」 제60조부터 제66조까지의 규정에 따라 평가한 가액 · B: 채무액 · C: 증여가액」 | 기준시가 평가면 A·C가 양도시 기준시가(§61)와 담보평가(§66)·임대 환산(§61⑤) 중 큰 값이다 |
| §159①1호 | 「A: 법 제97조제1항제1호에 따른 가액(제2호에 따른 양도가액을 「상속세 및 증여세법」 제61조제1항ㆍ제2항ㆍ제5항 및 제66조에 따라 기준시가로 산정한 경우에는 취득가액도 기준시가로 산정한다)」 | 취득가액 = 취득시 기준시가 × B/C |

⇒ 양도시 기준시가가 없으면 **증여가액 C를 정할 수 없다**(보충적 평가액과 담보평가액 중 어느 쪽이 큰지 판정 불가). 엔진은 그 값을 0으로 받아 담보평가를 C로 고르고(채무비율 1), 자산별 양도가액 분모(보충적 평가액 합)가 0이라 양도가액을 0으로 낸다. 취득가액은 취득시 기준시가 × 1이 남아 양도차손 → 세액 0이다. 법령상 값이 아니라 **입력 누락의 산물**이므로 입력을 요구한다.

증여세 계산기는 같은 경우를 이미 막는다(`components/calc/gift-tax-form-validate.ts:247-256` — 「양도시(증여시) 기준시가를 입력하세요. (양도소득세 §159 안분 분모 필수)」). 양도세 계산기만 빠져 있다.

- 1983 상속 행의 ⑧ 차단은 상속 의제 ③ 분모 규칙(`transfer-tax-validate-clause-a.ts:279`)이 우연히 막는 것이다. 기준시가 평가는 3자 max를 쓰지 않으므로(Q-25) 문구가 사실과 다르고, 기준시가 평가 화면에서 숨은 ① 칸에 값이 남아 있으면 그 규칙이 빠져 통과한다.

### R-4 (같은 칸 · 반대 방향)

| 양도시 기준시가 | 4억 | 6억 | 비움 |
|---|---|---|---|
| 결과 | 95,038,182 | 95,038,182 | ⑧·⑫ 막힘 — 「§164⑥ … 환산취득가액도 비교합니다 — 양도시 기준시가를 입력하세요」 |

담보 승이면 취득가액 = 의제취득일 기준시가 × 채무비율이고 양도가액 = 채무액이라 양도시 기준시가가 쓰이지 않는다(값을 바꿔도 세액 같음). 그런데 A안 가드가 ③ 비교를 이유로 막는다 — 막는 이유가 틀렸다.

## 3. 설계

### 3.1 ⑧ — 기준시가 평가 양도시 기준시가 필수 (`transfer-tax-validate-bg.ts`)

`validateBurdenedGiftAsset`의 (5-c) 취득시 기준시가 검사 **바로 앞**에 둔다(화면 순서: 부담부증여 카드 → 양도정보의 양도시 기준시가 → 취득시 기준시가).

```
if (asset.bgValuationMode === "sangjeungbeop_standard" && !stdPriceAtTransferComesFromElsewhere(asset)) {
  const info = buildBurdenedGiftInfo(asset);          // ④와 같은 leaf — 토지 ㎡당 × 면적 fallback 포함
  if (info.landStdPriceAtTransfer + info.buildingStdPriceAtTransfer <= 0)
    return fieldError("standardPriceAtTransfer", …);
}
```

- 대상: 주택·건물·상가·토지·재개발 완공 아파트(공용 칸 `standardPriceAtTransfer`). 일반건물·겸용·조합원입주권은 `stdPriceAtTransferComesFromElsewhere`가 제외한다 — 각자 칸 규칙이 이미 막는다(§2 실측).
- 판정 값은 ④ `buildBurdenedGiftInfo`가 엔진에 보낼 값 그대로다(3중 패턴 — 토지는 「양도시 기준시가 ‖ ㎡당 × 면적」).
- 문구(안): 「부담부증여 기준시가 평가 — 양도시 기준시가(토지는 또는 양도 당시 ㎡당 공시지가 + 면적)를 입력하세요. 증여가액과 양도가액이 이 값으로 정해지므로 비우면 계산할 수 없습니다 (소득세법 시행령 제159조 제1항 제2호).」
- `validateBurdenedGiftAsset`이 상속 의제 검사(`transfer-tax-validate-acquisition.ts:145` → `:179`·`:182`)보다 먼저 돌아 1983 상속 행도 이 문구가 먼저 뜬다.
- 축 B·함께 양도: 지분·자산마다 `validateBurdenedGiftAsset`이 불린다(V-1에서 확인).

### 3.2 엔진 fail-fast (`burdened-gift-apportionment.ts`)

같은 파일의 담보 승 취득시 기준시가 0 차단(`collateralForcedStdInMarketMode && … <= 0` → `TaxCalculationError(INVALID_INPUT)`)과 같은 층위로:

```
if (isStandardMode && sangjeungbeopValuation.supplementary === 0) throw new TaxCalculationError(INVALID_INPUT, "…양도시 기준시가를 입력하세요…");
```
