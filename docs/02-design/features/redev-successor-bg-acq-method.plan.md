# 승계조합원 완공 아파트 — 부담부증여 매매 막다른 길 · 취득가액 산정 방식 무시(평가액 대체)

> **출처**: `redev-successor-acq-price-required.plan.md` §5 · #2577 리뷰 게이트 C-3 — ① 부담부증여 × 승계 × 매매에서 ⑧이 숨은 칸을 요구한다 ② 엔진이 `rightsValue`(§166④1호 평가액)를 승계취득가액 대용으로 받는다
> **깊이**: L3 — ①은 지금 계산할 수 없는 화면 경로를 연다. ②는 화면에서 조용히 틀린 세액(매매사례가액을 입력해도 숨은 취득가액으로 계산)을 고친다.

## 1. 실측

시료(E2-01·#2577 anchor와 같은 값): 인가 2016-02-20 · 입주권 승계취득 2020-04-15 · 준공 2022-12-02 · 2023-02-16 양도 920,000,000 · 승계취득가액 450,000,000 → 양도차익 470,000,000 · 산출세액 327,250,000(단기 70%). 「⑧」은 화면 검증, 「E-n」은 Playwright(워크트리 dev 서버), 그 밖은 route probe(세율 mock).

### 1.1 부담부증여 × 승계 × 매매 (항목 A)

부담부증여 시가 920,000,000 · 채무 300,000,000 · 산정방식 실지 · 실지취득가액 450,000,000.

| 행 | 입력 | ⑧ | 응답 · 양도차익 · 산출세액 |
|---|---|---|---|
| **E-1** | 화면 — 위 입력 그대로 | **「입주권을 매매로 승계취득한 취득가액(실지거래가액)을 입력하세요」** · 카드 안 `fixedAcquisitionPrice` 칸 **0개** · 요청 없음 | — (계산 불가) |
| B0 | 같은 입력 · route 직접 | 같은 오류 | 200 · 153,260,870 · 105,532,609 |
| B1 | + 인가 후 필요경비 50,000,000 | 같은 오류 | 200 · 136,956,523 |
| B2 | 기준시가 평가 · 취득시 기준시가 300,000,000 | 같은 오류 | 200 · 150,000,000 |
| B3 | 취득원인 **증여** | **통과** | 200 · 153,260,870 · 105,532,609 |
| B4 | 매매 + 숨은 `fixedAcquisitionPrice` 450,000,000 잔존 | 통과 | 200 · 같은 값 |

- 엔진 값은 §159 안분과 맞다: 양도가액 = 920,000,000 × 300/920 = 300,000,000 · 취득가액 = 450,000,000 × 300/920 = 146,739,130 → 153,260,870. 인가 후 필요경비도 채무비율로 안분된다(50,000,000 × 300/920 = 16,304,347 — B1 차이와 같다). 보유기간은 준공일 기산(단기 70% — 105,532,609 = (153,260,870 − 2,500,000) × 70%).
- **증여로 취득한 승계(B3)는 이미 화면에서 계산된다** — 같은 엔진 경로가 매매에서만 ⑧에 막혀 있다.
- **원인**: ⑧ E2-01 매매 분기(`transfer-tax-validate-redev.ts:336-343`)가 부담부증여를 제외하지 않는다. 부담부증여는 상단 취득가액 영역을 렌더하지 않는다(`CompanionAcqPurchaseBlock.tsx:376` · `redevHidesGeneralAcqSection`와 별개 게이트). 승계조합원 카드는 부담부증여에서도 렌더된다(`RedevelopmentBlock.tsx:228`). #2577의 증여 분기는 처음부터 부담부증여를 뺐다(`:346-355`).

### 1.2 승계 완공 아파트 × 취득가액 산정 방식 (항목 B)

| 행 | 입력 | ⑧ | 본문 `acquisitionPrice` · `acquisitionMethod` · `rightsValue` | 응답 · 양도차익 · 산출세액 |
|---|---|---|---|---|
| R0 | 실거래가 | 통과 | 450,000,000 · actual · 450,000,000 | 200 · 470,000,000 · 327,250,000 |
| **E-2** | 화면 — 주택에서 「감정가액」 → 자산 종류 「재개발/재건축 APT」 → 「승계조합원」 | 통과 | **0 · appraisal** · 450,000,000 | 200 · 470,000,000 · 327,250,000 |
| **E-3** | 화면 — 같은 순서로 「매매사례가액」 | 통과 · 카드에 `similarSalesValue` 칸 · `fixedAcquisitionPrice` 칸 **없음** | 0 · salesCase · 450,000,000 | 400 `similarSalesValue`(그 칸은 화면에 있다) |
| **S1** | 매매사례가액 500,000,000 · 숨은 취득가액 450,000,000 | 통과 | 0 · salesCase · 450,000,000 | **200 · 470,000,000 · 327,250,000** — 매매사례가액이 아니라 숨은 값으로 계산 |
| S2 | 매매사례가액 500,000,000 · 취득가액 비움 | **`fixedAcquisitionPrice`(숨은 칸)** | 0 · salesCase · 0 | 400 `acquisitionPrice` — 막다른 길 |
| S3 | 감정가액 450,000,000 | 통과 | 0 · appraisal · 450,000,000 | 200 · 470,000,000 — 개산공제 0 |
| S4 | (대조) 일반 주택 감정가액 450,000,000 · 취득시 기준시가 300,000,000 | 통과 | 0 · appraisal | 200 · 필요경비 9,000,000(개산공제 3%) |
| R7 | API — 취득가액 0 · 평가액 999,000,000 | — | 0 · actual · 999,000,000 | **200 · −79,000,000 · 0** |
| CS1 | 컴패니언 매매사례 | 「첫 번째 자산 전용」 | — | (⑧이 막는다) |
| CS3 | 컴패니언 감정가액 | 통과 | 컴패니언 `fixedAcquisitionPrice` 450,000,000 · appraisal | 200 · 실거래가와 같은 값(개산공제 없음) |

- **산정 방식 라디오가 승계 완공 아파트에 렌더된다** — 실거래가·환산·감정·매매사례 4종(`CompanionAcqPurchaseBlock.tsx:157-180`). 그 영역을 숨기는 술어 `redevHidesGeneralAcqSection`(`redev-acquisition-price-source.ts:50-58`)이 승계를 제외하기 때문이다(취득가액 칸이 그 영역에 있다). 자산 종류를 바꿔도 감정·매매사례 플래그는 지워지지 않는다(E-2·E-3).
- **엔진 승계 산식은 산정 방식을 읽지 않는다** — 취득가액 = `actualAcquisitionPrice > 0 ? 그 값 : rightsValue > 0 ? 평가액 : 중단`(`redevelopment-successor.ts:75-85`). ④는 감정·매매사례면 `acquisitionPrice`를 0으로 싣고(`transfer-tax-api.ts:319-320`), 승계면 `rightsValue`에 화면 취득가액을 미러한다(`transfer-tax-api-redev.ts:93-96`). ⇒ 감정가액은 우연히 같은 값(그 칸이 감정가액 칸이다)이지만 §163⑥ 개산공제가 빠지고, 매매사례가액은 **숨은 칸 값**으로 계산된다.
- ⑧ 승계 분기는 환산만 「미지원」으로 막는다(`transfer-tax-validate-redev.ts:306-308` — 칸 지정 없음). 감정·매매사례는 막지 않는다.
- 평가액 대체(`rightsValue`)는 API 우회(R7)이기도 하다 — §166④1호 「관리처분계획등에 따라 정하여진 가격」은 원조합원 종전자산 평가액이지 승계인의 취득가액(§97①1호 가목 · §163⑨)이 아니다.

## 2. 설계

### 2.1 항목 A — ⑧ 매매 분기에서 부담부증여 제외

⑧ E2-01 매매 분기에 `asset.transferType !== "burdened_gift"`를 더한다(#2577 증여 분기와 같은 형태). ⑫는 부담부증여 실지취득가액을 이미 요구한다(`burdenedGiftInfo.actualAcquisitionTotal` — #2577 probe B2 400). ④⑤⑬⑭ 변경 없음.

### 2.2 항목 B — 승계 완공 아파트는 실거래가로 (Q-2 권장안 a 기준)

1. ⑤ — 승계 완공 아파트에서 산정 방식 라디오를 숨기고 **실거래가 취득가액 칸으로 고정**한다. 라디오만 숨기면 남은 플래그 때문에 칸이 감정가액·매매사례가액 칸으로 바뀌어 보인다(E-3 — `acqBasisValue`가 플래그에서 정해진다, `CompanionAcqPurchaseBlock.tsx:108`). 렌더 판정도 같은 술어를 쓴다.
2. ④ — 승계 완공 아파트는 감정·매매사례·환산 플래그를 무시하고 `acquisitionPrice` = 화면 취득가액 · `acquisitionMethod: "actual"`(주 자산 `primaryAcquisitionModeFlags`의 `blocksAppraisalSalesCase`에 승계 APT 추가 · 컴패니언 payload 같은 leaf).
3. ⑧ — 승계 분기의 「환산 미지원」 차단(`:306-308`)을 같은 술어로 무시한다(라디오가 없으므로 잔재 플래그). 매매 분기는 그대로(이제 칸이 항상 보인다).
4. 엔진 — `rightsValue` 대체를 없앤다. 취득가액 = `actualAcquisitionPrice > 0`이 아니면 `INVALID_INPUT`.
5. ⑫ — #2577 규칙에서 `rightsValue > 0` 대체를 뺀다(`transfer-tax-schema-required-refines.ts:328`). `inheritedAcquisition` 예외는 유지.

## 3. 결정 게이트

### Q-1 항목 A — 부담부증여 매매 승계를 연다

- (a) **⑧ 매매 분기에서 부담부증여 제외 — 시가·기준시가 평가 모두** (권장) — 엔진 값이 §159 안분과 맞고(1.1), 같은 경로가 증여 취득(B3)으로 이미 열려 있다. 기준시가 평가의 「취득 당시 기준시가」 시점(V-3)은 미해소로 남지만 **이 결정을 바꾸지 않는다** — 엔진은 입력한 값을 그대로 쓰고(B2), 같은 경로가 증여 취득으로 이미 계산된다(V-4). V-3는 그 칸의 기준일 안내 문제라 별건이다.
- (b) 시가 평가만 열고 기준시가 평가 × 승계는 사유 문구로 막는다(매매·증여 모두) — V-3 해소 전 보수안. 증여 취득 기준시가 평가는 지금 계산되는 경로라(V-4 ✅ — 200 · 150,000,000) 그 경로를 새로 막게 된다.
- (c) 유지 — 막다른 길이 남는다.

### Q-2 항목 B — 승계 완공 아파트의 취득가액 산정 방식

- (a) **실거래가 전용**(권장) — 2.2. 환산은 이미 「미지원」이고, 감정·매매사례는 엔진이 읽지 않아 조용히 틀리거나(S1) 개산공제가 빠진다(S3). 같은 저장 상태의 세액은 그대로다 — 지금도 엔진은 취득가액 칸 값으로 계산한다(S1·S3·E-2). 바뀌는 것은 ① 그 값이 화면에 보이게 되고(S1: 숨은 450,000,000이 칸에 드러나 사용자가 고칠 수 있다) ② S2(취득가액 비움)가 막다른 길에서 보이는 칸 요구로 ③ API 평가액 우회(R7 — 200 · 세액 0)가 400으로. 감정가액을 고른 경우는 그 칸 값을 실거래가로 읽어 같은 세액(개산공제가 없는 것도 지금과 같다). 법 §97①1호 나목(추계) 경로를 화면에서 닫는 한계가 남는다 — (b)로 열 수 있다.
- (b) 산정 방식 지원 — 엔진 승계 산식이 감정가액·매매사례가액을 취득가액으로 쓰고 §163⑥ 개산공제를 붙인다. 개산공제 기준 「취득 당시 기준시가」가 신축주택 기준인지(V-2) 먼저 정해야 한다. 작업이 크다(엔진·④⑤⑧·결과 산식).
- (c) 엔진 대체만 제거 — **기각**: E-2(화면 — 남은 감정가액 플래그)가 `acquisitionPrice` 0으로 와서 계산 불가가 된다.

### 결정 (2026-10-26)

- **Q-1 = (a)** — ⑧ 매매 승계 분기에서 부담부증여 제외(시가·기준시가 평가 모두). 근거: 엔진 §159 값 일치 · 증여 취득으로 같은 경로가 이미 열려 있음 · V-3는 칸 안내 문제로 별건.
- **Q-2 = (a)** — 승계 완공 아파트는 실거래가 전용(2.2). 근거: 엔진이 산정 방식을 읽지 않아 감정·매매사례 선택이 조용히 틀리거나 막다른 길이 된다. 추계(나목) 지원은 (b)로 후속.
