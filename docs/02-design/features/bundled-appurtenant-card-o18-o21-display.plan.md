## 0. 요약

- **O-18은 실재하는 표시 결함이다 — 의심이 아니라 측정으로 확인했다.** 함께 양도 결과의 «합산 과세 내역» 카드가 세율군이 **하나**일 때 중과 세율을 **두 번** 더한다. 2주택 중과 한 군 시료에서 화면은 «세율 (기본 62% + 중과 20%p) **82%**»인데 산출세액은 62% 기준이다(997,500,000 × 62% − 35,940,000 = 582,510,000 = 엔진 `groupCalculatedTax`). 같은 종류의 결함은 상세명세서·신고서·자산별 카드에서 2026-09에 이미 고쳤고(`surcharge-rate-double-count`) 이 카드만 남아 있었다.
- **O-21도 실재한다 — 그런데 O-10 범위(중과)보다 넓다.** 부수토지 카드(한 장·이내분)가 주택 단기 세율(60%/70%)을 받는데 신고서 세율구분 코드는 토지 코드 `1-15`/`1-20`이다. 정본 표(별지 제84호서식 작성방법 3쪽)에서 `1-15`는 «주택 및 조합원입주권 **제외**» 40%, `1-20`은 50%라 **한 열 안에서 코드(40%)와 ⑨세율(60%)이 어긋난다.** **중과가 없는 1주택 단기 시료에서도 같다** — O-10으로 생긴 문제가 아니라 일체과세 분기(영 §167의5)에서부터 있던 것이다.
- 세액은 어느 쪽도 바뀌지 않는다(표시·코드만). 합계·산출세액·그룹 세액은 측정에서 모두 기존 값과 같았다.

## 3. 판단과 설계 (권고안)

### O-18
- **D-1** 단일 군: 라벨 «세율 (중과 20%p 포함)» · 값 **62%**(= `appliedRate`). 중과가 없으면 라벨 접미 없음.
- **D-2** 다군 행: 값 `62%` + 접미 «(중과 20%p 포함)» — 기존 `MultiTransferPropertyBreakdown.tsx:415`와 같은 어휘로 맞춘다.
- 세액 코드는 건드리지 않는다. `appliedRate − surchargeRate`로 «기본 42%»를 따로 적는 안은 **채택하지 않는다** — 군 안에 호가 여럿이면 `appliedRate`는 «표시용 최고세율»(`transfer-tax-aggregate-group-tax.ts:476`)이라 뺄셈이 성립하지 않는다(`groupRateText`도 같은 이유로 «(호별 합계)»로 비운다).

### O-21
- **D-3** 이내분·한 장 카드(주택 세율을 받은 카드)의 코드를 주택 코드(`1-39`/`1-46`)로 적고, 초과분(`__excess`)·독립 나대지는 토지 코드를 유지한다. 판별은 V-8 측정으로 정한다.
- **D-4** 검증 oracle은 구현 비의존: 정본 표의 «코드 → 단일세율»(1-15 40% · 1-20 50% · 1-39 60% · 1-46 70%)을 상수로 두고, **모든 시료·모든 열에서 «고정세율 코드이면 ⑨세율 = 그 코드의 세율»**을 단언한다.
