## 0. 발단

P12(§104⑤ 호별 합산) 3단계를 마치며 남긴 한계 —
「split 자산의 주택 파트가 2년 미만 + 조정 다주택이면 `rateClause`가 §104⑦ 후단 승자로
오염된다」 — 를 별건으로 착수하려고 조사하다가, **더 크고 명확한 결함(E-1)**을 발견했다.

**조사에서 바뀐 것 3가지**:
1. 오염 축이 **하나가 아니라 둘**이다 — §104⑦ 후단(다주택)뿐 아니라 **§104① 후단(비사업용
   토지)**도 승자에 따라 호가 갈린다.
2. 호 판정이 **3곳**에 흩어져 있다(dual이 아니라 **triple-truth**).
3. 그중 `rateClauseKeyOf`(P9가 D-11을 고치며 만든 것)에 **비사토 축이 통째로 없다** — 이것이
   실측 가능한 결함 E-1이다.

## 1. 검증된 법령 (법제처 Open API · MST 280405 · 시행 2026-07-01)

### 1.1 「해당 호」가 둘 이상일 수 있는 근거

- **§104① 후단**: 「하나의 자산이 다음 각 호에 따른 세율 중 **둘 이상에 해당**할 때에는
  해당 세율을 적용하여 계산한 양도소득 산출세액 중 **큰 것**을 그 세액으로 한다」
- **§104⑦ 후단**: 「해당 주택 보유기간이 2년 미만인 경우에는 [중과세율] … 과 제1항제2호 또는
  제3호의 세율을 적용하여 계산한 양도소득 산출세액 중 **큰 세액**을 … 산출세액으로 한다」

⇒ **자산 하나가 여러 호에 「해당」하고, 그중 하나가 「적용」된다.**
「해당」과 「적용」은 다르며, §104⑤2호 단서는 그 구분 위에 서 있다.

### 1.2 §104⑤2호 단서가 「해당 호」를 요구한다

> 다만, 둘 이상의 자산에 대하여 §104① 각 호, ④ 각 호 및 ⑦ 각 호에 따른 세율 중
> **동일한 호의 세율이 적용되고, 그 적용세율이 둘 이상인 경우** … 합산한 것에 대하여
> **각 해당 호별 세율**을 적용하여 산출한 세액 중에서 **큰 산출세액**의 합계액으로 한다.

효과절이 「**각 해당 호별** … 중 **큰** 것」이므로 **자산이 복수 호에 해당함**을 전제한다.
⇒ 그룹핑 키는 **승자**가 아니라 **「해당 호 집합」**이어야 한다.

**본문의 계산 단위**는 예규가 확정했다 — 「"자산별"에서 "자산"의 의미는 §104 **각 호별로
합산한 자산**」(「기획재정부 재산세제과-536」 2018.6.19. · 국세청
「기준-2018-법령해석재산-0098」[법령해석과-1715] 2018.6.21.).
선행 계획서 §1.6-A 참조.

## 3. 결함 E-1 — `short_term` 그룹의 **입력 순서 의존** (실측 완료)

### 3.1 메커니즘

`classifyRateGroup`(`:72`)이 **2년 미만 자산을 전부 `short_term`으로** 보낸다.
비사업용 토지가 2년 미만이면 그 그룹에 들어가는데, `rateClauseKeyOf`가 비사토 축을 보지
않으므로 **사업용 토지와 같은 키**가 된다 → `sameRateClause` 참 → **합산 1회**:

```ts
const tr = calcTax(groupTaxBase, parsedRates, records[idxList[0]].correctedSingleInput);
//                                            ^^^^^^^^^^^^^^^^^ 입력 목록의 **첫 자산**
```

⇒ 첫 자산이 비사토면 그룹 전체에 §104①8호가, 사업용이면 §104①2호가 적용된다.

### 3.2 실측 (2026-08-02 · throwaway probe)

**구성**: 둘 다 2025-01-01 취득 · 2026-06-01 양도(**17개월** → §104①2호 구간) · 기본공제 소진

| 자산 | 성격 | 과세표준 | 해당 호 | 자산 단독 세액 |
|---|---|---:|---|---:|
| **N** | **비사업용** 토지 | 300,000,000 | **{①8호, ①2호}** | **124,060,000** (누진 94,060,000 + 10% 30,000,000 > 40% 120,000,000 → ①8호 승) |
| **P** | 사업용 토지 | 200,000,000 | {①2호} | **80,000,000** (40%) |

| 입력 순서 | 그룹 세액 | 판정 |
|---|---:|---|
| **A. `[N, P]`** (비사토 먼저) | **224,060,000** | 5억 전체에 §104①8호 |
| **B. `[P, N]`** (사업용 먼저) | **200,000,000** | 5억 전체에 §104①2호 40% |
| **차이** | **24,060,000** | 🔴 **입력 순서에 따라 세액이 달라진다** |

### 3.3 도출값 — **자산별 합**(2호 본문)

N과 P가 **공유하는 호는 ①2호뿐**이고 **①8호는 N만** 해당한다.
합산하면 어느 쪽이든 법문에 어긋난다:
- ①8호로 합산 → P에 없는 비사업용 가산이 붙는다(**과대 20,000,000**)
- ①2호로 합산 → N의 비사업용 가산이 사라진다(**과소 4,060,000**)

⇒ **「동일한 호의 세율이 적용되고」 요건 불충족 → 단서 미적용 → 2호 본문(자산별 합)**.
R7 감사(2026-07-29 · `docs/00-pm/transfer-open-items.plan.md:554-575`)가
`multi_house_surcharge`의 ⑦1호/⑦3호 혼재를 **같은 논리로** 고쳤다.

| | 세액 |
|---|---:|
| 2호 본문 = N 124,060,000 + P 80,000,000 | **204,060,000** |
| 1호 = 전체 합산 누진(base 500,000,000) | 174,060,000 |
| **§104⑤ MAX** | **204,060,000** |

⇒ 현행 A는 **20,000,000 과대**, B는 **4,060,000 과소**다.

### 3.4 발현 범위

- **필요 조건**: 같은 과세기간에 **비사업용 토지**와 **그 외 자산**을 **둘 다 2년 미만** 보유로
  양도. 두 자산이 같은 단기 구간(둘 다 1년 미만 또는 둘 다 1~2년)이어야 같은 키가 된다.
- 🔶 **미측정**: 「비사토 승 vs 단기 승」이 자산마다 갈리는 경우(N₁은 ①8호 승, N₂는 ①2호 승)도
  같은 키가 되어 합산된다. E-2와 얽힌 국면이라 착수 시 함께 실측한다.

## 4. 결함 E-2 — `rateClause` 승자 오염 (🔶 미실측)

`calcTax`의 `rateClause`는 §2.1에서 본 대로 **승자 기준**이다. 이것을 그룹핑 키로 쓰는 곳은
**②를 거치지 않는 경로** — 즉 **P12 2단계가 만든 파트 호별 묶음**
(`transfer-tax-aggregate-helpers.ts` 누진 호 분기)과 **③ `clauseKey`**(자산 내부)다.

**발현 조건**(선행 계획서 §4.11 「알려진 한계」):
- 누진 호 그룹(2년 이상 자산만 있다)에 **split 주택 자산**이 있고
- 그 자산의 **파트가 2년 미만**(토지를 나중에 취득)이며 **조정 다주택**이라
  §104⑦ 후단이 발동하고
- 같은 그룹에 **같은 「해당 호 집합」인 파트/자산이 또 있어** 승자가 갈려야 한다

⇒ **조건이 4중이라 좁다.** 조합 구성이 선결 과제이며, 구성 실패 시 🛑 보류 확정도 선택지다.
(선행 계획서에서 D-7 조합 구성이 2회 실패한 뒤 3회차에 성립한 전례가 있으므로,
「구성 못 했다」를 「발현 불가」로 단정하지 않는다.)

**⚠️ 비사토 축은 누진 호 그룹에서 발현 불가**(구조적) — 한 필지는 취득일이 하나뿐이라
자산이 2년 이상이면 파트도 2년 이상이다. 자산이 2년 미만이면 `short_term` 그룹으로 간다.

## 5. 설계 — `calcTax`가 「해당 호 **후보 목록**」을 반환한다

### 5.1 핵심

```ts
interface CalcTaxResult {
  rateClause?: RateClause;              // 기존 — 실제 **적용**된 호(표시·기록용, 유지)
  candidateClauses?: RateClause[];      // 신설 — 그 자산/파트가 **해당**하는 호 전부(정렬)
}
```

- `:391`·`:403`(§104① 후단) → `["104-1-8", shortTermClause(...)]`
- `:460`·`:472`(§104⑦ 후단) → `[surchargeClause(...), shortTermClause(...)]`
- 단정 지점은 후보가 하나 → `[rateClause]`

**그룹핑 키 = 정렬된 `candidateClauses` 조인.** 승패와 무관해진다.

### 5.2 세 판정을 후보 목록으로 통일

| 현행 | 변경 |
|---|---|
| ② `rateClauseKeyOf` (입력 기반 재구성) | **폐기** → `candidateClauses` 사용. 비사토 축 누락(E-1)이 자동 해소된다 |
| ③ `clauseKey`(split-rate) | `finals[i].rateClause` → `finals[i].candidateClauses` |
| P12 2단계 파트 묶음 | `p.rateClause` → 파트의 `candidateClauses` (`SplitRatePart`에 필드 추가) |

⇒ **triple-truth가 단일 소스로 수렴한다.** `calcTax`가 호를 아는 유일한 지점이 된다.

### 5.3 ⚠️ 합산 시 세율 적용 — 「각 해당 호별 세율 중 큰 것」

후보가 둘 이상인 그룹을 합산하면 **합산액에 각 후보 호를 적용해 큰 것**을 취해야 한다(단서).
현행은 `calcTax(mergedBase, 대표 rateInput)`이 그 MAX를 **내부에서** 수행한다
(§104① 후단·⑦ 후단이 `calcTax` 안에 있다) ⇒ **신규 세율 로직이 필요 없다.**
D-11(P9)이 같은 성질을 이용했다(선행 계획서 §4.7).

### 5.4 범위 밖

- **1호(전체 합산 누진)** — 과세표준 합계액이라 호와 무관. 불변.
- **기본공제 배분**(§103②) — `allocateBasicDeduction`은 자산 단위 `idx` 기반. 별개 최적화.
- **차손 통산** — §102①은 §94①1·2·4호 / 3호 / 5호 / 6호의 **소득 구분 4개**이지 §104① 각 호가
  아니다(원문 실측). 무관.
