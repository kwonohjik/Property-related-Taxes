## 1. 개요 및 활성화 방식 결정

### 1.1 연부취득이란 (§10의5)

연부(年賦)란 매매대금을 **2년 이상**에 걸쳐 분할 지급하는 매매 방식이다.
각 회차 지급일이 각각의 취득시기가 되고, 회차별로 신고·납부 의무가 별개로 발생한다.

| 항목 | 내용 |
|---|---|
| 정의 | 매매대금을 2년 이상 분할 지급 (§6 17호) |
| 취득시기 | 각 회차 지급일 (§20⑤) |
| 신고·납부 기한 | 각 회차 지급일 + 60일 (§20⑤) |
| 과세표준 | 각 회차 사실상 지급액 (§10의5) |
| 취득 원인 분류 | 유상취득(매매)의 한 형태 — 별개 enum 아님 |

### 1.2 옵션 비교 및 권장안 결정

#### 옵션 A — 매매 내 토글 방식 (권장안)

Step0에서 `acquisitionCause === "purchase"` 선택 시 연부 `ToggleCard`를 표시한다.

```
[취득 원인 선택: 매매]
  └─ ToggleCard (amber) — "연부취득 (2년 이상 분할 지급, §10의5)"
       ON 시: 회차 입력 섹션 펼침 (Step1로 이동 후 표시)
```

장점:
- 연부취득이 법상 매매의 일종이라는 사실을 UI가 정확히 반영
- 기존 `ACQUISITION_CAUSE_LABELS` / `AcquisitionCause` 타입 변경 불필요
- 취득원인 드롭다운 항목 수 유지 (사용성)
- 간주취득 패턴(Step 1-D)과 유사한 방식으로 일관성 유지

단점:
- 매매 선택 후 토글을 찾아야 하는 추가 탐색 단계

#### 옵션 B — 별도 취득원인 enum 추가

`ACQUISITION_CAUSE_LABELS`에 `"installment"` 항목 추가.

단점:
- 연부취득이 법상 별개 취득원인이 아님 (§6 열거에 없음) — 법령과 불일치
- API 변환 + 엔진 타입 모두 `AcquisitionCause`에 `"installment"` 추가 필요 — 누락 위험 높음
- 다주택·법인 중과 등 분기에서 매매와 동일하게 처리되어야 하는데, 새 enum이 있으면 분기 각각에 조건 추가 필요

#### 옵션 C — 통합 토글 + 자동 감지

1회차 이상 입력 시 자동으로 연부 처리.

단점:
- 암묵적 동작으로 사용자가 자신이 연부 처리되었는지 인지하기 어려움
- "2년 이상" 법정 요건을 사용자가 명시적으로 확인할 기회가 없음

**결론: 옵션 A (매매 내 토글 방식) 채택**

## 2. 마법사 흐름

### 2.1 전체 흐름 (연부 ON/OFF 비교)

```
[연부 OFF — 일반 매매]
Step0 → Step1 → Step2(*) → Step3 → Step4(*) → Step5 → 결과

[연부 ON — 연부취득 매매]
Step0 (취득정보 + 연부 토글 ON + 매매계약일 입력)
  → Step1 (물건상세 + 연부 회차 섹션)
  → Step2(*) → Step3 → Step4(*) → Step5
  → 결과 (연부취득 요약 + 회차 표 + 신고기한 목록)

(*) 조건에 따라 skip 가능 (기존 computeNextStep 로직 그대로)
```

연부 ON 시 Step2~5는 **일반 매매와 동일한 단계를 그대로 통과**한다.
다주택·중과·감면 분기는 연부와 무관하게 전체 취득가액 기준으로 계산한다.

### 2.2 Step별 변경 사항

| Step | 연부 OFF | 연부 ON |
|---|---|---|
| Step0 | 기존과 동일 | 매매 선택 시 연부 ToggleCard 표시, ON이면 계약일 필드 활성화 |
| Step1 | 기존과 동일 | 기존 내용 + "연부 회차 정보" amber 카드 추가 |
| Step2~5 | 기존과 동일 | 동일 (변경 없음) |
| 결과 | 기존과 동일 | 연부취득 요약 카드 + 회차별 표 추가 |

### 2.3 Step0 변경 상세

기존 Step0의 `isOnerous` 분기에 연부 토글이 추가된다.

```
취득 원인 = 매매 선택
  └─ ToggleCard (amber, variant="card")
       제목: 연부취득 (2년 이상 분할 지급, §10의5)
       설명: 매매대금을 2년 이상 걸쳐 분할 지급하는 방식. 회차별로 별도 신고 의무.
       ON 시 children 영역 (Step0 내부):
         ├─ 매매계약일 (DateInput) — 연부 2년 이상 검증의 기준점
         ├─ 총 매매계약금액 CurrencyInput (선택) — 시가표준액 비교용
         └─ 안내 배너: "회차 입력은 다음 단계(물건 상세)에서 합니다."
```

연부 토글 ON 시 `form.reportedPrice` 입력란은 **숨김 처리**한다.
회차 합산이 과세표준이 되기 때문에 총 취득가액 단독 입력은 의미가 없다.

잔금 지급일 라벨도 `"마지막 회차 (잔금) 지급일"`로 변경한다.

### 2.4 Step1 변경 상세

기존 물건 상세 카드(sky) 하단에 연부 회차 섹션(amber)이 추가된다.

```
Step1 구조 (연부 ON 시):
  [sky 카드] 물건 상세 (기존 그대로)
  [amber 카드] 연부 회차 정보 ← 신규 (InstallmentPaymentsSection)
```

## 3. 모드 결정 (합산 vs 회차별)

### 3.1 Phase A — 합산 모드 (기본, 구현 필수)

- 모든 회차 합산 → 단일 엔진 호출 → 기존 결과 화면 재사용
- 기존 엔진 `determineTaxBase()` 로직이 이미 합산 처리 (`installments.reduce`)
- 결과 화면에 회차별 신고기한 표 추가 (신고기한은 UI에서 `paymentDate + 60일`로 계산)
- 세율·중과는 취득 시점 기준 1회 계산 (모든 회차에 동일 세율 적용)

**합산 모드의 한계**: 다주택자의 경우 각 회차 지급 시점에 주택 수가 달라질 수 있어 세율이 다를 수 있다.
결과 화면 하단에 이 사실을 안내 배너로 명시한다.

### 3.2 Phase B — 회차별 모드 (향후 구현, 현재 보류)

- 각 회차마다 엔진 호출 (병렬 N회)
- 각 회차 지급일 시점의 세율·주택 수·중과 적용
- 새 API 구조 필요: `POST /api/calc/acquisition`이 `installments[]`를 받아 배열 결과 반환
- `InstallmentResultTable` 전용 컴포넌트 필요
- Phase B는 현재 엔진이 회차별 개별 결과를 반환하지 않아 추가 엔진 작업 필요 — 별도 설계 문서 작성 후 구현

**Phase A만으로 Definition of Done 달성 가능** — Phase B는 선택 구현.

## 4. 다른 흐름과의 결합·호환성

### 4.1 호환 조합

| 조합 | 처리 방식 | 비고 |
|---|---|---|
| 매매 + 연부 | 기본 케이스 | Phase A 합산 모드 |
| 주택 + 연부 | 주택 현황(Step2) + 회차 정보(Step1) 모두 입력 | 다주택 중과는 취득 시 주택 수 기준 |
| 법인 + 연부 | Step4 법인 중과 그대로 | 12% 중과 + 회차 합산 |
| 조정지역 + 연부 | 일반 매매와 동일 | 2주택 중과 + 회차 합산 |
| 생애최초 + 연부 | 감면 적용 | Step5 생애최초 감면 그대로 |
| 토지 + 연부 | 가능 | 주택 현황 Step skip, 회차만 입력 |
| 비주거 건물 + 연부 | 가능 | 4% 세율 + 회차 합산 |
| 사치성 + 연부 | 가능 | 사치성 중과 + 회차 합산 |

### 4.2 비호환 조합 — UI에서 토글 비노출

| 조합 | 이유 |
|---|---|
| 무상취득(증여·상속) + 연부 | 연부는 매매 전용. 증여·상속은 분할 지급 개념 없음 |
| 부담부증여 + 연부 | 부담부증여는 유상·무상 분리 처리, 연부와 구조 충돌 |
| 원시취득(신축 등) + 연부 | 원시취득은 공사비 기준, 분할 지급 개념 없음 |
| 교환 + 연부 | 교환은 동시 교환이 원칙 |
| 공매·경매 + 연부 | 공매·경매는 낙찰가 일시납 원칙 |
| 간주취득 + 연부 | 간주취득 자체가 별도 과세표준 체계 |

**UI 구현**: 연부 토글은 `acquisitionCause === "purchase"` 일 때만 렌더한다.

### 4.3 다주택 + 연부 — 결과 화면 안내 배너

합산 모드는 취득 시점(최종 회차 기준 또는 등기일)의 주택 수로 단일 세율을 계산한다.
그러나 중도금 납부 시점과 잔금 납부 시점 사이에 종전 주택을 처분하면 실제 중과 여부가 달라진다.

결과 화면에 amber 안내 배너:

```
연부취득 + 다주택 주의사항
이 결과는 취득 시점 기준 주택 수로 세율을 계산한 합산 간이 계산입니다.
각 회차 지급일 시점의 주택 수가 달라 중과세율이 회차별로 다를 수 있습니다.
정확한 회차별 세액은 세무사에게 상담하세요.
```

표시 조건: `result.taxBaseMethod === "installment" && result.isSurcharged`
