# 1985.1.1.~1990.8.30. 상속 토지 — §164④ 입력 경로 부재 (dead-end)

> **상태**: ✅ **구현 완료** (2026-08-06). U-1~U-4 전건 해소 · RTL 4건 + **E2E 2건**(§6.1).
> **대조 실험**: `landPre1990` 게이트를 `false`로 두면 P-1이 **실패**한다 → 복원 시 통과.
> **선행**: [`inheritance-pre-deemed-clause-a-b-separation.plan.md`](inheritance-pre-deemed-clause-a-b-separation.plan.md) Phase D — **엔진은 준비 완료**, UI만 없다
> **세목**: 양도소득세 — 「소득세법 시행령」 §163⑨1호 · §164④

---

## 1. 한 줄 요약

**의제취득일 이후 ~ 개별공시지가 최초고시 전**(1985.1.1. ~ 1990.8.30.)에 상속·증여받은 **토지**는 취득가액을 산정할 **입력 경로가 아예 없다**.

- ① 상증법 평가액 → UI가 **상속개시일 현재 개별공시지가**를 요구하는데, 그 기간에는 **존재하지 않는 값**이다
- ② §164④ 등급 환산 → **입력 위젯이 노출되지 않는다**

⇒ 사용자가 화면에서 취득가액을 만들 방법이 없다. **dead-end**다.

---

## 2. 실태 (실측)

### 2.1 ① 경로 — **코드가 이미 알고 숨긴다** (착수 후 정정)

> ⚠️ 당초 "존재하지 않는 값을 요구한다"고 적었으나 부정확했다. 실제로는 **보충적평가 보조계산 섹션 자체가 숨겨진다.**

```ts
// PostDeemedInputs.tsx:80-82
const isPreDisclosure =
  (isLand && inheritanceDate < LAND_FIRST_DISCLOSURE_DATE) ||   // 1990-08-30
  (isHouse && inheritanceDate < HOUSE_FIRST_DISCLOSURE_DATE);   // 2005-04-30

// 보충적평가 섹션 게이트
{isSupplementary && !isPreDisclosure && … && ( … 개별공시지가 × 면적 … )}
```

⇒ **코드가 "이 기간엔 공시지가로 평가할 수 없다"를 이미 알고 있다.** 문제는 **대체 경로를 주지 않은 것**이다.

① 자체의 입력 경로(「상속세 신고가액」 필드)는 살아 있다 — 감정·매매사례로 확인한 값을 넣을 수 있다. 보조계산 섹션은 그 값을 자동으로 채워주는 도구일 뿐이다.

### 2.2 ② 경로 — **주택엔 있고 토지엔 없다** (비대칭)

`pre1990Grade_*`(§164④ 등급 환산) 입력을 렌더하는 곳은 셋뿐이다.

| 렌더 위치 | 노출 조건 |
|---|---|
| `CompanionAcqPurchaseBlock` | `CompanionAcquisitionCauseSection:141` — **`acquisitionCause === "purchase"`** |
| `PreDeemedInputs` | **pre-deemed**(상속개시일 < 1985.1.1.) 전용 |
| `GeneralBuildingAcquisitionCards` | 일반건물 경로 |

⇒ **post-deemed 상속 토지는 어디에도 해당하지 않는다.** `CompanionAcqInheritanceBlock`에 `pre1990` 참조는 **0건**이다.

⭐ **핵심은 자산 간 비대칭이었다** — 미공시 상속**주택**은 `showHouseValuation`(`PostDeemedInputs:75`)으로 **`isPreDisclosure`와 무관한 독립 섹션**을 갖고, 그 안의 `HouseValuationSection`이 부수토지 §164④ 등급환산을 이미 제공한다. **토지만 그 대칭 경로가 없었다**(anchor **P-4**가 이를 실증한다 — 주택에서는 §164④ 위젯이 이미 뜬다).

### 2.3 엔진·API는 이미 준비돼 있다

| 계층 | 상태 |
|---|---|
| 엔진 소비 | ✅ **Phase D 완료** — `calcPostDeemed`의 `sec164Std`가 `landValuationStdPrice`를 본다(anchor PL-1~PL-3) |
| 엔진 주입 | ✅ `shouldInjectLandMax` — pre/post 구분 없음 |
| STEP 0.4 | ✅ `transfer-tax.ts:85` `if (rawInput.pre1990Land)` — pre/post 구분 없음 |
| API 빌더 | ✅ `buildPre1990LandPayload` — 등급 3종·면적·1990 ㎡당가만 보고 만든다 |
| **UI 입력** | ❌ **없음** ← 유일한 갭 |

⇒ **UI 한 곳만 열면 전 계층이 이어진다.**

> ⚠️ **Phase D 커밋 서술 보정**: "PL-1이 실제 오류를 실증한다"고 적었는데, **현재 실사용자는 그 경로에 도달할 수 없다**. 엔진 결함은 실재했고 고친 것이 맞으나, 사용자 영향은 **이 UI 작업 후에 발생**한다.

## 3. 법령 근거

**§163⑨1호** — "1990년 8월 30일 개별공시지가가 고시되기 전에 상속 또는 증여받은 **토지**의 경우에는 상속개시일 또는 증여일 현재 상증법 §60~66에 따라 평가한 가액과 **제164조제4항의 규정에 의한 가액 중 많은 금액**"

**§164④** — 1990.8.30. 고시 전 취득 토지의 취득당시 기준시가

```
1990.1.1. 기준 개별공시지가 × (취득 당시의 시가표준액 ÷ [1990.8.30. 시가표준액 + 직전 시가표준액] ÷ 2)
```

⇒ 개별공시지가가 없는 기간을 위해 **토지등급가액으로 환산**하는 규정이다. 정확히 이 사안을 겨냥한다.

⭐ **1호의 조건은 「1990.8.30. 고시 전 상속·증여」뿐이고 의제취득일과 무관**하다 — 선행 계획서 Phase D에서 확정했다.

## 4. 변경 설계

### D-1. `PostDeemedInputs`에 §164④ **독립 섹션** 추가 ✅

**주택 `showHouseValuation` 블록을 미러**한다 — `isPreDisclosure`로 숨겨지는 보충적평가 섹션 **밖**에 둔다.

> ⚠️ 처음엔 보충적평가 섹션 **안**에 넣었다가 P-1이 계속 실패했다. 그 섹션이 `!isPreDisclosure` 게이트로 막혀 있었기 때문이다 — **막힌 방 안에 문을 단 셈**이었다.

```tsx
const landPre1990 = asset.assetKind === "land" && !!inheritanceDate && inheritanceDate < "1990-08-30";

{landPre1990 && (
  <div className="… amber …">
    <p>개별공시지가 미공시(1990.8.30. 이전 상속·증여) — … §164④ 환산액 중 <strong>큰 금액</strong> … (소령 §163⑨1호)</p>
    <Pre1990LandValuationInput … />   {/* 신규 위젯 제작 불요 — 재사용 */}
  </div>
)}
```

주택 블록과 문구·스타일을 맞춰 **자산 간 일관성**을 유지했다.

### D-2. ① 경로 — **변경 없음**

당초 "① 필드를 숨기지 않는다"고 적었으나, **이미 숨겨져 있고 그것이 옳다**(§2.1). ①의 실제 입력 경로는 「상속세 신고가액」 필드이고 그대로 살아 있다(anchor **P-5**).

### D-3. 공유 필드 — **위험 낮음** (U-1 해소)

`pre1990Grade_*`는 asset factory에서 `""`로 초기화되고 명시적 리셋 로직이 없다. 다만 **등급은 그 토지의 취득 당시 등급**이라 pre/post 모드가 바뀌어도 값이 유지되는 것이 오히려 자연스럽다. 별도 조치 불요.

**Pre-Do**: RTL P-1을 선작성해 **현행에서 실패**(섹션 미노출)를 먼저 확인한다.

### 6.1 E2E가 RTL과 다르게 지키는 것

RTL은 컴포넌트 단위로 **노출**만 본다. E2E는 **화면 → API → 엔진 → 결과**를 실제 브라우저로 관통시킨다 — 문이 열린 것과 그 문으로 들어가 계산이 되는 것은 다른 사실이기 때문이다.

- pre1990\* 필드를 **시드에 넣지 않는다** — 화면 입력만으로 채워져야 dead-end 해소가 증명된다.
- 수치: 등급 3종 동일 ⇒ 비율 1.0(Case ②) ⇒ ② = 100,000/㎡ × 1,000㎡ = **100,000,000**.
  ① 신고가액 **50,000,000** < ② ⇒ **② 채택** — max 선택이 세액을 실제로 움직인 것을 응답 body(`data.result.inheritedAcquisitionDetail`)로 직접 확인한다.
- **대조 실험**: `landPre1990`을 `false`로 두면 §164④ 섹션 단언에서 **실패**(element not found) → 복원 시 통과.

> ⚠️ **E2E가 실제 결함 하나를 잡았다** — 최초 시드에 `decedentAcquisitionDate`가 없어 계산 API가 **400**(`상속의 경우 피상속인 취득일이 필수입니다`)으로 막혔다. RTL은 API를 타지 않으므로 이 차단을 볼 수 없다.

## 10. 🟠 별건 — 증여는 §163⑨ 경로를 타지 않는다

§163⑨1호·2호·본문은 모두 **"상속 또는 증여"**를 대상으로 한다. 그런데 `buildInheritedAcquisitionPayload`는 **`acquisitionCause === "inheritance"`에서만** 호출된다(`transfer-tax-api-inheritance.ts:25·154`).

⇒ **증여로 취득한 자산은 §163⑨ 취득가액 의제 자체가 적용되지 않는다.** 본 계획(토지 UI)보다 **범위가 크고 세액 영향도 크다** — 별도 조사·계획이 필요하다.

⚠️ 다만 증여에는 `CompanionAcqGiftBlock`·이월과세 등 별도 경로가 있으므로, **다른 곳에서 등가로 처리되고 있을 가능성**을 먼저 확인해야 한다. 「부재는 증거가 아니다」.
