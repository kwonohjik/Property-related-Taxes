## 2. 진단 — 부자연스러움의 근본 원인

- **(A) 두 판정 트랙 혼재**: 비과세(§154·§155)와 주택수·중과(§167의3·§104⑦)가 ① 안에서 교대. 중과용 "감면주택 제외"가 비과세용 거주기간·§154 단서 사이에 삽입됨.
- **(B) 인과 역순**: 취득일 기준 조정지역(L354, 거주 2년 필요 여부의 *원인*)이 그 결과인 거주기간 입력(L304)보다 **아래**.
- **(C) 추상 수치 ↔ 실체 입력 분리**: ①의 "세대 보유 주택 수=2채"(추상)와 ③ 다른 보유 주택 목록(실체)이 멀리 떨어짐. 같은 §167의3 항목(감면주택 제외 ①L242 · 주택 목록 ③)이 두 곳으로 분산.
- **(D) 트랙 순서 뒤집힘**: ②(일시적2주택=비과세) → ③(주택 목록=중과)이나, 사용자 판단 깔때기상 비과세 특례가 중과 입력보다 앞서야 자연스러움(전액 비과세면 중과 무의미 — 엔진도 STEP 1a에서 조기 반환). ※ 엔진 STEP 순서 자체는 중과(0.5)→비과세(1)이나, 이는 rate 조기 계산일 뿐 결과 지배 순서는 비과세 우선(§3 근거 참조).

## 3. 제안 — 깔때기(funnel) 재배치

**정렬 근거 (실측 정정 2026-07-19)**: 엔진의 실제 STEP 순서는 중과 판정(`transfer-tax.ts:179` STEP 0.5)이 비과세 판단(`transfer-tax.ts:272` STEP 1)보다 **먼저**다 — 중과세율을 rate 입력으로 조기 계산하기 때문. 그러나 **전액 비과세 시 STEP 1a(L274)에서 조기 반환**하므로 결과적으로 비과세가 지배한다. 따라서 UI는 엔진 STEP 순서(중과 먼저)가 아니라 **사용자 판단 깔때기 = 결과 지배 순서**(비과세면 중과 무의미 → 비과세 여부 먼저 확정 → 아니면 주택수·중과)에 정렬한다. (CLAUDE.md "UI 순서 = 엔진 계산 로직 순서"는 여기선 rate 계산 순서가 아닌 **판단 결과 지배 순서**로 해석.)

| 신 순서 | 섹션 | 담는 항목 | 트랙 |
|---|---|---|---|
| ① | 세대 기본 | 1세대 해당 · 세대 보유 주택 수(분기점) · [입주권 자산] 입주권 수 | 공통 |
| ② | 1세대1주택 비과세 판정 | 취득일 조정지역 → 1세대1주택 효과 배너 → 거주기간 입력 → 거주요건 경고 → §154① 단서 면제 | 비과세 |
| ③ | 비과세 특례 | 일시적 2주택 · **대체주택 §156의2** · 합가(혼인·동거봉양) (현 ② 블록 전체) | 비과세 |
| ④ | 주택수·중과 판정 | 다른 보유 주택 목록+분양권(현 ③) · 조특법 감면주택 제외(현 ①L242) · 양도일 조정지역 + 중과 검토 안내 | 중과 |
| ⑤ | 특수 상황 | 미등기·NBL·중과 (현 ④) | 중과 |

### 핵심 이동 4가지 (우선순위 순)

1. **조정지역 2토글 목적별 분리** ⭐ 최고가치
   - 취득일 기준(비과세 거주요건) → ②로 이동, **거주기간 입력 바로 위**.
   - 양도일 기준(중과 기준) + 중과 검토 안내(L362) → ④ 중과 그룹.
   - 근거: 두 토글이 현재 한 grid(`grid grid-cols-1 sm:grid-cols-2`, L343)에 묶였으나 서로 반대 트랙을 먹임 → 원인(취득일 조정지역)을 결과(거주기간) 앞으로.
   - **주의**: 분리 시 공유 2-column grid가 해체되어 각 토글은 소속 섹션에서 standalone full-width `ToggleCard`가 된다(레이아웃 변경 — 기능·필드 불변).
2. **조특법 감면주택 제외(현 ①L242) → ④로 이동** (다른 주택 목록 인접). 같은 §167의3 주택수 산정 항목 통합.
3. **②(일시적2주택) ↔ ③(다른 주택 목록) 트랙 순서 정리**: 비과세 특례를 중과 입력보다 앞에.
4. **거주기간·§154 단서를 "비과세 판정" 서브그룹으로 묶기**: 흩어진 개별 카드 → 명시적 시각 경계.

## 4. 리스크·준수사항

- **표시 조건(gate) 전부 보존**: `isOneHousehold` / `primaryKind==="housing"` / `parseInt(householdHousingCount)>=2` / `right_to_move_in` 게이트는 위치만 이동, 조건 불변.
- `residenceShortfall` 경고(L319)는 거주기간 카드에 종속 → 함께 이동.
- **3중 패턴·useEffect→store 미러링 금지** 유지 — onChange 직접 set만 재배치, 미러링 도입 없음.
- **엔진·API·Zod·validation 무변경** — 순수 JSX 순서 재배치이므로 14 동기화 지점 영향 없음(⑤ UI 위젯 위치만).
- 조정지역 자동판별 배너(L144)·`regulatedAuto` 파생(store 미러링 없이 useMemo)은 섹션 밖 상단 유지.
- **섹션 tone**: 현 ①sky/②emerald/③violet/④rose. 재배치 후 새 ②(비과세)·④(중과) 트랙에 tone 일관성 1줄 검토 권장(색값 자체는 `tones.ts` 정본이라 무변경 — 배치만 조정). 인라인 `bg-${tone}` 하드코딩 금지 유지.
