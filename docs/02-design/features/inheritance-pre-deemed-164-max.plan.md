## 1. 한 줄 요약

`calcPreDeemed`가 `max(① 상증법 평가액, ③ 환산취득가)`만 계산하고 **②(§164④~⑦ 취득당시 기준시가)를 빠뜨린다**. 코드 주석이 스스로 "Phase 2"라 적어둔 갭이다. ②가 더 큰 케이스에서 **취득가액 과소 → 세액 과대**다.

## 3. 법문 근거 (법제처 현행, 2026-07-01 시행 · 전문 확인)

### 3.1 「소득세법 시행령」 §163⑨ — **근거는 여기다**

> ⑨ 상속 또는 증여받은 자산에 대하여 법 제97조제1항제1호가목을 적용할 때에는 **상속개시일 또는 증여일 현재** 「상속세 및 증여세법」 제60조부터 제66조까지의 규정에 따라 평가한 가액 … 을 **취득당시의 실지거래가액으로 본다**. 다만, 다음 각 호의 어느 하나에 해당하는 경우에는 각 호의 구분에 따라 계산한 금액으로 한다.
> 1. … **1990년 8월 30일 개별공시지가가 고시되기 전**에 상속 또는 증여받은 **토지**의 경우에는 … 평가한 가액과 **제164조제4항의 규정에 의한 가액 중 많은 금액**
> 2. 「상속세 및 증여세법」 제61조제1항제2호 내지 제4호의 규정에 의한 **건물의 기준시가가 고시되기 전**에 상속 또는 증여받은 **건물**의 경우에는 … 평가한 가액과 **제164조제5항 내지 제7항의 규정에 의한 가액 중 많은 금액**

🔴 **핵심 — §163⑨은 「의제취득일」로 나뉘지 않는다.** 조건은 오직 **「기준시가 고시 전 상속·증여」**다.

의제취득일(1985-01-01) 전 상속이면 개별공시지가(1990-08-30)·건물 기준시가(2005) **둘 다 고시 전**이므로 **1호·2호에 당연히 해당한다.**

⇒ **pre-deemed에서 ②를 max에 넣을 근거는 §163⑨ 그 자체**다. post-deemed와 **같은 조문**이다.

### 3.2 「소득세법 시행령」 §176조의2④ — **다른 축이다. 혼동 금지**

> ④ … 의제취득일 전에 취득한 자산(상속 또는 증여받은 자산을 포함한다)에 대하여 **제3항제1호부터 제3호까지의 규정을 적용할 때에** 의제취득일 현재의 취득가액은 다음 각 호의 가액 중 **많은 것**으로 한다.
> 1. **의제취득일 현재** 제3항제1호 내지 제3호의 규정에 의한 가액
> 2. 취득 당시 실지거래가액이나 제3항제1호·제2호 가액이 확인되는 경우로서 … **생산자물가상승률**을 곱하여 계산한 금액을 합산한 가액

⚠️ ④의 max 대상은 **제3항 제1호~제3호**(매매사례가액·감정가액·환산취득가액)뿐이다. **제4호(기준시가)는 명시적으로 빠져 있다.**

⇒ **§164 기준시가(②)를 ④의 max에 넣을 근거는 없다.** ②의 근거는 §163⑨이지 §176조의2④가 아니다. **두 규정은 대상도 축도 다르다.**

| | 규정 | max 대상 |
|---|---|---|
| **§163⑨** | 상속·증여 자산의 **취득당시 실지거래가액 의제** | ① 상증법 평가액 ↔ **② §164④~⑦** |
| **§176조의2④** | 의제취득일 전 취득 자산의 **추계(1~3호) 적용 시** | ①' 의제취득일 현재 1~3호 ↔ ②' 물가상승률 방식 |

⇒ 현행 `calcPreDeemed`의 `max(① 상증법, ③ 환산)`은 **두 축을 한 번에 섞은 근사**다. ②를 더하는 것이 §163⑨ 문언에 맞다.

### 3.3 「시점 확정 필요」의 답 — **상속개시일**

코드 주석이 남긴 미결(`값·시점 확정 필요`)의 답이 §163⑨ 본문에 있다:

> **상속개시일 또는 증여일 현재** … 평가한 가액

②(§164④~⑦)도 같은 문장의 비교 대상이므로 **상속개시일 기준**이다. **의제취득일(1985-01-01)이 아니다.**

⇒ post-deemed가 쓰는 `housePriceAtInheritanceUsed`(취득 시점·미스케일)와 **같은 성격의 값**이다.

## 4. 무엇을 바꾸나

### D-1. `calcPreDeemed`에 ② 추가

```ts
// 현행
const acquisitionPrice = Math.max(reported, converted);

// 변경 — §163⑨1호·2호: 기준시가 고시 전 상속·증여면 ②도 비교 대상
const sec164Std = input.houseValuationStdPrice ?? input.commercialValuationStdPrice ?? 0;
const acquisitionPrice = Math.max(reported, converted, sec164Std);
```

`selectedMethod`·`preDeemedBreakdown`·`buildPreDeemedFormula`에 ② 분기를 추가한다(표시 계층은 **금액이 틀린다** — 선행 계획서 교훈).

### D-2. 주입 게이트 확장

`inheritance-acquisition-helpers.ts:151`

```ts
// 현행 — post-deemed 전용
const shouldInjectPostDeemedHouseMax = !!houseValuationResult && !isPreDeemed && isHousePreDisclosure;
```

`!isPreDeemed` 조건을 제거해 pre-deemed에도 주입한다. 상가 §164⑥(`:156` `shouldInjectCommercialMax`)도 동일.

⚠️ **pre-deemed는 `shouldInjectHouseValuation`(`:146`)이 같은 값을 `standardPriceAtDeemedDate`(③ 환산 **분자**)로도 쓴다.** 한 값이 두 용도로 가되 **필드는 분리**해야 한다 — 이것이 주석이 말한 "환산 분자와 구분되는 값"의 실체다. 값은 같고 **역할이 둘**이다.

### D-3. 필요경비 처리 정합

- ①·② = 실지거래가액 **의제** → 자본적지출·양도비 **실제 공제**
- ③ = 추계 → **§163⑥ 개산공제**

②가 채택된 경우 개산공제를 적용하면 **이중 혜택**이다. `calcPostDeemed`가 이미 "①·② 실지거래가액 의제 → 개산공제 없음"으로 처리하므로 **같은 규칙을 pre에도** 적용한다.

## 6. 논점

### V-1. §176조의2④와의 적용 순서 — **미확정**

§163⑨이 「취득당시 실지거래가액」을 정하고, §176조의2④는 「의제취득일 현재 취득가액」을 정한다. **두 결과가 다를 때 어느 것이 최종인가**에 대한 명문을 확인하지 못했다.

- 현행 코드는 `max(①,③)`으로 **둘을 한 번에 섞고 있어** 이 순서 문제를 우회한다.
- ②를 더해도 같은 방식(3자 max)이면 **현행 근사의 연장**이다 — 새 위험을 만들지 않는다.
- ⚠️ **예규·심판례 확인 전까지 3자 max로 두고, 순서 재편은 별건**으로 남긴다.

### V-2. ③의 분자 시점 — **별건**

§176조의2④1호는 "**의제취득일 현재**" 1~3호 가액인데, 현행은 `housePriceAtInheritanceUsed`(**상속개시일** 기준)를 환산 분자로 쓴다. 시점이 어긋날 수 있다.

**본 계획의 범위 밖**이다 — ② 추가와 직교하고, 건드리면 pre-deemed 전건이 흔들린다. 별건으로 기록만 한다.
