법정 기한: 양도일이 속하는 달의 말일부터 2개월(「소득세법」 §105①1호). 양도일이 달라지면 기한이 달라진다.

## 1. 측정 (V 레지스터)

공통: 단독 APT, 취득가 4억, 권리가액 20억, 수령 5억, 고시일 다음날 2024-03-01, 다주택 시료. 「같은 날」은 폼 양도일을 고시일 다음날로 넣은 값이고, 이 값이 사실관계에 맞는 값이다.

**V-1 단건**

| 폼 양도일 | 신고일 | 현행 세액 | 현행 판정 | 같은 날 세액 | 차이 |
|---|---|---|---|---|---|
| 2024-06-01 | 2024-07-15 | 97,405,000 | 기한 내(8/31) | 107,117,164 | 9,712,164 **과소** |
| 2024-06-01 | 2024-09-15 | 106,532,734 | 기한 후(8/31) | 108,324,986 | 1,792,252 **과소** |
| 2024-01-10 | 2024-04-15 | 106,532,734 | 기한 후(3/31) | 97,405,000 | 9,127,734 **과대** |
| 2024-03-01 | 2024-05-15 | 97,405,000 | 기한 내(5/31) | 97,405,000 | 없음 |

축 B(50/50)도 같다: 폼 2024-06-01·신고 2024-07-15 → 97,405,000, 같은 날 107,117,164.

⚠️ 판정 파생만 고시일로 바꾸면 틀린 값이 나온다. `lateFiling.statutoryDeadline`이 폼 기준으로 남아 115,972,164가 된다. 가산세는 지연일 등 여러 값이 같은 기준일을 써야 한다.

**V-2 함께 양도(단독 APT + 주택 10억, 고시일 다음날 2024-03-01, 폼 2024-06-01)**

| 신고일 | 사실관계 | 세액 |
|---|---|---|
| 2024-07-15 | APT 기한(5/31) 경과, 주택 기한(8/31) 이내 | 357,555,000, 가산세 없음 |
| 2024-09-15 | 둘 다 경과, 기한은 8/31로 일괄 | 391,061,154 |

가산세는 신고 단위로 계산해 자산별 기한을 담을 칸이 없다. 같은 달이면(고시일 다음날 2024-06-01 · 폼 2024-06-20) 기한이 8/31로 같아 문제가 없다: 신고 8/15 → 357,555,000, 9/15 → 391,061,154.

**V-3 미측정**: 브라우저 화면, 저장 이력 복원(마이그레이션 파생), 수정신고 경로의 법정신고기한, 전 자산 단독 함께 양도의 가산세, 폼 양도일을 읽는 나머지 소비처의 값 영향.

## 2. 결정 요청 (Q 레지스터)

**Q-1 단건·축 B (D-1)** — **a) 전 자산이 단독이면 폼 양도일이 첫 자산의 고시일 다음날과 같아야 한다고 ⑧에서 막는다(권장).** 토글 카드가 이미 「양도일은 소유권이전 고시일의 익일로 입력하세요」라고 안내하지만 강제하지 않았다. 날짜가 같으면 기존 파생이 그대로 맞고(V-1 마지막 열), 다른 소비처도 함께 맞는다. b) 유효 양도일 함수를 만들어 소비처마다 바꾼다 — 고칠 곳이 많고 누락 위험이 있다. c) 유지.

**Q-2 함께 양도 (D-2)** — **a) 자산별 기한이 다르고 신고일이 가장 이른 기한을 넘으면 ⑧에서 막고 「따로 계산」으로 안내(권장).** 기한 내 신고는 가산세가 없어 값이 맞으므로 계속 허용한다. b) 자산별 가산세 계산을 새로 만든다 — 엔진 변경이 크다. c) 유지.

**Q-3 ⑫** — **a) ⑧만 막는다(권장).** ④가 양도일을 바꿔 보내 ⑫는 폼 날짜를 볼 수 없고, 가산세 본문도 클라이언트가 만든다. 그래서 API 직접 호출에는 이 차단이 적용되지 않는다. b) 본문에 폼 날짜를 추가로 싣고 ⑫도 막는다.

## 3. 구현 계획 (Q 전부 권장안 기준)

1. anchor 먼저(원본에서 실패 확인): 단건·축 B 날짜 불일치 차단, 같은 날 통과·세액 불변, 함께 양도 기한 초과 차단·기한 내 통과·같은 달 통과, 대조군(단독 없음).
2. `lib/calc/`의 leaf 판정을 ⑧이 부른다. 안내는 양도일 칸을 가리킨다.
3. 단독 신고 기존 시료 27개 파일 중 날짜가 다른 시료가 ⑧ 단언에 걸리면 사실관계에 맞게 고친다(세액 단언은 건드리지 않는다).
4. V-3의 브라우저·저장 이력을 재고, 틀린 값이 나오면 멈추고 보고한다.
5. 뮤테이션(기준선 통과 확인 후) → 전체 회귀 → tsc·eslint → 브라우저 → 이 문서에 결과 추가.

세액 계산 경로는 바꾸지 않는다. 지금 틀린 값을 내는 입력은 값이 바뀌는 대신 막히고, 날짜를 맞추면 「같은 날」 값이 나온다.
