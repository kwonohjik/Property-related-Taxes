# 함께 양도하는 재개발 자산 — 상속·증여 §164 기준시가(②)를 싣지 않아 버려진다

> **출처**: `redev-successor-inherit-right-no-sec164.plan.md` §4 V-1′(#2876) — 「컴패니언 · 승계 · 준공 뒤 받음 — 컴패니언은 ②를 싣지 않아 주 자산과 다르다」.
> **결정**: 사용자 「권장안으로」(2026-11-04) — Q-1 a · Q-2 a · Q-3 a.
> **검증 깊이**: L3 — 세액이 바뀐다(바로잡힌다). 측정하니 승계만이 아니라 **원조합원(종전 주택 상속)** 컴패니언도 같은 원인이었다.

## 0. 결론

- 원인 한 곳: ④ `ownsAcquisitionSubobject`(`lib/calc/transfer-tax-api-companion-payload.ts:730`)가 컴패니언 `right_to_move_in`·`redevelopment_apt`를 §163⑨ 운반(CP-3 — `inheritedAcquisition`·`inheritedHouseValuation`) 대상에서 통째로 뺀다. 그래서 화면에서 ② 칸을 채워도 컴패니언은 ①(`inheritanceValuation`)만 실린다.
- 법: 소득세법 시행령 §163⑨ 단서 2호는 자산이 주 자산인지 함께 양도하는 자산인지 가리지 않는다. 주 자산은 이미 max(①,②)다.
- 시험 수정(그 자산이 §163⑨ 주택 자산 ∧ 상속·증여면 운반)으로 엔진이 **이미** 맞게 계산함을 확인했다 — 컴패니언 ①+② = 컴패니언 ①을 ② 값으로 넣은 것과 같은 세액(§1.2).

## 3. 변경 계획 (Q 전부 a 기준)

1. ④ `ownsAcquisitionSubobject` — `right_to_move_in`·`redevelopment_apt`라도 `isSec163_9HouseAsset(asset) && isSec163_9Cause(asset.acquisitionCause)`면 운반 대상(거짓)으로 둔다. 부담부증여 제외(`isBgPreDeemedAsset`)는 지금 모양을 지킨다(구현 때 확인). 토지 출자 원조합원(`isSec163_9LandAsset`)의 §164④(`pre1990Land`)도 같은 갭인지 구현 전에 잰다(확인 필요 — §4 V-1).
2. ⑧ — 원조합원 컴패니언 ① 필수 규칙과 승계 규칙의 `isNonPrimaryAsset` 예외를 지워 주 자산과 같게(Q-2 a). 승계 메시지의 「함께 양도하는 자산은 §164 기준시가로 대신 계산하지 않습니다」 꼬리도 지운다.
3. ⑫ — 컴패니언 원조합원 ① 필수 refine(`refineOriginalMemberDeemedCompanion`)이 ②만 온 경우를 받는지 확인(시험 수정에서 200 — 코드 변경 없을 가능성). 준공 전 받음 승계 거절(#2876 `refineSuccessorAptRightNoSec164Inputs`)은 그대로.
4. 테스트 — #2586 anchor H-2d(「컴패니언은 ②를 대안으로 보지 않는다」)는 의도된 단언 반전. 원조합원 anchor의 컴패니언 행 추가. anchor → mutation → 회귀 → tsc/eslint → Playwright(컴패니언 ② 채움 → 본문 `companionAssets[0].inheritedHouseValuation` · 세액).

## 5. 법령 근거

- 소득세법 시행령 §163⑨ 단서 2호 — 건물 기준시가 고시 전 상속·증여받은 건물 = max(평가액, §164⑤~⑦). 주 자산·함께 양도 구분 없음(KoreanLaw MCP 현행 mst 290841 본문 · #2876 계획서 §5와 같은 조회).
- 원조합원 종전 주택 → 영 §166① 기존건물 취득가액 → 법 §97①1호가목 → 영 §163⑨ 단서 2호(`isSec163_9HouseAsset` 주석 · successor-right-carryover-contribution.plan.md §14·§15).
