# 승계조합원 상속 — 상속개시일 평가액 필수 · 재개발 상속 피상속인 취득일 필수 (⑧)

> **출처**: `redev-successor-bg-acq-method.plan.md` §9 「확인 필요로 남긴 것」 첫 줄 — 「상속 승계에서 상속 평가액 원천을 비우면 ⑧은 통과하고 엔진이 400으로 중단한다(종전부터 같은 갭)」.
> **검증 깊이**: L2 — ⑧만 바뀐다. 엔진·④·⑫는 그대로다. 정상 입력의 세액은 바뀌지 않는다(§4 값 불변 행). 다만 화면에서 숨은 값으로 계산되던 경로 1개(§2 I2)가 닫힌다.

## 1. 결함

| 행 | 입력 | 수정 전 ⑧ | 수정 전 서버 |
|---|---|---|---|
| I1 | 승계 완공 APT · 상속 · ① 평가액 비움 | 통과 | 400 INVALID_INPUT(엔진 트립와이어) |
| I2 | 같음 + 매매에서 남은 취득가액 450,000,000 | 통과 | **200 · 327,250,000** — 상속 카드엔 없는 칸의 값으로 계산 |
| I3 | ① 비움 + 평가방법 비움 | 통과 | 400 |
| C1 | 컴패니언 · ① 비움 | 통과 | 400 |
| F1 | 지분 1/2 · ① 비움 | 통과 | 400 |
| D1·D5·D7·D2 | 재개발 계열 상속(승계 APT · 승계 입주권 · 원조합원 입주권 · 원조합원 APT) · 피상속인 취득일 비움 | 통과 | 400(⑫ 「상속의 경우 피상속인 취득일이 필수입니다」) |
| D3 | 일반 주택 상속 · 피상속인 취득일 비움(대조) | **막음** | 400 |

- 원인 ①: 일반 자산은 `postDeemedClauseARequiredError`(`transfer-tax-validate-clause-a.ts`)가 ① 또는 ②를 요구한다. 재개발은 그 표에서 빠진다 — 「`validateRedevelopmentAsset`이 종전자산 취득가액을 필수로 요구」라는 근거인데, 승계조합원은 그 규칙도 제외된다(`!isSuccessor`). ④는 ① > 0 또는 (상속 ∧ §164 충족)일 때만 `inheritedAcquisition`을 싣는다(`buildInheritedAcquisitionPayload`).
- 원인 ②: `validateAssetAcquisition`의 재개발·승계 입주권 분기가 일반 상속 분기(피상속인 취득일 필수 — `transfer-tax-validate-acquisition.ts` 상속 분기)보다 먼저 `return null`한다. ⑫는 모든 상속 자산에 피상속인 취득일을 요구한다(`transfer-tax-schema-refines.ts` · 컴패니언 `transfer-tax-schema-companion-refines.ts`).
- 원인 ②는 원인 ①을 고친 뒤 화면에서 바로 다음에 만나는 같은 증상이라 함께 다룬다(E2E 뮤테이션 실행 중 발견 — 피상속인 취득일을 비운 시료가 ⑫ 400을 받았다).

## 2. 변경

1. ⑧ `transfer-tax-validate-redev.ts` — 승계 ∧ 상속 ∧ 부담부증여 아님 ∧ ① ≤ 0 ∧ (함께 양도하는 둘째 이후 자산 ∨ `!isSec164ClauseAFilled`) → `publishedValueAtInheritance` 칸. 주 자산의 술어는 ④의 `sec164Ready`와 같은 3경로(주택·상가·토지 §164 완전 충족)다. 컴패니언은 ④가 ①(`inheritanceValuation`)만 싣고 ②는 싣지 않으므로(`transfer-tax-api-companion-payload.ts` `ownsAcquisitionSubobject`) ①을 요구한다 — ②만 채운 경우 안내 한 줄을 붙인다. 부담부증여는 §159가 취득가액을 정한다(④도 싣지 않는다).
2. ⑧ `transfer-tax-validate-acquisition.ts` — `redevInheritedDecedentDateError`를 재개발 분기·승계 입주권 분기 끝에 붙인다. 각 분기의 고유 검사가 먼저다. (이후 정정: 분기별 두 줄은 V-2 수정의 마지막 관문 `inheritedDecedentDateError`로 대체됐다.)
3. 시료 정정 `successor-unsupported-notice-g3-11` G-4 — 상속 승계 시료가 매매 기본값의 `fixedAcquisitionPrice`로 계산되고 있었다(I2와 같은 상태). 평가액 칸으로 바꿨고 결과(비과세 판정)는 같다.

질문 Q-n 없음 — 일반 자산과 같은 규칙을 재개발 승계에 맞추는 것이다(⑧↔④↔⑫ 정합).

### 취득가액 리뷰 게이트(2026-10-26) — FAIL 1 → 반영

- **FAIL 1 반영**: 컴패니언 승계 상속 · ② 전부 채움 · ① 비움 → ⑧ 통과 ↔ 엔진 400(실측 CA). ④ 컴패니언이 ②를 싣지 않는다. ⇒ 컴패니언은 ①을 요구(H-2d · P9·P10). ②를 싣게 하는 대안은 V-1·V-3과 묶어 별건.
- 법령: 소득세법 시행령 §163⑨ 본문(상속개시일 현재 상증법 §60~§66 평가액 = 취득당시 실지거래가액) · 소득세법 §97①1호 · §104②1호(피상속인 취득일)는 리뷰가 KoreanLaw MCP로 확인. §163⑨ 단서 2호(건물 기준시가 고시 전 상속 **건물**)가 입주권 상속에 닿는지는 해석례·재결 검색 0건 → V-1 유지.
- 문구: 새 메시지의 「시행령 §163⑨」를 「소득세법 시행령 §163⑨」로 고쳤다. 같은 파일의 기존 증여 메시지(#2577)도 같은 약식이다 — 이 PR에서는 건드리지 않는다.
- 피상속인 취득일 규칙: 승계 APT의 세액에는 쓰이지 않는다(1999·2010·2019 → 모두 327,250,000 — 준공일 기산). ⑫가 모든 상속 자산에 요구하므로 ⑧이 같은 칸을 먼저 짚을 뿐이다 — 그래서 메시지에 §104②1호 인용을 붙이지 않았다(단기보유 통산에 쓰인다는 오해 방지).
