# 국외전출세 2027.1.1. 개정 대응 (소득세법 §118의9~§118의18) — 계획 색인

> 상태: **계획(PR-0) · 사용자 결정 완료(2026-11-27, §2.1)** · 구현 착수 PR-1
> 엔진·API: [stock-transfer-exit-tax-2027.engine.plan.md](stock-transfer-exit-tax-2027.engine.plan.md) (Q-1~Q-12 · V-1~V-16 · K-n)
> 화면: [stock-transfer-exit-tax-2027.ui.plan.md](stock-transfer-exit-tax-2027.ui.plan.md) (UQ-1~UQ-9 · D-1~D-9 · V-1~V-14)

## 1. 출발점

- 부칙 <법률 제21221호, 2025.12.23.>
  - 제1조 2호: §118의9~§118의18 개정규정을 **2027.1.1.** 시행한다.
  - 제8조: 「2027년 1월 1일 이후 거주자가 **출국하는** 경우부터 적용」한다.
  - 기준일은 **출국일**이며, 실제 양도일이 아니다.
- 바뀌는 것 3가지
  1. 대상에 §94①3호 다목(국외주식등)이 추가된다.
  2. §118의11이 1호(20%/25% 누진)와 2호(중소기업 10% / 그 밖 20%)로 갈린다.
  3. 시행령 §178의8②(국외주식등 제외 3가지, 5억원 이하 등)와 §178의9②3호(시가 = §178의3)가 신설된다. 둘 다 시행령 부칙 제36129호에 따라 2027.1.1. 시행이다.
- 현행 엔진(`lib/tax-engine/stock-transfer/exit-tax.ts`)은 `departureDate`를 0번 참조한다. 세율은 단일 누진표다. 따라서 연혁 게이트·세율 분기·국외 종목이 모두 신규다.
- 회귀 기준(음성 시료): 교재 사례(PR #3695)는 2026.9.1. 출국이다. 갑 41,875,000 · 을 14,500,000이 그대로 나와야 한다.
  - 이 사례는 실제 양도일이 2027.3.1.이다. 게이트를 실제 양도일로 걸면 깨진다.
- 조회 주의: 시행령 MST 290841을 `efYd` 없이 조회하면 시행예정 문언이 섞여 나온다. 종전/개정은 `lawId + efYd`(20261231 / 20270101)로 구분해 조회한다.

### 2.2 PR-7 결정 (2026-11-27) — 2호 경정청구 일반화(PR-7a 엔진·API → PR-7b 화면)

| # | 결정 | 구현 메모 (PR-7a) |
|---|---|---|
| P-1 | **실제 양도가 환율 (엔진 V-9)** | 국외주식 실제 양도가는 «외화 1주당 양도가(`priceForeign`) + 실제 양도일 기준환율(`exchangeRate`)»을 직접 입력한다. 환산은 `toKrwExact`(외화 단가 × 양도 주수 × 환율을 1회 절사). 국내 종목은 원화 단가(`pricePerShare`). 반대 쪽 필드가 오면 `INVALID_INPUT`. «환산 기준일 법령 명시 없음 — 확인 필요»를 결과 warnings에 고지한다 |
| P-2 | **부분 양도** | 종목마다 `holdings[].actualTransfer = { shareCount, … }`. 조정공제·외국납부세액공제는 양도한 주식 수만큼만 계산하고 양도하지 않은 주식은 넣지 않는다. 양도 주수가 보유 주수보다 많거나 1 미만·비정수이면 `INVALID_INPUT`. `actualTransfer`가 없는 종목 = 양도하지 않은 종목. 제외된(비과세 대상) 종목에 입력이 오면 조용히 무시하지 않고 `INVALID_INPUT` |
| P-3 | **혼합 조정공제 (엔진 V-7) = 구분별 세율** | 구분 b마다 `산출세액(TB_b) − 산출세액(TB_b − 구분 b의 가액 하락분)`(1호 누진표 · 2호 스칼라), 조정공제 = 구분별 합. 단일 구분이면 종전 식과 같다(K-16: 2호 나목 하락 200,000,000 × 20% = 40,000,000). 구분이 둘 이상이면 결과에 «확인 필요»를 고지한다 |
| P-4 | **외국납부세액 = 종목별 (엔진 V-8)** | §118의13①은 「해당 자산의 …」라 종목별 식이다 — 종목마다 `외국납부세액 × [양도가액(§118의12①이면 실제 양도가액) − 필요경비] ÷ (실제 양도가액 − 필요경비)`. 총액을 종목에 자동 안분하지 않는다(종목별 입력 필수). 한도 = 총액 기준(산출세액 − 조정공제액) — **구분 간 한도 귀속 규정이 없어** 구분별로 나누지 않고 총액 하나로 적용하며, 구분 ≥2이면 «확인 필요»를 고지한다 |
| P-5 | **기존 입력 호환** | 전역 `actualTransferPricePerShare`·`actualTransferDate`·`foreignTaxPaid*`·`domesticSourceTaxWithheld`는 유지(2026 출국 교재 갑 41,875,000 불변). 종목별 입력과 전역 입력이 동시에 오면 `INVALID_INPUT`. 2호 과세 종목이 있거나 구분이 둘 이상인데 전역 입력이 오면 종전처럼 차단하되 «종목별 입력을 쓰라»고 안내한다 |
| P-6 | **§118의14 비거주자 세액공제 (엔진 V-14) 판단** | §119 11호(KoreanLaw MCP 실독, 2026-11-27): 가목 「내국법인이 발행한 주식 또는 출자지분과 그 밖의 유가증권」 / 나목 「외국법인이 발행한 주식 또는 출자지분(증권시장에 상장된 것만 해당한다)」. → 1호 종목(내국법인)과 2호 중 내국법인 발행(`isListedForeignCorp=false`)은 §118의14① 대상. **2호 중 외국법인 발행(기본값)은 나목의 「증권시장」이 국내 증권시장만인지 해외 시장을 포함하는지 법문에 없어 국내 과세 여부를 판정할 근거가 불명확 → 차단 + 고지**(`INVALID_INPUT`, 외국납부세액으로 입력하도록 안내). 영 §179⑪1(증권시장 양도 25% 미만 소유 제외)은 판정하지 않는다 — 원천징수액(§156①7)을 사용자가 입력하는 구조라 그 입력이 곧 국내 과세의 선언이다. §118의14②(외국납부세액공제와 배타)는 종전대로 유지 |
| P-7 | **하락분 비교 단위 (설계 선택)** | 사용자 결정 3개 외 법문이 정하지 않은 부분: 실제 양도가액과 출국일 양도가액의 비교는 **종목별**(종목 간 상계 없음). §118의13①이 「해당 자산」별이고 §118의12①이 상계를 정하지 않아서다. 실제 양도가액이 더 높은 종목이 섞이면 «확인 필요»를 고지한다 |

필드 정의(⑫ 정본): `holdings[].actualTransfer = { shareCount, transferDate?, pricePerShare? | priceForeign? + exchangeRate?, foreignTaxPaid? | foreignTaxPaidForeign? + foreignTaxExchangeRate? (+ foreignTaxCurrencyCode?), domesticSourceTaxWithheld? }`. `foreignTaxExclusionReason`(§118의13②)은 종전대로 최상위 하나다.

| W-4 | **토글 OFF = 값 전부 초기화** | `actualTransfer: ExitTaxHoldingActualForm \| null`(null = 양도하지 않음). 외국납부세액 방식(원화↔외화) 전환은 안 쓰게 된 쪽을 비운다 |
| W-5 | **결과** | 엔진 echo만 읽는다 — `holdingDetails[].actualTransfer` · `bucketDetails[].adjustmentDeduction·priceDrop`. 확인 필요 고지는 엔진 `warnings`(주의사항) |
