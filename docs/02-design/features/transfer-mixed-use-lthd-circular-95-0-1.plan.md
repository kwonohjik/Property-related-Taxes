## 4. 수정 설계

### 4.1 단건 — `buildHousingPart` (W-1·W-2)

일반 분리취득 경로(`transfer-tax-lthd.ts:404-430`)와 **같은 게이트·같은 leaf**를 쓴다.

```ts
const appurtenant =
  !housingLthdExcluded && useTable2 && gainSplit.landHoldingYears > gainSplit.buildingHoldingYears
    ? resolveAppurtenantLandLthdRate({
        landHoldingYears: gainSplit.landHoldingYears,
        houseHoldingYears: gainSplit.buildingHoldingYears,
        residenceYears,
        useTable2,
        transferDate,
      })
    : undefined;
const landDedRate = appurtenant ? appurtenant.rate : calcLongTermRate(/* 종전 그대로 */);
```

- 배제(미등기·§104⑦)는 leaf가 모르므로 게이트에서 먼저 거른다(배제면 종전 경로 → 0).
- echo `landHoldingRate`: 표1이 이기면 `appurtenant.rate`(전부 보유분), 표2가 이기면 `calcLongTermRate(건물 연수, 0, true, false, transferDate)`. 일반 경로 `transfer-tax-lthd.ts:455-458`과 같은 규칙이다.
- 결과 echo: `MixedUseHousingPart.appurtenantLthd?`를 추가한다. 형태는 `SplitPartResult["appurtenantLthd"]`(`types/transfer-split-gain.types.ts:128-143`)와 같다(`houseHoldingYears`·`table1Rate`·`table2Rate`·`table1Applied`·`changedFromOwnYears`·`basis`). 표시 계층은 이 값을 그대로 읽는다.
- `transferDate`는 이미 `buildHousingPart` 인자다(§155의3 기한 판정용, `transfer-tax-mixed-use.ts:487`).
- leaf 헤더의 호출부 목록에 겸용 경로를 추가한다.

### 4.2 다건 — 주택 토지 카드 (W-3)

- 카드에 내부 필드 하나를 싣는다. 가칭 `appurtenantHouseAcquisitionDate`(= 건물 취득일)이고 **주택 부수토지 카드에만** 싣는다. `TransferTaxInput`에 optional로 추가하고, 서버(route)가 만든 카드에만 존재한다. 폼·Zod·API 변환(⑫⑬⑭)을 거치지 않으므로 14개 동기화 지점 중 해당하는 곳이 없다(Do 단계에서 grep으로 재확인).
- 단건 엔진 `transfer-tax-lthd.ts:502` 직전에 둔다. `propertyType === "housing"` ∧ 이 필드 있음 ∧ `useTable2` ∧ 토지 연수 > 건물 연수(이 필드부터 양도일까지)이면 같은 leaf로 공제율을 정한다. 결과에 같은 echo를 싣는다.
- 기각한 대안: 겸용 엔진이 계산한 토지분 공제율을 카드에 «덮어쓰기 값»으로 싣는 방식. 카드의 표2 대상 판정(`useTable2`)은 aggregate가 다시 하므로, 공제율만 옮기면 판정 소스가 둘이 된다.
