## 2. 🔴 산식 정정 — 「초지 **또는** 사료포」

두 표 모두 열 묶음 헤더가 접속사를 **의도적으로 구분**한다:

| 열 묶음 | 접속사 | 처리 |
|---|---|---|
| 축사 **및** 부대시설 | 및 | 둘 다 더한다 |
| 초지 **또는** 사료포(사료밭) | **또는** | **둘 중 하나** = `max` |

종전 구현(`livestock-standards.ts`)은 **넷을 모두 합산**했다. 문언대로면
`축사 + 부대시설 + max(초지, 사료포)`이고, 표에서 항상 초지 ≥ 사료포이므로 실질은 **초지 값**이다.

### 근거의 한계 — 미확정 구간임을 명시한다

**권위 있는 근거를 찾지 못했다** (2026-08-06 실측):

| 출처 | 결과 |
|---|---|
| 법제처 법령해석례 | **0건** (「목장용지」·「목장용지 기준면적」 모두) |
| 조세심판례 | 국심1994경1281 **1건** — 그러나 본문이 「(내용없음)」 |
| 국세청 해석 | 0건 |

⇒ **문언 해석**이다. 그리고 한도가 줄어 **납세자에게 불리한 방향**이므로
「법 근거 없이 불리 적용 금지」 원칙과 긴장 관계에 있다. **사용자 결정으로 채택**했다(2026-08-06).

## 3. 재산세 목장용지 한도 신설

종전 `separate-taxation.ts`는 `isLivestockFarm` 플래그만 보고 **한도 없이 전량 0.07%**를 줬다.
§102①3호는 "…계산한 **토지면적의 범위에서** 소유하는 토지"로 한정한다.

```
기준면적 = (축사 + 부대시설 + max(초지, 사료밭)) × 마릿수 ÷ 가축두수 단위
인정면적 = min(목장용지 면적, 기준면적)
초과분   = 종합합산 이관
```

**초과분은 세액에 반영하지 않는다** — 종합합산은 인별 전국 합산이라 단일 필지 계산기가 세율을
정할 수 없다. 공장용지·별도합산 경로와 **동일하게** 경고 안내만 하고 과세표준은 인정분에만 매긴다.
안분 로직은 `apportionByArea`로 **공장·목장이 공유**한다(이중 진실 제거).

### §102⑨1호 게이트

**도시지역** 목장용지는 **1989.12.31 이전부터 소유**한 것으로 한정된다(1990.1.1 이후 상속·법인합병
취득 포함). 이 게이트는 **면적보다 먼저** 걸린다 — 대상이 아닌데 면적을 묻는 것은 오입력을 부른다.

### 미입력을 통과시키지 않는다

축종·마릿수·전체 면적이 없으면 범위를 알 수 없다. 모른 채 전량 0.07%를 주면 종합합산
누진(0.2~0.5%)보다 훨씬 낮아 **납세자에게 유리한 추정**이 된다 ⇒ 엔진은 던지고 validate가 먼저 막는다.
