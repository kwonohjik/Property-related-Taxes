## 1. 발단

`W-2` 시·군·구 인접 매트릭스를 생성하다 Vworld가 반환하는 시도코드에 **`12`(전남광주통합특별시)**가

## 2. 검증된 사실

### 2.1 통합 시행일 — **2026-07-01**

「전남광주통합특별시 설치를 위한 특별법」 (법령ID 015064 · MST 286591)
— 공포 **2026-06-02** · 시행 **2026-07-01**. 법제처 실측 2026-08-01.

> **§7①** 전라남도와 광주광역시를 각각 폐지하고 정부의 직할(直轄)로 통합특별시를 다음과 같이
> 설치하며, **약칭은 광주특별시**로 한다.
>
> | 명칭 | 관할구역 |
> |---|---|
> | **전남광주통합특별시** | 종전의 전라남도 일원 및 광주광역시 일원 |

이 문서에서 **「전남광주통합특별시」**(또는 시도코드 `12`)는 위 특별법상의 이 지자체 하나만을 가리킨다
— 창원시(2010년 마산·진해 통합)처럼 통칭 「통합시」로 불리는 다른 사례와는 **무관**하다
(창원은 코드 `48121`~`48129`로 정상).

⇒ 시행된 지 한 달이며, 외부 API는 이미 전환을 마쳤다.

### 2.2 프로젝트에 코드 체계가 **셋** 섞여 있다

| 소스 | 광주 | 전남 | 전북 | 강원 | 광역시 | 건수 |

## 5. 설계 쟁점 — 단순 치환은 **틀린다**

### 5.1 구 코드를 신 코드로 바꾸기만 하면 안 되는 이유

양도세는 **과거 양도**를 다룬다(경정청구 5년 · 수정신고). 2021년 광주 양도를 지금 계산하면:

- 주소검색은 **항상 현행 `12xxx`**를 준다 (과거 시점 주소검색이라는 것은 없다)
- 조정지역 이력은 **그 시점 광주광역시**에 대한 것

⇒ 판정 집합이 `12xxx`만 알면 **저장된 이력·수동 입력의 구 코드**가 깨지고,
`29xxx`만 알면 지금 조회한 주소가 깨진다. **양쪽을 다 인식해야 한다.**

### 5.2 방향 — 코드 정규화 레이어 (권장)

```
lib/geo/sigungu-code-alias.ts  (신규)
  normalizeSigunguCode(code) → 현행 대표 코드
  expandSigunguAliases(code)  → [현행, 구] 전부
```

각 판정 집합은 조회 시 `expandSigunguAliases`를 거치게 한다 — 데이터 파일을 **건드리지 않고**
양쪽 코드를 모두 인식시킬 수 있다(회귀 표면 최소).

### 5.3 `sigungu-codes.ts`는 별칭으로 못 고친다 — **재생성**

10개 시도가 구 체계이고 154개뿐이라 별칭 몇 개로 메울 수 없다.
다행히 **W-2에서 만든 자산으로 재생성이 가능하다**:

- 좌표·이름: `.legal-cache/adsigg-raw.json` (Vworld 256건)
- 인접: `lib/geo/administrative-district-adjacency.json` (654 관계)
- 스크립트: `scripts/build-sigungu-adjacency.ts` 확장

단 NBL은 **5자리계**이고 매트릭스는 10자리계다 — 변환 지점을 명시해야 한다.

시·도명 매핑을 더하면 대부분 회수되나 「동구·서구·중구」 동명 충돌을 조심해야 한다.

> ⚠️ 5자리 직접 입력 경로(`SigunguSelect.tsx:40` — `onChange(trimmed, trimmed)`)는
> 이름 = 코드라 이름 기반 복구가 불가능하다.

## 6-D. Y-3 — 🔴 **신규 결함 D-4**: 지역기준/가액기준 분류가 광주에서 뒤집힌다

`multi-house-surcharge-count.ts`의 `classifyRegionCriteriaByCode`가 시·도 코드를 **하드코딩**한다:

```ts
if (sidoCode === "29") return "REGION"; // 광주   ← 통합 코드는 12다
…
return "VALUE"; // 기타 도 지역 (기본값)
```

⇒ 현행 PNU(`12xxx`)는 이 분기를 타지 못하고 **기본값 VALUE로 조용히 떨어진다**.

| 코드 | 분류 |
|---|---|
| 구 `29110` 광주 동구 | REGION |
| **현행 `12210` 통합 동구** | **VALUE** ← 뒤집힘 |
| 전남·강원(42→51)·전북(45→52) | VALUE (원래 VALUE라 무해) |

VALUE는 「양도 공시가 3억 초과만 주택 수 산입」이라, 광주 3억 이하 주택이 **주택 수에서 빠진다**.

**세액 실측**(서울 주택 20억 양도 + 광주 2억 주택 보유 · 조정지역):

| | 유효 주택수 | 총부담 |
|---|---|---:|
| 구 `29110` | 2 → `multi_house_2` | 855,178,500 |
| 현행 `12210` | **1** → 중과 없음 | **466,768,500** |

⇒ **−388,410,000** 차이. (방향 판단은 아래 법령 쟁점에 달려 있다.)

> 이 파일 주석은 군위군(47720→27720) 편입 사례를 두고 이미
> 「**행정구역 개편이 세법상 취급을 바꿔버린 셈**」이라 적어 두었다 — 같은 함정이 광주에서 재발했다.

### 6-D.1 🔶 그런데 「올바른 답」이 REGION인지 **확정할 수 없다** — 세무 판단 필요

「전남광주통합특별시 설치를 위한 특별법」(MST 286591 · 시행 2026-07-01) 실측:

> **§7①** 전라남도와 광주광역시를 각각 **폐지**하고 정부의 직할로 **전남광주통합특별시**를 설치한다.
> **§7②** 통합특별시는 이 법으로 정하는 범위에서 **서울특별시에 준하는 지위**를 가진다.

한편 소득세법 시행령 §167의3①1호(MST 286211 · 시행 2026-07-01)는

> **수도권 및 광역시·특별자치시**(광역시에 소속된 군 … 제외) **외의 지역**

만 열거하고 **전남광주통합특별시를 반영하지 않았다**. 문언 그대로면 전남광주통합특별시는 그 목록
**밖**(→ VALUE)이나, 「서울특별시에 준하는 지위」와 정면으로 충돌한다.

⇒ **X-2 별칭으로는 해결되지 않는다.** 조정지역·인구감소지역은 「지역 실체가 같으니 코드만
이어주면 된다」가 성립했지만, 여기는 **지위 자체가 바뀌어** 코드 문제가 아니라 **법령 해석 문제**다.
따라서 코드를 수정하지 않았다 — 근거 없이 어느 방향으로도 바꾸면 안 된다.
