# 저장 이력 복원과 가산세 — 복원은 유지하나, 복원 뒤 입력을 고치면 가산세가 켜지거나 꺼진다 (측정 + 계획)

> 출처: `receive-only-filing-deadline.plan.md` 별건(세션 시드에서 「가산세 자동 적용」 안내와 요청이 어긋남).
> 규칙: 추정 금지 — 수치는 모두 throwaway probe 실측이다(로컬 개발 서버 + Playwright, 요청 본문·응답·저장 폼을 직접 읽음). probe는 커밋하지 않는다. 측정 기준 코드 = master `b6d507d82`. 이번 PR은 문서만 바꾼다.

## 0. 결론

| 질문 | 결과 |
|---|---|
| 정상 저장한 이력을 복원하면 가산세가 빠지는가 | **빠지지 않는다.** 화면 입력 → 계산 → 저장 → 복원 → 재계산의 세액이 같다(V-1). |
| 그럼 어디서 어긋나는가 | 복원 자체가 아니라 **파생 시점**이다. 가산세 파생이 자산 입력을 고칠 때마다 돌아, 양도일·신고일을 건드리지 않아도 가산세가 꺼지거나 켜진다(V-3). |
| D-1 수동으로 켠 가산세가 꺼진다 | 기한 내 신고 + 과소신고·지연납부를 켠 폼에서 **상세주소만 고쳐도** 가산세가 꺼지고 입력이 지워진다. 경고 없음. **494,300 / 39,600 과소**. 복원과 무관하게 새 입력에서도 난다. |
| D-2 끈 가산세가 켜진다 | 기한 후에 끈 폼에서 상세주소만 고쳐도 다시 켜진다. 664,530 차이. 경고 없음. |
| D-3 안내가 상태와 다르다 | 가산세가 꺼져 있어도, 수정신고 모드여도 「가산세 자동 적용」이라고 표시한다(V-2·V-5). 이것이 출처 별건의 정체다. |

법 근거: 기한 내 신고여도 과소신고가산세(「국세기본법」 §47의3①)와 납부지연가산세(「국세기본법」 §47의4①1호)는 생긴다. 그래서 「기한 내 = 가산세 OFF」는 자동 켜기의 해제로만 맞고, 사용자가 켠 값을 지우는 근거가 되지 않는다.

## 1. 측정 (V 레지스터)

공통 시료: 재개발 APT 청산금 수령 단독(양도일 2024-01-26, 기한 2024-03-31). 세액은 총 납부세액이고, 세액 자체의 법령 대조는 이번 범위가 아니다. 가산세 ON·OFF 차이를 보려고 쓴 값이다.

**V-1 정상 흐름**

| 경로 | 저장 폼 | 안내 | 요청에 가산세 | 세액 |
|---|---|---|---|---|
| 기한 내(신고 3/31) — 기준값 | OFF | 없음 | 없음 | 6,101,700 |
| 신고일을 화면에서 6/30으로 입력 → 계산 | ON · 무신고 | 있음 | 있음 | 6,766,230 |
| 위 이력 복원 → 재계산 | ON · 무신고 | 있음 | 있음 | **6,766,230** |

다건도 복원 뒤 폼과 요청이 유지된다(`migrateMultiForm` + `buildPropertyPayload` 단위 실측, ON → 요청 있음, OFF → 없음). 복원은 저장값을 그대로 싣고 파생을 돌리지 않는다(`lib/calc/transfer-resume-entry.ts:166`). `migrateLegacyForm`의 파생(`lib/stores/calc-wizard-migration.ts:315`)은 `assets`가 없는 구 스키마 세션만 지난다(`lib/stores/calc-wizard-store.ts:293`).

**V-2 꺼진 채 저장된 이력**

| 경로 | 저장 폼 | 안내 | 요청에 가산세 | 세액 |
|---|---|---|---|---|
| Step6 토글 OFF → 계산 | OFF | — | 없음 | 6,101,700 |
| 위 이력 복원 → 재계산 | OFF | **「가산세 자동 적용」** | 없음 | 6,101,700 |

OFF로 저장되는 경로는 Step6 토글로 실측했다. 자동 켜기가 없던 시기의 이력도 같은 모양이겠으나, 그런 이력이 실제로 있는지는 사용자 브라우저 IndexedDB라 확인할 수 없다.

**V-3 복원 뒤 상세주소만 수정** (원인: `app/calc/transfer-tax/TransferTaxCalculator.tsx:182`가 `"assets" in patch`면 파생을 돌린다)

|---|---|---|---|---|
| 기한 내 · ON 과소신고(수동) | **OFF · 정상** | 6,596,000 | 6,101,700 | **494,300 과소** |
| 기한 내 · ON 지연납부만(수동) | **OFF · 정상** | 6,141,300 | 6,101,700 | **39,600 과소** |
| 기한 후 · OFF | **ON · 무신고** | 6,101,700 | 6,766,230 | 664,530 |
| 기한 후 · ON 과소신고(수동) | 유지 | 6,596,000 | 6,596,000 | 없음 |

꺼질 때 `filingType`·`paymentDeadline`·`actualPaymentDate`도 지워진다(`lib/calc/filing-deadline.ts:92`). 이력이 아니어도 재현된다: 새 폼에서 기한 내 신고, Step6 토글 ON, 상세주소 수정 → OFF.

`"assets"` 트리거는 부담부증여 전환으로 기한이 2↔3개월로 바뀌는 경우를 위한 것이다(§105①3호, 같은 파일 164행 주석). 필요한 조건은 그 전환뿐인데 모든 자산 입력에 걸려 있다.

**V-4 기존 테스트**: `__tests__/lib/filing-deadline.test.ts`는 순수 함수만 본다. 계산기 핸들러의 트리거를 지키는 테스트는 찾지 못했다(`derivePenaltyFields` grep 기준).

**V-5 수정신고 이력 복원**: 저장 폼 OFF인 수정신고 모드에서도 안내가 뜬다. 수정신고는 ④에서 일반 가산세 블록을 보내지 않으므로(`lib/calc/transfer-tax-api-body-blocks.ts:263`) 문구가 사실과 다르다.

**V-6 시드 착오 정정**: 수정 후 「총 양도가액을 입력하세요」로 막힌 측정이 있었으나, 시드에 자산 양도가액이 없어 `Step1.tsx:187`이 폼 값을 비운 것이었다. 값을 넣으면 재현되지 않는다. 결함이 아니다.

**V-7 미측정**: 다건 화면의 실제 입력 흐름(다건도 같은 계산기를 임베드한다 — `MultiTransferTaxCalculator.tsx:472`), 백업 가져오기 후 복원, 신고일을 옮기는 경로의 수동 ON, 주식·상속·증여의 같은 구조.

## 2. 결정 (Q 레지스터)

**Q-1 파생을 언제 돌리나**
- a. **권장** — 양도일·신고일의 값이 실제로 바뀌었거나 「전 자산 부담부증여」 판정이 바뀌었을 때만 돌린다. 다른 자산 입력에서는 돌리지 않는다.
- b. 지금처럼 모든 자산 입력에서 돌리되 수동 값을 표시해 보호한다. 저장 필드가 늘고 구 이력에 그 표시가 없다.

**Q-2 날짜가 바뀌었을 때 켜고 끄는 기준**
- a. **권장** — 기한 경과 여부가 **뒤집힐 때만** 켜고 끈다. 기한 내→기한 내, 기한 후→기한 후에서는 사용자의 ON·OFF를 유지한다. ON이면서 납부기한이 옛 기한과 같으면 새 기한으로 맞춘다(옛 기한이 남으면 지연일이 틀어진다).
- b. 현행 유지 — 날짜를 고치면 기한 내일 때 항상 끈다. 날짜를 고쳤을 때 수동 과소신고 입력이 지워지는 문제가 남는다.

**Q-3 안내 문구**
- a. **권장** — 상태대로 표시한다. ON: 「가산세 자동 적용」 유지 / OFF: 「가산세 계산이 꺼져 있어 세액에 포함되지 않습니다」 / 수정신고: 기한 경과 사실만.
- b. 안내를 빼고 Step6에서만 본다. 기한 후 신고를 알릴 곳이 없어진다.

**Q-4 꺼진 채 저장된 이력을 복원할 때 켤 것인가**
- a. **권장** — 켜지 않는다. 사용자가 끈 값과 구분할 방법이 없고, 저장된 결과와 재계산 값이 달라진다. Q-3 안내로 알린다.
- b. 기한 후면 복원 때 켠다. 사용자가 끈 이력이 조용히 바뀐다.
