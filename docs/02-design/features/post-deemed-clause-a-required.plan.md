## 0. 한 줄 요약

의제취득일(1985.1.1.) **이후** 상속에서 ①(상속개시일 상증법 평가액)을 비우면, **주택·토지·건물**은
아무 경고 없이 **취득가액 0**으로 계산된다. E-1(#1114)이 pre-deemed에서 막은 것과 구조가 같지만,
**여기는 선언이 아니라 필수 입력** 문제다 — post-deemed에는 갈 곳(나목)이 없기 때문이다.

**상가는 이미 막고 있고**(그 게이트가 옳았다), **주택·토지·건물만 빠져 있다.**

### 실측 (Playwright · 상속 토지 · 상속개시일 1998-07-01 · ① 비움)

| | |
|---|---|
| `inheritedAcquisitionDetail` | **`undefined`** — ① 없으면 payload 빌더가 특례 payload를 만들지 않아 엔진 특례를 **아예 안 탄다** |
| 취득가액 | **0** |
| 양도차익 | **500,000,000** = 양도가액 **전액** |
| 총 납부세액 | **124,366,000** |
| 경고 | **0건** — 엔진 warning조차 생성되지 않는다(§8 Y-8) |

화면에 취득가액이 `0`으로 **표시는 된다**. 그러나 그것이 「내가 안 넣어서」인지 화면이 말하지 않고,
**상속 부동산의 상증법 평가액이 0일 수는 없으므로** 사실상 침묵이다.

## 1. 법령 — post-deemed에서 ①은 **항상 산출 가능**하다

### 1.1 verbatim (2026-08-07 조회)

| 조항 | 본문 |
|---|---|
| **법 §97①1호 단서** | "다만, **가목의 실지거래가액을 확인할 수 없는 경우에 한정하여** 나목의 금액을 적용한다." |
| **시행령 §163⑨ 본문** | "상속 또는 증여(…)받은 자산에 대하여 법 제97조제1항제1호**가목**을 적용할 때에는 상속개시일 또는 증여일 현재 「상속세 및 증여세법」 제60조부터 제66조까지의 규정에 따라 평가한 가액(…)을 취득당시의 실지거래가액으로 **본다**." |
| **상증법 §60①** | "…재산의 가액은 상속개시일 또는 증여일(…) 현재의 **시가**에 따른다." |
| **상증법 §60③** | "제1항을 적용할 때 **시가를 산정하기 어려운 경우에는** 해당 재산의 종류, 규모, 거래 상황 등을 고려하여 **제61조부터 제65조까지에 규정된 방법으로 평가한 가액을 시가로 본다**." |

### 1.2 결론 — 「가목을 확인할 수 없는 경우」가 성립하지 않는다

§163⑨은 상속 자산의 취득가액을 상증법 §60~66 평가액으로 **의제(본다)**한다. 그리고 상증법 §60③은
**시가를 못 구해도 보충적 평가(§61~65)로 간다**고 정한다.

> ⇒ **평가액이 「없다」는 상태는 법적으로 성립하지 않는다.** 산출 방법이 항상 남아 있다.
> ⇒ 따라서 법 §97①1호 단서의 「가목을 확인할 수 없는 경우」에 해당하지 않고, **나목(환산)에 도달하지 않는다.**

이것이 **E-1(pre-deemed)과 갈리는 지점**이다:

| | pre-deemed | **post-deemed** |
|---|---|---|
| 나목(③ 환산) | **있다** — §176조의2④가 의제취득일 기준으로 적용 영역 | **없다** — §163⑨ 의제가 그 자리를 대신한다 |
| ①·② 없을 때 | 「확인 불가」를 **선언**하면 ③으로 (E-1) | **갈 곳이 없다** ⇒ **필수 입력** |
| 해법 | 선언 토글 + 차단 | **차단만** |

### 1.3 ②(§164⑤~⑦)도 가목이다 — post-deemed에서도

§163⑨**2호**는 「건물의 기준시가가 고시되기 **전에** 상속…받은 건물…평가한 가액과 §164⑤~⑦ 가액
**중 많은 금액**」이라 한다. 조건은 **「기준시가 고시 前」이지 「의제취득일 前」이 아니다**
(주택 2005-04-30 · 상가 2005-01-01 前). ⇒ post-deemed에도 ②가 성립하는 구간이 있고, 엔진도
`calcPostDeemed`에서 `max(①,②)`로 계산한다.

⇒ **게이트는 「① 또는 ②」**다. ① 단독을 요구하면 ②를 다 채운 사용자를 막는다(D-5에서 상가에
같은 정정을 했다 — #1114).

### 2.1 모드를 가르지 않는 이유

증여는 `giftEstimatedModeError`가 post-1985 추계를 차단하지만 **상속에는 그 게이트가 없다**.
그리고 §1.2대로 post-deemed 상속은 애초에 추계로 갈 수 없으므로, **모드와 무관하게** 막는 것이 맞다.
(상가 블록도 「`isEstimated` 무관하게 먼저 처리한다」고 명시한다.)

### 2.2 `fixedAcquisitionPrice`는 ①이 아니다

상속의 ① 소스는 **`publishedValueAtInheritance` 하나뿐**이다
(`transfer-tax-api-inheritance.ts:52-54` — 증여만 `fixedAcquisitionPrice`).

stale 세션에 `fixedAcquisitionPrice`가 남아 있어도 그 값은 **§163⑨ 경로로 가지 않는다**.
⇒ 게이트 판정에 **포함하지 않는다**. 그런 세션은 차단되는 것이 맞다 — 특례가 적용되지 않는데
사용자는 그 사실을 모르기 때문이다.

⚠️ **상속에는 `fixedAcquisitionPrice` 입력 UI가 없다**(P2b/P2c로 폐지). 실사용자는 이 상태를
만들 수 없고, 만드는 것은 **테스트 시드**뿐이다 — §8 R-1의 회귀 3건이 전부 이것이다.

## 4. 설계

### 4.1 규칙

> **post-deemed**(기준일 ≥ 1985-01-01) **상속** · 자산이 **주택·토지·건물** ·
> `isMixedUseHouse`가 아님 → **①(`publishedValueAtInheritance`) 또는 ②(§164⑤~⑦ 완전 충족)** 중
> 하나를 요구한다. 둘 다 없으면 **차단**.

메시지는 상가와 **같은 문구**를 쓴다 — 같은 규칙이 자산별로 다르게 말할 이유가 없다:

```
{label}: 상속개시일 평가액(상속세 신고가액)을 입력하세요.
```

⚠️ **여기에 「선언」을 통과 사유로 넣지 않는다.** `preDeemedClauseAUnconfirmed`가 true여도
post-deemed에서는 무시한다 — 이미 E-1 anchor **X-12c**가 상가에 대해 그것을 고정하고 있다.

### 4.2 예외 3종 — 각각 근거가 다르다

| 예외 | 근거 |
|---|---|
| **상가**(`commercial_building`) | 이미 전용 블록이 같은 규칙으로 막는다. 중복 차단은 메시지만 흐린다 |
| **겸용주택**(`isMixedUseHouse`) | 취득가액의 실제 소스가 `mixedAcqHousingPrice`·`mixedAcqLandPricePerSqm`·`mixedAcqCommercialBuildingPrice`다. ①이 없어도 계산이 성립한다(E2E `mixed-use-inheritance-acquisition` 통과) |
| **재개발**(`redevelopment_apt`) | §166③④ 별도 경로 — 권리가액·추가분담금이 취득가액을 만든다. 이미 다른 사유로 차단된다 |

⚠️ **용도변경·부담부증여는 예외가 아니라 배치 문제다** — `validateAssetAcquisition`의 조기
return(`:109`·`:113`)보다 **뒤**에 두면 그 조합에서 dead code가 된다. E-1과 **같은 자리**
(`sec164PartialInputError` 뒤)에 둔다.

### 4.3 술어는 E-1과 공유한다

②의 충족 판정은 **`isSec164ClauseAFilled`**(`transfer-tax-validate-clause-a.ts`)를 그대로 쓴다.
E-1이 이미 쓰는 함수다 — 새로 만들면 `hasPre1990` 제외 로직 같은 것을 다시 잘못 가져올 위험이 있다
(memory `feedback_shared_predicate_argument_parity`).

### 4.4 엔진·API 무변경

차단만 추가하므로 payload·엔진·결과 화면이 바뀌지 않는다. **14 지점 중 ⑧ 하나**만 해당한다.

## 11. 결론

| | |
|---|---|
| **법령 축** | 상증법 **§60③**이 「시가를 산정하기 어려우면 §61~65로 평가한 가액을 시가로 **본다**」고 정한다 ⇒ **평가액이 없는 상태가 성립하지 않는다** ⇒ 법 §97①1호 단서의 「확인할 수 없는 경우」에 해당하지 않아 **나목 미도달** |
| **E-1과 다른 점** | pre-deemed는 ③(나목)이 있어 「선언 → 나목」이 성립하지만, **post-deemed는 갈 곳이 없다** ⇒ 선언이 아니라 **필수 입력** |
| **전제 정정** | 선행 설계서 §12의 「dead-end 위험」은 **과대평가**였다 — 보충적 평가 보조계산이 **이미 화면에 있다**(§3) |
| **범위** | **주택·토지·건물 3종 × 모드 무관**. 상가는 이미 있고, 겸용·재개발은 정당한 예외 |
| **비용** | 14지점 중 **⑧ 하나**. 신규 store 필드 **0개**, 엔진·API·결과 **무변경** |
| **회귀** | §8 전수 계수 — **3건, 전부 fixture 정정**(실사용자가 만들 수 없는 시드) |
| **착수 판정** | ✅ **가능**. 선행 미확인 없음 |
