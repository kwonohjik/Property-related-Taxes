## 1. 현상 (실측)

시료: 원조합원 입주권(종전 주택 · 인가일 2024-01-10 · 권리가액 900,000,000 · 청산금 납부 200,000,000 · 양도가액 1,300,000,000) · 비부담부증여(`transferType: "regular"`) · 취득원인 이월과세 · 증여 등기 2023-06-01 · 당초 증여자 취득 2012-01-01 취득가액 100,000,000 · 증여 당시 평가액 300,000,000. 증여세 상당액·증여자 자본적지출은 시료마다 표기한다. 완공 아파트 시료는 같은 값에 `assetKind: redevelopment_apt`·준공일 2025-09-01·청산금 수령은 소유권이전 고시 다음날 2025-12-02를 더했다.

### 1.1 증여세 상당액이 §166 양도차익에 반영되지 않는다 (세액 영향)

이월과세 A의 결과(`scenarioA.giftTaxAddedToExpense`)는 증여세 상당액을 산입했다고 싣지만, 같은 시나리오의 양도차익·결정세액은 증여세 0일 때와 같다. 신고서 필요경비는 0이다.

| 시료 | 증여세 상당액 | A `giftTaxAddedToExpense` | A 양도차익 | A 결정세액 |
|---|---|---|---|---|
| 입주권 · 납부 | 0 | 0 | 1,000,000,000 | 302,370,000 |
| 〃 | 30,000,000 | 30,000,000 | **1,000,000,000** | **302,370,000** |
| 〃 | 100,000,000 | 100,000,000 | **1,000,000,000** | **302,370,000** |
| 입주권 · 수령(청산금 100,000,000) | 0 / 30,000,000 | 0 / 30,000,000 | 1,211,111,111 / **1,211,111,111** | 401,135,000 / **401,135,000** |
| 완공 아파트 · 납부 | 0 / 30,000,000 | 0 / 30,000,000 | 1,000,000,000 / **1,000,000,000** | 269,686,363 / **269,686,363** |
| 완공 아파트 · 수령 | 0 / 30,000,000 | 0 / 30,000,000 | 1,300,000,000 / **1,300,000,000** | 356,876,666 / **356,876,666** |

결과 화면(E2E)에서도 증여세 30,000,000 입력 시 신고서 필요경비 0 · 전체 양도차익 1,000,000,000으로 증여세 산입 흔적이 없다.

### 1.2 증여자 자본적지출(§97의2①2호)도 반영되지 않는다 (세액 영향)

| 시료 | A `effectiveCapex` | A 양도차익 | A 결정세액 |
|---|---|---|---|
| 입주권 · 증여자 자본적지출 0 | 0 | 1,000,000,000 | 302,370,000 |
| 입주권 · 증여자 자본적지출 50,000,000 | 50,000,000 | **1,000,000,000** | **302,370,000** |

### 1.3 본인(수증자) 자본적지출·양도비·인가 전 실비는 정상 반영된다

같은 시료에서 자산의 자본적지출 20,000,000 → 양도차익 980,000,000(인가 후 분 필요경비 20,000,000) · 양도비 10,000,000 → 990,000,000 · 인가 전 분 필요경비 입력 3,000,000 → 997,000,000(인가 전 분 3,000,000). 클라이언트 변환(`transfer-tax-api-redev.ts:117~131`)이 자산 자본적지출·양도비를 `redevelopment.postApprovalExpenses`에 합쳐 보내기 때문이다. 증여세 상당액·증여자 자본적지출은 이월과세 계산이 엔진 안에서 `inputAFinal`에 얹는 값이라 그 경로를 타지 않는다(원인 — §1.4).

### 1.4 원인

`transfer-tax-carryover.ts`가 증여세를 `inputAFinal.transferExpense`(실가 모드)나 `expenses`(환산 모드)에 얹고 증여자 자본적지출은 `effectiveCapex`로 `capitalExpenditure`에 얹는다. 재개발 경로(`runRedevelopment` → `computeRedevelopmentSplit`)는 `TransferTaxInput`의 `expenses`·`capitalExpenditure`·`transferExpense`를 읽지 않고 `RedevelopmentInfo.preApprovalExpenses`·`postApprovalExpenses`만 읽는다. 부담부증여(§159)와 같은 원인이다(#2703 §1.5).

### 1.6 법령 근거

- 「소득세법」 제97조의2 제1항(2026-10-29 조회 현행 본문): 제2호 「제97조제1항제2호에 따른 필요경비에는 거주자의 배우자 또는 직계존비속이 해당 자산에 대하여 지출한 같은 호에 따른 금액을 포함한다」 · 제3호 「거주자가 해당 자산에 대하여 납부하였거나 납부할 증여세 상당액이 있는 경우 필요경비에 산입한다」. 대상 자산은 같은 항 본문의 「제94조제1항제1호 및 제3호에 따른 자산이나 그 밖에 대통령령으로 정하는 자산」.
- 「소득세법 시행령」 제163조의2 제1항(현행 본문): 그 자산 = 「법 제94조제1항제2호가목 및 같은 항 제4호나목의 자산」(부동산을 취득할 수 있는 권리 포함 — 입주권). 제2항: 증여세 상당액 = 증여세 산출세액 × 해당 자산가액 / 증여세 과세가액, 한도 = 「양도가액에서 법 제97조제1항 및 제2항의 금액을 공제한 잔액」.
- 「소득세법 시행령」 제166조 제1항(현행 본문): 인가 전 양도차익의 필요경비는 「법 제97조제1항제2호 및 제3호 또는 제163조제6항에 따른 필요경비」, 인가 후는 「법 제97조제1항제2호 및 제3호에 따른 필요경비」. §97의2①2·3호를 말하지 않는다(**명문 없음** — 산입 분기는 해석 판단이다. #2703과 같은 판단을 쓴다).
