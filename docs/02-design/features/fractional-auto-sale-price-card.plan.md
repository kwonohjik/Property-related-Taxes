## 2. 결정 요청 (Q 레지스터)

**Q-1 (별건 ①과 공통) 카드와 사이드바가 같은 흡수 헬퍼를 쓰는가**
- **a) 규칙은 «흡수값은 `absorbFractionalResidual` 하나, 복사 금지»로 두고, 카드는 지금 그대로 둔다(권장).** ①이 사이드바 전용 분기에 흡수를 넣을 때 이 함수를 쓴다.
- b) 카드도 같은 헬퍼로 바꾼다 — 카드에 자산 배열을 prop으로 내려 `computeApportionedSaleMap` 값을 읽는다.
- a 근거: 카드는 주 자산에만 있고 route 200 입력에서 주 자산은 흡수하지 않는다(V-2~V-4). b가 바꾸는 표시는 V-5의 400 입력뿐이고, 대가는 prop 체인 추가(`CompanionAssetsSection` → `CompanionAssetCard` → `AssetSectionTransfer` → `CompanionSaleModeBlock`)다. 다만 앞으로 컴패니언에 금액을 표시하게 되면 그때는 이 헬퍼를 써야 한다 — anchor로 잠근다(§3).

**Q-2 V-6 막다른 길** — **a) ⑧에서 지분 모드(`assetSplitMode === "fractional"`)이면 지분 100%를 «지분 분할은 각 지분이 100% 미만이어야 합니다»로 막고, 없는 칸 오류를 내지 않는다(권장).** b) 합계 100% 검사만 지분 모드 전체로 넓힌다. c) 이 PR에서 다루지 않고 별건으로 둔다.
- a 근거: «없는 칸을 입력하라»는 오류는 사용자가 풀 수 없다. 지분 분할에서 한 지분이 100%면 나머지 지분이 있을 수 없어 합 100%도 성립하지 않는다. 다만 지분 모드에서 자산을 1개로 줄인 경우, 지분 입력 전 빈칸 경우와의 관계는 구현 시 격자로 대조한다(⑧↔⑫ 격자).
- 계산 결과에는 영향이 없다 — 지금도 route까지 가지 못하는 입력이다(V-6 안분·기준시가 있음 제외, 그 입력은 ⑧이 막히게 된다).

**Q-3 V-5 총액 100원 미만의 ⑧ 통과 → ⑫ 400** — **a) 그대로 둔다(권장).** 실제 거래 금액이 아니다. b) ⑧에 컴패니언 확정가 ≥ 1원 검사를 추가한다.

**Q-4 컴패니언 안내문** — 흡수 자산도 «총양도가 × 지분율로 자동 계산»이라고 읽는다(사이드바는 잔액 흡수 후 값). **a) 그대로 둔다(권장).** 숫자가 없고, 1~2원 정수 보정(대역 끝에서는 그보다 큼)을 일일이 설명할 근거 조문도 없다. b) «잔액은 한 지분에 반영됩니다» 문구를 더한다.
