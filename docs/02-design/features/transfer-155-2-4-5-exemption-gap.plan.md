# 작업계획서 — 상속(§155②③)·합가(§155④⑤) 1세대1주택 비과세 판정 엔진 갭

- 요청: 방금 §155①(일시적 2주택) 갭 해소에 이어, **상속주택·동거봉양 합가·혼인 합가**의 비과세 경로 미구현 갭도 계획화.
- **갭 성격(실측 확정)**: **엔진 자동판정 부재**(count=1 수동 입력 시 비과세 정상 — `transfer-tax-exemption.ts:253·258`). 엔진이 §155②③④⑤ **요건(상속주택 순위·§155④⑤ 합가 10년 처분기한·선순위 상속주택)을 자동 판정·검증하지 않는 것**이 갭. **⚠️ §155②(일반주택 양도)는 처분기한 없음** — "상속 5년"은 §167의3①7호 **중과 주택수 배제**이지 비과세 요건 아님(혼동 주의). **단, UI 안내를 따라 count=2로 두면 과세되는 실질 손해**(§3).
- **실질 리스크**: **UI 약속-엔진 불일치**. 섹션③ 헤더(`Step4.tsx:360`)가 "혼인합가·동거봉양합가 특례에 해당하면 2주택 상태에서도 1세대1주택 비과세가 그대로 적용됩니다"라고 **비과세를 약속**하나, 그 안 `MergeDateSection` 위젯·엔진 배선은 **중과배제 전용** → 사용자가 문구를 믿고 `householdHousingCount=2`로 두면 **과세**된다.
- 성격: **대 규모**(Tier 0+1+2 완전 — 엔진 비과세 판정 신설 + §155②③ 신규 입력 14지점 + 상속주택 자체 양도). **결정 확정(§5, 2026-07-19)**. Tier별 커밋 분할 권장.

## 1. 배경 — 현행 배선 실측 (2-fork)

### 1-1. 비과세 엔진은 상속·합가를 자동 인식 안 함
- `checkExemption`(`transfer-tax-exemption.ts:164~278`): E-5 대체주택 → E-3 일시적 2주택(§155①, 방금 확장) → `:253` `householdHousingCount !== 1` **배제 게이트** → E-4 §154① → E-1/E-2. **`isInherited`·`marriageMerge`·`parentalCareMerge` 참조 0건**(grep).
- `marriageMerge`·`parentalCareMerge`는 `transfer-tax.ts:193~194`에서 **`mhInput`(중과)로만** 주입. `checkExemption` 호출(`:272`)엔 미전달.
- 상속주택 "주택수 제외" 플래그는 **`TransferTaxInput`에 부재**(`isInherited`는 `multi-house-surcharge.types.ts:61` `HouseInfo`에만).

### 1-2. 기존 필드는 전부 중과배제 트랙 (완주 배선)
| 필드 | 정의 | 소비(전부 중과) |
|---|---|---|

- UI: `MergeDateSection`(무조건 렌더, `Step4.tsx:486`) — 위젯 문구 "중과 배제"(`MergeDateSection.tsx:26·41·49`). `isInherited`는 `HouseEntryEditor.tsx:174~201`(§167의3①7호 "주택 수 배제"). **모두 중과 라벨**.

## 2. Pre-Do 법령 (KoreanLaw 대조 완료 — 소득세법 시행령 mst=286211; §155②③④⑤·§154⑧3호 원문 일치. Do 착수 시 시행일 버전 1회 재확인)

- **§155②(상속주택)**: 상속주택[피상속인 상속개시 당시 1주택; 2주택 이상이면 순위 1호 최장보유·2호 최장거주·3호 상속개시당시거주·4호 기준시가최고] + **일반주택**(상속개시 당시 보유; 상속개시 2년 내 피상속인 증여분 제외) 각 1채 소유 1세대가 **일반주택 양도** 시 1세대1주택으로 봄. **처분기한 없음**. 단, 상속인·피상속인 상속개시 당시 1세대면 동거봉양 합가로 취득한 상속만 상속주택으로 봄.
- **§155③(공동상속주택)**: 다른 주택 양도 시 공동상속주택은 해당 거주자 주택으로 **안 봄**(예외: 최대지분자 — 2명↑이면 거주자>최연장자).
- **§155④(동거봉양)**: 1주택자가 60세↑ 직계존속(60세 미만 요양급여 포함) 동거봉양 합가 → 2주택. **합친 날부터 10년 내 먼저 양도** 주택 1세대1주택.
- **§155⑤(혼인)**: 1주택자끼리 혼인 or 60세↑ 직계존속 동거봉양 무주택자가 1주택자와 혼인 → 2주택. **혼인한 날부터 10년 내 먼저 양도** 주택 1세대1주택.
- 공통: 특례 주택도 각 §154① 보유·거주 요건 충족해야(합가·혼인 전 보유분). "먼저 양도"는 세대 내 첫 양도.
- **§154⑫(공동상속 거주기간)**: 공동상속주택 거주기간은 해당 주택에 거주한 공동상속인 중 **최장거주자 기준**(2-A2 공동상속 거주요건 판정에 사용).

## 3. 갭 성격 판정 (우선순위 근거)

| 관점 | 판정 |
|---|---|
| 세액 정확성 | **오류 아님** — `householdHousingCount=1` 수동 입력 시 비과세 정상. 자동 우회로 `temporaryTwoHouse`(E-3) 쓰면 **잘못된 처분기한 강제**(§155②는 처분기한 없음) → 올바른 우회는 count=1 직접 입력뿐 |
| UX/신뢰 | **높은 리스크** — 섹션③ 헤더가 비과세를 약속하나 미배선 → 문구 신뢰 사용자는 과세됨(침묵 손해). 요건(처분기한·순위) 자동 검증도 없음 |
| 자동화 완결성 | 미흡 — 취득세엔 `house-count/inheritance.ts`(§28의4⑤ 공동상속)·`household.ts`(동거봉양)가 있으나 양도세 비과세 미사용 |

→ **세액 오류가 아니므로 방금 §155① 갭보다 우선순위는 낮으나, UI 약속 불일치는 즉시 완화 가치가 있음**(§4 최소대안).

## 4. 작업 범위 (3-tier — 결정 필요)

### Tier 0 — UI 문구 정합 (즉시·저비용, 역작업 방지)
현행 미배선 상태의 **오해만 제거**하되, **Tier 1/2 구현 후에도 유효한 중립 문구**로(역작업 회피 — "미지원 경고"는 Tier 1/2가 되돌려야 함):
- 섹션③ 헤더(`Step4.tsx:360`, ✅Tier0 반영): 일시적 2주택=비과세 / 합가=중과배제 구분 **동작 중립 서술**. `MergeDateSection`(:26·41·49)은 이미 "중과 배제/경감" 정확 → **무변경**(실측).
- 엔진 무변경·14지점 무관. **오해 즉시 차단** + Tier 1/2 흡수 시 문구 유지.
- **§8 순서**: Tier 1(합가) 머지 시 섹션③ 합가 부분만 "비과세 자동 적용"으로 갱신 — Tier 0 중립 문구가 이를 방해하지 않도록 작성.

### Tier 1 — 합가 비과세 자동 판정 (§155④⑤, 중규모)
기존 `marriageMerge`·`parentalCareMerge`(TransferTaxInput 이미 존재)를 **비과세 트랙에 배선**. `checkExemption`에 합가 경로 추가(E-3 뒤, `:253` 배제 게이트 **앞**):
- 진입: `householdHousingCount === 2 && (input.marriageMerge || input.parentalCareMerge)`.
- 판정: 합가일(`marriageDate`/`mergeDate`)부터 **10년 내 양도** + 양도 주택 §154① 보유·거주 요건(`meetsOneHouseHoldingResidence` 재사용) 충족 → `isExempt`(12억 이하) / 부분과세(초과).
- **합가 전 취득 게이트(필수)**: 양도 주택 `acquisitionDate < 합가·혼인일`이어야 특례 적용(§155④⑤ "합가 전 보유 주택"). 합가 후 취득분 부적용.
- **"먼저 양도" 확인 토글(결정3)**: `isFirstTransferredInMerge` boolean **신규 1필드** — ①폼·④API·⑧validation·엔진(선양도 아니면 특례 미적용). 위젯 `ToggleCard`(violet, "세대 내 먼저 양도하는 주택입니다"), `MergeDateSection` 내 배치.
- 그 외 **기존 필드(`marriageMerge`·`parentalCareMerge`) 비과세 트랙 소비만 추가** → 나머지 14지점 N/A, `checkExemption` 로직 + 결과 라벨.
- ⚠️ 중과 트랙과 **이중 소비**(같은 marriageMerge를 두 엔진이 read — **입력 중복 아님**) — 상호 독립·무해. 단 비과세 확정 시 중과 판정 moot 순서 앵커.

### Tier 2 — 상속주택 비과세 자동 판정 (§155②③, 대규모·완전 구현)

**2-A. 일반주택 양도**(§155② 표준): 양도=일반주택 + 세대에 상속주택 → 상속주택을 주택수에서 제외 → E-4 §154① 판정. **하위 단계화**(YAGNI·커밋 분할):

**2-A1(최빈·기본)**: 피상속인 1주택 + 상속인 일반주택 1채. 순위·공동상속 없음.
- **⚠️ 입력 — 기존 필드 단일 소스 재사용(이중 입력 금지, High E)**: `HouseEntry.isInherited`/`inheritedDate`(중과용, `calc-wizard-asset-nbl.ts:80·96`)를 **비과세 판정도 함께 소비**(mirror-pattern·"같은 의미 폼 필드 양방향 통합" 정책 — `components/calc/CLAUDE.md`). 별도 상속 플래그 신설 금지. 추가로 "양도 대상=일반주택" 컨텍스트만 필요.
- 상속개시 2년내 피상속인 증여분 제외 게이트.

**2-A2(순위·공동상속)**: 피상속인 2주택↑ 순위(§155②1~4호: 최장보유·최장거주·상속개시당시거주·기준시가최고) + §155③ 공동상속(소수지분 제외·최대지분자만 산입·2명↑ 거주자>최연장자, 거주기간 §154⑫ 최장거주 기준) + 동거봉양 상속 예외(상속개시 당시 1세대면 동거봉양 합가 상속만).
- **§155② 전용 정보만 신규 신설**(순위 판정용 피상속인 주택별 보유·거주기간, 공동상속 지분율) → 14지점 신규(착수 시 필드별 매핑 표). 상속 여부 자체는 2-A1의 기존 `isInherited` 재사용.

**2-B. 상속주택 자체 양도**(결정4 — §155② 아님): 양도 대상이 상속주택. 일반 1세대1주택 판정이되 §154⑧3호 보유·거주기간 통산.
- **⚠️ 현행 미구현(실측)**: `checkExemption`은 `calculateHoldingPeriod(input.acquisitionDate, …)`(`tax-utils.ts:183`)로 취득일 직접 사용, `decedentAcquisitionDate` 통산·backdate **grep 0건**. → **신규 로직**이나 기존 `residenceTransitionAcquisitionDate?`(`transfer.types.ts:233`, optional 취득일 override) 패턴 재사용 → **중간 규모**(대규모 아님).
- **통산 범위(§154⑧3호 정확)**: **상속개시 전 상속인·피상속인이 동일세대로서 거주·보유한 기간**만 통산(피상속인 전체 보유기간 아님). **동일세대 아니면 통산 없음 → 상속개시일 기산**(별도세대 분기 명시).
- ⚠️ 취득세 `house-count/inheritance.ts`(§28의4⑤)·`household.ts`는 지방세 기준이라 **재사용 불가** — 양도세 전용 구현.

## 5. 결정 확정 (2026-07-19 사용자)

1. **접근 범위**: **Tier 0+1+2 전체** (UI 정합 + 합가 §155④⑤ + 상속 §155②③).
2. **Tier 2 상속 복잡도**: **완전 구현** — 피상속인 2주택↑ 순위 판정(1~4호), 공동상속(§155③) 소수지분 제외, 동거봉양 상속 예외, 상속개시 2년 내 증여분 제외 전부.
3. **"먼저 양도하는 주택"**(§155④⑤): **확인 토글 추가** — 세대 내 첫 양도 여부를 사용자가 확인(폼 신규 boolean 필드).
4. **양도 주택이 상속주택 자체**인 경우: **포함**(2-B) — §155② 표준(일반주택 양도)에 더해, 상속주택 자체 양도 시 1세대1주택 비과세(피상속인 보유기간 통산 §154⑧3호·거주요건)도 지원.

## 6. 리스크 · 정책

- **feedback_no_unfavorable_application_without_legal_basis**: 자동 판정 미구현이 "불리"로 작용(사용자가 비과세 놓침). 단 명문 없이 **유리(비과세) 확대**는 금지 — 요건(처분기한·순위) 정확 검증 필수.
- **중과 트랙 회귀 0**: 비과세 트랙 배선 추가가 기존 중과배제(marriageMerge·isInherited 중과 소비)를 건드리지 않아야. 이중 소비 앵커.
- **feedback_numeric_impact_verify_before_bug_claim**: 본 갭은 "세액 오류 아님"으로 실측 확정 — 계획서에 과대 표현 금지(수동 우회 명시).
- **temporaryTwoHouse 오용 방지**: 사용자가 합가/상속을 E-3로 우회하면 잘못된 처분기한. Tier 1 구현 시 합가는 전용 경로로.
- **mirror-pattern·이중 소스 금지(High E)**: 상속 여부(`isInherited`)는 **기존 HouseEntry 단일 소스 재사용** — 비과세용 별도 상속 플래그 신설 금지(dual-source·"양방향 통합" 정책 위반). §155② 전용 순위·지분만 신규. Tier 2 신규 필드는 클라이언트 8 + API 6 전부, Tier 1 먼저양도 토글은 ①④⑧+엔진.
