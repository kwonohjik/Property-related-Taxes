## 0. 요약

토지만 본인 × 건물(주택) 소유자 **다른 세대**일 때, **주 카드**는 #2657에서 「부수토지가 아닌 일반 토지」 세율로 판정한다(서면법규과-944 — 보유 1년 미만 50% · 1~2년 40%). 그런데 **같은 묶음의 부수토지 카드는 여전히 짝 주택의 일체과세 세율**을 쓴다 — 짝 주택이 오래 보유돼 있으면 토지를 8개월만 가졌어도 **누진세율**(38%)이다(V-1).
같은 사실(다른 세대 토지, 8개월 보유)인데 주 카드 50% · 부수토지 카드 38%로 갈리는 **한 묶음 내부 모순**이다. 같은 묶음의 장특 표2 배제는 #2668이 이미 고쳤다 — 세율은 그때 O-1로 남겼다.

원인은 한 곳이다(§2) — 세율 분기 T-1.5(`transfer-tax-rate-calc.ts:236-241`)가 `landNature === "appurtenant_to_housing"`만 보고, 짝 주택이 「토지만 본인 × 다른 세대」인지를 모른다. 이 사실은 부수토지 카드 입력에 없고 verdict(`appurtenantHouseVerdict`)에만 실어 보낼 수 있다(#2668 `houseTable2Subject`와 같은 구조).
권고 수정은 verdict에 한 값(`houseLandOnlyOtherHousehold`)을 싣고 T-1.5의 `resolveCompanionLandRate`에 넘기는 `landNature`만 비우는 것이다 — **분기 전체를 건너뛰면 사용자의 수동 세율 지정이 무시된다**(V-5, 측정). 입력·Zod·API 변경 없음. 순방향·역방향 모두 같은 verdict 경로라 코드가 늘지 않는다(V-3).

⚠️ 법 근거의 한계는 #2657과 같다 — 서면법규과-944는 **2014.8.28. 시행분 사건**이고(현행 표 이전은 같은 문언 구조에 따른 추론) 부수토지 카드에도 그대로 적용된다(§4 Q-1).

## 3. 설계

D-1 **verdict에 한 값**: `houseLandOnlyOtherHousehold?: boolean` — `toHouseVerdict`가 `landOnlyBuildingOwnerOtherHousehold(house)`(`land-only-owner-household.ts:84`)로 채운다. `undefined`(verdict 미주입 직접 호출) = 종전.
D-2 **T-1.5**: `resolveCompanionLandRate`에 넘기는 `landNature`를 verdict가 참이면 `undefined`로 한다 — 수동 오버라이드는 그대로 먼저 처리되고(Q-2 a), 자동 일체과세만 `applied:false`로 떨어져 **일반 토지 세율 경로**(보유 1년 미만 50% · 1~2년 40% · 2년 이상 누진)를 탄다. 부수토지 카드는 `propertyType === "land"`라 `nonHousingForRate`가 필요 없다.
D-3 **고지**(Q-3 a): 다른 세대 부수토지 카드가 자기 취득일 기준 2년 미만 보유일 때만 기존 `LAND_ONLY_OTHER_HOUSEHOLD_RATE_NOTICE` 문안을 카드 경고로 단다(그 밖에는 세율 종류가 값에 닿지 않아 말하지 않는다 — 주 카드의 `landOnlyOtherHouseholdRateNotice`와 같은 규칙). `land-only-appurtenant-card-notice.ts`에 함수 하나 + `transfer-tax.ts:559` 배열에 항목 하나(한 줄 — 765줄 유지).

**하지 않는 것**: 같은 세대·소유자 같음(의도된 일체과세 — V-2) · 부수토지 카드의 다주택 중과(O-2) · 후행 취득 토지 표2 연수(O-4) · 입력 필드·Zod·API · UI(V-8). 14 동기화 지점: 신규 입력 필드가 없고 verdict는 **엔진 내부 값**이라 ⑫⑬⑭ 해당 없음.
