# 상가 §164⑥ 환산 — 신고서 「취득가액 = 양도가액」·양도차익 0 원인 분석 및 수정 계획

작성 2026-08-04 · 상태 **원인 확정(입력 오류 + 진단 부재)** · 대상 양도소득세(상업용건물·오피스텔)

법령 표기: 이하 「소득세법 시행령」 제164조 각 항을 §164⑤·§164⑥·§164⑧, 같은 영 제163조 제6항을
§163⑥(개산공제)로 축약한다.

## 1. 증상 (사용자 보고)

환산취득가 모드(상가, 취득 2000-12-07 · 양도 2026-02-16 · 양도가액 540,000,000)에서 신고서가:

| 항목 | 표시 |
|---|---|
| 양도가액 | 540,000,000 |
| **취득가액** | **540,000,000** (= 양도가액) |
| 필요경비 | – |
| 전체 양도차익 | **0** |
| 과세표준·산출세액·결정세액 | 0 |

입력값(화면 확인): 개별공시지가 3시점 3,120,000 / 4,130,000 / 9,815,000(대지 12.59㎡),
건물 기준시가 3시점 23,000,692 / 25,791,920 / 32,952,479, §164⑤ 준용 확인 ON.

**✅ Q-1 해소(2026-08-04 사용자 확인)**: ① 최초고시 ㎡당 고시가를 **2,178,000 → 21,780,000으로
10배 오입력**했다. 재현 케이스 B와 같은 구조 — 최초고시 단가가 양도 단가를 넘어 환산취득가가
양도가액 이상이 됐다. **엔진 산식은 정상이고, 결함은 「그 사실을 사용자에게 알리지 않은 것」이다.**

## 2. 재현 실측 (2026-08-04)

같은 입력에 ① 호별 ㎡당 고시가만 바꿔가며 실제 API를 태웠다(Playwright, 응답 캡처):

| 케이스 | 최초고시 ㎡당 | 양도시 ㎡당 | 양도차익 | 비고 |
|---|---|---|---|---|
| A | 5,000,000 | 5,000,000 | 99,299,587 | 정상 |
| **B** | **6,245,000** | **5,000,000** | **0** | ⬅ **증상 재현** |
| C | 3,000,000 | 5,000,000 | 275,579,753 | 정상 |
| D | (미입력) | (미입력) | — | **validate가 차단**(요청 0건) |

⇒ **미입력 때문이 아니다**(D). 최초고시 단가가 양도 단가보다 **높을 때** 양도차익이 0이 된다.

### 산식상 필연 (버그 아님)

§164⑥ 환산취득가 = 양도가액 × P_A ÷ P_B
 · P_A(취득시 환산기준시가) = INT(최초고시 호별총액 × 취득기준시가합 ÷ 최초고시 기준시가합)
 · P_B(양도시 호별총액) = 양도 ㎡당 고시가 × 연면적

본 건의 기준시가합 비율은 62,281,492 ÷ 77,788,620 = **0.8006**이므로,
최초고시 단가가 양도 단가의 **1.249배**를 넘으면 P_A ≥ P_B → 환산취득가 ≥ 양도가액 → 양도차익 0.

## 3. 확정 결함 — 신고서가 상가 환산을 **실가 모드로 표시**한다

엔진은 상가 §164⑥ 결과를 **실가처럼 주입**하고 `useEstimatedAcquisition: false`로 내린다
(`lib/tax-engine/transfer-tax-commercial-step.ts:119~120,151` — 설계상 의도).

그런데 신고서 표시는 그 플래그로 환산 모드를 판정한다:

```ts
// components/calc/results/transfer/FilingFormTableHelpers.ts:564
} else if (result.usedEstimatedAcquisition && result.estimatedBase !== undefined) {
    // 환산 분기: 취득가액 = estimatedBase(환산취득가), 필요경비 = 개산공제 + 양도비
} else {
    // 실가 분기 — 상가 §164⑥이 **여기로 떨어진다**
    const engineAcqPrice = totalTransferPrice - effGainForAcq - totalEngineExpenses;  // :580
```

⇒ 상가는 항상 **역산**(`양도가액 − 양도차익 − 필요경비`)으로 취득가액을 표시한다(실측: 3케이스 모두 `usedEstimatedAcquisition:false`).

- 양도차익 > 0이면 역산값이 우연히 환산취득가와 **일치**해 문제가 드러나지 않는다(A·C).
- **양도차익 0이면 역산이 `취득가액 = 양도가액`을 내놓는다** — 사용자가 "환산이 안 됐다"고 읽는 화면이 정확히 이것이다.

**결함의 성질**: 값이 틀린 게 아니라 **표시가 유도값**이라 자기검증이 불가능하다. §163⑥ 개산공제도
환산 항목으로 분해되지 않고 필요경비에 합산돼 버린다(증상의 "필요경비 –").

## 4. 수정안

> **우선순위 재조정(Q-1 해소 후)**: 이 사건의 실질 피해는 "오입력을 알아채지 못한 것"이다.
> 사용자는 10배 오입력을 했는데 화면은 「취득가액 = 양도가액 · 세액 0」만 보여줬고, 그래서
> **엔진 결함으로 오인**했다. 따라서 **진단 정보 노출(P1·P2)이 최우선**이다.

### P1 — 신고서 환산 분기에 상가 경로 편입 (핵심)

`result.commercialBuildingValuationDetail`이 있으면 환산 모드로 표시한다.
`usedEstimatedAcquisition` 플래그에 의존하지 않는다 — 그 플래그는 엔진 내부 계산 경로용이지
**표시 계약이 아니다**(dual-truth).

```ts
const cbDetail = result.commercialBuildingValuationDetail;
const isEstimatedDisplay =
  (result.usedEstimatedAcquisition && result.estimatedBase !== undefined) || !!cbDetail;
const estimatedBaseForDisplay = result.estimatedBase ?? cbDetail?.<환산취득가 필드>;
```

- 취득가액 = **환산취득가 직접 표시**(역산 금지)
- 필요경비 = §163⑥ 개산공제 + 양도비로 분해
- ⚠️ `commercialBuildingValuationDetail`의 실제 필드명은 **미확인** → P0에서 확정(§5 Q-2)

> P1의 효과: 역산을 걷어내면 취득가액 칸에 **진짜 환산취득가**(양도가액을 초과하는 값)가 찍힌다.
> 「취득가액 6억 > 양도가액 5.4억」이 보이면 사용자가 즉시 입력을 의심할 수 있다. 지금은 두 값이
> 같게 보여 단서가 전혀 없다.

### P2 — 양도차익 0 케이스 안내

산식상 환산취득가가 양도가액 이상이 될 수 있다. 지금은 결과가 0으로만 나와 사용자가 원인을 알 수 없다.

결과 화면에 근거를 밝힌다: "최초고시 ㎡당 고시가(x)가 양도시(y)보다 높아 환산취득가가 양도가액
이상입니다 — 양도차익이 0입니다. 입력한 두 고시가를 확인하세요."

**자동 보정은 하지 않는다** — 법령상 환산취득가가 양도가액을 넘는 것을 금지하는 규정을 확인하지
못했다(§5 Q-3). 확인 전까지 계산은 그대로 두고 **안내만** 한다.

### P3 — 입력 단계 경고 (승격 — 실사례가 나왔다)

①에서 **최초고시 ㎡당 고시가 > 양도시 ㎡당 고시가**이면 그 자리에서 경고한다.
자릿수 오입력(10배)은 이 부등호로 대부분 걸린다.

- **차단은 하지 않는다** — 최초고시가 양도보다 높은 것이 법령상 불가능하지는 않다(시세 하락 구간).
  경고만 띄우고 계산은 진행한다(자동 안분 fallback 금지 정책과 같은 취지 — 임의 보정 금지).
- 문구 예: "최초고시(2005) ㎡당 고시가가 양도시보다 높습니다 — 자릿수를 확인하세요.
  이 경우 환산취득가가 양도가액을 넘어 양도차익이 0이 될 수 있습니다."
- 같은 검사를 ③ 건물 기준시가·② 개별공시지가에도 넣을지는 P3 착수 시 판단(과잉 경고 주의).
