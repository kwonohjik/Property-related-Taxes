## 3. 결함과 수정안

### D-1 장특 보유기간 — 두 지점 (Q-1)

1. **일반 경로**(`transfer-tax-lthd.ts` split 분기): 통칙 게이트 `ownsLand && ownsBuilding && …`가 토지만 본인을 뺀다. `selfOwns === "land_only"`도 허용한다. 비교 대상(주택 보유연수)은 `splitDetail.building.holdingYears`로 건물을 소유하지 않아도 채워져 있다. 다른 세대는 `useTable2`가 꺼져 있어 leaf가 표1을 그대로 돌려주므로 게이트를 열어도 값이 변하지 않는다.
2. **⑳ 경로**(`buildRentalLthdParts`): `selfOwns !== "both"` → undefined가 토지만 본인을 뺀다. `building_only`만 빼고, 토지만 본인은 `land = { gain, holdYears: 토지 연수, houseHoldYears?: 토지가 더 오래되면 건물 연수 }` · `building = { gain: 0, … }`로 만든다. 합 일치 방어(`landGain + buildingGain === housingGain`)는 그대로 쓴다(건물분 0은 #2652가 이미 보장).

효과: 2.1 표의 「근거가 가리키는 값」과 일치. 합가일은 입력이 없어 토지가 먼저일 때 표2 보유연수는 **주택 취득일부터의 상한값**이다 — 이미 달린 합가일 고지(G-3 Q-3 a)가 그 한계를 말한다. 새 입력·결과 필드 없음(14지점 불필요).

### D-2 같은 세대 세율 기산 (Q-2)

`landOnlyRateInput`(`land-only-owner-household.ts`)을 `max(토지, 주택)`으로 바꾸고, 단건 STEP 7(`transfer-tax.ts:680` 인라인 치환)이 이 함수를 쓰게 한다. 토지가 나중이면 종전과 같고(#2652), **토지가 먼저일 때만** 주택 취득일이 기산일이 된다. 다건 파트 시드(`transfer-tax-split-part-seeds.ts`)·다건 엔진 교정(`aggregate-asset-records.ts`)은 이미 `max`라 단건이 따라온다.

### D-3 다른 세대 세율 종류 (Q-3)

같은 함수의 다른 세대 분기: 취득일 = 토지 취득일, `nonHousingForRate: true`(이미 있는 내부 필드 — 겸용 상가 카드가 쓴다). 단기세율이 「주택, 조합원입주권」 괄호 밖(일반 자산)으로 판정된다. 다건은 파트 시드(`transfer-tax-split-part-seeds.ts:49`)가 주택 `max`로 기산하므로 다른 세대는 토지 취득일로 가르고 `nonHousingForRate`를 싣는다(C4). 2021.6.1. 전 양도분은 현행 단기세율 연혁(`data/short-term-rate-history.ts`)이 이미 가른다.
