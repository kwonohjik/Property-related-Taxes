- 작성: 2026-10-28 · 상태: 📝 계획(사용자 결정 대기 — §2) · 출발점: `bg-single-carryover-statement-price-rows.plan.md` §1.2 · §6(#2692) — 미채택 시나리오 요약 카드·비교 카드의 B 취득가액 300,000,000(채무비율 미적용)을 별건으로 남겼다. 사용자 요청(2026-10-28) 「별건을 계획서 작성해」. **측정 중 묶음(함께 양도·지분 분할) × B 채택에서 같은 echo가 더 큰 결함을 낸다는 것을 확인해 범위에 넣었다(§1.2).**

## 1. 현상 (실측)

시료: 토지 · 부담부증여 시가 400,000,000 · 채무 80,000,000(채무비율 0.2) · 당초 증여자 감정가액 250,000,000 · 취득시 기준시가 150,000,000 · 증여 당시 평가액(`giftDateValuation`) 300,000,000 · 양도인 실지취득가액(`bgActualAcquisitionLand`) 300,000,000(별도 표기 시 280,000,000).

### 1.1 단건 — 미채택 시나리오 요약 카드·비교 카드 B 열

| 시료 | 채택 | 카드 「취득가액 [증여 당시 평가액]」 | B의 실제 취득가액(슬롯) | B 양도차익 |
|---|---|---|---|---|
| 감정가액 · 증여세 2M · 실지취득 300M | A | **300,000,000** | 60,000,000 | 20,000,000 |
| 감정가액 · 증여세 2M · 실지취득 280M | B | **300,000,000** | 56,000,000 | 24,000,000 |
| 환산 · 증여세 0 · 실지취득 280M | B | **300,000,000** | 45,000,000 | 33,920,000 |
| 실지 · 증여세 2M · 실지취득 280M | B | **300,000,000** | 56,000,000 | 24,000,000 |
| 주택(토지 100M · 건물 50M) 감정가액 · 증여세 2M | A | **300,000,000** | (양도 80,000,000 − B 양도차익 20,000,000 = 60,000,000) | 20,000,000 |

- 카드 값 300,000,000은 시료 입력(`giftDateValuation`)을 그대로 적은 것이고, **같은 열의 양도차익은 §159 슬롯으로 계산한 값**이라 「양도가액 − 취득가액 = 양도차익」이 서지 않는다(80,000,000 − 300,000,000 ≠ 20,000,000). 실지취득가액을 280,000,000으로 바꾸면 슬롯은 56,000,000으로 움직이는데 카드는 300,000,000 그대로다 → 슬롯은 `giftDateValuation`이 아니라 **양도인 실지취득가액 × 채무비율**을 읽는다.
- 미채택 요약 카드(`CarryoverScenarioAFilingCard`·`CarryoverScenarioBFilingCard`)는 **양도가액 행이 그려지지 않는다**(`shownTransferPrice > 0` — 결과뷰가 폼 계약금액 0을 넘긴다. #2692 §1.2). A 카드의 취득가액(당초 증여자 취득가)은 부담부증여를 이미 반영해 맞다(50,000,000).

### 1.2 묶음(함께 양도 · 지분 분할) × B 채택 — 자산별 취득가액 300,000,000 · 필요경비 **음수** (합산 신고서 항등식 깨짐)

| 시료(전부 route 200 · ⑧ 통과) | 채택 | 자산별 양도 / 취득 / 필요경비 / 차익 | 합산 신고서 합계열 [양도, 취득, 필요경비, 차익] |
|---|---|---|---|
| 함께 양도 · 증여세 2M × 2 | A | 80M / 50M / 1.3M / 28.7M | [160M, 100M, 2.6M, 57.4M] — 정상 |
| 함께 양도 · 증여세 30M × 2 | **B** | 80M / **300M** / **−240M** / 20M | [160M, **600M**, **0**, 40M] — 160 − 600 − 0 ≠ 40 |
| 지분 50/50 · 증여세 30M | **B** | 40M / **150M** / **−120M** / 10M | [80M, **300M**, **0**, 20M] |
| 혼합(1번 이월과세 B + 2번 매입 감정가액) | **B**(1번) | 1번 80M / **300M** / **−240M** / 20M · 2번 80M / 50M / 1.08M / 28.92M | [160M, **350M**, 1.08M, 48.92M] |
| 함께 양도 · 증여세 30M × 2 · 실지취득 280M | **B** | 80M / **300M** / **−244M** / 24M | — |

- 필요경비 음수는 합산 신고서·명세서의 `Math.max(0, …)` clamp에 잘려 0으로 보인다 → 「취득가액 600,000,000 · 필요경비 0 · 양도차익 40,000,000」. 결정세액(4,365,000 · 1,365,000 · 4,835,400 · 5,565,000)·양도차익은 정상이다.
- A 채택은 정상(자산별 취득가액 50,000,000). **B가 채택되는 순간** 틀린다 — 증여세 상당액이 커서 B가 채택되는 것은 흔한 시료다.

### 1.3 원인 (코드로 확정)

- B 취득가액 echo: `scenarioB.acquisitionPrice = ct.giftDateValuation`(`transfer-tax-carryover.ts:553`, 조기반환의 `makeEmptyScenarioB(ct.giftDateValuation)`도 같다). 일반(비부담부증여) 이월과세는 B의 취득가액이 실제로 `buildInputB`의 `acquisitionPrice = giftDateValuation`이라 맞지만, **부담부증여(§159)는 엔진이 STEP 0.48에서 취득가액을 §159 값(양도인 실지취득가액 × 채무액 / 증여재산 평가액 등)으로 덮어쓴다** — 그 값이 `resultB.transferBurdenedGiftBreakdown`의 슬롯이다. A는 이미 슬롯을 echo로 싣는다(`bgAcqPrice` — `transfer-tax-carryover.ts:344`, 주석에 「표시와 실제 쓰인 값이 어긋난다」 선례가 있다).
- 묶음 표시: `resolveDisplayAcquisitionAndExpense`(`transfer-tax-aggregate-display-echo.ts`)가 `adoptedCarryoverAcquisitionPrice`(= B 채택이면 `scenarioB.acquisitionPrice`)를 §166·분리·**§159 명세(`bgTotals`)보다 앞**에 둔다(위계 주석 「이월과세 → §166 → 분리 → §159」). 그래서 B 채택 묶음의 자산별 취득가액이 300,000,000이 되고, 필요경비는 「양도가액 − 취득가액 − 양도차익」 역산이라 −240,000,000이 된다. 그 위계는 B를 부담부증여로 인식하지 못한 채 만들어졌다.
- 단건 결과뷰의 채택 시나리오 표(상세 명세서·신고서 양식)는 #2695가 슬롯으로 고쳐 정상이다. 이 결함은 **카드(echo 직접 읽기)** 와 **묶음 표시**에 남아 있다.

## 2. 사용자 결정 (대기)

### Q-1 고칠 곳

- **(a) 엔진 echo + 묶음 표시 위계 둘 다 (권장)**: ① `scenarioB.acquisitionPrice`를 부담부증여일 때 `resultB`의 §159 슬롯 합으로 싣는다(비부담부증여는 `giftDateValuation` 그대로) → 미채택 요약 카드·비교 카드가 맞는다. ② `resolveDisplayAcquisitionAndExpense`에서 §159 명세가 있으면(재개발 §166 제외) 이월과세 채택 echo보다 슬롯을 먼저 읽는다 → B가 **적용배제 조기반환**(B 미계산 · `makeEmptyScenarioB`)으로 채택돼도 묶음 표시가 맞는다.
- (b) 엔진 echo만: 카드·묶음(계산된 B)은 닫히지만 적용배제 조기반환 B 채택 묶음은 남는다(V-2).
- (c) 묶음 표시 위계만: 합산 신고서는 닫히지만 단건 카드는 300,000,000 그대로.

### Q-2 B 카드 라벨 (부담부증여일 때)

- **(a) 「취득가액 [수증자 취득가 × 채무비율 — 소령 §159①1호]」 (권장)**: 값이 슬롯이면 「증여 당시 평가액」이라는 라벨은 거짓이다(§1.1 — 실지취득가액 280M이면 56M). 엔진이 `CarryoverScenarioBDetail`에 **부담부증여 안분 취득가액임을 알리는 echo**(`acquisitionIsBurdenedGiftShare?: boolean`)를 싣고 두 카드가 그것으로 라벨을 가른다(UI가 부담부증여 여부를 다른 필드로 역추론하지 않는다 — `feedback_ui_engine_dual_truth_avoidance`). 조문 인용은 구현 때 KoreanLaw로 본문 재확인(코드는 이미 `buildBgAcquisitionFormula`가 「시행령 §159①1호」를 인용한다).
- (b) 라벨 「증여 당시 평가액」 유지 + 값만 슬롯: 라벨과 값이 다른 것을 가리켜 오독을 부른다.
- (c) 일반 라벨 「취득가액 [채무비율 안분]」: 근거 조문을 밝히지 않는다.

### Q-3 미채택 요약 카드의 양도가액 행

- **(a) 결과뷰가 부담부증여 슬롯의 양도가액을 `transferPrice`로 넘겨 행을 그린다 (권장)**: 양도가액은 A·B가 같다 — §1 모든 시료에서 80,000,000(채택 슬롯 기준). 단건 결과뷰는 #2695의 `resolveBgCarryoverSingleDisplay(result)?.transferPrice`를 재사용.
- (b) 숨김 유지: 카드 두 장이 「취득가액 − 양도차익」만 보이고 양도가액이 없다.
