## 1. 검증된 법령 (법제처 Open API, 2026-07-31 · MST 280405 · 시행 2026-07-01)

### 1.1 §104⑤ — 비교과세

> ⑤ 해당 과세기간에 §94①1호·2호 및 4호에서 규정한 자산을 **둘 이상 양도하는 경우** 양도소득
> 산출세액은 다음 각 호의 금액 중 **큰 것**(… **감면세액을 차감한 세액이 더 큰 경우의 산출세액**을
> 말한다)으로 한다. 이 경우 제2호의 금액을 계산할 때 §104①8호 및 9호의 자산은 동일한 자산으로
> 보고, **한 필지의 토지가 §104의3에 따른 비사업용 토지와 그 외의 토지로 구분되는 경우에는
> 각각을 별개의 자산으로 보아** 양도소득 산출세액을 계산한다.
> 1. 해당 과세기간의 양도소득과세표준 **합계액**에 §55①에 따른 세율을 적용하여 계산한 산출세액
> 2. §104①~④ 및 ⑦에 따라 계산한 **자산별** 산출세액 합계액. **다만, 둘 이상의 자산에 대하여
>    §104① 각 호, ④ 각 호 및 ⑦ 각 호에 따른 세율 중 동일한 호의 세율이 적용되고, 그 적용세율이
>    둘 이상인 경우 해당 자산에 대해서는 각 자산의 양도소득과세표준을 합산한 것에 대하여**
>    §104①·④ 또는 ⑦의 각 해당 호별 세율을 적용하여 산출한 세액 중에서 큰 산출세액의
>    합계액으로 한다.

⚠️ **「④ 각 호 및 ⑦ 각 호」를 생략하지 말 것** — v1.8까지 이 인용이 "§104① 각 호 …"로
줄여 쓰여 있었는데, **D-11의 논거가 바로 ⑦ 각 호**(다주택 중과)다. 단서는 ①호뿐 아니라
⑦호에도 걸린다.

**단서를 빠뜨리면 2호가 항상 과소**해진다. 누진세율 호에 해당하는 자산을 개별 계산하면
누진공제를 자산 수만큼 받기 때문이다.

### 1.2 프로젝트 정본은 단서를 **절반만** 구현하고 있다 (v1.9 정정)

`lib/tax-engine/transfer-tax-aggregate-helpers.ts:415-419` 주석이 단서를 그대로 옮겨 놓았고,
`:429-446`이 「적용 호가 갈리면 본문(자산별 합계), 같으면 합산 1회」로 분기한다.
2026-07-29 #591 감사 R7에서 세액까지 검증됐다(입력 순서 의존 324,060,000 / 274,060,000
→ 도출값 280,120,000).

**즉 D-1은 새 해석이 필요한 문제가 아니라, 정본이 이미 쓰는 규칙을 split 경로에만 빠뜨린
내부 불일치다.**

> 🔴 **v1.9 정정 — "정본은 단서를 이미 구현하고 있다"는 절반만 맞다.**
> 단서는 요건이 **둘**이다: ⓐ「동일한 호의 세율이 적용되고」 ⓑ「그 **적용세율이 둘 이상**인 경우」.
>
> | 요건 | 정본 | 판정 |
> |---|---|---|
> | ⓐ 동일 호 → 과세표준 합산 1회 | ✅ 구현 (`:432` `mixedTier` 분기) | D-1은 이 규칙을 split에 빠뜨린 것 |
> | ⓑ 적용세율이 둘 이상 → **합산액에 호별 세율을 각각 적용해 큰 것** | ❌ **미구현** | **D-11** — 자산별 `calcTax`가 고른 승자로 그룹을 나눠 개별 세액을 합한다 |
>
> ⇒ D-1(split만의 결함)과 D-11(정본 자체의 결함)은 **같은 단서의 다른 절**이다.
> §1.2를 근거로 "정본을 그대로 따르면 된다"고 판단하지 말 것 — D-11 국면에서는 정본도 틀렸다.

### D-8 — 모델 A는 §104⑤ 어느 호도 아니다 (**v1.8 재판정 — 유보 해소**)

> 🔴 **v1.7까지의 「세무 판단 대기」 결론은 폐기한다.** 유보 사유였던 "§104⑤ 본문의

> ⓐ 겸용주택은 **토지 + 건물**이라 §94①1호 자산이 이미 둘이다(선행 계획서 G-1이 split
>    경로에서 이미 채택해 §104⑤ MAX를 적용 중인 논거 — 겸용만 다르게 볼 근거가 없다).
> ⓑ 그와 별도로 §104⑤ 본문 **후단**이 한 필지 안 비사토/그 외를 **각각 별개 자산으로
>    의제**하며, 교재가 든 첫 예시가 「건물의 부속토지 중 기준면적 이내분/초과분」이다.
>
> ⇒ 남은 것은 세무 판단이 아니라 **구현 결정**이다.

| | 산식 | 위치 |
|---|---|---|
| **모델 A** | `누진(합산 과세표준) + 10%p × 비사토 귀속 과세표준` | 겸용 `transfer-tax-mixed-use-totals.ts:160-164` · 단건 `transfer-tax-rate-calc.ts:367-371`(**D-10**) |
| **모델 B** = §104⑤ | `MAX(1호 합산누진, 2호 호별 산출세액 합)` | split `transfer-tax-split-rate.ts:545-551·587` |

**모델 A가 틀린 이유는 3가지다**:

1. **법정 산식이 아니다** — §104⑤1호는 가산 **없는** 합산 누진이고, 2호는 **호별** 산출세액
   합(비사토는 §104①8호 = 누진 + 10%p를 **자기 과세표준에만**). 모델 A는 1호의 과세표준
   범위(전체 합산)에 2호의 가산을 얹은 **제3의 산식**이다.
2. **개정 전 취급과도 다르다** — 2018.4.1. 전에는 §104① 후단으로 **필지 전체**가 비사업용
   중과였다(§1.5). 모델 A의 부분 안분은 그보다 가볍지만, 그 취급은 대법원 2012두15371과
   §104⑤ 후단 신설로 **이미 폐기**됐다. 즉 모델 A는 **어느 시점 법에도 근거가 없다**.
3. **항상 법정 상한을 초과한다**(아래 실측 · 수학적으로 예외 없음).

**모델 A ≥ 모델 B가 항상 성립**한다. 누진세율의 열등가성(`Σ누진(파트) ≤ 누진(합계)`)에서
`2호 ≤ 누진(합계) + 10%·N = A`이고 `1호 = 누진(합계) ≤ A`이기 때문이다. 등호는 비사토가

2024-12-01 취득 → 2026-06-01 양도 = **1년 6개월**), 기본공제 소진.

```
[엔진] 그룹: progressive[A] base=78,000,000 tax=12,960,000
             short_term[B,C] base=400,000,000 tax=240,060,000   ← 합산 base인데 세액은 개별 합
[엔진] 산출세액 253,020,000 (byGroups 채택 · byGeneral 165,260,000)
```

| 계산 | B·C 부분 | 총 산출세액 |
|---|---:|---:|
| **엔진 현행**(개별 MAX 후 합) — B 90,000,000 + C 150,060,000 | 240,060,000 | **253,020,000** |
| **교재 사례2 규칙**(합산 4억 → MAX(60% 240,000,000, 중과 254,060,000)) | 254,060,000 | **267,020,000** |
| | | **과소 14,000,000** |

B는 개별로 단기 60%가 이기고(90,000,000 > 82,060,000), C는 개별로 중과가 이긴다
(150,060,000 > 150,000,000). 승자가 갈리는 순간 `surcharge` 값이 달라져 `mixedTier`가 켜지고
**자산별 합**으로 떨어진다 — 그룹 과세표준은 이미 400,000,000으로 합산돼 있는데도 그렇다.

**영향 범위** — 겸용(`buildTotalTax`)과 split은 **중과 파트가 항상 1개**라 발현하지 않는다.
**다건 aggregate 전용** 결함이다. 발현 조건: 같은 과세기간에 **주택 2채 이상**을 양도하고,
그 주택들이 **동일 호의 중과 대상**이면서 **보유 2년 미만**이어서 자산별로 승자가 갈릴 때.

🔶 **미확인** — `short_term` 그룹 외에 `multi_house_surcharge` 그룹에서도 같은 구조가
발현하는지는 조합을 구성하지 않았다.

⚠️ **§104④(지정지역 비사토) 후단은 대상이 아니다** — 법문에는 같은 구조의 후단이 있으나
`calcTax`에 **§104④ 분기 자체가 없다**(§4.1-R 실측 — P1에서 `104-4-3` 타입을 speculative로
판정해 폐기한 근거와 동일). 엔진에 없는 분기를 미확인 항목으로 세우지 말 것.

### 4.2 D-2·D-3 — 겸용주택 세율·비과세

**설계 방침: 세율 적용을 `calcTax`로 일원화하지 않는다.** 겸용 엔진은 주택분·상가분·비사토분
3부분을 자체 파이프라인으로 만들고 `buildTotalTax`가 조립하는 구조라, `calcTax`로 갈아끼우면
개산공제·장특·안분이 얽힌 9파일이 전부 흔들린다(Surgical Changes 위반).

대신 `buildTotalTax`에 **세율 결정 책임만** 추가한다:

```
buildTotalTax(housingIncome, commercialIncome, nonBizIncome, brackets,
              basicDeductionLimit,
+             rateContext: { isUnregistered, housingHoldingMonths, commercialHoldingMonths })
```

- **D-3 미등기** — §91①·§95②·§103①1호 단서는 세율 결정보다 **앞단**에서 걸린다.
  비과세·장특은 각 part 계산에서, 기본공제는 `buildTotalTax`에서 확정되므로
  「상단 1곳 게이트」로는 안 되고 `isUnregistered` 플래그가 ⓐ주택분 비과세 판정
  ⓑ각 part 장특 ⓒ`buildTotalTax` 기본공제 ⓓ세율의 **4개 지점**에 모두 도달해야 한다.
- **D-2 단기세율** — 주택분은 §104①2·3호 괄호("이에 딸린 토지 포함")로 60%/70%,
  상가분은 40%/50%. 보유기간 기산일은 파트별(`landAcquisitionDate`/`buildingAcquisitionDate`).
  주택분 부수토지 기산일은 선행 계획서 G-3에서 확정한 **`max(토지, 건물)`** 규칙을 재사용한다.

> **⚠️ 자기모순 정정 (v1.1)** — v1.0은 "§104⑤ MAX를 도입하되 비사토 +10%p 모델(모델 A)은
> 건드리지 않는다"고 썼다. **이는 성립하지 않는다.** §104⑤ MAX를 도입하는 순간 비사토는
> 2호 안에서 자기 과세표준에만 +10%p를 받으므로 그것이 곧 모델 B이고, 모델 A는 대체된다.
> 동시에 성립시킬 수 없다.
>
> **정정된 P3 범위 — 비사토 파트가 없는 겸용주택으로 한정한다.**
> `buildTotalTax`의 `nonBizIncome === 0`이면 모델 A의 **가산 항이 0**이 되어
> `A = 누진(합산 과세표준) = §104⑤1호`가 된다. 즉 D-8이 다투는 쟁점
> (「비사토 +10%p를 합산 누진에 가산하느냐, 2호 안에서 자기 과세표준에만 붙이느냐」)이
> **발생하지 않는다.** `nonBizIncome > 0`이면 D-8 판단 전까지 **현행 경로(모델 A)를 유지**한다.

그 함수가 이미 `MAX(perAssetTotal, aggregateProgressive)`를 수행하고(`:587`),

**④ 다건은 자산별로 단건 엔진을 다시 부른다**(`transfer-tax-aggregate.ts:264`
`calculateTransferTax(singleInput, rates)`) ⇒ 각 자산이 `resolveSplitAwareTax`를 탄다.
따라서 **자산 내부 MAX 결과가 aggregate 2호에 들어간다** — 이는 split 자산이 **이미 그렇게
동작**하는 구조이고, 그 정합성 쟁점은 **D-7**로 별도 등록돼 있다. P8은 split과 **같은 구조**를
따라 내부 일관성을 지키고, 다건 정합은 D-7/D-11 범위로 남긴다.

#### 설계 — `resolveSplitAwareTax`에 부분 비사토 분기 추가

```
현행:  if (!ctx.splitDetail) return fallback();          // = calcTax 단독 = 모델 A
정정:  if (!ctx.splitDetail) return computePartialNblTax(ctx) ?? fallback();
```

`computePartialNblTax` — 진입 조건 `isNonBusinessLand && 0 < ratio < 1`:

```
nblBase   = applyRate(taxBase, ratio)          // 현행 모델 A와 **같은 안분 기준**(면적비율)
otherBase = taxBase − nblBase
2호 = calcTax(nblBase,   {isNonBusinessLand:true,  ratio:1})   // §104①8호 + 후단
    + calcTax(otherBase, {isNonBusinessLand:false})            // §104①1호(또는 단기)
1호 = calculateProgressiveTax(taxBase, brackets)               // §55① 누진만
반환 = MAX(1호, 2호)
```

- **세율 로직 신규 0** — 각 파트를 `calcTax`에 그대로 위임한다. 2년 미만이면 §104① 후단
  (토지 단기 50%/40%)도 `calcTax`가 이미 처리한다.
- **기본공제 안분은 면적비율 유지**. split은 「최고세율 파트에 전액 귀속」을 쓰지만, 현행
  모델 A가 `applyRate(taxBase, ratio)`로 안분하고 있어 **그 기준을 바꾸면 P8 범위를 넘는다**
